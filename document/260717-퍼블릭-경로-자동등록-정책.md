# 퍼블릭 경로 자동 등록 정책

| 항목 | 내용 |
|------|------|
| 문서 유형 | **정책 SoT** — 퍼블릭 경로(routePublications) 등록 조건·자동 심사 규칙의 단일 진실 |
| 최초 작성 | 2026-07-17 |
| 상태 | **반영중** |
| 관련 | [결정 로그](260707-RTW-결정-로그.md) · [상태보드 §3.6](260707-RTW-기능-인벤토리-상태보드.md) · [Ontology](260714-RTW-Ontology.md) |

> **핵심 결정 (2026-07-17)**: 관리자 수동 검수를 폐기하고, 아래 조건을 통과하면 **자동 등록**한다.
> 철학: **"등록은 자동, 노출은 사용자 평가"** — 퍼블릭 경로의 목적은 좋은 코스의 공유이지 운동 기록 인증이 아니다.
> **완주 조건 폐기**: 완주 요구의 원래 목적은 품질이 아니라 **경로 선점 방지**였다. 선점은 §2의 직접 장치로 막고, 지도만 보고 설계한 좋은 코스도 등록을 허용한다.

## 1. 자동 등록 조건 (필수 게이트)

신뢰 경계는 **Cloud Function**(`autoReviewPublicRouteRequest`, Admin SDK). 클라이언트 검사는 UX 프리체크일 뿐이며 최종 판정은 서버가 한다.

| # | 게이트 | 값 | 이유 |
|---|---|---|---|
| G1 | 최소 연장 | **≥ 5,000 m** (운영 목표. **현재 코드는 dev 완화 100m** — 출시 전 복원) | 테스트·의미 없는 경로 방지. 완주 조건 폐기로 dev 완화 사유는 소멸(지도 설계만으로 5km 생성 가능)했으나, 로컬 테스트 편의상 100m 유지 중 |
| G2 | 최대 연장 | **≤ 120,000 m** | 비정상 초장거리 차단 (2026-07-17 300km→120km 하향) |
| G3 | 제목 | 1~80자, 제어·숨김 문자/줄바꿈/과반복 금지 | 의미 없는·깨진 제목 방지 |
| G4 | 금칙어 | **서버 내장 한/영 비속어 리스트**(정규화 매칭 + 예외어: 시발점·시발역 등), 제목·소개 모두 | 부적절 콘텐츠 차단. 외부 API 없이 동작 — 리스트 품질만큼 커버 (한계 인지) |
| G5 | 개인정보·링크 | 전화번호·이메일 패턴 차단, URL 합계 ≤ 2 | 광고·개인정보 노출 방지 |
| G6 | 최소 포인트 | 좌표 ≥ 20개, ≤ 5,000개(기존 상한), 밀도 ≤ max(500, km×400) | 퇴화 geometry·비정상 데이터 차단 |
| G7 | 최소 직경 | 경로 외접 사각형(bbox) 대각선 **≥ 500 m** | 좁은 영역을 뱅뱅 도는 스팸 차단. ※ "시작=종료 근접 차단"은 순환·왕복 코스가 정당하므로 **채택 안 함** — 이 게이트가 그 의도(퇴화 경로 차단)를 대체 |
| G8 | 중복 | 지문(fingerprint) 동일 published/pending 차단 + **같은 savedRoute 1회만 출판** + 지문·geometry가 원본 savedRoutes 문서와 일치해야 함(위조 방지) | 동일 경로 재등록·경로 바꿔치기 방지 |
| G9 | 유사도 | 기존 published·타 pending과 형태 유사도 **≥ 90%**(동일 profile) 차단 | 사실상 같은 코스 난립 방지 |
| G10 | 태그 | 1~3개, 허용 목록 내 | 기존 규칙 유지 |
| G11 | tier | registered_free/paid/admin (Guest 불가) + 제목 정책 동의 | 기존 규칙 유지 |
| G12 | 횟수 quota | free 5회/일 · paid 10회/일 (기존 서버 quota) | 남용 속도 제한 |

**소개(publicSummary)**: 선택 입력(0~500자). 입력 시 G3~G5 검사 대상. — 빈 등록을 막지 않는 이유: 진입 마찰 최소화.

**의도적으로 넣지 않는 조건**: 완주 여부 · 평균 속도 · 운동 시간 · 고도 · 난이도 — 운동 기록 인증이 아니므로.

## 2. 선점 방지 — 미완주 출판 상한 (완주 조건의 대체 장치)

| tier | 미완주 출판 상한 |
|---|---|
| registered_free | **3** |
| registered_paid | **5** |
| admin | 무제한 |

- **미완주 출판** = 본인 published publication 중, 원본 `savedRoutes` 문서가 완주(completed=1)가 아니거나 삭제된 것.
- 상한 도달 시 신규 자동 등록 거절: *"미완주 상태로 등록한 퍼블릭 경로가 N개입니다. 기존 코스를 완주하면 추가 등록이 가능합니다."*
- **Ride-to-unlock**: 등록해 둔 코스를 실제로 완주하면 슬롯이 회복된다 — 설계만 하는 선점꾼은 3~5개에서 멈추고, 실제로 달리는 사용자는 계속 등록 가능.
- 원본 savedRoute를 **삭제해도 슬롯은 회복되지 않는다**(삭제=미완주 취급) — 삭제로 상한 우회 불가.
- ※ 계획 단계의 "pending 개수 상한" 표현은 본 장치로 정밀화 — 자동 심사에서 pending은 수 초 내 소멸하므로 pending 상한은 선점을 못 막고, 동료 제안 원의(未완주 **경로** 개수 제한)가 이것이다.

## 3. 아키텍처 · 흐름

```
클라이언트                              서버 (신뢰 경계)
─────────                              ────────────────
① 로컬 프리체크(빠른 피드백)
② publicRouteRequests 생성 (pending)   ← Rules: 소유·구조 검증 (완주 요구 제거)
③ CF autoReviewPublicRouteRequest 호출 → G1~G12 + §2 전체 재검증 (Admin SDK)
                                        ├ 통과: publication 생성 + 신청 approved (원자적)
                                        └ 탈락: 신청 rejected + rejectionReason 기록
④ 결과 표시: 등록 완료 / 거절 사유
```

- `routePublications` 클라이언트 직접 create는 **계속 금지**(Rules) — 자동 등록은 전부 CF 경유.
- 자동 심사 필드: `autoReviewed: true`, `reviewerUid: null`. 수동 심사와 구분 가능.
- **탈락도 기록**: `status: "rejected"` + 사유 — 이력·통계·정책 튜닝 근거.
- **CF 연결·서버 오류 폴백(2026-07-18 개정)**: 자동 검수 CF에 도달하지 못하면(projectId 미설정·네트워크·5xx·응답 파싱 실패 등) 클라이언트가 방금 만든 pending 신청을 **즉시 회수(withdraw)** 하고 사용자에게 *"잠시 후 다시 시도"* 를 안내한다. → pending이 갇히지 않고 같은 savedRoute 재신청 차단(§G8)에도 걸리지 않아 곧바로 재시도 가능. **관리자 수동 심사로 폴백한다는 종전 약속은 폐기.**
- **콘솔 전용 안전망**: 관리자 심사 UI(`AdminPublicRouteQueue`·심사 탭·진입 버튼)는 제거됐다(2026-07-18). CF 회수마저 실패해 pending이 예외적으로 남는 극단 상황만을 위해 심사 백엔드(`loadPendingPublicRouteRequests`·`approvePublicRouteRequest`·`rejectPublicRouteRequest`·`isRouteReviewer`·`config/routeReviewers`)는 코드로 유지하되, 화면 진입점 없이 콘솔로만 조작한다. 신고·회수(archived)도 이 경로.
