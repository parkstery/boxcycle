## 0. 먼저 — 이 도구들이 있는 이유

Phase 5 의 성과는 폴더가 예뻐진 것이 아니다. **조용히 깨져 있던 것 다섯**을 찾은 것이다
(셀 ID 3중 복제 · 동행 페달 계단화 · 레이어 top 다툼 · red 계약 시험 방치 · 에뮬레이터 지도
블랙아웃). 전부 **에러도 로그 이상도 내지 않았다.**

그래서 이 도구들은 「정리」가 아니라 **「조용한 파손을 소리나게 만드는 장치」** 다.
그 목적을 잊으면 게이트는 통과 도장이 된다.

| 도구 | 역할 | 언제 |

## 2. 구조를 바꾸는 표준 절차

```
① 선언을 먼저 고친다        apps/web/dep-layers.json
② 보고 모드로 영향을 본다    node scripts/check-dep-direction.mjs
③ codemod 로 옮긴다         node scripts/move-lib-files.mjs <plan.json>
④ 확인한다                  tsc · npm run test:next-ride · --check
⑤ 게이트를 세웠으면 깨뜨린다  node scripts/verify-gates-alive.mjs 에 케이스 추가
```

`plan.json` 은 `{ "lib/<옛경로>": "lib/<새경로>" }`(`apps/web/src` 기준). 선언에서 생성하면
사람이 손으로 적을 일이 없다.

> **이동은 위반을 줄이지 않는다 — 위치만 바뀐다.** 위반을 갚으려면 의존을 뒤집거나
> 포트를 넣어야 한다. 그 구분을 흐리면 「정리했다」는 착각만 남는다.

## 3. 게이트를 다룰 때의 규율 넷

### ① 세웠으면 깨뜨린다

「통과」는 게이트가 살아 있다는 증거가 아니다. `verify-gates-alive.mjs` 가 이것을 자동화한다
— 게이트마다 **「이런 잘못을 저지르면 막아야 한다」** 는 변조를 만들어 실제로 실패하는지 본다.

```
node scripts/verify-gates-alive.mjs      # 깨끗한 트리에서만
```

새 게이트를 붙이면 **이 파일에 파괴 케이스를 함께 넣는다.** 넣지 않은 게이트는
다음 사람이 살아 있는지 알 수 없다.

### ② 판정 앞에 M0 를 세운다

「0건이니 통과」 앞에 **「세는 일이 작동하는가」** 를 둔다. `check-dep-direction` 의 M0 7항목이
본보기다 — 수집 하한 · 알려진 사실 재현 · **검출기 생존(합성 그래프)** · 전원 배정 ·
**깨진 경로 0** · 수집 범위 포함.

특히 **깨진 코드가 게이트를 좋아 보이게 만든다.** 이동이 중단돼 import 가 깨졌을 때
위반이 59 → 25 로 「줄었다」 — 해석 못 한 엣지를 버렸기 때문이다.

### ③ 고치면 죽는 검산을 만들지 않는다

「알려진 결함 X 가 검출되는가」로 도구 생존을 확인하면 **X 를 고치는 순간 죽는다.**
경로를 박아 둔 감시자도 파일을 옮기면 죽는다. 둘 다 Phase 5 에서 실제로 겪었다.

→ **합성 입력으로 알고리즘 자체를 시험**하고, 실제 대상은 **선언에서 조회**한다.

### ④ 규칙 완화를 눈에 보이게 한다

게이트를 통과하는 가장 쉬운 길은 코드가 아니라 **규칙을 넓히는 것**이다. 실제로
`peerMotion.mayImportRepoOf=["trail"]` 한 줄이면 위반이 41 → 35 로 준다.

그래서 baseline 이 **허용 규칙의 해시 지문**을 갖는다. 지문이 바뀌면 수치와 무관하게
실패하고 재고정을 요구한다 — **의도한 정당한 변경도 걸리는 것이 정상**이다.

## 4. 파일 이동에서 `tsc` 가 못 잡는 것

codemod 가 다섯 번 놓쳤고 전부 보강했다. 그래도 **이 목록은 외워 두는 편이 낫다.**

| 종류 | 증상 |
|---|---|
| 동적 `import("...")` | 타입체크 통과, **실행 시점에** 터짐 |
| 부수효과 `import "x"` | `from` 이 없어 정규식이 놓침 |
| `.mjs` 의 짝 `.d.mts` | 선언만 남아 암묵적 any |
| 문자열 경로 | `readFileSync("lib/…")` · `ssrLoadModule(…)` — **시험만 ENOENT** |
| **정규식 단언** | `/from "…lib\/foo"/` — 이스케이프돼 평문 검색이 놓침 |

codemod 가 「확인 필요」 목록을 내면 **끝까지 읽어라.** `tail` 로 자르면 도구를 만든 의미가 없다
(그렇게 해서 peer-sync replay 하네스를 한 번 죽였다).

## 5. 지도 레이어를 추가할 때

1. `lib/map/layerOrder.ts` 의 `RTW_LAYER_RANK` 에 **랭크를 정해 넣는다**(등록하지 않으면 계약 시험이 막는다)
2. 순서를 세울 때 **`moveLayer(id)` 를 beforeId 없이 부르지 않는다** — 무조건 top 이고, 그것이 P4 를 만들었다
3. 한 레이어 교정은 `moveLayerByRank`, **여러 개는 `applyRtwLayerOrder`**(낱개로는 그룹이 정렬되지 않는다)

**라이더가 실제로 그려지는지는 헤드리스로 알 수 없다**(preserved 레이어가 생성되지 않음 — 감사 P3).
라이더가 걸린 변경은 **Chief 실기 확인이 최종 게이트**다.

## 6. 실행·확인 — 어느 폴더에서 무엇을 돌리나

> **기본 폴더는 리포 루트 `C:/20.HDev/boxcycle`.** 루트가 `apps/web` 으로 위임하므로
> 웹 앱 명령도 루트에서 된다. 폴더를 적지 않은 명령은 주지 않는다 —
> 루트·`functions`·`apps/web` 이 섞여 있어 그것만으로 한 번 헤맨다.

### 6.1 먼저 — 지금 무엇이 필요한가

바꾼 것으로 고른다. 위에서 아래로 갈수록 비용이 커진다.

| 무엇을 바꿨나 | 필요한 것 |
|---|---|
| `apps/web/src/**` (클라이언트 소스) | **강력 새로고침만** (`Ctrl+Shift+R`) — 서버 재시작 불필요 |
| `.env`·`.env.emulator`·`vite.config.ts`·`package.json`·새 의존성 | **dev 서버 재시작** (Vite 는 시작할 때만 읽는다) |
| `firestore.rules`·indexes | `deploy:firestore` |
| `functions/**` | `deploy:functions` |
| 배포된 화면을 확인해야 함 | `deploy:hosting` |

**파일을 옮겨도 대개 재시작은 필요 없다.** Vite 는 요청 시점에 다시 해석한다 —
서버가 새 경로를 내주는지는 이렇게 **재 보고** 판단한다(추측 금지):

```
curl -s http://localhost:5000/src/lib/<옮긴 파일을 import 하는 모듈>.ts | grep "^import"
```

옛 경로가 200 을 돌려주는 것은 정상이다 — **SPA 폴백으로 index.html** 이 나온 것이지
낡은 모듈이 아니다. 본문을 봐야 구분된다.

Vite 가 `Failed to resolve import` 를 뱉으면 그때는 재시작한다.

### 6.2 앱 띄우기

| 목적 | 폴더 | 명령 | 결과 |
|---|---|---|---|
| 화면만 잠깐 | `C:/20.HDev/boxcycle` | `npm run dev` | :5000 — ⚠️ **운영 Firebase 에 실제로 쓴다**(projectId `boxcycle-dc2df`, 실 Mapbox 토큰) |
| 데이터가 쌓이는 시험 | `C:/20.HDev/boxcycle` | 창1 `npm run emulators` → 창2 `npm run dev:emulator` | :5002 (격리) |

`.env` 와 `.env.emulator` 는 **projectId 가 같다** — 다른 것은 `VITE_USE_EMULATOR` 뿐이다.
에뮬레이터 모드는 Mapbox 키를 두지 않고 `.env` 의 실토큰을 **상속**한다(2026-09-25 블랙아웃).

앱은 **폰 가로 전용**이다. 세로면 회전 오버레이가 클릭을 가로챈다.

## 7. 다음 사람에게

### 남은 방향 위반 **14건** (2026-09-26 Phase 6-D6 기준)

Phase 5 는 35 로 끝났고 Phase 6-D 가 21건을 갚았다. **남은 14건은 저위험이 아니다** —
여기까지가 「옮기면 끝나는 것」이고, 아래는 전부 **결정이나 실기 확인이 선행**해야 한다.

| 묶음 | 수 | 왜 남았나 |
|---|---|---|
| 발행 fan-out 계열 (`ride`·`peerMotion`·`trail/repo` ↔ firebase·서로의 repo) | 9 | **포트를 넣어야 갚아진다**(`trailLiveRidePort` 선례). 실주행 peer 발행 경로라 회귀가 나면 **동행 위치가 조용히 어긋난다** — Chief 실기 확인 필요 |
| `route/repo → identity/repo` | 2 | 남의 도메인 저장소를 읽는다. **읽기 모델 소유권(D1)** 결정이 선행 |
| `peerMotion → rider` | 1 | peer 페달 위상을 **rAF 에서 적분**하는 자리. 옮기면 Phase 5 가 막 고친 계단화 경로를 건드린다 |
| `rider → map` | 1 | 라이더 렌더 경로는 **헤드리스로 확인할 수 없다**(감사 P3) |
| `trail → peerMotion` | 1 | **게이트 오탐에 가깝다** — `trailLiveRideSink` 가 `trailLiveRidePort` 를 구현하는 것이고, 남의 포트를 구현하려면 그 타입을 import 할 수밖에 없다. 포트 구현을 방향 위반으로 셀지 별도 판정이 필요하다 |

### 무엇이 계속 나왔나 — 「결정만 적고 옮기지 않은 것」

Phase 6-D 에서 걸린 것은 대부분 **판단이 아니라 실행 누락**이었다.

- `peerSyncPolicy` 헤더가 「`PEER_LIVE_RIDE_*` 는 `trail/` 소유」라 **적어 두고도** 값은
  `rideSyncPolicy` 에 있었다
- `terms/productTerms` 의 `DEFAULT_TRAIL_ID` re-export 는 **아무도 경유하지 않았다**
- `route/resolvePublicationIdFromDoc` 은 **route 소비자가 0** 이고 Trail 저장소 셋뿐이었다

> **결정을 적어 두고 옮기지 않으면, 다음 사람은 그것이 이미 된 일이라고 읽는다.**
> 소유권을 옮겼으면 **계약 시험에 구조 단언을 함께** 넣어 되돌아갈 때 red 가 되게 한다
> (G5 의 「Trail 라이브 주행 수명은 trail 이 갖는다」가 그 예다).

### 옮기기 전에 — 감시자가 그 경로를 박아 두었는지 본다

`firebase/functionsEmulatorUrl.ts` 를 옮기려다 멈췄다. 두 가지가 걸렸다.

1. **firebase 도메인의 선언된 책임에 「에뮬레이터 배선」이 들어 있다** — 오배치가 아니다
2. `functions-http-url-gate` 가 그 **경로를 하드코딩**하고 있다 — 옮기면 감시자가 죽는다
   (§3-③ 「고치면 죽는 검산」)

대신 이미 통하는 패턴을 썼다 — `firebase` 를 아는 부분만 `repo/` 로 내린다(D3 2층 구조).
`publicRouteRequests` 는 575줄 중 상당수가 Firestore 라 **통째로**, `tierQuota` 는
정책 진입점을 남기고 **fetch 한 덩어리만** 갈랐다.

### `publishLiveLocationFanout` 을 `services/` 로 옮기지 마라

그 모듈은 스스로 「조립 지점」이라 적고 있고 소비자도 App 계층 훅 하나뿐이라
`src/services/` 로 옮기면 **위반 7건이 한 번에 사라진다.** 그런데 **엣지는 하나도 바뀌지
않고 규칙 지문에도 드러나지 않는다** — §2 가 경고하는 「정리했다는 착각」 그 자체이고,
규칙 완화보다 나쁘다(규칙 완화는 최소한 diff 에 남는다).

### 이동이 위반을 **늘린** 실제 사례 (2026-09-26)

`account/tierQuota.ts` 를 `account/repo/` 로 내렸더니 `account → firebase` 1건이 사라지는
대신 `route → account/repo` · `route/repo → account/repo` **2건이 생겼다.** 되돌렸다.

판정 기준은 `repoAccess` 에 적혀 있다 — **「식별자를 안다」와 「DB 를 읽는다」는 다르다.**
`assertTierQuotaClient` 는 남의 DB 를 읽는 것이 아니라 **account 에게 제 쿼터를 강제해
달라고 부르는 것**이므로 저장소가 아니다. 원격 호출이라고 다 repo 는 아니다.
