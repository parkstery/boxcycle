---

## 0. 먼저 — 이 도구들이 있는 이유

Phase 5 의 성과는 폴더가 예뻐진 것이 아니다. **조용히 깨져 있던 것 다섯**을 찾은 것이다
(셀 ID 3중 복제 · 동행 페달 계단화 · 레이어 top 다툼 · red 계약 시험 방치 · 에뮬레이터 지도
블랙아웃). 전부 **에러도 로그 이상도 내지 않았다.**

그래서 이 도구들은 「정리」가 아니라 **「조용한 파손을 소리나게 만드는 장치」** 다.
그 목적을 잊으면 게이트는 통과 도장이 된다.

---

## 1. 도구 지도

| 도구 | 역할 | 언제 |
|---|---|---|
| `apps/web/dep-layers.json` | **의존 방향의 단일 출처** — 도메인 20개 책임 · 허용 엣지 DAG · `lib/` 파일 전원 배정 | 도메인·파일 위치를 바꾸기 **전에** |
| `scripts/check-dep-direction.mjs` | 방향 위반·순환 판정. M0 자가검산 7항목 → baseline 래칫 | 상시(`--check` 는 pre-push) |
| `scripts/move-lib-files.mjs` | 파일 이동 + 상대경로 재계산 | 파일을 옮길 때 |
| `scripts/repair-lib-imports.mjs` | 이동이 중단됐을 때 **앞으로 고치는** 복구 | 사고 시 |
| `scripts/verify-gates-alive.mjs` | 게이트를 **일부러 깨뜨려** 보고 되돌린다 | 게이트를 추가·수정한 뒤 |
| `apps/web/src/lib/map/layerOrder.ts` | 지도 레이어 순서 단일 출처 | 레이어를 추가할 때 |

## 2. 구조를 바꾸는 표준 절차

```
① 선언을 먼저 고친다        apps/web/dep-layers.json
② 보고 모드로 영향을 본다    node scripts/check-dep-direction.mjs
③ codemod 로 옮긴다         node scripts/move-lib-files.mjs <plan.json>
④ 확인한다                  tsc · npm run test:next-ride · --check
⑤ 게이트를 세웠으면 깨뜨린다  node scripts/verify-gates-alive.mjs 에 케이스 추가
```

`plan.json` 은 `{ "lib/<옛경로>": "lib/<새경로>" }`(`apps/web/src` 기준). 선언에서 생성하면
사람이 손으로 적을 일이 없다.

> **이동은 위반을 줄이지 않는다 — 위치만 바뀐다.** 위반을 갚으려면 의존을 뒤집거나
> 포트를 넣어야 한다. 그 구분을 흐리면 「정리했다」는 착각만 남는다.

---

## 3. 게이트를 다룰 때의 규율 넷

### ① 세웠으면 깨뜨린다

「통과」는 게이트가 살아 있다는 증거가 아니다. `verify-gates-alive.mjs` 가 이것을 자동화한다
— 게이트마다 **「이런 잘못을 저지르면 막아야 한다」** 는 변조를 만들어 실제로 실패하는지 본다.

```
node scripts/verify-gates-alive.mjs      # 깨끗한 트리에서만
```

새 게이트를 붙이면 **이 파일에 파괴 케이스를 함께 넣는다.** 넣지 않은 게이트는
다음 사람이 살아 있는지 알 수 없다.

### ② 판정 앞에 M0 를 세운다

「0건이니 통과」 앞에 **「세는 일이 작동하는가」** 를 둔다. `check-dep-direction` 의 M0 7항목이
본보기다 — 수집 하한 · 알려진 사실 재현 · **검출기 생존(합성 그래프)** · 전원 배정 ·
**깨진 경로 0** · 수집 범위 포함.

특히 **깨진 코드가 게이트를 좋아 보이게 만든다.** 이동이 중단돼 import 가 깨졌을 때
위반이 59 → 25 로 「줄었다」 — 해석 못 한 엣지를 버렸기 때문이다.

### ③ 고치면 죽는 검산을 만들지 않는다

「알려진 결함 X 가 검출되는가」로 도구 생존을 확인하면 **X 를 고치는 순간 죽는다.**
경로를 박아 둔 감시자도 파일을 옮기면 죽는다. 둘 다 Phase 5 에서 실제로 겪었다.

→ **합성 입력으로 알고리즘 자체를 시험**하고, 실제 대상은 **선언에서 조회**한다.

### ④ 규칙 완화를 눈에 보이게 한다

게이트를 통과하는 가장 쉬운 길은 코드가 아니라 **규칙을 넓히는 것**이다. 실제로
`peerMotion.mayImportRepoOf=["trail"]` 한 줄이면 위반이 41 → 35 로 준다.

그래서 baseline 이 **허용 규칙의 해시 지문**을 갖는다. 지문이 바뀌면 수치와 무관하게
실패하고 재고정을 요구한다 — **의도한 정당한 변경도 걸리는 것이 정상**이다.

## 4. 파일 이동에서 `tsc` 가 못 잡는 것

codemod 가 다섯 번 놓쳤고 전부 보강했다. 그래도 **이 목록은 외워 두는 편이 낫다.**

| 종류 | 증상 |
|---|---|
| 동적 `import("...")` | 타입체크 통과, **실행 시점에** 터짐 |
| 부수효과 `import "x"` | `from` 이 없어 정규식이 놓침 |
| `.mjs` 의 짝 `.d.mts` | 선언만 남아 암묵적 any |
| 문자열 경로 | `readFileSync("lib/…")` · `ssrLoadModule(…)` — **시험만 ENOENT** |
| **정규식 단언** | `/from "…lib\/foo"/` — 이스케이프돼 평문 검색이 놓침 |

codemod 가 「확인 필요」 목록을 내면 **끝까지 읽어라.** `tail` 로 자르면 도구를 만든 의미가 없다
(그렇게 해서 peer-sync replay 하네스를 한 번 죽였다).

## 5. 지도 레이어를 추가할 때

1. `lib/map/layerOrder.ts` 의 `RTW_LAYER_RANK` 에 **랭크를 정해 넣는다**(등록하지 않으면 계약 시험이 막는다)
2. 순서를 세울 때 **`moveLayer(id)` 를 beforeId 없이 부르지 않는다** — 무조건 top 이고, 그것이 P4 를 만들었다
3. 한 레이어 교정은 `moveLayerByRank`, **여러 개는 `applyRtwLayerOrder`**(낱개로는 그룹이 정렬되지 않는다)

**라이더가 실제로 그려지는지는 헤드리스로 알 수 없다**(preserved 레이어가 생성되지 않음 — 감사 P3).
라이더가 걸린 변경은 **Chief 실기 확인이 최종 게이트**다.

## 6. 실행·확인

| 목적 | 명령 (폴더: `C:\20.HDev\boxcycle`) |
|---|---|
| 화면만 잠깐 | `npm run dev` → :5000 — ⚠️ **운영 Firebase 에 실제로 쓴다** |
| 데이터가 쌓이는 시험 | `npm run emulators` + `npm run dev:emulator` → :5002 (격리) |
| 계약 스위트(≈3초) | `npm run test:next-ride -w boxcycle-web` |
| 구조 판정 | `node scripts/check-dep-direction.mjs` |
| 게이트 생존 | `node scripts/verify-gates-alive.mjs` |

`.env` 와 `.env.emulator` 는 **projectId 가 같다** — 다른 것은 `VITE_USE_EMULATOR` 뿐이다.
앱은 **폰 가로 전용**이다.
