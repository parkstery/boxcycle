Chief 요구: 첫 인트로 「시작하기」와 두 번째 인증 선택의 「시작」을 두 번 누르지 않도록, 인트로는 잠시 보여준 뒤 두 번째 화면으로 자동 전환한다. Supervisor가 작은 기본값 2초를 선택했다. 이는 화면 전환 승인이며 자동 인증·자동 주행 승인이 아니다. 기본 Developer Cursor AI·CLI. 모든 설명·질의·결과는 한국어로 작성한다.

## 소유·범위

다른 담당도 함께 쓰는 저장소다. 기존 dirty는 모두 보존하고 임의로 되돌리거나 커밋에 섞지 않는다. 특히 index.html의 사진 preload와 AGENTS·운영 지침, archive 색인·프로세스/메모리 보고는 수정하지 않는다.

허용 파일:
- `apps/web/src/App.tsx`: 기존 showAppIntro 조건 바로 뒤에 useEffect([showAppIntro])를 둔다. false이면 타이머 없이 return. true일 때 window.setTimeout으로 2_000ms 뒤 setIntroDismissed(true)만 호출하고 cleanup은 window.clearTimeout이다. 상수 이름은 APP_INTRO_DURATION_MS를 권장한다. 같은 화면이 다시 보이면 새 타이머를 시작한다. 인증·경로·지도 함수는 호출하지 않는다. JSX는 `<AppIntroScreen />`으로 바꾼다.
- `apps/web/src/components/auth/AppIntroScreen.tsx`: onStart props·CTA 버튼·화살표·포커스 스크롤 핸들러를 제거하고 인자 없는 표현 컴포넌트로 둔다. 관련 설명을 자동 전환 인트로에 맞춘다. 브랜드·제목·설명·사진·출처·고정 차단 레이어는 유지한다.
- `apps/web/src/components/auth/AppIntroScreen.css`: 더 이상 쓰지 않는 CTA 관련 규칙과 그 규칙에만 해당하는 설명을 제거한다. 기존 문구·사진·그라데이션·출처 레이아웃·스크롤·글자 크기·색을 보존한다.
- `apps/web/scripts/ride-verify/entry-contract.mjs`: 구현 전에 소개 계약을 자동 전환 기준으로 갱신한다. 소개 region/제목 앵커, App의 기존 showAppIntro 게이트, 시간 지정·showAppIntro 조건·타이머 cleanup·표현 컴포넌트·게스트 카드 상호 배제를 고정한다. 단순히 깨진 앵커를 삭제해 통과시키지 않는다.
- `apps/web/e2e/rideEntryHelpers.ts`, `apps/web/e2e/ride-entry.spec.ts`: 소개 CTA 클릭을 없애고 소개가 자동으로 닫히는 것과 다음 인증 화면을 기다리도록 수정한다. 기존 함수명·외부 호출 계약은 유지하며 지연된 인증 초기화·소개 생략 케이스를 계속 지원한다. stale 주석만 해당 범위에서 수정한다. 다른 주행 셀렉터 문제를 확대 수정하지 않는다.
- 결과 `03-result-01.md`.

새 props·컴포넌트·훅·디버그 스위치·상시 도구가 필요 없는 작은 변경이다. 새 파일이 필요하면 먼저 결과에 이유를 보고한다. 아카이브/옛 ops의 QA 스크립트는 현재 제품 계약이 아니므로 일괄 수정하지 않는다. Mapbox 전환은 앞선 논의일 뿐 이번 승인에 포함하지 않는다. 사진 onLoad를 기다리지 않아 실패·지연 시에도 화면 전환한다. 명시 로그아웃·로그인 상태·탈퇴 안내·busy/error 예외는 기존 showAppIntro 조건 그대로다.

## 검증·완료

ride-verify 스킬과 HARNESS를 읽고 계약→정적 검증 순서를 지킨다. `apps/web`에서 다음 실행과 종료 코드를 기록한다.

1. `node scripts/ride-verify/verify-selectors.mjs`
2. `node --test scripts/identity/auth-session-gate-render.test.mjs`
3. `npx.cmd eslint src/App.tsx src/components/auth/AppIntroScreen.tsx e2e/rideEntryHelpers.ts e2e/ride-entry.spec.ts scripts/ride-verify/entry-contract.mjs` (무시되는 파일은 그 사실을 구분)
4. `npm.cmd run build` (타입 검사 포함)
5. `npx.cmd playwright test ride-entry --list` (수집만. 실제 Firebase 접속·실인증 금지)
6. 제품 파일 `git diff --check`.

Supervisor는 실제 App의 useAppAuth만 fixture로 대체하고 외부 요청을 차단한 단일 headless browser에서 시간을 제어해 1999ms/2000ms 경계, 사용자 동작 없이 다음 카드 표시, 자동 인증 없음, 다음 「시작」을 누를 때만 콜백 호출, StrictMode/게이트 조건 변경 시 cleanup, 사진 실패·지연, 대표 폰 가로·PC를 독립 검증한다. Firebase 에뮬레이터 준비가 없으면 실주행 e2e는 미실행으로 기록하며 성공으로 보고하지 않는다.

commit/push/deploy/browser/server/subagent 및 다른 변경 금지. 결과에는 실제 모델·세션·branch/HEAD/초기 dirty·변경·실행 명령과 종료 코드·실패/미실행/한계를 구분한다. 사진 선요청 선행 변경은 보존한다.

새 디버그 코드·주소 스위치·스크립트를 만들면 `apps/web/dev-tools.json` 에 등록한다(분류·목적·켜는 법·만료). 운영에서 켜지는 도구 화면은 동적 import 로 분리한다.
