# 계획 — 페이서(Pacer) 2명

## 1. 무엇을 만드나

혼자 달릴 때(실제 동행 0명) 내 라이더 앞뒤 **±20m 안**에 페이서 2명이 함께 달린다. 페이서는 내 속도를 기준으로 랜덤하게 가속·감속해 나를 추월하거나 추월당한다.

## 2. 트래픽 — 0

페이서는 **브라우저 안에서만** 계산·렌더한다. RTDB 송수신·Firestore 읽기/쓰기·Functions 호출이 **하나도 없다.** 입력은 이미 로컬에 있는 내 화면 거리·속도뿐이다. 남는 비용은 GLB 2개 렌더(동행은 이미 최대 30명 설계, `PEER_MAX`)뿐이므로 Chief 조건대로 **2명**.

결과: 페이서는 **나에게만** 보인다. 다른 사람 화면에는 없다.

## 3. 핵심 설계 결정

| # | 결정 | 이유 |
|---|---|---|
| D1 | 페이서를 `PeerMotionRegistry` 에 **넣지 않는다**. 그리기 단계(MapView rAF 의 `specs`·DOM 마커 목록)에서만 합친다 | 레지스트리에 들어가면 `hasActivePeers()` 가 참이 되어 내 표시 지연(`companionDisplayDelayMs`)이 켜지고, HUD 「다른 라이더 없음」·동행 수가 틀어진다 |
| D2 | 기준 거리는 **내 라이더가 그려지는 거리**(`sampleLiveLngLat` 이 쓰는 dist) | 내부 거리 기준이면 표시 지연이 있을 때 페이서-나 간격이 화면에서 어긋난다 |
| D3 | 움직임 모델은 `lib/ride/pacer/` 의 **순수 함수**(시드 PRNG). firebase·peerMotion·trail import 금지 | 통신 계층이 아님을 구조로 보장 + 합성 입력으로 단위 시험 |
| D4 | 좌우 차선 오프셋 ±1.2m(페이서 A 오른쪽, B 왼쪽) | 추월 시 내 라이더와 겹치지 않게 |
| D5 | 실제 동행이 1명이라도 생기면 페이서는 빠진다 | 진짜 사람 우선. 동행이 나가면 다시 뒤쪽에서 합류 |
| D6 | 설정 「페이서」 토글, 기본 켜짐, uid 별 localStorage 저장 | Chief 결정. 저장 패턴은 `useCalorieProfile` |
| D7 | 정복·기록·결과·Trail 멤버·동행 수·HUD 동행 블록에 **절대 포함하지 않는다** | 가짜 사람이 실적·소셜 지표에 섞이면 안 된다 |

## 4. 움직임 모델 (요약 — 수치는 지시 01 §3)

- 상태: `gapM`(나와의 거리, 앞+/뒤−), `relV`(내 속도 대비 차이), `targetGapM`, 다음 재목표 시각.
- 15~40초마다 새 목표 간격. 지금 앞에 있으면 70% 확률로 뒤쪽 목표 → 추월 장면 보장.
- `relV` 는 목표를 향한 비례 제어, 상한 ±1.5m/s(저속에선 축소), 변화율 ≤ 0.4m/s².
- |gap| ≤ 20m 하드 클램프. 내가 멈추면 함께 멈춤. 일시정지 중 동결. 경로 [0, 길이] 클램프.
- dt ≤ 0.25s 클램프(창 숨김 후 복귀 시 튐 방지).

## 5. 검증 전략

1. 단위: 합성 속도 프로파일 10분 — 간격 범위·추월 횟수·가속 상한·정지·결정성.
2. 사보타주: 클램프 제거 시 시험이 실패하는지 확인.
3. 정적 계약: `lib/ride/pacer/**` 가 firebase·peerMotion·trail 을 import 하지 않음.
4. e2e: 혼자 주행 시 페이서 2 렌더 · `companionDisplayDelayMs()===0` · 토글 끄면 0 · 끔/켬 네트워크 요청 수 비교.
5. Chief 육안: 추월 장면 캡처.
