## 3. 움직임 모델 (`pacerMotion.ts`)

### 3.1 API (이름은 바꿔도 되지만 형태는 유지)

```ts
export type PacerId = "pacer-a" | "pacer-b";
export type PacerState = {
  id: PacerId;
  gapM: number;        // 나와의 경로 거리 차(앞 +, 뒤 −)
  relVMps: number;     // 페이서 속도 − 내 속도
  targetGapM: number;
  retargetInSec: number;
  laneM: number;       // 차선 오프셋(오른쪽 +)
  phaseRev: number;    // 크랭크 위상(렌더용, 연속값)
};
export type PacerWorld = { pacers: PacerState[]; rng: () => number };

export function createPacerWorld(seed: number): PacerWorld;
export function stepPacerWorld(
  world: PacerWorld,
  input: { dtSec: number; selfSpeedMps: number; status: "running" | "paused" },
): void;                                     // 제자리 갱신
export function resolvePacerDistM(selfDistM: number, gapM: number, routeLenM: number): number;
export function pacerSpeedMps(selfSpeedMps: number, p: PacerState): number; // ≥ 0
```

### 3.2 수치 (상수로 export 해서 시험이 참조)

| 상수 | 값 | 의미 |
|---|---|---|
| `PACER_MAX_GAP_M` | 20 | \|gap\| 하드 클램프 |
| `PACER_SOFT_GAP_M` | 18 | 목표 간격 상한·경계 밀어내기 시작 |
| `PACER_MIN_TARGET_ABS_M` | 4 | 목표 간격 절댓값 하한(옆에 계속 붙어 있지 않게) |
| `PACER_RETARGET_SEC` | [15, 40] 균등 | 재목표 주기 |
| `PACER_CROSS_PROB` | 0.7 | 지금 앞이면 뒤쪽, 뒤면 앞쪽 목표를 뽑을 확률 |
| `PACER_GAIN_PER_SEC` | 0.08 | desiredRelV = gain × (target − gap) |
| `PACER_MAX_REL_V_MPS` | min(1.5, max(0.3, 0.2 × selfSpeed)) | 상대속도 상한(저속 축소) |
| `PACER_MAX_ACCEL_MPS2` | 0.4 | relV 변화율 상한 |
| `PACER_DT_MAX_SEC` | 0.25 | dt 클램프 |
| `PACER_LANE_M` | A +1.2 / B −1.2 | 좌우 차선 |
| 초기 gap | A −8 / B +6 | 시작 시 하나는 뒤, 하나는 앞 |

### 3.3 규칙

1. `dtSec` 는 [0, 0.25] 로 클램프. `status === "paused"` 면 **아무것도 바꾸지 않는다**.
2. `retargetInSec -= dt`, 0 이하가 되면 새 목표: 확률 `PACER_CROSS_PROB` 로 현재 gap 의 반대쪽, 아니면 같은 쪽. 절댓값은 [4, 18] 균등. 다음 주기는 [15, 40] 균등.
3. `desiredRelV = clamp(gain × (target − gap), ±maxRelV)`. `relV` 는 `desiredRelV` 쪽으로 이동하되 `|ΔrelV| ≤ 0.4 × dt`.
4. 페이서 속도가 음수가 되지 않게 `relV ≥ −selfSpeed`. **내가 멈추면**(selfSpeed < 0.5) `desiredRelV = 0` 으로 두어 함께 선다(뒤로 가지 않는다).
5. `gap += relV × dt` 뒤 `clamp(gap, ±20)`. 클램프에 닿으면 `relV` 를 0 으로 두고 목표를 반대쪽으로 즉시 다시 뽑는다.
6. `phaseRev` 는 페이서 속도로 `estimateCrankRpmFromSpeedKmh`(기존 함수) 를 써서 적분. 속도 ≤ 0.38 km/h 면 그대로.
7. `resolvePacerDistM` 은 `clamp(selfDist + gap, 0, routeLen)`. 완주 지점에서는 결승선 앞에서 멈춘다.
8. 같은 seed → 같은 궤적(결정성). seed 는 주행 시작 시각(ms) 등에서 만든다.

## 4. 렌더 연결 (`MapView.tsx`)

### 4.1 표시 조건 (모두 참일 때만 그림)

- `pacerEnabled === true`
- `liveRiderMotionRef.current?.sessionStatus` 가 `"running"` 또는 `"paused"`
- `routeGeometryRef.current` 존재, `sampleLiveDistMRef.current?.()` 가 null 아님
- **실제 동행 없음**: `getPeerMotionRegistry().hasActivePeers() === false` (MapView 는 components 라 import 가능. `lib/ride/pacer` 쪽에서 부르지 말 것)

### 4.2 프레임 흐름

- 페이서 world 는 `useRef` 로 보관. 주행 시작(`idle → running`) 마다 새 seed 로 재생성.
- 표시 조건이 거짓이 되면(동행 등장·토글 끔·idle) world 를 버리고 렌더 목록에서 제거. 다시 참이 되면 **재생성**(초기 gap 부터 다시).
- 매 프레임 `stepPacerWorld` 호출 → 각 페이서 `distM = resolvePacerDistM(...)` → `getPointOnRouteByDistance`·`headingAtRouteDistanceMeters`(기존 함수, peer 와 같은 것) → `offsetLngLatLateral(lngLat, hdg, laneM)`.
- `buildFeatures` 게이트(`showPeerSprites`, 줌 14 이하에서 안 그림)를 **페이서에도 동일하게** 적용. step 은 게이트와 무관하게 언제나 돈다(동행과 같은 이유).

### 4.3 합치는 위치

- DOM 마커: `syncPeerDomMarkers(map, [...peerFeatures, ...pacerFeatures], ...)` — 페이서 feature 는 기존 `PeerDomGJFeature` 모양, id 는 `pacer-a`/`pacer-b`, label 은 `"페이서"`.
- GLB: 기존 `specs.push({ kind: "peer", ... })` 루프 다음에 페이서를 `kind: "pacer"` 로 push.
- 이름표가 동행과 구분되게 CSS 클래스 하나 추가 허용(예: `map-view__rider-nametag--pacer`, 약간 흐린 톤). 크기 규칙은 [UI 공간밀도 원칙](../../reference/product/260924-RTW-UI-공간밀도-원칙.md) 준수.

### 4.4 진단 노출 (DEV·e2e 용)

`window.__rtwPacerDiag = () => ({ enabled, visible, count, gaps: number[], companionDelayMs })` 를 DEV 에서만 설치. `companionDelayMs` 는 `companionDisplayDelayMs()` 값.
