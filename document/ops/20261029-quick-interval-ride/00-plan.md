# 인터벌 경로 묶음 — 실행 계획

2026-10-29 Supervisor Claude Code(Opus 5.5). 두 묶음을 한 순서로 묶는 계획이다: [경로 거리 부족 안내](../20261029-interval-route-hint/README.md), [간편 인터벌 주행](README.md).

## Chief 결정 (2026-10-29)

> 인터벌은 모두 25km/h로 해. 향후 이 기준을 개인의 평균 속도로 치환되도록 하는 방안을 고려하기로 한다.
> 1. 맞춘다. 2. 짧아지지 않게 해.
> 계획서를 써 놓고 코덱스 작업을 이어받아서 처리하고 나서 진행하자.

| 항목 | 확정 |
|---|---|
| 인터벌 기준 속도 | **모든 인터벌 계산이 25 km/h를 쓴다**: 거리 부족 안내, 주행 시작 경고(「운동시간이 더 길어요」), 간편 인터벌 목표 거리 |
| 주행 시작 경고 | 내 평균(없으면 20) 대신 25 km/h로 통일한다 |
| 간편 인터벌 목표 거리 | 인터벌 시간 × **25 km/h × 1.3**. 일반 주행 최소 거리보다 짧아지지 않는다 |
| 향후 | 기준 속도를 개인 평균 속도로 바꾸는 방안을 검토한다(이번 범위 밖) |

## 설계 원칙 — 기준 속도는 한 곳에서만

나중에 개인 평균으로 바꿀 때 한 곳만 고치면 되도록 만든다.

- 기준 속도는 `resolveIntervalBasisKmh()` 하나에서만 정한다(안내 묶음의 `lib/route/intervalRouteDistance.ts`). 지금은 `INTERVAL_ROUTE_BASIS_KMH = 25`를 돌려준다.
- 안내, 시작 경고, 간편 목표 거리가 모두 이 함수를 부른다. 다른 곳에 25를 직접 적지 않는다. 단위 시험으로 이것을 확인한다: 함수의 값을 바꾸면 세 계산이 함께 바뀌어야 한다.
- 표시 문구의 「시속 25 km 기준」도 같은 값으로 그린다.
- 나중에 개인 평균으로 바꿀 때 검토할 것(지금은 하지 않음):
  - 기존 `resolveUserAverageKmh`의 3~60 km/h 범위 검사를 재사용할지
  - 기록이 적을 때 얼마부터 믿을지(최소 거리·시간)
  - 체험 속도로 달린 주행을 평균에서 뺄지
  - 25보다 낮은 평균을 그대로 쓸지, 아니면 25를 하한으로 둘지
