# 지시01 — 서버 `getLeaderboard`

2026-10-23 · task · 담당 Claude impl-standard · 감리 Claude · 계약 [01-plan.md](01-plan.md) · 보고 `03-result-01.md`

범위: `functions/` 만(다른 실행자가 `apps/web` 를 동시에 고친다).

1. `functions/src/leaderboardCore.ts` — **순수 함수**: 입력(주행 행 목록 {uid, endedAtMs, distanceMeters, newMeters, tier, publicationId}, 회원 uid 집합, 닉네임 맵, 퍼블릭→applicantUid 맵, live uid→trailId 맵, 요청자 uid·익명 여부, board, period, nowMs) → 계약의 응답. 기간 경계는 KST(주 = 월요일 0시). t1 만, 회원만 순위. 동점은 값이 같으면 같은 순위·다음은 건너뜀(1,2,2,4). `around` 는 내 위아래 2명, top 과 겹치는 줄은 뺀다. 숫자는 km 소수 1자리.
2. 적재(읽기 전용, admin SDK): `rides` 를 기간 하한 이후 `endedAt` 로 조회(인덱스 `status+endedAt` 활용, `status=="completed"`), Auth 로 익명 여부, `users/{uid}.nickname`, `routePublications` 의 `applicantUid`, live = collectionGroup `livePublicationRides` 에서 `lastSeenAt` 30초 이내. 필요한 인덱스가 없으면 `firestore.indexes.json` 에 **추가만** 하고 보고에 적는다.
3. 캐시: 전체 순위를 `leaderboardCache/{board}_{period}` 에 저장, 5분 안이면 재사용. `firestore.rules` 는 고치지 않는다(기본 거부로 클라이언트 접근 불가인지 확인해 보고).
4. `functions/src/leaderboard.ts` — `getLeaderboard` onRequest(GET, region·invoker public·CORS·`Cache-Control: no-store`, Bearer 검증은 `adminDashboard.ts` 의 `parseBearerToken` 재사용, 게스트 허용). 잘못된 board/period 는 400. `index.ts` export.
5. 시험(`leaderboardCore.test.ts`, `package.json` test 에 등록): t0 제외, 게스트 제외·projectedRank, 동점 순위, KST 주 경계(일요일 23:59 vs 월요일 00:00), around 겹침 제거, pioneer uses(자기 주행 제외), live 표시, 응답에 uid 없음.
6. 금지: 운영 데이터 쓰기·배포·규칙 변경·git 명령. 검사: functions 에서 `npm run build`·`npm test`·`npm run lint`.
