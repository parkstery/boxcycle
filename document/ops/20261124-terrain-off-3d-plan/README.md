## 1. 결론

1. **방향은 성립한다.** 2km까지 그리게 맞춰도 지형 OFF가 ON보다 강남·파리·남산에서 약 2배, 스텔비오에서 약 4배 빠르다. 마이애미(평지)는 약 1.3배다.
2. **다만 지형만 끄면 화면이 빈다.** 지형 OFF에서 건물이 일부만 나온 원인을 찾았다. 먼저 이 시야 제한을 풀어야 한다(§2).
3. **지금의 OFF FPS에는 여유가 과장돼 있다.** 카메라 3m에서 265m까지만 그린 값이다. 1~2km까지 그리면 떨어진다.
4. **하락의 상당 부분은 되찾을 수 있다.** 건물보다 글자(라벨)와 그림자의 비용이 컸다. 나무 1,500그루의 추가 비용은 측정 흔들림 안이었다.
5. **한국 경로는 Mapbox 3D만으로 채워지지 않는다.** 조사한 지점에는 나무·랜드마크·건물 외벽 데이터가 거의 없다. 가로수와 숲은 우리가 만들어 넣어야 한다.

## 4. 목표와 합격 기준

- **성능**: 실제 앱 주행 10초에서 최저 1초 24FPS 이상, p95 41.7ms 이하. PC는 5개 장소 모두, 스마트폰 가로는 Chief 기기 기준.
- **시야**: 1km(Chief 확정) 안의 건물이 타일 경계에서 비지 않는다. 그 너머는 안개와 하늘로 닫는다. 「지평선까지」를 건물 데이터를 무한히 그리는 것이 아니라 **빈 경계가 보이지 않는 상태**로 정의한다.
- **구도**: 카메라 높이·피치·거리는 현재 값 유지(고정 90).
- **유지**: 도로명·지명(고정 90), 라이더·주행선·이정표·도착 연출.

## 5. 단계별 계획

각 단계는 「그림 → Chief 확인 → 다음 단계」로 진행하고 순서를 건너뛰지 않는다. 구현은 수퍼바이저가 직접 한다.

### 0단계 · 미커밋 정리와 회귀 막기

현재 미커밋 변경을 나눈다.

- **제품 반영**: Standard 기본값, 주행 지형 OFF, `disable3dCutoff.ts`, `standardRideNames.ts`, `apply3DState`의 지형·건물 분리.
- **실험**: `ride3DPreview`, `rideCameraPosePreview`, `rideCameraTolerancePreview`, 배율 슬라이더. 제품 카메라 경로(`applyFollowCameraJumpTo`)에 끼어 있으므로 제품 커밋에서 제외하고 기록만 보존한다.
- **발견한 회귀**: `apps/web/src/App.tsx:633`의 도착 연출 조건에 `enable3D`가 있다. 지형을 기본 OFF로 하면 **도착 연출이 나오지 않는다.** 지형과 분리한다.

검증: map 시험, 셀렉터 계약, `tsc -b --noEmit`, 지형 ON/OFF 두 경우의 도착 연출.

### 1단계 · 시야 확장 (핵심)

신규 `apps/web/src/lib/map/rideViewDistance.ts` 한 곳에 모은다.

- 원거리 한계를 `max(SDK 값, 시야 거리)`로 올린다.
- 시야 안의 z14 이하 타일만 z15로 나눈다. 시야각·시야 거리 밖은 그대로 둔다.
- 적용 조건: 주행 중 · 지형 OFF · 카메라 2~6의 낮은 구도 · Mercator · SDK 3.23.1. 하나라도 다르면 SDK 기본으로 돌아간다. 주행 종료·카메라 1·스타일 전환에서 복원한다.
- Standard 기본 투영은 globe로 시작한다. 시험은 Mercator로 고정했으므로 제품의 주행 줌에서 같은 경로를 타는지 먼저 확인한다.
- 원거리 한계를 바꾸는 공개 API는 SDK 3.23.1 소스에서 찾지 못했다. 내부 함수를 감싸는 방식이므로 **SDK 버전을 고정하고 버전 계약 시험**을 둔다.
- 안개를 시야의 약 70% 지점부터 시작해 끝이 잘려 보이지 않게 한다.

검증: 5개 장소 전후 그림, 타일 요청 수·수신량, 급회전 때 건물 튐, 종료 후 복원, 실제 앱 FPS.

중단 기준: 2단계 절감 후에도 실제 앱에서 강남·남산 1km가 24FPS 미달이면 시야를 500m로 내리고 Chief에게 보고한다.

### 2단계 · 비용 회수

1. ~~상호·교통 라벨 OFF~~ → Chief 결정으로 모든 글자 ON. 글자 조각의 거리만 300m로 줄인다. 미커밋 `standardRideNames.ts`의 「지명」 레이어는 실제로 상호 데이터(`poi_label`)를 쓰므로 지명 데이터로 바꾼다.
2. 3D 그림자는 OFF에서 시작하고 여유가 있으면 켠다.
3. 멀리 있는 라벨을 제한한다(라이더 앞 300m 안팎).

검증: 라벨·그림자 각각의 전후 10초를 2회 교대, 도로명 가독성 그림.

### 3단계 · 가로수와 숲 (지형 손실의 주 보완)

- **가로수**: 경로와 주변 도로 양옆. 간격 10~16m, 좌우 어긋남·크기·회전을 위치로 계산해 매번 같은 자리에 놓는다.
- **숲·공원**: 지도의 숲·공원 면 안에 흩뿌린다. `standardRideNames.ts`가 이미 추가하는 streets-v8 소스를 재사용한다.
- **금지 위치**: 건물, 차도·자전거도로 위, 물, 교량, 터널, 교차로.
- Mapbox에 실제 나무가 있는 곳은 그것을 우선하고 겹쳐 심지 않는다.
- 모델은 자체 저용량 3~5종(활엽·침엽·야자·관목). 시험에 쓴 Mapbox 나무는 가까이서 줄기만 커 보여 그대로 쓰지 않는다.
- 상한 1,500그루에서 시작한다. 서버·Firestore는 쓰지 않는다.

검증: 남산·아라뱃길·여의도·스텔비오·안시 그림, 라이더와 나무 겹침 0, 줄기가 카메라를 가리지 않음, FPS 전후.

### 4단계 · 건물 외관과 원경

- 외벽 데이터가 있는 도시는 Standard 외벽을 켠다.
- 없는 곳(한국 등)은 높이·건물 번호에 따른 색 변화부터 하고, 창문 무늬는 가까운 건물에만 넣는다. 기존 무늬는 점무늬처럼 어지러워 크기와 거리를 다시 정한다. Chief가 시안에서 고른다.
- 원경은 하늘·안개를 먼저 다듬는다. 그다음 선택 사항으로 **먼 산 능선**(2~20km, 지도 표면을 다시 칠하지 않는 별도 저해상도 물체)을 시험한다. 성능은 미측정이며 실패하면 채택하지 않는다.

### 5단계 · 자동 품질 조절

느려지면 다음 순서로 낮춘다: 그림자 → 나무 수 → 외벽 무늬. 1km 시야의 자동 축소 여부는 이 단계에서 Chief에게 다시 묻는다. 도로명·라이더·주행선은 낮추지 않는다. 5초 이상 24FPS 미만이면 한 단계 내리고, 20초 이상 여유가 있을 때 한 단계 올려 왕복을 막는다.

### 6단계 · 지형 OFF로 바뀌는 기능 정리

| 기능 | 지형 OFF에서 | 처리 |
|---|---|---|
| 도착 연출 | 나오지 않음 | 0단계에서 분리 |
| 라이더 경사(고정 34) | 평면 | Chief 결정 ⑥ |
| 「3D 뷰」 버튼(고정 35) | Standard에서는 지형만 켜고 끔 | Chief 결정 ⑤ |
| 지형 이상 자동 2D(고정 36), 카메라 지형 회피(고정 86) | 쓰이지 않음 | 코드 보존 |
| 표고 그래프 | 별도 API라 영향 없음 | 유지 |

결정 후 [Chief 지정 디자인 고정](../../reference/product/261024-RTW-Chief-지정-디자인-고정.md)에 반영한다.

### 7단계 · 실기와 배포

스마트폰 가로에서 최소 FPS, 20분 발열, 데이터 사용량, 흰 화면 유무 확인 → 전체 게이트 → 승인 후 커밋·푸시·Hosting. 서버·Rules·DB 변경은 없다. 지도 불러오기 횟수가 늘지 않는 설계이며, 타일 수신량 증가는 1단계에서 실측한다.
