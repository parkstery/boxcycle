# 4단계 결과 — 건물 외관·안개와 하늘·먼 산 능선

2026-11-25 · Claude Code 직접 구현(위임 없음, Mapbox 요금 조회만 web-fetch 에이전트) · 상태: **Chief 「4단계 모두 적용하겠다. 적용 후 커밋해」 → 로컬 커밋·미배포**

Chief는 개발 서버 비교판(`?look=all`)에서 원주 코스를 달리며 직접 검수하고 골랐다. 그 화면의 패널 값은 38FPS·최저 31·p95 45.7ms(주행 1분 41초, 페이서 2)다.

## 바꾼 것

| 파일 | 내용 |
|---|---|
| `apps/web/src/lib/map/rideBuildings.ts` (신규) | 건물 번호·높이로 색 21가지, 250m 안의 건물에 창문 무늬(한 층 3.3m). 100m 움직이면 다시 고름 |
| `apps/web/src/lib/map/rideRidge.ts` (신규) | 실제 표고에서 방향별 능선 각도(1.2~25km)를 구해 시야 끝에 띠 세 겹으로 세움 |
| `apps/web/src/lib/map/rideScenery.ts` (신규) | 안개·하늘, 위 둘의 켜고 끄기 |
| `MapView.tsx`·`layerOrder.ts`·등록부 | 연결. 비교용 `?ridelook=0` |

적용 조건: 주행 중 · 지형 OFF · 피치 60° 이상 · 줌 15 이상 · Standard 지도. 카메라 1·지형 ON·주행 종료에서는 원래대로 되돌린다. 저녁 지도에서는 건물만 적용하고 낮 하늘·능선은 넣지 않는다. SDK가 3.23.1이 아니면 아무것도 하지 않는다.

## 안개가 1km 시야를 가리고 있었다

SDK 안개 거리의 단위는 「화면 높이만큼의 거리」다. Standard 기본값(약 14~20)은 카메라 2에서 **약 97m에서 시작해 120m쯤 90%** 가 된다(SDK 식으로 계산). 새 값은 250m에서 시작해 1km에서 약 90%이고 카메라가 바뀌어도 실제 거리가 같다.

## 시안과 다른 점

- **표고 조각을 줄였다.** 시안은 z11 약 15장·약 1.8MB, 제품은 z10 최대 9장(장당 약 130KB)이고 이웃 값을 이어 계단을 없앤다. 600m마다 다시 계산하며 받은 조각은 기억한다. 요청이 실패하면 1분 뒤에 다시 본다.
- 능선 계산을 4ms씩 나눠 주행 프레임을 막지 않는다.

## 비용

표고 조각은 Mapbox Raster Tiles API다. 공식 요금표(2026-11-25 조회): **월 75만 요청까지 무료**, 이후 1,000건당 0.25달러. 주행 한 번 9장으로 잡아도 월 약 8만 회까지 무료 범위이고, 긴 주행은 조각이 더해진다. 건물은 이미 받는 조각을 쓰므로 추가 요청이 없다. 서버·Firestore 변경 없음.

## 검증

- 통과: map 묶음 227/0(새 시험 11건 포함), tsc 오류 0, 새 파일 lint 0, 의존 방향·dev-tools·DB 통로, 셀렉터 21단계.
- 미통과: code-tidy `knip exports` 188(병행 rider15의 2건, 그대로).
- **제품 코드로 옮긴 뒤의 화면은 자동으로 확인하지 않았다**(Chief 직접 검수). 전체 `test:quick`은 푸시 검사에서 돈다.

## 남은 확인

- 파리·뉴욕처럼 외벽 자료가 있는 도시에서 창문이 겹치는지. SDK 코드로는 같은 가림 규칙을 쓰지만 화면 확인은 없다.
- 카메라 2~6을 바꿀 때 무늬가 다시 맞춰지는 순간, 100m마다 창문 건물을 다시 고르는 순간의 튐.
- 굽은 벽·모서리가 많은 벽에서 창문이 세로 줄무늬처럼 좁아지는 곳(Chief 검수 화면에도 보임).
- 스마트폰 속도·데이터.

## 시안 도구
