## 범위

- 우선 `src/lib/geo/entryLocation.ts`의 startLocate: 브라우저 권한 응답 대기까지 자체 8000ms watchdog이 소모되어 성공 응답을 무효화하는지, fake clock으로 지연 승인(8초 초과 후 한국 테스트 좌표 성공) 재현부터 확인한다. 실제 개인 좌표는 사용·기록하지 않는다.
- 브라우저의 위치 취득 timeout과 사용자의 권한 선택 시간을 혼동하지 않도록 수정한다. prompt/unknown에서 자체 타이머로 자동 Rome 확정하지 않는다. 위치 취득 오류/denied/unsupported, 명시 Rome 선택, 세션 비활성화 후 늦은 성공 차단은 유지한다. 이미 granted일 때의 무응답 방어는 유지 가능. 새로운 watchPosition/좌표 저장·전송·로그 금지.
- MapView bootFlyHold/Target 소비를 함께 조사한다. 한국 테스트 좌표 성공 뒤 실제 지도 camera가 해당 좌표로 가는지 기존 테스트 방식 또는 headless fixture로 검증한다. 지도 움직임·초기 로드·zoom 효과가 현재 위치 이동을 취소하면 최소 수정하고 재현 증거를 남긴다. 인증 기능·주행 카메라·검색 명시 이동을 재설계하지 않는다.
- 소유: 위 geo 파일, 관련 hooks/useEntryLocation.ts, components/map/MapView.tsx, App.tsx 최소 접점, scripts/identity/entry-location.test.ts와 필요한 기존 관련 시험. 새로운 디버그 도구보다 기존 시험 사용. UI 변경이 필요하면 이유를 결과에 기록한다.
