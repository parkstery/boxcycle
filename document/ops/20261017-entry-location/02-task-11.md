## 구현 확정

- 지원 브라우저: 최초 「어디에서 시작할까요?」 카드의 **현재 위치 동작 자체**가 실제 visible `<geolocation lang="ko">` 컨트롤이다. 브라우저가 정하는 「위치 사용」 label 존중. 기존 별도 blue버튼으로 native 컨트롤을 여는 전환 금지. 합성 click/투명 overlay/브라우저 guardrails 우회 금지. 실제 클릭 가능한 native 요소를 primary 파랑/흰색·충분 대비로 표시. 주변 정적 caption 「내 위치 근처에서 시작」과 보조 `(위치공유 필요)`는 유지하되 caption을 별도 버튼처럼 꾸미지 않는다. 둘째 「앱 기본 위치에서 시작」은 기존 버튼 그대로.
- 미지원 브라우저: 최초 현재 위치 버튼 클릭 동기 구간에서 기존 onChooseCurrent→getCurrentPosition 호출. 별도 앱 동의/confirm/alert 금지.
- EntryLocationDialog의 consentOpen state/wrapper/pure view 분리는 필요 없어지므로 간결하게 제거 가능. NativeAllowControl hook 자식만 유지, 초기 phase choice에서 바로 렌더. native 결과 acceptPosition 연결 유지. 위치 native요소는 유효 좌표 올 때까지 마운트 유지. 오류·거절은 작은 인라인 상태로 알리고 최초 두 선택지를 유지한다.
- NativeControl.permissionStatus는 문서대로 **string** (`granted|denied|prompt`)이다. `{state:...}` 타입/접근은 잘못이므로 교정.
- Supervisor 독립 eslint에서 이미 2error 확인: createElement에 ref객체를 직접 전달한 refs 판정, effect안 setConsentOpen의 set-state-in-effect. 중간 카드 state 폐기로 후자는 제거. 전자는 안정 callback ref(useCallback 또는 함수ref)로 교정하고 eslint 재검증. 기존 App hook geo 최소 연결 외 범위 확대 금지.
- native label 자체는 커스텀 불가이므로 이전 blue버튼과 문자 동일성을 맞추려고 중간 화면을 재도입하지 말 것. Chief 최신 최소 클릭이 우선.
