## 확정 구현

1. 기존 초기 카드 두 버튼과 현재 위치 버튼 둘째줄 `(위치공유 필요)` 유지. 첫 버튼 클릭은 앱 내 작은 공유 동의 카드로 전환: **위치 공유를 허용하시겠어요?** / 위치를 공유하면 내 주변 지도에서 시작합니다 / 허용 동작과 취소. 취소·거절은 초기 선택으로 복귀, 지구본 유지. 클릭 전 위치 API 요청 금지(prompt/unknown/denied). 경고 alert/confirm/사이트 설정을 직접 바꾸라는 기본 안내 전부 제거.
2. 공유 카드의 허용 동작은 지원 브라우저에서 **실제 visible `<geolocation lang="ko">` native control**. 브라우저 label은 조작 불가하므로 native 문구 존중. 주변에 허용 의미를 명확히 설명. 사용자가 이 native control을 실제 클릭→브라우저 허용/거절 dialog→허용 후 location 이벤트 position.coords로 진행. autolocate/watch 금지, 중복 getCurrentPosition 금지. CSS guardrails 준수(불투명/충분 대비, 44px 근접 터치, 숨김·겹침·강제 syntheticclick 금지). `<geolocation>` 자체는 React.createElement나 좁은 로컬 타입으로 구현 가능, JSX 전역 대규모 타입 확장 금지.
3. 미지원 브라우저에는 같은 카드의 일반 **허용** 버튼. 클릭 동기 구간에 기존 onChooseCurrent→getCurrentPosition 요청. 자동 허용 흉내 금지. 이미 영구 차단되어 미지원으로 복구 불가하면 실패를 정직하게 작은 인라인 상태로 표시하고 취소/기본 위치 선택 유지(설정 alert 없음). 모든 브라우저에서 차단 해제가 가능하다고 보고하지 않는다.
4. 네이티브 position을 기존 session→hook→App→MapView boot target에 연결하기 위해 최소 `acceptPosition(lng,lat)` 추가를 Supervisor 승인한다. EntryLocationSession/State에 추가, 활성이고 phase choice일 때만 유효 좌표 받아 generation bump/타이머정리, ready/granted/target[ lng,lat ] zoom fallback, notice null로 전환. 비활성/이미 ready/locating/잘못된 좌표 무시. App에 onPosition 연결. 이 결과를 그대로 지도 목적지로 사용. consent 취소 시 native element unmount·이벤트 구독 cleanup(취소/기본 위치 확정 뒤 늦은 결과는 무시). 네이티브 오류/거절은 동의 카드에서 재시도·취소 가능하며 성공으로 간주하지 않는다.
5. 소유: EntryLocationDialog.tsx/css(필요시 작은 분리 컴포넌트), lib/geo/entryLocation.ts, hooks/useEntryLocation.ts, App.tsx의 prop 연결 한 줄, scripts/identity/entry-location.test.ts, scripts/ride-verify/entry-contract.mjs 최소 앵커, 새 관련 *.test.*. 기존 지시07/08 세션 회귀 보존. 인증/지도 엔진/저장/감시/외부 API 변경 금지.
6. 기존 시험은 컴포넌트 함수를 직접 호출한다. useState 추가 시 이를 무턱대고 직접 호출해 invalid hook으로 깨지 말 것. UI를 pure view + state wrapper로 나누어 기존 렌더 시험이 pure view를 사용하게 하거나, 실제 React mount 시험으로 이동한다. wrapper의 실제 클릭 동작은 브라우저 component fixture로 검증해야 한다(단순 source 문자열 시험만으로 PASS 금지).
