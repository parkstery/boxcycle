## 확정 동작·소유

- 위치 차단(choice/denied)에도 활성 버튼 두 개: **내 위치 근처에서 시작**, **앱 기본 위치에서 시작**. 기본 위치는 기존 콜로세움. 질문은 어디에서 시작할까요 유지. blocked 설명은 권한을 브라우저 설정에서 허용한 뒤 내 위치 근처 버튼으로 다시 시도할 수 있다고 간결히 안내.
- `chooseCurrent`는 denied에서도 사용자 클릭 한 번당 위치 요청 한 번 가능하게 한다. 브라우저 설정에서 허용한 뒤 같은 버튼을 누르면 한국 테스트 좌표로 ready가 되어야 한다. 권한 우회·자동 반복 요청 금지. denied에서 클릭할 때 unknown 방식으로 시작하여 권한 선택 시간에 자체 8초 타이머를 적용하지 않는다(지시07 유지).
- 실제 위치 요청이 denied 오류로 끝나면 **ready/fallback이 아니라 choice/denied/target null**로 돌아와 같은 두 버튼을 유지한다. 명시 기본 위치 버튼으로만 콜로세움 확정. 타이머 정리·generation·중복 클릭 방지·취소 후 늦은 응답 차단 유지. 기승인 정상·prompt 지연 승인·기타 오류의 기존 동작은 유지.
- 소유: src/components/auth/EntryLocationDialog.tsx, src/lib/geo/entryLocation.ts, scripts/identity/entry-location.test.ts, e2e/rideEntryHelpers.ts, scripts/ride-verify/entry-contract.mjs와 필요시 ride-entry.spec.ts 최소 연결. 제품 식별자 chooseRome 등 일괄 rename 금지. App/지도 카메라/인증/위치 저장·전송·별도 IP API 변경 금지.
- 버튼 라벨 변경은 공용 e2e helper에 반영. entry-contract에 위치 선택 단계 앵커를 먼저 추가/수정. denied 회귀 시험을 새 요구에 맞춰 갱신하고 (1)차단 상태 양 버튼 표시/콜백 (2)denied→명시 내 위치→다시 denied에도 선택 유지 (3)허용 후 재시도→한국 좌표 (4)명시 기본 위치 확정 (5)대기중 취소 회귀를 검증.
