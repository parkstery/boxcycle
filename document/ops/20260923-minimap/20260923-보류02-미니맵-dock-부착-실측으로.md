## §1 원인 — 이미 특정했다. 다시 찾지 마라

`RouteDock.css:562`

```css
@media (max-height: 560px) {          /* 폰 가로 */
  .route-dock-anchor { --mapbox-logo-clearance: 0.35rem; }
}
```

폰 가로에서는 Mapbox 로고가 이미 화면 밖이라 **dock 이 여백을 회수하고 더 내려간다.**

`RouteMinimap.css:11` 은 같은 이름의 변수를 **자기 파일에 2.875rem 으로 복사**해 두고
**그 미디어쿼리가 없다.** 그래서 폰에서만 미니맵이 dock 보다
`(2.875 − 0.35)rem × 13.5px ≈ 34px` 위에 뜬다. PC(height > 560)는 두 값이 같아 붙어 보인다.

지시04 §3 이 「RouteDock 의 bottom 계산식과 **같은 값을 공유**하라, 두 벌로 베껴 쓰면
한쪽만 바뀐다」고 했는데 베껴 쓰는 쪽으로 갔다. 그 경고가 그대로 현실이 됐다.

## §2 고치는 방법 — 식을 맞추지 말고 **dock 을 잰다**

미디어쿼리 한 줄을 미니맵 CSS 에 더 복사하면 지금은 맞지만, **세 번째 분기**(safe-area,
브라우저 주소창 높이, 다른 화면 높이 임계)가 생기면 또 어긋난다. 이미 같은 함정을 한 번 밟았다.

**RouteDock 엘리먼트의 실제 위치를 측정해서 거기에 붙여라.**

```
dockTop = document.querySelector('.route-dock-anchor').getBoundingClientRect().top
미니맵 bottom(px) = window.innerHeight − dockTop + 간격(0.35rem 환산 px)
```

- 갱신 시점: `ResizeObserver`(dock 엘리먼트 + 뷰포트) + `window.resize` +
  `orientationchange`. 이미 있는 observer 에 얹어라
- **dock 이 펼쳐졌을 때는 위치를 바꾸지 마라.** 펼침은 일시적인데 미니맵이 따라 올라가면
  화면이 출렁인다. `.route-dock-anchor--open` 이 **아닐 때의 top 만 기록**해 두고 그 값을 쓴다.
  최초 렌더가 펼침 상태였다면 접힘 값을 얻을 때까지 현재 CSS 식을 폴백으로 쓴다
- dock 을 못 찾으면(쿼리 실패) 지금 CSS 식으로 폴백한다. **미니맵이 사라지면 안 된다**
- `RouteMinimap.css` 에 복사돼 있는 `--mapbox-logo-clearance` · `--mm-collapsed-dock-h` 는
  **폴백 전용**임을 주석에 명시하라. 평상시 값은 측정이 준다
- `availH`(상한) 계산도 같은 측정값을 쓴다 — 상단은 좌상단 블록 rect 로,
  하단은 dockTop 으로. 상수 `--mm-tl-block: 2.55rem` 도 같은 이유로 **실측으로 바꿔라**
  (`.map-hud__tl` rect bottom). 같은 함정이 위쪽에도 그대로 있다

### ⚠ 측정이 **언제** 다시 일어나야 하는가 (Chief 실기 추가 관찰)

> 「높이를 줄이면 RouteDock 에서 간격이 조금 더 늘어나긴 하지만 **RouteDock 위에 놓여 있는
>  느낌**이다. 그런데 **폰에서는 RouteDock 과 뚝 떨어져** 중간에 독립군처럼 있다.」(Chief)

데스크톱 990×400 에서는 간격이 조금 벌어지는 정도인데 실기 폰에서는 훨씬 크다.
즉 `max-height:560px` 분기 **하나로는 전부 설명되지 않는다.** 실기에는 더 있다 —
루트 글꼴 크기(폰 가로 13.5px), `env(safe-area-inset-*)`, 모바일 브라우저 주소창이
들고 나며 바뀌는 **visualViewport**. 그래서 **식을 맞추는 방식은 어차피 진다.**

측정 방식으로 가되, **다시 재는 시점**을 다음으로 못 박아라:

- `window.resize` · `orientationchange`
- `window.visualViewport` 의 `resize` · `scroll` (모바일 주소창 개폐 — **이게 실기 전용 변수다**)
- dock 엘리먼트 `ResizeObserver` — ⚠ **ResizeObserver 는 위치 이동에는 발화하지 않는다.**
  크기가 그대로인 채 dock 이 위아래로 움직이는 경우를 놓친다. 위 이벤트들이 그 구멍을 메운다
- 마운트 직후 **rAF 1회 재측정**(첫 페인트 전 rect 는 확정 전일 수 있다)
- 폰트 로드 완료(`document.fonts.ready`) 후 1회 — rem 기반 dock 높이가 그때 바뀐다

값이 바뀌지 않으면 상태를 갱신하지 마라(리렌더 폭주 방지). 1px 미만 변화는 무시한다.

## §3 합격 조건 — 숫자로, 두 화면 모두에서

**미니맵 bottom 과 접힌 dock top 사이 간격이 두 뷰포트에서 같아야 한다.**

| 뷰포트 | 조건 |
|---|---|
| `900×400` (PC·height>560) | `dockTop − minimapBottom` = 간격값 ±1px |
| `740×300` (폰 가로·height≤560) | **같은 값** ±1px |

두 값이 다르면 아직 식이 갈라져 있는 것이다. **차이를 그대로 보고하고 원인을 적어라.**

추가로 `360×640`(세로) 같은 극단 화면에서 미니맵이 dock 이나 좌상단을 **침범하지 않는지**
한 번 확인하라(앱은 폰 가로 전용이고 세로는 회전 오버레이가 덮지만, 계산이 음수로
터지지 않는지 보는 것이다).

## §3.5 ⚠ 네 하네스는 이 버그를 **재현할 수 없다** — 측정기부터 고쳐라

지시04 보고는 740×300 과 1161×870 **모두 간격 4.6px** 이라고 했다. 그런데 Chief 실기에서는
폰만 크게 벌어진다. 보고가 거짓이어서가 아니라 **측정기가 현실을 담고 있지 않아서**다.

`apps/web/.out/jisi04-minimap/minimap-harness.html` 을 보면:

```
38:  .route-dock-anchor {
40:    --mapbox-logo-clearance: 2.875rem;      ← 손으로 베낀 사본
```

**제품의 `@media (max-height: 560px) { --mapbox-logo-clearance: 0.35rem }` 이 사본에 없다.**
그래서 하네스에서는 dock 과 미니맵이 같은 값을 쓰고 **항상 붙어 보인다**.
이 리포에 이미 있는 함정이다 — **항상 참이 되는 게이트는 게이트가 아니다.**

이번 라운드에서 먼저 할 일:

1. 하네스가 **제품 CSS 파일 자체를 불러오게** 하라 —
   `RouteDock.css` · `RouteMinimap.css` · 루트 글꼴 크기를 정하는 전역 CSS 를
   `<link>` 또는 `@import` 로 **원본 경로에서** 읽는다. 손으로 베낀 선언은 전부 지운다
2. DOM 도 제품과 같은 클래스·중첩 구조로 만든다(지금처럼 `route-dock-anchor` 만 흉내 내지 말고
   `route-dock__shell` · `route-dock__caret` 까지)
3. **고치기 전에 먼저 재라.** 그 상태에서 740×300 의 간격이 900×400 과 **다르게 나와야 한다**
   — 그게 「측정기가 이제 버그를 본다」는 증거다. **그 수치를 보고에 먼저 적어라**
4. 그 다음 §2 의 측정 방식으로 고치고, 두 뷰포트 간격이 같아짐을 보여라

> **before(버그 재현) → after(수정)** 두 수치가 같은 측정기에서 나와야 합격이다.
> before 를 못 만들면 after 도 믿을 수 없다.
