## §0 확정된 설계 (개발계획서 D1~D6). 바꾸지 마라

두 번째 Mapbox 인스턴스 금지 — **SVG 한 장**. 주행 중(`riding`·`paused`) 상시 표시.
그리는 것은 **전체 경로 · 시점 · 종점 · 현재 위치** 넷. **탭 동작 없음**(단 터치는 지도로 내려보내지 않는다).

## §1 ⚠ 먼저 풀어야 할 것 — 네 측정 뷰포트가 실기기보다 100px 이상 높다

지시01 을 **900×400** 에서 쟀고 「남는 세로 169.9px」를 보고했다. 그런데 이 앱의
**폰 가로 실제 CSS 높이는 약 275px** 이다(`MapHud.css` 의 `@media (max-height: 560px)`
주석이 근거다). 높이가 125px 줄면 **남는 세로는 그대로 125px 줄어** 45px 안팎이 된다.
**그 높이에는 미니맵이 들어가지 않는다.**

따라서 이 라운드의 첫 작업은 **실측**이다:

1. 뷰포트 **두 개**에서 잰다 — `900×400`(기존) 과 **`740×300`**(폰 가로 근사)
2. 각각에서 **좌상단 블록 bottom** 과 **접힌 RouteDock top** 사이의 세로 px 를 보고하라
3. 그 값이 미니맵 높이의 상한이다. **상한을 넘겨 만들지 마라** — 넘기면 RouteDock 을
   덮거나 계기판을 가린다

### ⚠【정정 · Chief 2026-09-23 15:5x】 「1/6」의 뜻 — 정사각형이 아니다

> 「1/6 의 의미는 정사각형이 아니다. 폰을 가로 모드로 놓고 보게 되므로 **미니맵도 같은 비율의
>  크기**를 말한 거야. **가로가 긴 미니맵**이지. 폰 자체의 세로 길이는 여유가 별로 없으니
>  **상대적으로 여유있는 가로 길이라도 늘여 줘야** 그렇지 않아도 작은 미니맵이 덜 작아 보이지.
>  미니맵이라고 아무것도 안 보이면 안 되잖아.」(Chief)

따라서 **16:9 고정이 아니다.** 미니맵은 **화면(뷰포트)과 같은 종횡비**를 갖는다 —
화면을 그대로 축소한 상자다. 폰 가로 740×300 이면 종횡비 ≈ **2.47:1**, 900×400 이면 2.25:1.

크기를 정하는 순서:

1. **높이** = §1 에서 실측한 세로 여유의 대부분(위아래 4px 씩만 남긴다). 세로가 상한이다
2. **폭** = 높이 × 화면 종횡비. **그리고 세로를 더 못 키우는 만큼 가로로 벌어라** —
   폭 상한은 **화면 폭의 42%** 까지 허용한다. 그 안에서 크게 잡아라
3. 종횡비는 **런타임에 계산**한다(`window.innerWidth / innerHeight`, resize 시 갱신 →
   `aspect-ratio` 또는 폭 계산에 사용). 하드코딩 금지 — 기기마다 화면비가 다르다
4. 결과 면적비를 보고하라. **1/12 보다 작으면 작은 것이다** — 그 경우 폭 상한(42%)까지
   키운 뒤에도 얼마인지 적고, 더 키우려면 무엇을 포기해야 하는지 한 줄로 적어라

> **가독이 목적이다.** 「아무것도 안 보이는 미니맵」은 실패다. 상자가 작을수록 경로 선은
> 상대적으로 굵어야 한다 — 선 굵기·점 크기를 상자 크기에 비례시키지 말고 **최소값을 지켜라**
> (경로 밝은 선 ≥ 1.5px, 외곽선 ≥ 3px, 현재 위치 점 지름 ≥ 7px).

### 입력 (새로 만들지 마라 — 이미 있는 것)

| 필요한 것 | 어디 있나 |
|---|---|
| 경로 기하 | `routeGeometry` (LineString) |
| bbox | `boundsFromLineCoordinates()` — `lib/geo.ts` |
| 현재 위치 | `liveForMap` (`App.tsx:1429`) — **항상 경로 폴리라인 위의 점**이다 |
| 표시 여부 | `stage` 가 `riding` · `paused` |

### 좌표 변환 — 등축(uniform) 스케일을 지켜라

bbox 를 상자에 맞출 때 **가로·세로 배율을 따로 주면 경로가 찌그러진다.**

- 배율은 `min(가로배율, 세로배율)` **하나**를 쓰고 남는 쪽은 가운데 정렬한다
- 경도 1도는 위도 1도보다 짧다 — x 에 **`cos(중심위도)`** 보정을 넣어라.
  넣지 않으면 우리 위도(약 37°)에서 경로가 가로로 25% 늘어난다
- 안쪽 여백 6px. 경로가 한 점에 가까운 축퇴 경우(bbox 폭·높이 0)에도 **NaN 이 나오면 안 된다**
  — 0 나눗셈 가드를 넣고, 그 경우 중앙 점 하나로 그려라

### 그리기

- 경로 선: 어두운 외곽선(굵게) 위에 밝은 선(가늘게) **2겹**. 위성 이미지 위에서도 읽혀야 한다
- 시점·종점: 작은 점 + 각각 `S` · `E` 구분(모양이나 색으로. 글자는 작아서 안 읽히면 빼도 된다)
- 현재 위치: **주황 점 + 흰 테두리**(HUD 강조색 계열). 경로 선보다 위에 그린다
- 틀: 기존 `hud-glass` 계열과 같은 결의 반투명 배경 + 1px 테두리 + 라운드
- 경로가 상자 종횡비와 다르면 **가운데 정렬**되고 남는 쪽에 여백이 생긴다(레터박스). 정상이다 —
  경로를 늘려 상자를 채우지 마라(§ 등축 스케일)

### 성능 — 경로 path 는 매 프레임 다시 만들지 마라

`liveForMap` 은 주행 중 계속 갱신된다. 경로 `d` 문자열은 **`useMemo`(기하 + 상자 크기)** 로
고정하고, 바뀌는 것은 **현재 위치 점의 좌표뿐**이어야 한다.
좌표가 1000개를 넘으면 균등 샘플링으로 줄여라(시각적으로 차이가 없는 선에서).

### 터치 (이 리포에서 네 번 반복된 함정)

- 컨테이너는 `pointer-events: auto`, `onPointerDown` · `onTouchStart` 에서
  `stopPropagation()` + `preventDefault()`. **미니맵을 눌러도 지도가 움직이면 안 된다**
- `pointer-events: none` 으로 통과시키는 방식은 **금지**(지도가 끌려간다)
- 탭해도 아무 일도 일어나지 않는다. 버튼으로 만들지 마라(`aria-hidden` + `role="img"` 적절히)

### 표시 조건

- `riding` · `paused` 이고 `routeGeometry` 가 있을 때만 **렌더 자체를 하지 않는다**(null 반환).
  CSS `display:none` 으로 숨기지 마라 — 안 보이는 SVG 가 계속 리렌더된다
- 위치: 좌측. 좌상단 블록 **아래**, 접힌 RouteDock **위**. 가로 기준선은 RTW·RouteDock 과 같은 좌측 여백

- RouteDock 을 **펼쳤을 때**(주행 중 사용자가 캐럿을 누른 경우) 미니맵과 겹치는지 확인하라.
  겹치면 그 사실을 캡처와 함께 보고하라 — **임의로 우측으로 옮기지 말고** 감리 판단을 받아라
- 지시01 의 좌상단 한 행 배치, QC·Account 겹침 없음이 그대로인지 재확인
- 주행이 끝나면(`summary`·`idle`) 미니맵이 사라져야 한다
