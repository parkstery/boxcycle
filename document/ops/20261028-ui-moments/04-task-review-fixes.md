## 2. 응원 실행 단위와 중복

- 첫주행종료→idle→새running에서 ended=true가 새주행까지 남아 모든 응원을 차단한다. 새 ride 시작에서 메모리 초기화. paused→running은 새주행이 아님. 이전 종료 payload가 잠깐 남아도 새주행을 막거나 옛종료를 재생하지 않게 한다.
- 이미 재생한 step의3초예고는 paused에서 지우지 않는다. 예고→pause→resume(남은3초 동일)에서1회만.
- 큰시간점프로 완료를 넘겼으면 해당 사건을 소비 상태로 표시해 다음정상틱에서 뒤늦게 재생하지 않는다. 시작/경유/절반/예고도 지난 사건을 큐에 쌓지 않는다. 현실적인 큰시간점프 기준과 실제단계변경을 구분한다(일반3초 경과를 무조건 과거사건으로 취급하지 말 것).
- 인터벌 완료 후 같은 주행에서 설정변경/끄고켜기→다시완료가 가능해야 한다. **주행 실행과 인터벌 실행 단위를 구분**: useRideInterval의 revision/run key(설정변경/다시켜기/새주행)를 응원 입력에 전달하여 intervalStarted/Completed/warnedStep을 초기화하는 방식 권장. DB필드 추가 아님. 순수단위와 React 실제 hook 재시작 둘다 검증. 준비0초면 실제첫고강도에 맞는 응원, 무조건 준비부터 문구 금지.
- hook은 pause/종료/해제/언마운트에 오래된 표시timeout·효과음 재생대기를 취소. 새/현재전환 메시지가 표시 중일 때 다음틱의 낮은우선순위 절반/경유가 덮어쓰지 않게 한다. 실제 전환/종료는 예고보다 우선하고 대기 큐는 만들지 않는다. 현재 null-event 틱이 과거 메시지를 무조건 계속 남기는지 확인.
- useRideMoments 새 exhaustive-deps 경고는 disable 없이 없앤다(입력을 안정된 필드로 분해하거나 안정적memo 계약).

## 3. 효과음 실패·취소

AudioContext 생성자 throw도 try/catch로 조용히 처리. 느린 resume Promise가 pause/종료/해제 뒤 완료되어 옛소리를 재생하지 않도록 generation/cancel을 구현한다. 필요시 기존 oscillator도 취소. audio 기본끔·TTS중충돌회피 유지. 취소 API는 hook에서 실제로 사용하고 새 의존성/외부API 금지.

## 4. 설정/시험 품질

- 선택3개와 선택적인 직접설정은 유지. 접힌 기본 화면에서도 준비/고저/반복/마무리 구성과20:10 라운드/휴식이 간결하게 읽혀야 한다(현재 총시간만으로는 구성 파악 어려움). 펼치면 입력과 중복요약은 제거. 불필요한 창높이 증가 금지.
