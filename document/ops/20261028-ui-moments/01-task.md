## 확정 구현 범위

### A. 주행 HUD와 패널

1. 실제 viewport 800×360, 736×360, 699×273, 667×300 기준 계기판 시각 rect와 텍스트가 화면 폭 50%를 넘지 않는다. 3열×2행 등 작은 구성. 거리 `누적 / 전체 km`는 한 줄, 단위와 값 가독성 유지. 계기판 압축 때문에 우상단 카메라/지도/계정 버튼이 줄어들거나 겹치지 않도록 독립 영역을 확보한다.
2. 계정의 앞 닉네임 약자 원만 제거하고 닉네임 자체를 유지한다. 기존 계정 기능과 데이터 유지.
3. 상단 순위 칩을 제거하고 오른쪽 측면 반달형 핸들로 순위표를 펼치고 접는다. 왼쪽 MENU도 같은 외형으로 넓힌다. 시안 visible 34×72 / target 44×76 정도를 기준으로 실제 가로 높이에 맞추되 양쪽 동일 형상, 최소 실효 터치44px, click 및 drag/swipe, 키보드·aria-expanded·controls 유지. **기존 EdgePanelHandle/edgePanelDocumentGesture를 재사용·확장**하고 제스처 처리기를 중복 등록하지 않는다. 오른쪽에 삭제된 맵 뷰를 복원하지 않는다. 순위판은 기존 데이터·바탕 없는 윤곽선 표현과 전체 순위 진입을 보존한다. 펼쳐진 순위와 주행 종료 버튼이 작은 높이에서도 겹치면 안 된다.
4. 인터벌 안내는 계기판 아래 왼쪽. 오른쪽 순위와 중앙 라이더/다음 길을 침범하지 않는다. 기존 지도조작·주행 시작/일시정지/종료·주소/미니맵 접기 계약 유지.
5. 결과창은 가로444×194·최소10px와 저장/저장 안 함/기록 의미를 유지하면서 시안처럼 성과(거리/새도로), 보조 수치, 순위, 저장을 정렬한다. 같은 거리 완주 반복과 의미 없는 꽉 찬 완료 막대/빈 줄은 정리한다. 기존 의미 있는 행동을 삭제하지 않는다.

### B. 인터벌 최소 구성과 최근값

6. 프리셋8개 버튼을 단일 선택창3개로 단순화한다. 회복형1:2 = 준비300/고60/저120/반복5/마무리300초(25분), 균형형1:1 = 준비300/고60/저60/반복8/마무리300초(26분), 짧은 반복20:10 = 준비600/고20/저10/반복8/라운드2/라운드사이휴식180/마무리300초(26분). 3라운드면 휴식은 사이2번이며33분. 난이도·건강효과·RPE/RPM 강제 처방을 추가하지 않는다.
7. `직접 조절`은 기본 접힘. 준비/고/저/반복/마무리 조절, 짧은 반복에는 라운드(1~3)·라운드 사이휴식(0~1800초)도 조절. 기존초단위0~1800 준비/마무리,고저5~600,반복1~30 정수 계약과 0초준비/마무리 건너뜀 유지. 시안의 분 입력으로 인해 기존 초 값을 반올림/손실하지 말 것. 펼쳤을 때 입력과 같은 요약을 반복해 창을 키우지 않는다. 내용 기반 폭·높이, 699×273에서도 필수 입력/적용/닫기 접근 가능. 불가피하면 내부 영역만 제한 스크롤하되 적용 행 고정, 큰 min-height/빈 영역 금지.
8. 현재 localStorage v1의 사용자 지정 값을 보존하고 새로운 선택/라운드 필드가 없으면 rounds=1/rest=0으로 복원한다. 저장을 적용할 때만 최근 값을 영속화. 새 기본은 1:2이며 기존 설정이 있으면 기존값 우선(프리셋과 다르면 직접 설정으로 표시). 초안 변경/닫기와 실제 적용 분리. 동일 설정 재적용은 운동 재시작 안 함. 실제 변경을 주행 중 적용하면 기존처럼 준비부터 재시작. 최근 값은 새로고침·재진입 시 복원. 사용 스위치 기본 끔/주행별시간 리셋/완료후 자유주행 유지. 배경복귀·일시정지는 기존 accumulatedMs 기준.
9. rounds와 round-rest를 순수 시간 계산에 추가하고 라운드 사이에만 휴식, 마지막 라운드 뒤 추가휴식 없음. view에는 필요시 round/totalRounds/다음단계 표시 추가. 기존 1라운드 계약과 사용처 호환. step/round/phase 전환과 마지막 회복→마무리→완료 경계 검증.

### C. 무센서와 순간 응원

10. **출시 시 무센서15~18고정속도는 장래 방향이며 지금 강제하지 않는다. Chief는 개발 단계50km/h 조절이 필요하다고 명시했다. 기존 개발 속도 조절·센서/주행 물리·저장/순위/도로망 계산을 그대로 둔다.** 무센서에서도 인터벌 타이머를 제공하고 RPM/운동 수행을 측정한 것처럼 만들지 않는다. RPM은 — 또는 타이머 표현, `페달 강도 직접 조절` 같은 짧은 안내. 센서 연결 안내는 기존 센서 진입에서 자발적으로 볼 수 있게 하며 반복 구매 팝업 금지. 시안의16km/h와 모의 센서 선택은 제품에 고정하지 않는다.
11. 주행 시작, 거리50% 통과, 실제 경유지 통과(목표 거리50%와 별도), 인터벌 시작/고·저전환3초 예고/전환/완료, 목표 완주/자발 종료에 짧은 응원 연출을 제공한다. 기존 코칭 하단 한 자리를 공유(우선 메시지로 대체)하고 별도 상시 배너를 더하지 않는다. 중앙을 가리는 큰 축하 금지. 작은 글자 강조/짧은 빛/완료 강조 정도로 절제. 문구는 승인 시안 참조, 실제 새도로 수치가 확정됐을 때만 표시한다.
12. **전환 안내 > 경유/절반 같은 일반 성취**. 동시 이벤트 중복·뒤늦은 이벤트 큐 폭주 금지. 주행 시작/종료는 각1회, 경유지는 지점당1회, 절반은 주행당1회, 인터벌 예고는 전환당1회. paused→running은 새 시작이 아니고 종료시 대기 이벤트 취소. 큰 시간 점프로 지난 구간을 재생하지 않는다. 준비/회복/마무리0초·구성변경·켜기끄기·다음주행·오래된 timeout에 안전해야 한다. 인터벌 완료는 주행 종료를 부르지 않는다.
13. 시각2~3초, map pointer-events 방해 없음, reduced-motion에서는 움직임 제거. 효과음은 기본 꺼짐·명시적으로 켠 경우만 짧은 WebAudio 신호, 자동재생 실패는 조용히 무시. 기존 TTS/BGM/코칭 음성이 겹치지 않게 하고 새로운 API/라이브러리/외부 서비스는 추가하지 않는다. 설정 UI는 기존 주행 설정 내 작은 효과음 선택 정도로 한정. 타이머마다 React 전체App 불필요 리렌더·지도재렌더를 유발하지 않게 분리한다.

## 검증과 산출물

- 먼저 현 구조를 필요한 범위만 읽고 관련 구현을 끝낸다. src 원본 import하는 순수/React 시험으로 인터벌 경계·저장 호환·이벤트중복/우선순위·일시정지와 복귀를 검증한다. 소스 문자열만 확인하는 시험으로 동작시험을 대체하지 않는다.
- `cd C:\20.HDev\boxcycle\apps\web`; `node scripts/ride-verify/verify-selectors.mjs`; `npx tsc -b --noEmit`; 변경파일 eslint; `npm run build`; 관련 단위/React시험; 루트 `node scripts/check-dep-direction.mjs --check`; `git diff --check`. 단위 전체 quick는 마지막에1회만 돌리고 실패를 숨기지 않는다.
- 프리뷰를 실제 제품 컴포넌트로 연결하고 `e2e/ride-ui-moments.spec.ts` 등을 작성하여800×360/736×360/699×273/667×300에서 HUD≤50%,컨트롤 비찌그러짐/비겹침,좌우tap/swipe,인터벌왼쪽·순위오른쪽,설정3개·초안/최근값/0초·라운드·결과를 확인. 기존 관련e2e는 새승인과 직접 충돌하는 기대만 수정(옛중앙/초성/순위원형/8프리셋), 나머지 시험을 삭제·약화하지 않는다. 실제 계정/운영 Firebase를 쓰지 않는다.
