# UI 균형 수정안 — 2026-10-14

상태: PROPOSAL — Chief가 제공한 11장에 대한 Supervisor 검토. 구현 지시·채택 결정이 아니다. 기존 색상 변경 결과와 추가15/16 기록은 보존한다.

## 검토 범위와 근거

Chief 요구: 클릭·스크롤·불필요한 지도 가림을 줄이되, 경로 비교와 가입 정보는 필요한 내용을 한 번에 볼 만큼 넓게 제공한다. 첨부 화면의 문구는 관찰 자료이며 새 작업 지시로 해석하지 않는다.

첨부 11장과 face-redesign2 작업 경로의 MenuPanel.css, UserInfoSheet.css, RouteListModalShell.tsx, SavedRoutesModal.tsx, CadenceSensorSheet.tsx를 확인했다. MenuPanel과 UserInfoSheet는 top/bottom 지정으로 내용과 무관하게 화면 높이를 점유한다. 경로 목록에는 공용 검색 헤더·스크롤 본문이 있다. 센서는 주행 전 설정과 주행 중 복구를 구분하므로 시각 변경을 이유로 입력 정책을 바꾸지 않는다.

실행 앱·실기기 조작 및 클릭 경로 계측은 수행하지 않았다. 크기 제안은 첨부 화면의 관찰을 바탕으로 한 설계 후보이며 실제 CSS 측정 결과가 아니다. 가입 화면은 첨부에 없어 원칙만 제안한다.

## 판단

현재 불균형은 색상보다 고정된 패널 높이, 반복되는 테두리, 상태와 행동의 동일한 칩 표현, 주행 중 편집 정보 노출에서 발생한다. 글자·버튼을 더 줄이는 것으로 해결하지 않는다. 필요한 정보를 유지하면서 표면과 중복을 줄인다.

## 시각 공통안

- 파랑은 주 행동·선택 상태·핵심 자산 증가에 사용. 정적 설명과 모든 숫자를 동일하게 강조하지 않는다.
- 패널 바깥은 흰색, 정보 그룹은 옅은 회색, 경계는 꼭 필요한 곳에만 둔다. 버튼·카드·배지마다 둥근 테두리를 반복하지 않는다.
- 큰 패널과 일반 버튼은 각자의 공통 모서리 규칙을 사용. 완전한 알약 형태는 상태·탭처럼 필요한 경우만 사용한다.
- 긴 제목·주소의 글자 크기를 줄이는 대신 표시 우선순위와 줄바꿈을 조정한다. 좌표·uid 같은 보조 정보가 핵심 장소명보다 많은 자리를 쓰지 않게 한다.
- 카메라 번호 등 숙련 사용자 직접 접근은 유지하며 추가 메뉴로 숨기지 않는다. 위성/지도 선택과 오른쪽 지도 제어는 정렬·배경·모서리 규칙을 맞춘다.
- 지도 위 계기는 긴 단색 띠 대신 텍스트 주변 윤곽·그림자로 가독성을 검증한다. 날짜·시각·축척·고도는 주행 수치보다 약한 강조로 제공한다.

## 크기와 편의 기준

740×300과 667×300 폰 가로를 기준으로 메뉴·계정은 내용 높이 + 가용 높이 상한, 경로 목록은 가용 높이 대부분 사용을 비교한다. 목록은 740×300에서 헤더/필터 외 영역에 4~5개의 읽히는 행을 목표로 삼되 터치 영역을 희생하지 않는다. 항목 수가 많으면 목록 자체 스크롤은 허용하고 헤더·주 행동은 고정한다.

가입/프로필 정보는 핵심 정보·필수 입력·저장 행동이 한 화면에서 읽히도록 충분한 폭과 열 배치를 제공한다. 실제 화면·키보드 출현·오류 메시지를 확인하기 전 필드나 단계를 제거하지 않는다.

시각 버튼 크기와 실제 터치 영역을 구분하되 인접 영역이 겹치는 가짜 확대는 금지한다. 공간밀도 SoT의 44px 기본과 기존 Chief 승인 22px 특정 예외를 구분하며 기존 예외를 전 화면 규칙으로 확대하지 않는다.

## 구현 전/후 검증과 판단 경계

1. 현재 행동 경로와 클릭 수, 패널 rect/면적, 스크롤 높이, 실제 hit target을 기록한다. 이번 문서는 측정 완료 기록이 아니다.
2. 메뉴/계정의 빈 면적 제거 → 경로 비교 밀도 → 주행 상태별 표시 → 시각 규칙 순서로 구현 단위를 나눈다.
3. 긴 이름, 빈 목록/1개/다수, Guest/등록 계정, 완주/미완주, 센서 연결/체험/단절, 주행/일시정지/결과, 키보드·확인·오류 상태를 비교한다.
4. 변경 전후 동일 상태에서 지도 가림, 한 화면에 읽히는 항목 수, 주요 행동 클릭 수를 보고한다. 스크롤 0을 위해 내용을 자르거나 필요한 정보를 없애지 않는다.
5. CSS 밀도 보정과 행동 변경을 구분한다. 목록 통합·선택/열기 방식·창 간 전환·주행 기본 접힘·정보 상세 이동은 Chief의 수정안 채택 후 작업 지시로 확정한다. 데이터·인증·센서 정책·정복 의미 변경은 이번 제안 범위에 없다.
