## 1. 분류 — 모든 개발용 코드·파일은 셋 중 하나

| 분류 | 뜻 | 예 | 수명 |
|---|---|---|---|
| **제품** | 사용자 기능 | `?subscription=`, 공유 링크 | 제품과 같음 |
| **상시 도구** | 계속 쓰는 진단·측정 | perflab, mapcut, camlab, lightlab, 실GPU 측정 스크립트 | 등록부에 남는 동안. 연 1회 사용 여부 점검 |
| **일회성** | 한 작업의 조사·실험 | 특정 버그 재현 프로브, 일회성 요약 스크립트, UI 캡처 픽스처 | **만료일 필수**. 기본값 = 만든 묶음이 닫힐 때 |

판단이 애매하면 일회성으로 등록한다. 계속 쓰게 되면 그때 상시로 올린다(Chief 확인).

## 2. 등록부 — `apps/web/dev-tools.json` 한 곳

`dep-layers.json` 과 같은 방식. 항목마다:

| 필드 | 내용 |
|---|---|
| `id` | 짧은 이름 |
| `kind` | `module`(디버그 코드) · `query`(주소 스위치) · `script`(실행 스크립트) |
| `path` 또는 `key` | 파일 경로 또는 쿼리 키 |
| `class` | `product` · `permanent` · `temporary` |
| `purpose` | 한 줄 목적 |
| `enable` | 켜는 법(예: `?perflab=1`, `node apps/web/scripts/perf/run-real-gpu.mjs`) |
| `bundle` | 만든 작업 묶음 폴더 |
| `added` | 날짜 |
| `expires` | `temporary` 만, 날짜 |

시험 파일(`*.test.*`)과 package.json·다른 코드가 부르는 스크립트는 등록하지 않아도 된다(이미 연결이 기록이다).

## 3. 위치

1. 디버그 코드는 `apps/web/src/lib/debug/` 에만 둔다.
2. 스크립트는 `apps/web/scripts/<도메인>/` 또는 루트 `scripts/`. **`.out` 안에 실행 코드를 두지 않는다.**
3. `.out` 은 지워도 되는 산출물만. git 추적 금지. 남겨야 할 수치·그림은 결과·보고 문서로 옮긴다.

## 4. 운영 번들

1. 상시 도구의 화면·계측 코드는 **주소 스위치가 있을 때만 동적 import** 로 불러온다. 제품 코드에는 스위치 판정 같은 가벼운 함수만 남긴다.
2. DEV 전용 도구는 `import.meta.env.DEV` 로 막아 운영 빌드에서 빠지게 한다.
3. 감리는 운영 빌드 결과에 도구 화면 문자열(예: "결과 복사")이 기본 청크에 없는지 확인한다.

## 5. 푸시 게이트 — `scripts/check-dev-tools.mjs`

pre-push 에서 실행한다. 실패 조건:

1. `src/lib/debug/` 의 파일이 등록부에 없다.
2. `src` 의 쿼리 키(`.get("키")`, `*_QUERY_KEY = "키"`)가 등록부에 없다.
3. `apps/web/scripts/`·루트 `scripts/` 의 시험이 아닌 파일이 아무 데서도 불리지 않고 등록부에도 없다.
4. git 이 `/.out/` 아래 파일을 추적한다.
5. 등록부 항목의 파일·키가 더 이상 없다(등록부 낡음).
6. `temporary` 항목이 만료 후 30일을 넘겼다. (만료~30일은 경고만)

## 6. 묶음을 닫을 때 (종료 조건에 추가)

1. 그 묶음이 만든 `temporary` 항목을 지우거나, 계속 쓸 것은 `permanent` 로 올린다(Chief 확인).
2. `.out` 의 필요한 수치·그림을 결과 문서로 옮긴다. 이후 `.out` 은 지워도 되는 상태.
3. ops 목록(README)과 PROGRESS 에 상태를 반영한다.

## 7. 정기 점검

- Supervisor 가 월 1회: 만료 경고 목록, 30일 넘은 종료 묶음의 `.out` 정리, `permanent` 중 3개월 안 쓴 것 보고.
- 결과는 PROGRESS 에 한 줄.

## 8. 작업 지시서에 넣을 문장

> 새 디버그 코드·주소 스위치·스크립트를 만들면 `apps/web/dev-tools.json` 에 등록한다(분류·목적·켜는 법·만료). 운영에서 켜지는 도구 화면은 동적 import 로 분리한다.
