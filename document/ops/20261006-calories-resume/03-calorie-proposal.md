# 칼로리 개선 제안

> 제안 당시의 기록이다. 이후 Chief의 「칼로리 계산 변경해」 요청으로 구현했다. 임의 체중 가정 없이 미입력은 미산정, 체중은 UID별 로컬 설정에만 보관한다. 현재 구현·검증은 [18 최종 검수](18-review-supervisor.md)를 따른다.

문서 유형: proposal. 작성: 2026-10-06. 상태: 제안 — 코드 미변경.

## 권장 순서

현재 거리(km)×30은 지도상 주행거리 환산값이다. 가상속도나 이동수단 변경만으로 칼로리가 달라져 운동량 추정으로 적합하지 않다. 같은 실제 운동이 가상 경로/속도에 의해 바뀌어서는 안 된다.

1. 먼저 '추정 kcal'로 표시하고 새 계산을 체중+실제 활동시간+사용자 선택 운동강도의 stationary cycling MET로 전환한다. 체중/강도 미입력 시 임의로 정확한 개인 칼로리를 표시하지 않는다. 안내 후 입력하도록 하거나 가정을 명시한 참고값으로만 제공한다.
2. 표준 근사식: kcal ≈ MET × 체중(kg) × 활동시간(h). 휴식 대사분을 포함한 총 운동 에너지다. 순수 활동분만 보여줄 경우 (MET−1)×체중×시간으로 별도 정의해 혼용하지 않는다. 본 제안은 총량을 사용한다.
3. paused 시간 제외. running이라도 실제 페달/출력 신호가 없다면 '운동 시간'으로 단정하지 않고 입력 방식과 추정 근거를 표시한다. 수동 가상 주행만으로 kcal를 적립하지 않는 방안을 권한다. 케이던스(RPM)는 부하/저항을 알려주지 않아 강도를 자동 확정할 수 없다.
4. 1차 강도 선택의 예시는 가벼움4·보통6·강함8 MET. 이는 UX용 근사 가정이며 개인 측정이나 입력한 RPM/가상속도의 자동환산이 아니다. Compendium stationary의 실제 사례는 50W=4, 90–100W=6, 126–150W=8 MET. 실제 watts 입력이 없는 현재 앱에서 이 구간을 측정했다고 주장하면 안 된다.
5. 실제 calibrated 파워 입력이 추가되면 시간별 watts를 적분하거나 watts 기반 stationary MET로 개선한다. 심박 추정은 심박센서/개인정보/검증이 준비된 별도 후속이다. 파워·심박이 있다고 무조건 정확하다고 표시하지 않는다.

예: 70kg·실제활동30분·6MET → 약210kcal(총량), 활동분만은175kcal. 가상 주행거리와 무관하게 동일한 운동 조건이면 동일한 값이다. 값은 개인 오차가 있는 추정치로 정수 표시한다.

## 저장·회귀

계산 함수를 한 곳으로 모으고 HUD/종료보고/주행저장/서버누적에 같은 값을 전달한다. 계산 방식 버전, 근거 입력(체중·MET·활동시간·신호 유형)과 gross/net를 스냅샷으로 저장해 이후 설정 변경이 과거 기록을 뒤집지 않게 한다. 기존 거리×30 기록은 legacy로 유지하며 근거 없이 소급 재계산하지 않는다. 체중은 필요 목적·저장 범위를 최소화한다. 이번 요청은 개선안이므로 구현/기존기록 변경은 하지 않는다.

검증 기준: 동일 운동/가상거리 변화→동일kcal, pause추가→불변, 체중/시간/강도비례, 재개offset→이번세션만 계산, 신호미수집과0출력 구분, HUD/기록/집계일치.
