# 이어달리기 조건·개선 방침

문서 유형: execution — Supervisor 조사 보고. 작성: 2026-10-06.

> 아래 조사는 변경 전 기준이다. 이후 Chief 요청에 따라 칼로리와 단일 재개 대상을 구현했다. 현재 동작·검증 범위는 [18 최종 검수](18-review-supervisor.md), 재개 정본은 [설계 §9.5.6](../../reference/architecture/260703-Conquest-정복-레이어-설계.md#956-단일-이어달리기-유지-2026-10-06)을 따른다.

## 변경 전 조건

| 항목 | 현재 코드 기준 |
|---|---|
| 인증 | 인증 완료 사용자만 주행 시작. Guest는 익명 인증 완료이며 로컬 저장 정책을 사용 |
| 경로 | 본인 SavedRoute가 존재하고 로드 가능해야 함. 삭제·깨진 geometry는 재개 불가 |
| 진행 | completed≠1, 0<lastProgressRatio<0.98 |
| 재개 지점 | SavedRoute의 서버 max 진행률을 사용, offset 상한0.97×경로거리 |
| 주행 준비 | idle·routeGeometry·인증/configured·센서 또는 명시 수동입력 준비. Go로 시작 |
| 유효 기록 | 현재 테스트 기준 거리>100m이고 시간>5초. 둘 중 하나라도 이하이면 폐기 |
| 안내 후보 | 최근 유효주행 종료시각 내림차순으로 재개/연장 후보 하나 반환. 최신 다른주행이 옛 재개 안내를 가림 |
| 기록 한도 | 최근 주행 50개. 오래된 A의 기록이 밀려 안내를 잃을 수 있음 |

## 보고된 문제와 차이

다른 경로 B를 달려도 A의 진행률이 즉시 지워지는 것은 아니다. 현재 내경로에서 A를 로드하면 progress 조건에 따라 재개할 배선이 존재한다. 그러나 다음 주행 카드는 B/새경로 후보를 먼저 반환해 A의 재개 안내가 사라진다. 자동후보·최근기록 의존은 장기 경로 UX에 맞지 않는다. 실제 TTL삭제 등은 진행률 자체의 소실이다.

## Chief 정책을 반영한 변경 기준

A의 단일재개슬롯을 별도로 보존한다. 다른경로선택/주행·카드숨김·재시작은A포기가아니다. A유지중B를자동교체하거나동시에이어달리기로제공하지않는다. B는처음부터타는것은가능하다. 모든재개진입(카드·내경로·최근기록·Go)에같은slotguard를적용한다.

명시적인 '이어달리기 종료'는 기회해제이며 경로삭제나진행률리셋이아니다. A의완주/삭제/진짜무효는해제조건이다. '처음부터'는이번회차restart로취급하여A슬롯을유지한다. 활성A를TTL90일만료로잃지않도록단일A만TTL보호하고포기시기존미완주보관정책으로복귀한다. 로딩실패는삭제로간주하지않는다.

등록사용자는기존users문서optional단일slot을사용하고원자적조건부갱신을적용한다. Guest는uid별기존local정책을유지한다. 새Rules권한확대·서버함수·주기적광역읽기·칼로리수식변경은포함하지않는다. 구현·시험최종결과는 [작업입구](README.md)에연결한다.

칼로리의 권장 개선은 [03 제안](03-calorie-proposal.md). 현재체중/출력/심박수집은없고, running시간과cadence>0 pedal초는있다. 체중·실제활동시간·stationaryMET기반으로전환하되 입력없는가상주행에서운동량을측정했다고보이면안된다.
