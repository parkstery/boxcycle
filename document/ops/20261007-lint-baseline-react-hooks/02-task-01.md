## 고치는 방법 (이 코드베이스 관례 — 이 중에서 고른다)

**set-state-in-effect** (effect 본문에서 동기 setState)
1. **입력 키와 함께 저장 → 렌더에서 파생**: 비동기 결과를 `{ key, value }` 로 저장하고, 렌더에서 `resolved.key === 현재key ? value : 기본값`. 입력 없음·로딩 상태 리셋용 동기 setState 를 없앤다. 참고 구현: `src/hooks/useRoutePlanning.ts` 의 `useReverseGeocodedLabel`(커밋 `8cc228f`).
2. **「이전 값 비교」 렌더 중 갱신**: `const [prevX, setPrevX] = useState(x); if (x !== prevX) { setPrevX(x); setY(...) }`. 참고: `useSavedRoutesWorkspace.ts`(검수 `../20261006-lint-baseline-saved-routes/04-review-08.md` — 렌더 중 clear 가 effect cleanup 보다 먼저 일어나 in-flight 결과가 되채우는 창을 막은 방법까지 볼 것).
3. 구독 콜백·비동기 콜백 안의 setState 는 허용된다 — 동기 부분만 옮긴다.

**refs** (렌더 중 `ref.current` 쓰기/읽기)
- 「최신 값 ref」(`fooRef.current = foo` 를 렌더 본문에서) → `useLayoutEffect(() => { fooRef.current = foo; })` 로 옮긴다.
- 렌더 결과가 ref 값에 의존하면 state 로 바꾸거나 렌더에서 쓰지 않게 한다.

**immutability** · **no-explicit-any**: 규칙 메시지에 맞게 개별 수정(any → 실제 타입 또는 `unknown` + 좁히기).
