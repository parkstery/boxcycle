## 구현 범위

1. Guest 로그아웃에서 resetGuestAccount·삭제·reload 분기를 제거하고 정상 signOut. UserInfoSheet 삭제 경고를 실제 동작에 맞춰 Google 연결 전 로그아웃하면 같은 Guest로 복귀 보장 안 됨을 안내. 브라우저 종료시 인증 보존. Guest 체험 정책/30일 미사용 안내와 결정 로그에 새 정책 기록(기존 문장 삭제 금지).
2. Guest 복원 검증: useAppAuth에서 reload/getIdToken(true) 등 서버 확인을 거쳐 유효할 때만 user를 앱에 노출. 확정된 user-not-found/user-disabled/token-invalid 등에서만 signOut·해당 UID 로컬 캐시 제거·자동 익명 생성 차단·시작 화면 만료 안내. 네트워크 오류는 만료로 판정하지 말고 쓰기 차단된 재시도 상태. localStorage/IndexedDB 전체 삭제 금지. Google 기존 계정에도 영향 최소. 중복 복원/로그인 경합 방지.
3. Guest 활동: 서버에서 timestamp를 기록하는 인증 HTTP 엔드포인트(기존 functions HTTP 패턴 사용). 접속 및 visible인 사용 중 5분 정도 간격, 활동은 서버 시간. Auth 실조회로 익명 여부 확인. 갱신과 삭제 예약은 Firestore transaction으로 직렬화. Google 연결 전에도 활동/삭제 상태 확인하고 삭제 예약 중에는 연결 금지. 등록 계정은 만료 대상 제외.
4. Guest lifecycle 서버: 마지막 활동 기준 30일·매일 KST 새벽 실행·작은 배치 cap·실패 재시도·구조화 집계. Auth-only Guest도 감지, activity 없는 기존 계정은 초기 관찰일부터 30일 유예. 보호 UID/admin/registered 제외. 최근 주행/presence 보호. 삭제 예약 → Auth disabled → 최신 provider 재확인(등록이면 취소·안전 복구) → 데이터 삭제 → Auth 삭제. 삭제중 marker와 Rules로 만료 전 ID 토큰의 Firestore/RTDB 재쓰기 차단. Firestore isSignedIn뿐 아니라 직접 request.auth 경로도 검토. RTDB marker는 서버만 쓰고 auth 사용자 본인 쓰기 차단. 일반 사용자 권한 확대 금지. 실패 후 재시도 가능한 상태·이미 Auth 없는 경우 재실행 처리. 기존 deleteAccountData 재사용하고 공용 자산 삭제 금지.
5. Auth와 Firestore/RTDB가 단일 원자 transaction이 아니므로 재검사만으로 race-free라고 주장하지 마라. Google 연결·활동·삭제 예약 사이 실제 직렬화/lease와 비활성화 검증을 구현·시험하고 남는 한계 명시. 삭제 예약 뒤 기존 탭 쓰기 차단과 중간 실패 복구를 시험하라.
