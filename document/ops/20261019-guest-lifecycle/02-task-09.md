# Task09 — GLM Admin 재생성 방지와 후보 누락 마감

수행자 OpenCode GLM-5.3. Supervisor Codex. Cursor는 web만 작업중이므로 충돌하지 않는다. 기존 변경을 되돌리지 않는다. 운영 Firebase·인증정보·UID·원본데이터·`.out/private-guest-lifecycle`·evidence 접근 금지. 코드/지시/익명화 fixture만 허용. 배포/커밋/푸시/에뮬레이터 기동 금지.

Task07 결과를 보존하고 다음 필수 결함을 수정한다. 소유권은 functions/src/guestLifecycle*, index.ts, routeTokenEnsureOnboarding.ts, tierQuotaHttp.ts, userTierCore.ts, routeTokenCore.ts, mileageOnRideCreated.ts, conquestOnRideCreated.ts, routeTokenOnRideCreated.ts와 필요한 공용 guest 쓰기 guard 신규파일/관련 시험이다. scripts Supervisor 시험은 수정 금지.

1. 07-supervisor-integration-findings.md의 Admin SDK 우회 해결. 삭제 예약/진행/실패/deleted marker는 Admin 개인자료 writer에서도 차단. users/conquest/routeTokenLedger 등 사용자 자료를 쓰는 트랜잭션에서 guestLifecycle/{uid}를 **쓰기 전에 같은 transaction으로 읽어** marker 경합을 직렬화한다. 단순 함수입구 확인만으로 race 해결 주장 금지. mergeUserAuthMeta 같은 비transaction set도 재생성을 막도록 변환. Guest marker 없는 정상 Google/Guest의 기존 동작은 보존.
2. index.ts 관련 HTTP2종, routeTokenEnsureOnboarding.ts, tierQuotaHttp.ts의 verifyIdToken(token,true) 적용. 삭제/차단 시 개인자료 생성 없이 종료. 기존 오류삼킴 때문에 onboarding이 계속되지 않게 한다. 새 guard 오류와 일시장애를 무조건 정상/401로 삼키지 않는다. 지연된 mileage/conquest/routeToken trigger도 tombstone 뒤 재생성 금지. 필요한 한정된 관련파일은 근거와 함께 결과에 명시.
3. guestLifecycleAdmin.listProfileUids는 conquest 부모가 없고 traces/chunks만 남아도 uid 발견, routeTokenLedger-only와 기존 개인귀속 정책의 nickname.ownerUid / publicRouteRequests.applicantUid 등도 발견하도록 accountDeletionCore 정책과 대조한다. Firestore listDocuments의 missing parent 포함 가능 또는 경로 검증된 group 스캔 사용. 공용 Trail hostUid만으로 후보 삼지 않는 원칙 유지. Supervisor emulator에 traces-only, ledger-only fixture가 이미 있다.
4. 단위시험: 정상 Google 영향없음, blocking 5상태 차단, 예약 transaction race, 지연 trigger, 후보 누락. build/lint/npm test 및 root guest-lifecycle-supervisor7 실행. 실제 emulator는 Supervisor가 수행하므로 준비하고 결과에 미실행 명시.
5. 결과03-result-09.md에 수행자/모델/실제 명령/exit/남은한계 기록. Task07 완료 주장은 그 당시 범위이며 새 발견은 새로 수정한다. 질문 없이 승인 범위 구현검증 완료.
