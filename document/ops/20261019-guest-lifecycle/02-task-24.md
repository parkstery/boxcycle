# Task24 — 종료 없는 브라우저 재시작·주소 분리 검증

Chief: 종료 없이 브라우저를 닫았다 열 때 새 Guest가 만들어지는 상황 해결. 스크린샷은 localhost5004와127.0.0.1:5004의 서로 다른 닉네임이며, 이는 서로 다른 origin이다. 같은 origin 브라우저 재시작 문제가 있는지는 별도 실제검증한다.

Supervisor Codex 소유: demo 실행기·Vite의 opt-in loopback 정규화·실제 persistent profile 브라우저 종료/재실행 spec·ops 기록. 인증/서버계정 생성 의미·운영Rules·계정삭제·임의 세션이식 금지. 기존 dirty 보존·커밋/푸시/배포 금지.

완료조건: 종료 클릭 없이 persistent profile로 Chromium 프로세스를 닫고 다시 띄워 같은UID·개인localfixture·Auth계정증가0을 반복확인. 종료 경로도 같은UID 유지. demo --serve에서 localhost5004를 정식주소로 삼아127.0.0.1 HTML navigation은 앱 로딩전 localhost로 redirect하여 별도Guest생성 방지. 일반 dev/전체e2e/LAN/운영은 opt-in없으면 동작보존. URL query/path 보존·JSON/module 요청비변경. 기존 두 origin 계정은 삭제·병합·token 복사하지 않음. 공식Firebase문서 근거로 web/향후Android 차이와 저장데이터삭제·서버초기화 한계를 구분.
