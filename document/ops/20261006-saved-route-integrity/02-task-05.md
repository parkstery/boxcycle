# 지시 05 — 고른 미완주 경로로 이어달리기 대상 교체 (지시 04 B 재작업)

- 담당: Developer(Cursor CLI) · 보고: `03-result-05.md` · 커밋·푸시 **금지**
- 전제: 지시 03·04 의 미커밋 변경 위에서 작업. 되돌리기·stash 금지. `functions/` 수정 금지.

## 배경
- [검수 04](04-review-04.md): 재개 offset 은 **단일 이어달리기 슬롯의 활성 경로**일 때만 적용(`App.tsx` `resumeRatio`). 슬롯이 아닌 미완주에 「이어 달리기」를 띄우면 실제로는 처음부터 → 라벨이 거짓.
- **Chief 결정(2026-10-06)**: 「고른 경로로 대상 교체」 — 어떤 미완주 경로든 「이어 달리기」를 누르면 그 경로가 새 이어달리기 대상이 되고 마지막 지점부터 이어 달린다. 대상은 여전히 **1개**. 이전 대상은 진행률을 그대로 가진다.

## 요구
1. **교체**: 내 경로에서 미완주 경로(`completed!==1 && 0<lastProgressRatio<0.98`)를 「이어 달리기」로 불러오면,
   - 슬롯 활성 경로가 없으면 → 그 경로로 확보(`ensureAcquired`).
   - 다른 경로가 활성이면 → 기존 대상 해제 후 새 경로 확보. 해제는 기존 「이어달리기 종료」(`abandon`/`abandonRideResumeSlot`)와 **같은 의미**(이전 대상 진행률 유지, TTL 90일 복원 — 설계 §9.5.6)를 따른다. 해제·확보는 순서 보장(해제 성공 후 확보), 실패 시 `routeSummary` 로 알리고 처음부터로 조용히 떨어지지 않게 한다.
   - 이미 활성이면 → 아무것도 하지 않음.
   - 결과: 로드 후 RouteDock 의 기존 「N%부터 이어달리기 / 처음부터」 선택이 나타나야 한다(`resumeRatio != null`).
   - 교체 성공 시 안내 한 줄(예: 「이어달리기 대상을 이 경로로 바꿨어요 — 42%부터」).
2. **결과 화면 저장도 대상 확보**: 지시 04 A 의 ad-hoc 미완주 저장이 성공하면, 슬롯이 **비어 있을 때만** 그 경로로 확보한다(§9.5.6 「빈 대상은 실제 주행의 진도 저장 성공 이벤트로 확보」와 동일). 비어 있지 않으면 교체하지 않는다(교체는 사용자가 고를 때만).
3. **라벨**: 미완주 경로 선택 시 툴바 「이어 달리기」 유지(이제 참). 대기(0%)·완주는 「열기」.
4. **현재 대상 표시**: 슬롯 활성 경로 카드에 작은 배지 「이어달리기 중」(기존 `saved-routes__badge` 계열, 진행률 줄 오른쪽). 다른 미완주는 진행률만.
5. 다른 경로를 「열기」(대기·완주)로 불러오는 것은 대상을 바꾸지 않는다(§9.5.6 유지).

## 구현 지침
- 슬롯 API 는 `hooks/useRideResumeSlot.ts`(App 의 `rideResumeSlot`). 교체 함수가 필요하면 이 훅에 `switchTo(routeId)` 같은 **하나의** 함수로 추가하고, 순수 판정(none/acquire/switch)은 `lib/ride/rideResumeSlotPolicy.ts` 쪽에 테스트 가능한 함수로 둔다.
- 게스트(로컬 슬롯) 경로도 같은 의미로 동작해야 한다(`abandonLocalRideResumeSlot` 대응 확인).
- 「이어 달리기」 의도는 `SavedRoutesPanel` → `SavedRoutesModal` → `RideRoutePanel` → App 의 기존 `onLoadRoute` 경로로 전달하되, 새 콜백을 추가하는 편이 단순하면 `onResumeRoute` 를 추가해도 된다(결과에 선택 이유 기재).
