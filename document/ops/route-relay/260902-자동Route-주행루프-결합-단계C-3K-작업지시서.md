## 2. [게이트] baseline — **확보 완료**, 그러나 §2.3 이 남았다

최초 진단 시 `test:route-token` 과 `test:e2e:ride` 가 통과하지 못했다. **둘은 서로 다른 문제가 아니라 같은 원인**이다.

```text
PID 58396  127.0.0.1:5001, 4400   ← Functions Emulator (수동 기동)
PID 50448  127.0.0.1:8080         ← Firestore Emulator (수동 기동)
PID 59020  0.0.0.0:5002           ← Vite dev:emulator
```

두 시험은 `emulators:exec` 로 **자기 에뮬레이터를 직접 띄운다.** 포트가 이미 잡혀 있어 기동에 실패했고, `test:e2e:ride` 의 ride-entry 1건은 그 결과 앱이 프로덕션 URL 로 폴백해 `ensureRouteTokenOnboardingHttp` 401 을 받은 것이다.

**이 401 은 3I §2 의 구멍이 아니다.** 정적 게이트가 있고 raw URL 은 helper 안에만 있다. 에뮬레이터가 없으니 helper 가 프로덕션 fallback 을 반환한 것이며, 그건 설계대로다.

### 2.1 baseline 을 먼저 확보해야 했던 이유

하필 이 두 시험이 **단계 C 가 깨뜨릴 가능성이 가장 큰 영역**을 지킨다.

- `test:route-token` — 구간당 Token 정확히 1개 차감. 단계 C 는 이어 달리기마다 자동 Route 를 새로 생성하므로 차감 계약을 직접 건드린다.
- `test:e2e:ride` — 주행 진입 시퀀스. 단계 C 는 종료→재진입 흐름 위에 자동 Route 진입을 얹는다.

green baseline 없이 시작하면, 나중에 이 시험이 실패했을 때 **단계 C 탓인지 원래 그랬는지 구분할 수 없다.** 그 구분을 잃는 대가가 baseline 확보 비용보다 훨씬 크다.

### 2.3 [신규 결함] 401 은 환경 문제가 아니었다 — 에뮬레이터 토큰이 프로덕션으로 나간다

green 이 됐지만 로그에 그대로 남아 있다.

```text
[ride-entry] 환경성 리소스 실패(회귀 아님):
401 https://asia-northeast3-boxcycle-dc2df.cloudfunctions.net/ensureRouteTokenOnboardingHttp
```

에뮬레이터가 정상 기동한 실행에서도 **프로덕션 URL** 을 호출했다. 원인 사슬을 확인했다.

1. `test:e2e:ride` 는 `emulators:exec --only auth,firestore,database` 다 — **Functions 에뮬레이터를 띄우지 않는다.**
2. `playwright.config.ts` 는 `FIRESTORE_EMULATOR_HOST` 를 감지해 vite 에 `VITE_USE_EMULATOR: '1'` 을 넘긴다.
3. 그러면 `firebase.ts` 가 `connectAuthEmulator()` 를 호출한다 → **ID token 이 에뮬레이터 발급**이 된다.
4. 그런데 그 env 에 `VITE_FUNCTIONS_EMULATOR_HOST` 가 없다. `resolveFunctionsHttpUrl()` 은 host 가 없으면 `null` 을 반환하고, `functionsHttpUrl()` 은 **프로덕션으로 폴백**한다.
5. 프로덕션 `verifyIdToken()` 이 에뮬레이터 토큰을 거부 → 401.

**3I §2 와 같은 결함 계열이며, 3I 가 다루지 않은 조합(`VITE_USE_EMULATOR=1` + Functions 에뮬레이터 없음)에서 남아 있다.** 프로덕션 사용자에게는 영향이 없다(운영에서는 Auth·Functions 가 모두 프로덕션이라 일관된다). 그러나 **에뮬레이터 e2e 에서 Route Token 온보딩이 조용히 실패**하므로, 그 경로의 Token 회귀를 잡지 못한다.

단계 C 의 3회 루프 e2e 는 **구간당 Token 1개 차감을 e2e 에서 관측**해야 하므로 이 구멍을 먼저 막아야 한다. 범위 확대가 아니라 단계 C 가 딛고 설 바닥이다.

#### 2.3.1 수정

1. **helper 를 엄격하게** — `VITE_USE_EMULATOR === "1"` 인데 `VITE_FUNCTIONS_EMULATOR_HOST` 가 없으면 프로덕션으로 폴백하지 말고 **명확히 실패**시킨다(throw). Auth 가 에뮬레이터인데 Functions 가 프로덕션인 조합은 성공할 수 없으므로 조용히 넘어가면 안 된다. `resolveFunctionsHttpOrigin()` 의 같은 폴백도 함께 막는다.
2. **e2e 배선** — `test:e2e:ride` 의 `emulators:exec --only` 에 `functions` 를 추가하고, `playwright.config.ts` 의 `underEmulator` env 블록에 `VITE_FUNCTIONS_EMULATOR_HOST` 를 넣는다. `test:route-token` harness 가 이미 쓰는 값을 재사용한다.
3. **허용 문구 축소** — ride-entry spec 의 「환경성 리소스 실패(회귀 아님)」 허용이 이 결함을 덮었다. **에뮬레이터 모드에서 `cloudfunctions.net` 으로 나간 요청은 허용 목록에서 제외**해 실패로 만든다.
4. 1·2 적용 후 `test:e2e:ride` 를 다시 돌려 **401 로그 자체가 사라지는지** 확인한다. 6 passed 만으로는 부족하다 — 로그에서 사라져야 한다.

## 3. 단계 C — 자동 Route 결합

계약은 [R1 §4](../ride-relay/260902-다음-주행-이어달리기-자동Route-결합-R1-작업지시서.md#4-단계-c--자동-route-결합-이-r1-의-신규-조항) 가 SoT 다. 여기서는 통합 후 확정된 사실만 덧붙인다.

### 3.1 진입점

`NextRideCard` 의 「지금 새 경로 연결」(phase-a report 의 `summaryActions` 에서 확인됨)과 260829 §3.3 「이 지점에서 새 경로」가 진입점이다. 이 동작이 끝난 상태 — Start 가 직전 종료점으로 고정되고 지도가 idle 인 상태 — 에서 **거리·방향 자동 Route 팝업을 1급 진입으로 붙인다.**

R1 §4.1 이 260829 §3.3-3 항을 대체했음을 잊지 않는다. 사용자는 도착점을 직접 찍는 것과 자동 Route 로 만드는 것 중 **어느 쪽이든** 고를 수 있어야 한다.

### 3.2 확정 계약 (R1 §4.2 재확인)

1. **Start 고정** — 직전 Ride 의 `sessionEndLngLat`. 사용자가 Start 를 옮기면 고정이 풀리고 일반 자동 Route 로 전환한다.
2. **직전 값 승계** — 목표 거리·이동수단은 직전 주행 값을 기본으로 채운다. 매번 다시 고르게 하지 않는다.
3. **Token 불변** — 구간당 1개. 이어 달리기라고 면제하지 않는다. 3F-C-R1 의 「거리 조정 재탐색 1회 무료」는 그대로.
4. **`offered`·`shortfall` 동작 불변** — 이 진입에서도 고지·고스트 마커·거리 조정 원클릭이 똑같이 동작한다.
5. **연속 누적** — 구간마다 별개 Ride 로 기록되고 앞 구간을 덮어쓰지 않는다.
6. `Journey` 용어·상위 데이터 모델은 이번에도 만들지 않는다.

### 3.3 시험

**3회 연속 루프 e2e** 를 `apps/web/scripts/ride-continue/` 에 추가한다. 자동 Route 생성 → 주행 → 종료 → 시트 닫기 → 「지금 새 경로 연결」 → 자동 Route 재생성을 3회 반복하며 회차마다 assert 한다.

- 새 Start == 직전 Ride 의 `sessionEndLngLat`
- 목표 거리·이동수단이 직전 값으로 채워져 있음
- Token 이 회차당 정확히 1개 차감 (3회에 3개)
- 이전 구간의 Ride·SavedRoute 가 변경되지 않음
- 각 구간 `distance` 가 목표 ±5m 이거나 `outcome` 이 `offered`/`shortfall` 로 정직하게 표기됨

Start 를 사용자가 옮기면 고정이 풀리는 분기도 시험한다.

기존 전량 회귀 유지: `test:next-ride`(40) · `test:distance-auto-route`(97) · `test:distance-auto-route-replay` · `test:route-token` · `test:e2e:ride` · `ride-continuation`(5) · functions/web build · `git diff --check`.
