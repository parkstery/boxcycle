## 3. 제거할 불필요한 단계

### 3.1 `목표 거리로 End 자동 찾기`

현재 이 버튼의 실제 기능은 숨겨진 `autoRouteForm`을 펼치고 기본 10km 원을 표시하는 것뿐이다. Route 탐색을 실행하지 않는다.

- 버튼과 이를 위한 접기·펼치기 상태를 제거한다.
- Start가 존재하고 End가 없으면 자동 Route 거리 컨트롤을 같은 설정창에 바로 표시한다.
- 별도의 자동 Route 창이 열린다는 인상을 없앤다.

### 3.2 `지도에서 방향 선택`

- 전체 폭 버튼을 제거한다.
- 목표 거리 slider 또는 숫자 입력을 사용한 시점에 자동으로 `pick_direction` 상태로 전환한다.
- 그 다음 지도 클릭이 즉시 기존 `handleMapPick`을 거쳐 Route 탐색을 시작하게 한다.
- 방향 선택을 위한 별도 확인 클릭을 요구하지 않는다.
- 선택 모드에서는 버튼 대신 작은 상태 문구 `지도에서 원하는 방향을 클릭하세요`만 표시한다.

## 4. 기본 Route와 자동 Route의 단일 인터페이스

하나의 Mapbox popup과 하나의 내부 상태 모델을 사용한다.

- Start·WP1·WP2·WP3·End 선택 행
- Route Token 한 줄
- 자동차·자전거·도보 아이콘 행
- 목표 거리 입력 행
- 짧은 상태·오류 행

자동 Route 진입·방향 선택·탐색 중·성공·실패 때 popup을 제거하고 다른 위치에 새 popup을 만들지 않는다. 같은 popup 내부의 상태 행만 갱신한다.

자동 Route 방향을 클릭해도 popup anchor가 방향 클릭 지점으로 이동하면 안 된다. Start를 선택했던 설정창이 유지되거나, 최소한 동일한 panel identity와 위치가 유지되어야 한다.

기존 수동 Route 흐름은 보존한다.

- 목표 거리 컨트롤을 사용하지 않은 상태: 기존 Start·WP·End 직접 지정
- 목표 거리 컨트롤을 사용한 상태: 다음 지도 클릭을 End 좌표가 아니라 방향으로 해석
- 자동 모드를 취소하거나 경로를 삭제하면 다음 지도 클릭을 다시 기본 지점 선택으로 복구

## 5. 목표 거리 컨트롤

3/5/10/15/20/30km 원형 버튼 행을 다음 한 행으로 교체한다.

```text
목표거리(km)   [──────── slider ────────] [ 10.0 ]
```

요구사항:

- slider와 숫자 입력은 하나의 `targetKm` 값을 공유한다.
- 허용 범위: 0.5~120km
- 기본 표시값: 10km
- step: 0.5km
- 50·55·60km 등 preset에 없던 값을 직접 입력할 수 있어야 한다.
- 숫자 입력과 slider 변경은 서로 즉시 동기화한다.
- 유효한 값으로 변경하면 원을 즉시 다시 그리고 화면 맞춤을 갱신한다.
- 유효한 거리 컨트롤 상호작용이 자동 Route 방향 선택 모드 진입 신호다.
- 입력 중 빈 값·NaN·범위 밖 값은 Route 요청을 보내지 않고 한 줄 오류로 표시한다.
- slider·숫자 입력만으로 Token을 차감하지 않는다. 실제 방향 지도 클릭으로 요청을 시작할 때만 Token 1개를 차감한다.

기본값 10km를 그대로 사용하려는 사용자가 별도 모드 버튼을 누르지 않도록, slider/숫자 입력을 클릭·포커스하거나 조작하면 현재 10km 값으로도 방향 선택 모드에 들어가야 한다.

## 6. 문구·밀도 1차 정리

- Token 영역은 `경로 생성 잔여 토큰 N개` 한 줄만 표시한다.
- `경로 생성 시 1개 사용` 문구를 제거한다.
- 시각적 `이동수단` 제목을 제거한다.
- 자동차·자전거·도보 아이콘은 유지한다.
- 아이콘에는 화면에 보이지 않는 접근성 이름과 tooltip을 유지한다.
- 거리 컨트롤을 한 행에 배치하고 불필요한 세로 여백을 줄인다.
- popup 폭은 300px 안팎을 우선하며 914×412 모바일 가로 화면에서 지도 대부분을 가리지 않게 한다.

결과 성공 popup의 `확인` 버튼 제거·결과 표시 방식의 최종 다듬기는 3D-2 후보로 남길 수 있다. 다만 이번 단계에서도 별도의 두 번째 popup을 새로 만들지는 않는다.

## 7. 상태·동시성 계약

1. 방향 지도 클릭 1회당 `getDistanceAutoRoute` 요청 1회
2. 탐색 중 추가 지도 클릭 무시
3. 성공 시 Token 정확히 1개 차감
4. 실패 시 Token 환불·잔액 유지
5. 잔액 0이면 방향 선택 진입 또는 요청 전에 명확히 차단
6. 이동수단 변경은 수동·자동 Route가 같은 `routeProfile`을 공유
7. custom 55km가 서버 요청의 `targetDistanceMeters=55000`으로 전달
8. 방향 클릭 좌표까지의 직선거리는 목표 거리를 덮어쓰지 않음
9. Route 생성 성공 시 목표 거리 원은 제거하거나 Route와 충돌하지 않는 기존 계약 유지

Functions·Token transaction·후보 알고리즘·거리 오차 20% 규칙은 이번 단계에서 수정하지 않는다. 추가 Firebase 배포도 하지 않는다.
