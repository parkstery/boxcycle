## 1. 목적

사용자 확인에서 두 가지 보완이 확정됐다.

1. 현재 `−`/`+` 40px 버튼은 거리 숫자 입력보다 상대적으로 커 popup의 균형과 slider 길이를 해친다.
2. 수동 End 지정과 거리·방향 자동 Route가 명시적 모드 없이 거리 컨트롤 focus/input으로 전환되어 사용자가 현재 지도 클릭의 의미를 알기 어렵다.

이번 작업은 거리 조작 버튼의 **시각 크기**를 숫자 입력 높이와 맞추고, slider 왼쪽에 checkbox를 추가해 지도 클릭 의미를 사용자가 직접 선택하도록 한다.

## 2. 거리 `−`/`+` 시각 크기

- `−`/`+` 버튼의 보이는 사각형은 거리 숫자 입력의 실제 높이와 동일한 한 변을 가진 정사각형으로 만든다.
- 세 요소가 같은 행에서 위·아래 중심선과 외곽 높이가 일치해야 한다.
- 숫자 입력과 버튼은 공통 CSS 높이 변수 또는 동등한 단일 기준을 사용해 다시 어긋나지 않게 한다.
- 현재 40×40px의 큰 시각 박스는 유지하지 않는다.
- 이전 사용자 요구였던 스마트폰 조작성을 버리지 않는다. 보이는 사각형은 작게 하되, 인접 컨트롤과 겹치지 않는 범위에서 투명 hit area 또는 충분한 gap으로 유효 터치 영역을 최대한 확보한다.
- hit area가 slider·checkbox·숫자 입력과 겹쳐 오조작을 만들면 안 된다.
- `−`/`+`의 0.5km 증감, min/max clamp·disable, 목표 거리 원 동기화는 유지한다.

## 3. 목표 선택 방식 checkbox

### 3.1 배치·표현

- 거리 행에서 `−` 버튼의 바로 왼쪽에 실제 checkbox를 둔다.
- checkbox의 접근 가능한 이름은 `거리와 방향으로 Route 찾기`로 한다.
- 시각적으로 의미가 불분명한 무라벨 checkbox만 두지 않는다. 한 줄을 유지할 수 있는 짧은 label(권장 `거리`) 또는 동등하게 즉시 이해 가능한 표시를 같은 행에 둔다.
- 별도 설명 행·새 카드·새 popup을 추가하지 않는다.

권장 구조:

```text
[✓ 거리] [−] [──── slider ────] [+] [3.0]
```

### 3.2 지도 클릭 의미

- **unchecked**: 현행 수동 Route 흐름. 지도 지점을 열어 `End`로 직접 지정할 수 있다.
- **checked**: 거리·방향 자동 Route 흐름. 다음 유효 지도 클릭을 Start 기준 방향 의도로 해석한다.
- checkbox 상태만 두 모드의 단일 진실이어야 한다. slider focus·숫자 입력 focus만으로 unchecked 상태를 자동 모드로 바꾸지 않는다.
- checkbox를 check하는 행동 자체는 provider 호출·Token 차감을 일으키지 않는다.
- checked 상태에서 지도 방향 클릭 1회가 자동 Route 요청 1회가 되는 기존 계약을 유지한다.
- unchecked 상태의 지도 클릭은 자동 Route 요청과 Token 차감을 절대로 일으키지 않는다.

### 3.3 선택 상태와 자동 요청 armed 상태를 분리

checkbox 선택 상태는 사용자가 직접 해제할 때까지 같은 페이지의 Route 편집 세션에서 유지한다.

- popup 닫기·재개방
- Route A 성공·Route B 재탐색
- 탐색 실패·network error·Token 0
- profile 변경

위 사건으로 checkbox를 자동 uncheck하지 않는다. 브라우저 reload 이후 영구 저장(`localStorage`)은 이번 범위가 아니다.

단, checkbox가 checked여도 popup을 닫으면 지도 클릭 가로채기(armed)는 즉시 해제한다. 이는 기존 Token 안전 규칙이다.

```text
checkbox checked = 사용자의 모드 선호 유지
popup pick armed = 현재 열린 popup에서 다음 지도 클릭을 자동 요청으로 받을지
```

- popup을 닫은 뒤 첫 일반 지도 클릭은 Token을 소비하지 않고 설정 popup을 연다.
- 다시 열린 popup은 checkbox checked 상태를 복원한다.
- popup이 열린 뒤의 다음 지도 클릭부터 거리·방향 입력으로 처리한다.
- checkbox를 uncheck하면 즉시 armed를 해제하고 목표 거리 원을 숨긴다. 기존 Route geometry·End·Token 잔액은 유지한다.
- Start가 없으면 checked 상태를 보존할 수는 있지만 자동 요청을 arm하지 않는다.
- `경로 삭제`와 주행 시작은 자동 요청 armed를 해제한다. checkbox 표시 선호를 임의로 바꾸지 않는다.

### 3.4 연관 컨트롤 상태

- unchecked에서는 slider·`−`·`+`·숫자 입력이 자동 Route를 arm하지 않도록 한다.
- 혼동 방지를 위해 unchecked 상태에서는 거리 조작 컨트롤을 disabled 또는 명확한 비활성 시각 상태로 둔다.
- checked로 바꾸면 마지막 유효 목표 거리를 복원하고 거리 조작을 활성화하며 목표 거리 원을 표시한다.
- Token 0이어도 checkbox 선택 상태는 유지하되 provider 호출 전에 차단하고 현행 부족 문구를 같은 popup에 표시한다.

## 4. 회귀 금지

1. Route A 성공 후 checked 상태로 Route B 재탐색
2. B 탐색 중 A 유지, 성공 후에만 교체
3. 매 요청 새 requestId와 성공당 Token 1개 차감
4. 실패 시 A·Token 유지
5. popup 재개방 후 목표 거리·profile·checkbox 복원
6. 자동 모드 profile 변경 시 기존 End 수동 재계산 금지
7. 수동 End·WP 지정 흐름 유지
8. Token 단일 행, 이동수단/`경로 삭제` 단일 행 유지
9. checkbox·거리 컨트롤 때문에 popup 폭·높이를 다시 키우지 않음

### 4.1 하단 상태 메시지 행 높이 고정

- popup 하단에는 상태 메시지 한 줄의 공간을 항상 예약한다.
- 메시지가 없는 idle 상태와 `경로 토큰 부족`·`탐색 중`·`경로 생성 완료 · …`·실패 메시지가 표시되는 상태의 popup 전체 높이가 같아야 한다.
- idle일 때 상태 요소를 `display: none` 또는 `hidden`으로 제거해 높이를 줄이지 않는다. 빈 상태는 `visibility: hidden`, 빈 placeholder 또는 동등한 방식으로 한 줄 높이를 유지한다.
- `autoRouteError`와 `inlineStatus`가 각각 별도 행을 차지해 두 줄 높이가 생기지 않게 하나의 status slot에서 우선순위에 따라 한 메시지만 표시한다.
- 지원 popup 폭에서는 상태 카피를 한 줄로 유지한다. 임의 잘림으로 의미를 잃지 않도록 필요하면 카피를 짧게 조정한다.
- checkbox on/off, Token 유무, 성공·실패 전환 중 popup 위치가 메시지 행 높이 변화 때문에 위아래로 점프하지 않아야 한다.

### 4.2 축소 버튼 hit area 겹침 금지

- 축소된 `−`/`+` 버튼의 투명 hit area가 checkbox·slider·숫자 입력 영역을 덮지 않아야 한다.
- pseudo-element를 시각 박스 밖으로 확장한다면 실제 grid gap보다 크게 확장하지 않는다.
- slider 양 끝 근처를 조작했을 때 `−`/`+` click으로 오인되지 않는지 최소 DOM/pointer 검증을 추가한다.

### 4.3 오른쪽 빈 컬럼 회수·slider 최대화

현재 popup 전체 `.map-view__pick`에 적용된 큰 `padding-right`가 닫기 버튼 아래까지 세로 빈 컬럼을 만들고 있다. 닫기 버튼 충돌 방지는 상단 주소·meta 영역에만 적용하고, 그 아래 pin·Token·profile·거리·상태 행은 popup의 사용 가능한 오른쪽 끝까지 사용한다.

- popup 전체에 닫기 버튼 폭의 오른쪽 padding을 적용하지 않는다.
- 주소·meta가 닫기 버튼 아래로 들어가지 않도록 상단 텍스트 영역에만 필요한 여백을 둔다.
- Start/WP/End, Token, 이동수단/`경로 삭제`, 거리 조작, 상태 행은 회수한 오른쪽 폭을 모두 사용한다.
- popup 외곽 폭을 키우는 방식으로 해결하지 않는다.
- 거리 행의 grid gap은 컨트롤 경계를 구분할 수 있는 최소치로 줄인다.
- 보이는 버튼은 숫자 입력 높이의 정사각형을 유지하되, 현재처럼 step hit wrapper가 각각 `2.75rem`을 고정 점유해 slider를 줄이지 않게 한다.
- hit wrapper의 layout 폭은 시각 버튼 크기에 가깝게 줄이고, 클릭 가능 영역을 확장하더라도 인접 컨트롤을 덮거나 slider 길이를 희생하지 않는다.
- checkbox label·`−`·`+`·숫자 입력의 고정 폭을 제외한 남은 폭은 전부 slider 열(`1fr`)에 배정한다.
- `0.5–120.0` 범위에서 slider의 작은 이동이 과도한 값 점프가 되지 않도록, 같은 popup 폭에서 변경 전보다 실제 track 길이가 명확히 길어져야 한다.

### 4.4 `−`/`+` 글리프 광학 중앙 정렬

- 버튼 외곽 사각형뿐 아니라 내부 `−`/`+` 글리프가 가로·세로 중앙에 보여야 한다.
- 단순 `align-items: center` 결과가 폰트 metric 때문에 위로 치우치면 글리프 전용 span과 1px 안팎의 optical offset을 사용한다.
- `−`와 `+`가 서로 다른 세로 위치에 보이지 않게 같은 기준을 사용한다.
- desktop과 가로형 스마트폰 viewport에서 실제 렌더 기준으로 확인한다.

## 5. 이번 범위에서 구현하지 않는 것

- popup drag·floating·edge docking·자동 위치 이동
- 사용자가 클릭한 도로와 최종 End 정렬 알고리즘 변경
- 후보 생성 계수·방향 허용각·점수식 변경
- Functions·provider·Token 정책 변경

위 항목은 사용자와 설계 방향을 결정한 뒤 별도 작업으로 진행한다.

## 6. 시험

최소 계약:

1. `−`/`+` 보이는 정사각형 한 변 = 숫자 입력 높이
2. checkbox가 `−` 왼쪽 같은 행에 존재하고 접근 가능한 이름 보유
3. unchecked 지도 클릭은 자동 POST 0회
4. slider/숫자 focus가 checkbox를 자동 check하지 않음
5. checked 지도 클릭은 자동 POST 1회
6. popup close 후 checked 값 유지·armed false
7. popup 재개방 후 checked 복원, 그 다음 지도 클릭에서 자동 POST
8. user uncheck 시 armed false·원 제거·기존 Route 유지
9. Route A→B·requestId·Token·geometry 회귀
10. Token 0에서 checked 유지·provider 전 차단
11. 상태 메시지 없음/부족/탐색/성공/실패에서 popup 높이 동일
12. `−`/`+` 확장 hit area가 checkbox·slider·숫자 입력과 겹치지 않음
13. 닫기 버튼용 오른쪽 여백은 상단에만 존재하고 하단 행은 전체 content 폭 사용
14. 거리 행의 남는 폭이 slider에 배정되고 현행 `2.75rem` step wrapper 고정 폭 제거
15. `−`/`+` 글리프의 렌더된 중심이 버튼 중심과 일치
