## 1. 우선순위

3B-R2의 UI·screenshot·commit 정리를 즉시 멈춘다. 이번 단계에서는 다음 사용자 수직 흐름이 실제 브라우저에서 성공하는 것만 최우선으로 처리한다.

```text
Start 선택 → 이동수단 선택 → 목표 거리 선택 → 지도에서 방향 클릭
→ 실제 Route 생성·지도 표시 → Route Token 정확히 1개 차감
```

popup 크기·여백·색상 등 UI 품질 개선은 이 흐름이 통과한 다음 단계로 미룬다.

## 2. 이미 확정된 원인

일반 개발환경의 `apps/web/.env`에는 다음만 설정되어 있다.

```text
VITE_FIREBASE_PROJECT_ID=boxcycle-dc2df
```

`VITE_USE_EMULATOR=1`과 `VITE_FUNCTIONS_EMULATOR_HOST`가 없으므로 현재 웹은 다음 운영 함수를 호출한다.

```text
https://asia-northeast3-boxcycle-dc2df.cloudfunctions.net/getDistanceAutoRoute
```

2026-08-31 독립 확인:

- `getDistanceAutoRoute` OPTIONS: **HTTP 404**
- Firebase 운영 함수 목록: **`getDistanceAutoRoute` 없음**
- `getMapboxDirections` OPTIONS: **HTTP 204**
- 포트 5000: 루트 worktree Vite
- 포트 5001: UI-circle worktree Vite
- 포트 5001에서 Functions Emulator가 실행 중인 것이 아님

따라서 현재 오류는 거리·방향 후보 계산이나 원 표시 문제가 아니라, 브라우저가 호출하는 새 서버 함수가 존재하지 않기 때문에 발생한다.

## 3. 이전에는 왜 작동했는가

정상 동작 참고 commit `2693f65`는 브라우저가 최대 35개 후보를 만들고, 이미 운영에 배포된 `getMapboxDirections`를 후보별로 호출했다.

Token 통합 이후에는 사용자 행동 한 번에 Token 하나만 차감하도록 후보 탐색 전체를 새 서버 함수 `getDistanceAutoRoute` 안으로 옮겼다. 이 설계 변경 자체는 맞지만 새 함수가 운영에 배포되지 않았다. Harness는 Emulator와 fake provider에서 통과했기 때문에 실제 일반 개발환경의 404를 잡지 못했다.

금지:

- `2693f65`의 브라우저 35회 후보 호출을 그대로 복원하지 않는다.
- 브라우저 direct Mapbox 우회를 추가하지 않는다.
- 후보별로 Route Token이 차감되는 구조로 되돌리지 않는다.
- UI 수정으로 서버 404를 가리지 않는다.

## 5. 운영 함수 단독 배포 승인 게이트

일반 `npm run dev`에서 현행 구조를 실제로 작동시키려면 다음 함수의 운영 단독 배포가 필요하다.

```powershell
npx firebase-tools deploy --only functions:getDistanceAutoRoute --project boxcycle-dc2df
```

단, 이 명령은 외부 운영 상태를 변경하므로 **사용자가 명시적으로 `getDistanceAutoRoute 단독 배포 승인`이라고 답하기 전에는 실행하지 않는다.**

승인 전 완료 보고에는 다음을 제출한다.

1. 실제 배포될 함수 이름이 `getDistanceAutoRoute` 하나뿐이라는 확인
2. Hosting·Firestore rules/indexes·다른 Functions가 포함되지 않는다는 확인
3. Functions build와 Route Token 전체 하네스 결과
4. 현재 운영 함수 목록과 `getDistanceAutoRoute` 404 증거
5. 배포 후 수동 검증 시 사용할 Guest 계정과 예상 Token 변화
