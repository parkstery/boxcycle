## 1. 4C 검증 결과 — 합류는 해결됐다

폰·2창 실사용에서 확인했다.

> 「이제 트레일에 참여하는 즉시 2명으로 표시된다. 이 부분은 확실하게 고쳐졌다.」

`max(aggregate, 1 + 실시간)` 이 **증가 방향**으로는 정확히 동작한다.

## 2. 확정된 제품 규칙 — 같은 Trail 만 동행

사용자 확정(2026-09-03):

> **같은 경로라도 Trail 번호가 다르면 동행이 아니다. 같은 Trail 번호만 동행으로 인정한다.**

이 규칙이 4C 설계의 전제를 바꾼다.

| 소스 | 범위 | 규칙 적합성 |
|---|---|---|
| `routeActivity` aggregate | **publication** — Trail 경계를 넘는다 | **부적합** |
| 실시간 Trail 구독(`liveRideHudSignal`) | **Trail** | **적합** |

4C 의 `max(aggregate, 1 + 실시간)` 은 규칙이 확정되기 전의 절충이었다. **이제 aggregate 인원수는 동행 블록에 들어갈 자격이 없다** — 다른 Trail 사람을 세기 때문이다.

## 3. 결함 — 이탈이 반영되지 않는다

라이더2 가 Trail 에서 나온 직후 화면.

| 화면 | 표시 | 실제 |
|---|---|---|
| 라이더2 (Trailhead, 주행 안 함) | 접속 목록에 **상대가 남아 있음** · 「지금 2명 주행」 | Trail 나옴, 주행 0:00 |
| 라이더1 (Trail 448, 주행 중) | 「지금 2명 주행」 **+** 「다른 라이더 없음」 | 혼자 |

### 3.1 원인

1. **감소가 aggregate 를 기다린다.** `companionDisplayedRiderCount` 는 `max(agg, 1 + others)` 라 **증가만 즉시**다. 상대가 빠져 `others = 0` 이 돼도 `agg = 2` 가 최대 60초 남아 2 로 표시된다.
2. **주행 중이 아니면 aggregate 원본을 그대로 쓴다.** `if (!selfRiding) return input.aggregateCount;` — 라이더2 는 주행을 멈췄으므로 낡은 2 가 그대로 나온다.
3. **4B 가 고친 모순이 이탈 경로에서 재발한다.** 실시간 신호는 즉시 `false` 가 되어 「다른 라이더 없음」을 쓰는데, 인원수는 aggregate 라 2 다. 한 블록 안에서 다시 충돌한다.

4C §4 판정 기준에 「상대 이탈 → aggregate 갱신 시점에 감소, 즉시일 필요 없음」이라고 쓴 것은 **감리의 판단 착오**다. 감소가 느린 것 자체보다, **느린 동안 모순이 표시되는 것**이 문제다.

### 3.2 별개 결함 — Trail 이탈 후 접속 목록 잔존

라이더2 화면의 접속 블록 헤더는 **Trailhead** 로 바뀌었는데 목록에는 이전 Trail 의 상대가 남아 있다. Trail 이탈 시 presence 구독·목록이 정리되지 않는다. §5 에서 별도로 다룬다.

## 4. 수정 — 동행 인원수는 Trail 실시간이 단일 진실

### 4.1 계산

```text
동행 인원수 = (내가 이 Trail 에서 주행 중이면 1 : 0) + 실시간 같은 Trail 주행자 수
```

- **aggregate 인원수 절을 쓰지 않는다.** `max` 를 버린다.
- 실시간 신호가 `0` 이면 인원수도 즉시 내려간다. 이탈이 곧바로 반영된다.
- 내가 주행 중이 아니면 인원수 절을 **표시하지 않는다.** 낡은 aggregate 를 대신 내보내지 않는다.

### 4.2 aggregate 는 버리지 않는다 — 자리를 옮긴다

aggregate 한 줄에는 인원수 말고 heat·최근 활동 절이 함께 있다. **그 절들은 유지한다.** 인원수 절만 실시간 값으로 대체하거나, 실시간 값이 없으면 인원수 절 자체를 뺀다.

`formatCompanionHudActivityLine` 이 이미 「인원 숫자 절만 치환」하도록 돼 있으므로 그 구조를 그대로 쓰고 입력만 바꾼다.

### 4.3 불변식 — 이것을 시험으로 고정한다

> **「지금 N명 주행」과 「다른 라이더 없음」은 어떤 상태에서도 동시에 표시되지 않는다.**

두 문장은 같은 소스(실시간 Trail 구독)에서 나와야 한다. 소스가 하나면 모순이 구조적으로 불가능하다. 4B·4C 에서 두 번 재발한 이유가 소스가 둘이었기 때문이다.

순수 함수 하나가 두 값을 **함께** 반환하게 만들고, 그 함수만 화면이 쓰게 한다.

## 5. Trail 이탈 시 접속 목록 정리

Trail 을 나오면 다음이 즉시 반영되어야 한다.

1. 접속 블록 목록에서 **이전 Trail 멤버가 사라진다.**
2. 헤더가 `Trailhead` 로 바뀌면 목록도 Trailhead 기준으로 교체된다. 이전 Trail 의 잔여 행이 남지 않는다.
3. 동행 블록의 인원수·빈 문장도 §4 규칙에 따라 함께 내려간다.

이탈 경로에서 presence 구독 해제와 로컬 상태 초기화가 어디서 누락되는지 찾아 고친다. **낙관적 로컬 제거**로 처리하고 서버 정리를 기다리지 않는다.

## 6. 시험

1. 순수 함수 시험 — §4.3 불변식. 입력 조합 전수:
   - `주행 중 · others=0` → 인원 **1**, 빈 문장 **표시**
   - `주행 중 · others=1` → 인원 **2**, 빈 문장 **없음**
   - `주행 안 함 · others=0` → 인원 절 **없음**, 빈 문장 표시
   - `주행 안 함 · others=1` → 인원 절 **없음**(또는 실시간 값), 빈 문장 없음
   - **어떤 조합에서도 「N명(N≥2)」과 「다른 라이더 없음」이 동시에 나오지 않음**을 assert
2. aggregate 가 `2` 인데 실시간이 `0` 인 입력에서 **1 로 표시**되는지 assert — 이번 버그의 최소 재현이다.
3. 4B·4C 회귀 시험 유지. `hasOtherLiveRiders` 파생 유지.
4. 빠른 회귀만 (3K-R2 §4 정책).

```text
npm -w boxcycle-web run test:next-ride
npm -w boxcycle-web run test:distance-auto-route
npm --prefix functions run build
npm -w boxcycle-web run build
git diff --check
```

5. 실사용 확인은 사용자가 2창으로 한다. 확인 항목:
   - 상대가 Trail 을 나가면 **수 초 안에** 내 화면이 「1명」으로 내려간다
   - 나간 쪽 화면의 접속 목록에서 상대가 사라진다
   - 어느 화면에서도 「N명 주행」 + 「다른 라이더 없음」이 함께 뜨지 않는다

## 7. 문서

- **결정 로그**에 한 줄 append — `[Trail]` `[Product]` 「**동행은 같은 Trail 만 인정** — 같은 경로라도 Trail 번호가 다르면 동행이 아니다. 따라서 동행 인원수의 단일 진실은 publication 범위 `routeActivity` aggregate 가 아니라 Trail 실시간 구독이다」. 근거로 이 문서를 링크한다.
- **[Ontology](../../260714-RTW-Ontology.md)** 의 동행·Trail 정의와 어긋나는 부분이 있으면 함께 정정한다. 없으면 「확인함」만 보고한다.

## 8. 금지·경계

- **aggregate 를 동행 인원수로 다시 쓰지 않는다.** Trail 경계를 넘는다.
- 폴링 주기·캐시 TTL 을 건드리지 않는다. 이번 수정은 소스를 바꾸는 것이지 주기를 줄이는 것이 아니다.
- 「다른 라이더 없음」 문장을 없애서 모순을 회피하지 않는다. 혼자일 때는 그 문장이 맞다.
- 인원수와 빈 문장을 **서로 다른 함수·다른 소스**로 계산하지 않는다. §4.3 불변식이 깨진다.
- `fix/hud-companion-4b` 위에 이어서 작업한다. 새 브랜치·새 worktree 를 만들지 않는다.
