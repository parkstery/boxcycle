## 1. 목적

> 2026-08-31 사용자 실동작 확인에서 일반 `npm run dev`가 미배포 `getDistanceAutoRoute`를 호출하여 실패함을 확인했다. UI·화면 증거 정리보다 Route 생성 실동작이 우선이므로 본 작업은 `DISTANCE-AUTO-ROUTE-3C` 완료 때까지 보류한다.

기능 로직을 다시 설계하지 않는다. 현재 구현에서 검수 중 발견된 Git 범위 오염과 화면 증거 누락만 정리하여, push·운영 함수 배포 여부를 판단할 수 있는 상태로 만든다.

이번 단계가 끝날 때까지 push·PR·merge·Firebase 배포를 하지 않는다.

## 2. 제품 기능 유지 조건

다음 구현은 그대로 유지한다.

1. 기본 경로 설정 popup 안에서 자동 Route를 시작한다.
2. 자동차·자전거·도보 선택은 하나의 공용 선택부만 사용한다.
3. 목표 거리 preset은 3/5/10/15/20/30km다.
4. 거리 선택 즉시 Start 중심의 목표 거리 원을 표시하고 전체 원이 보이도록 지도를 맞춘다.
5. 원은 Route 빨강 계열 `#ef4444`, 약 3px, opacity 0.95, 점선이며 실제 Route와 구분한다.
6. 지도 클릭 지점은 방향만 결정하고 클릭 거리로 목표 Route 거리를 바꾸지 않는다.
7. 사용자 행동 1회당 Route Token 1개만 서버 transaction으로 차감한다.
8. 서버 연결 실패와 허용 오차 내 후보 없음은 서로 다른 사용자 문구로 표시한다.

## 3. Git 범위 정리

현재 commit의 `apps/web/eslint.config.js` 변경을 이번 기능 범위에서 제외한다.

- `App.tsx`에 대한 `react-hooks/refs`, `react-hooks/set-state-in-effect` 전역 예외를 추가하지 않는다.
- 저장소 전체의 기존 lint 오류를 이번 작업에서 고치지 않는다.
- 해당 파일은 기준 commit `43db30681446d8c88871fda77802fe476209b035`와 같게 복원한다.
- 그 밖의 제품 파일을 lint 통과 목적으로 광범위하게 수정하지 않는다.

현재 commit은 로컬에만 있고 원격에 없으므로, 검증 통과 후 이 **한 개의 로컬 commit만 amend**하여 잘못 포함된 설정 변경을 제거한다. 과거 commit이나 다른 브랜치의 이력을 rewrite하지 않는다.

commit 제목은 유지한다.

```text
fix(route): compact auto route popup and restore circle preview
```

## 4. 빨강 원 화면 증거 재생성

기존 `.out/screenshots`의 주황 원 이미지는 완료 증거로 사용하지 않는다. 현재 HEAD의 빨강 원 구현으로 다음 네 화면을 새로 생성한다.

1. 1920×1080 · 3km
2. 1920×1080 · 10km
3. 1366×768 · 3km
4. 1366×768 · 10km

필요하면 `apps/web/scripts/distance-auto-route/capture-ui-circle-screenshots.mjs`를 최소 범위로 조정한다. 각 화면에서 다음을 육안 확인한다.

- 빨강 점선 원이 지도·물·녹지·도로 위에서 식별된다.
- Start 마커와 원 중심이 일치한다.
- 원 전체가 화면 안에 들어온다.
- 목표 거리 변경 시 이전 원이 남지 않는다.
- popup이 원의 중심이나 대부분을 가리지 않는다.

산출 이미지 자체는 제품 commit에 넣지 않는다. 파일의 절대경로와 생성 시각을 완료 보고에 적는다.
