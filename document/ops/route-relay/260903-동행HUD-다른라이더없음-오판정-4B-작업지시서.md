## 1. 증상

같은 경로를 2명이 주행 중인데 동행 블록이 **자기 자신과 모순**된다.

```text
접속 Trail 578
  · guest-HmXaWe
  · guest-vLPhVx (나)
동행 개포동 0.93
  지금 2명 주행        ← 서버 aggregate
  다른 라이더 없음      ← 같은 블록 안에서 정면 충돌
```

## 2. 원인 — 중복 제거 필터가 동행 목록을 통째로 비운다

`apps/web/src/App.tsx:1992-1999`

```ts
// 동행 블록은 접속(Trail) 블록에 이미 뜬 사람을 다시 보여주지 않는다
const activeTrailMemberUids = new Set(
  trailMembers.filter((m) => m.active).map((m) => m.key),
);
const coursePeerNames = peerHudLabels(
  coursePeerHud.filter((p) => !activeTrailMemberUids.has(p.id)),
);
```

2026-07-12 `6dc179b`(「접속·동행 중복 이름 제거」)가 넣은 필터다. 의도는 같은 이름이 두 블록에 두 번 나오는 것을 막는 것이었다.

그런데 **같은 Trail 에서 같은 경로를 달리면 동행자는 반드시 활성 Trail 멤버**다. 따라서 이 필터는 가장 흔한 경우에 `coursePeerNames` 를 **항상 빈 배열**로 만든다.

`apps/web/src/components/maphud/MapHud.tsx:315-323`

```tsx
{ridePresence.coursePeerNames.length > 0 ? ( …목록… ) : (
  <p className="hud-ride-presence__empty">다른 라이더 없음</p>
)}
```

빈 배열이면 **무조건** 빈 문장을 쓴다. 「동행이 없다」와 「동행이 있는데 위 블록에 이미 표시했다」를 **구분하지 못한다.**

반면 「지금 2명 주행」은 `courseActivityHudLine`(서버 `routeActivity` aggregate)이라 이 필터를 거치지 않는다. 그래서 한 블록 안에서 두 문장이 충돌한다.

### 2.1 `hudCompanionDiag.ts` 는 원인이 아니다

사용자가 지목한 `apps/web/src/lib/hudCompanionDiag.ts` 는 **현재 `main2` 에 존재하지 않는다.** 아래 미병합 브랜치에만 있고, 역할도 원인 코드가 아니라 **DEV 게이트 진단 도구**(동행 HUD 진단 ①~⑥)다.

실제 수정은 `liveRideHudSignal.ts` · `MapHud.tsx` · `PublicationSharedPresence.tsx` 쪽이다.

### 4.3 판정 기준

수정 후 다음 세 상태가 **구분**되어야 한다.

| 상황 | 동행 블록 |
|---|---|
| 동행 없음 | 「다른 라이더 없음」 |
| 동행 있고, 전원이 접속 블록에 이미 표시됨 | **빈 문장 없음** (aggregate 줄만) |
| 동행 있고, 접속 블록에 없는 사람 있음 | 그 사람 이름 목록 |

「지금 N명 주행」과 「다른 라이더 없음」이 **동시에 뜨는 일이 없어야 한다.** 이것이 이번 작업의 단일 수용 기준이다.
