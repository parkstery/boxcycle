## 1. 결함과 목표

현재 서버는 사용자가 5.0km 또는 10.0km를 입력해도 목표 거리와 가장 가까운 provider 후보 경로를 그대로 반환한다. `MAX_DISTANCE_ERROR_RATIO = 0.2`라서 목표 대비 ±20% 결과까지 성공으로 허용하며, provider geometry를 목표 연장에서 절단하는 단계가 없다. 실제 사용자 확인에서도 목표 5.0km에 5.07km가 반환됐다.

이 기능의 제품 계약은 "목표와 대략 가까운 Route"가 아니라 **사용자가 지정한 연장으로 끝나는 Route**다. 최종 성공 결과의 geometry·End·distance를 목표 연장에 맞춘다.

## 2. 필수 동작 계약

1. 목표 5.0km는 Route geometry 누적 연장 5,000m에서 끝나야 한다.
2. 목표 10.0km는 Route geometry 누적 연장 10,000m에서 끝나야 한다.
3. 목표보다 긴 provider Route를 선택한 뒤 geometry를 시작점부터 누적해 목표 지점에서 절단한다.
4. 목표가 선분 중간에 위치하면 해당 선분 위의 좌표를 보간해 마지막 좌표와 End로 사용한다.
5. 목표보다 짧은 Route는 성공 결과로 반환하지 않는다. 부족분을 직선으로 덧붙이거나 `distance` 숫자만 목표값으로 바꾸는 것도 금지한다.
6. 충분히 긴 후보를 찾지 못하면 실패 처리하고 현행 계약대로 차감한 Token을 환불하며 기존 Route를 유지한다.
7. 최종 반환 `geometry`, `end`, `distance`, cache 저장 값과 클라이언트 HUD가 같은 절단 결과를 가리켜야 한다.
8. 성공 1회당 Route Token 1개 차감, 실패 시 잔액 복원, 재탐색마다 새 `requestId` 계약을 유지한다.

## 3. 서버 구현 기준

### 3.1 authoritative 절단 함수

Functions 서버 core에 순수 함수를 둔다. 개념적 입력과 출력은 다음과 같다.

```text
input: LineString coordinates, targetDistanceMeters, originalDuration
output: clippedGeometry, clippedEnd, clippedDistance, clippedDuration
```

- 각 geometry 선분을 동일한 geodesic 거리 함수로 계산해 누적한다.
- 누적값이 목표를 처음 통과하는 선분에서 남은 거리 비율을 구해 좌표를 보간한다.
- 원래 좌표 중 목표 이전 좌표들과 보간 좌표만 새 LineString에 포함한다.
- 목표가 기존 vertex와 허용 오차 안에서 일치하면 중복 좌표를 추가하지 않는다.
- 빈 geometry, 좌표 1개, 비정상 수치, 총 연장 부족은 성공 객체가 아니라 명시적 실패 결과로 처리한다.
- 클라이언트의 표시값만 고치는 방식은 금지한다. API·cache의 원본 결과부터 정확해야 한다.

### 3.2 후보 선택

- provider 응답 중 geometry 총 연장이 목표 이상인 후보만 최종 성공 후보가 될 수 있다.
- 목표 이상 후보에서는 우선 초과량이 가장 작은 경로를 선택하고, 동률에는 현행 방향 tie-break를 유지한다.
- 현행 `MAX_DISTANCE_ERROR_RATIO = 0.2`는 최종 성공 허용 조건으로 사용하지 않는다. 필요하면 provider 후보 탐색·재시도 범위를 제한하는 내부 값으로만 이름과 역할을 명확히 바꾼다.
- 최초 후보군에 목표 이상 geometry가 없으면 무한 반복하지 않는 bounded 확장 탐색을 수행할 수 있다. 그래도 없으면 성공을 조작하지 말고 실패·환불한다.
- provider의 `route.distance`와 geometry 누적 연장이 다를 수 있으므로 절단 가능 여부와 최종 정확도는 실제 반환 geometry의 누적 연장을 기준으로 판정한다.

### 3.3 거리·End·duration 일관성

- `end`는 절단 geometry의 마지막 보간 좌표다. 절단 전 provider 종점을 재사용하지 않는다.
- `distance`는 절단 geometry를 같은 거리 함수로 재계산한 값으로 반환한다. 목표 숫자를 검증 없이 대입하지 않는다.
- 성공 허용 오차는 절단 계산의 수치 오차만 허용한다: `abs(distance - targetDistanceMeters) <= 5m`.
- HUD의 km 표시는 5.0 목표에서 `5.00`, 10.0 목표에서 `10.00`으로 확인 가능해야 한다. 표시 자리수 때문에 실제 계약 위반을 숨기면 안 된다.
- 절단 전 전체 Route의 `duration`을 그대로 반환하지 않는다. 최소한 절단 비율에 맞춰 재산정하고, provider가 segment별 시간을 제공한다면 실제 절단 위치까지 합산한다. 어떤 방식을 사용했는지 시험과 완료 보고에 명시한다.
- 성공 summary는 더 이상 `목표 5.0 km · 실제 5.1 km` 같은 근사 결과를 정상으로 표현하지 않는다. 목표 연장과 계산된 연장이 일치함을 간결히 표시한다.

## 4. cache·중복 요청 계약

- `requestId` cache에는 절단 완료된 geometry·End·distance·duration만 저장한다.
- 같은 `requestId` 재호출은 동일한 절단 결과와 동일 Token 잔액을 반환하고 추가 차감하지 않는다.
- 절단 또는 검증 실패 결과를 `found`로 cache하지 않는다.
- Route A가 있는 상태에서 Route B 생성 중에는 A를 유지하고, B의 정확 절단과 cache 저장이 성공한 뒤에만 교체한다.

## 5. 이번 작업에서 변경하지 않는 것

- popup 배치·checkbox·slider·`−`/`+` UI
- 사용자가 클릭한 도로와 최종 End를 더 가깝게 맞추는 방향 후보·점수 알고리즘
- popup drag·floating·edge docking
- Token 가격과 지급 정책

방향 일치도 개선은 정확 연장 계약을 고정한 다음 별도 작업으로 이어간다. 다만 이번 절단으로 방향 오차가 더 커지는지 측정값은 남긴다.

## 6. 필수 시험

서버 core/API 계약에 다음을 자동 시험으로 고정한다.

1. 5.07km geometry를 5,000m에서 절단: 최종 오차 ≤ 5m, End는 절단점
2. 10km보다 긴 geometry를 10,000m에서 절단: 최종 오차 ≤ 5m
3. 목표가 vertex와 정확히 일치하는 경우 중복 좌표 없음
4. 목표가 선분 중간인 경우 보간 좌표가 해당 선분 위에 존재
5. 총 연장이 목표보다 짧은 geometry는 성공 반환 금지
6. 복수 후보에서 짧은 후보 제외 후 최소 초과 후보 선택
7. 반환 `distance`와 반환 geometry 재계산 연장 일치
8. 반환 `end`와 geometry 마지막 좌표 일치
9. 절단 후 duration이 절단 전 전체 duration을 그대로 사용하지 않음
10. cache hit 결과 동일·추가 Token 차감 0회
11. 절단 실패 시 Token 환불·기존 Route A 유지
12. Route A→정확 연장 Route B 성공 시에만 교체·새 `requestId`·Token 1개 차감
