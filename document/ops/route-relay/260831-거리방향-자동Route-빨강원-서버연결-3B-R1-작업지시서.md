## 3. `Failed to fetch` 원인과 금지 사항

현재 호출 대상:

```text

```

확인된 상태:

- 운영 `getDistanceAutoRoute`: 미배포, OPTIONS 404
- 운영 `getMapboxDirections`: 배포됨, OPTIONS 204
- 따라서 방향·거리 후보 품질을 조정해도 현재 오류는 해결되지 않는다.

금지:

- 35개 후보를 브라우저의 `getMapboxDirections` 반복 호출로 되돌리지 않는다.
- browser direct Mapbox Directions 우회를 켜지 않는다.
- Token 차감을 클라이언트로 옮기지 않는다.
- `Failed to fetch`를 단순 후보 없음으로 오인해 허용오차 20%를 완화하지 않는다.

## 4. 로컬 검증 포트 정리

현재 3B Vite가 Functions Emulator 기본 포트 5001을 점유한다. 전체 하네스 실행 전에 다음을 정리한다.

- 루트 사용자의 5000 서버는 건드리지 않는다.
- 3B Vite 5001 프로세스만 정상 종료한다.
- 기존 Route Token 하네스 규약대로 Functions Emulator는 5001을 사용한다.
- 하네스 UI는 기존 runner가 지정하는 5010을 사용한다.
- 임의 포트 변경으로 하네스 계약을 우회하지 않는다.

포트 종료 대상과 PID를 확인한 뒤 정상 종료하고, 강제 종료가 필요하면 해당 3B Vite PID만 정확히 지정한다.

## 6. 오류 문구

네트워크 수준 연결 실패를 그대로 `Failed to fetch`로 노출하지 않는다.

권장 사용자 문구:

```text
자동 경로 서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요.
```

후보를 모두 탐색했지만 허용 오차 안의 Route가 없는 경우의 “경로를 찾지 못했습니다”와 서버 연결 실패를 구분한다.

방향 선택 안내에는 다음 의미가 드러나야 한다.

```text
지도에서 원하는 주행 방향을 선택하세요. 클릭한 지점까지의 거리가 아니라 방향만 사용합니다.
```

목표 Route 거리는 3/5/10/15/20/30km preset이 결정하고, 지도 클릭 지점과 Start 사이의 화면상 거리는 계산 입력으로 사용하지 않는다.
