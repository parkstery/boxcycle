## 1. 사용자 시나리오

사용자는 생성된 자동 Route를 곧바로 주행·저장하지 않고 다른 후보를 탐색할 수 있다.

```text
Route A 생성 성공
→ 현재 설정 popup과 자동 Route 세션 유지
→ 지도에서 다른 방향 클릭
→ Route B 탐색
→ 성공하면 Route A를 Route B로 교체
```

이 과정에서 예전 형식의 지점 선택 popup으로 되돌아가면 안 된다. 자동 Route 결과는 최종 확정 화면이 아니라 계속 비교할 수 있는 후보로 취급한다.

현행 Token 정책상 Route B 탐색도 새로운 Route 생성이므로 성공 시 Token 1개를 추가 차감한다. 재탐색을 무료로 바꾸는 정책 변경은 이번 범위가 아니다.

## 2. 확정된 원인

현재 코드의 세 조건이 함께 문제를 만든다.

1. `useDistanceAutoRoute`가 성공 후 `step="route_found"`로 전환한다.
2. `mapPickMode`는 `pick_direction`일 때만 `direction`을 반환하므로 성공 직후 `null`이 된다.
3. `MapView.buildPickPopup()`의 `syncAutoRouteUi()`가 `pins.start && !pins.end`일 때만 자동 Route 컨트롤을 표시한다.

결과적으로 생성된 End가 존재하는 상태에서 다음 지도 클릭은 일반 popup을 열고 자동 Route 컨트롤을 숨긴다.

## 3. 필수 동작

### 3.1 성공 직후 재탐색 가능 상태 유지

- Route 성공 후 현재 단일 popup을 유지한다.
- 상태 행은 `경로 생성 완료 · 다른 방향을 클릭하면 다시 탐색합니다`처럼 짧게 표시한다.
- popup이 열린 동안 다음 지도 클릭을 새 방향으로 해석한다.
- 별도의 `다시 탐색`·`방향 선택` 확인 버튼을 추가하지 않는다.
- 새 방향 클릭 직후 동일 popup의 상태 행을 `탐색 중`으로 갱신한다.

### 3.2 새 요청은 새 사용자 행동

- Route A의 requestId를 Route B에 재사용하지 않는다.
- 성공 직후 다음 방향 클릭 전에 기존 active requestId를 폐기한다.
- 방향 클릭 1회당 `getDistanceAutoRoute` POST 1회만 발생한다.
- Route B 성공 시 Token을 추가로 정확히 1개 차감한다.
- Route B 실패 시 해당 차감은 환불하고 Route A·Token 잔액을 유지한다.

### 3.3 기존 Route 교체 시점

- Route B 탐색 중에는 Route A를 지도에서 유지한다.
- Route B 성공 응답을 받은 뒤에만 Route geometry·End·거리·시간을 교체한다.
- 실패·network error·허용 오차 실패 때 Route A를 삭제하지 않는다.
- 중복 지도 클릭은 현재와 같이 무시한다.

## 4. 생성된 End가 있어도 단일 설정창 유지

- `pins.end` 존재 여부만으로 자동 Route 컨트롤을 숨기지 않는다.
- Start가 있고 자동 Route 기능을 사용할 수 있으면 같은 slider·숫자 입력·아이콘·Token 행을 표시한다.
- 생성 후 새 지도 클릭으로 popup을 다시 여는 경우에도 예전 `경로 탐색 유형 선택` 형식만 표시하지 않는다.
- popup을 닫았다가 다시 열어도 목표 거리와 이동수단은 마지막 자동 Route 값으로 복원한다.
- 예: 55km 자전거 Route를 생성했다면 다시 연 popup도 55.0km·자전거 상태여야 한다.

기존 수동 Route도 보존한다.

- 자동 Route 거리 컨트롤을 사용하지 않은 수동 세션에서는 End 직접 지정 흐름 유지
- End가 있는 수동 Route에서도 거리 컨트롤을 조작하면 자동 Route 모드로 전환 가능
- 자동 Route 모드에서 이동수단 변경은 기존 End로 즉시 수동 재계산하지 않고, 다음 방향 탐색에 사용할 profile을 바꿈

이를 위해 `End 존재`와 `자동 Route 세션 활성`을 같은 상태로 간주하지 말고 명시적으로 구분한다.

## 5. 자동 세션 종료 조건

자동 Route 방향 가로채기가 화면 밖에서 계속 남지 않게 한다.

다음 경우에는 자동 Route 세션을 해제한다.

- 사용자가 설정 popup의 닫기 버튼을 누름
- `경로 삭제`
- Start 삭제·변경
- 주행 시작으로 Route 편집이 잠김

popup을 닫은 뒤 일반 지도 클릭은 자동으로 Token을 소비하면 안 된다. 다시 열린 단일 설정창에서 거리 컨트롤을 사용하면 자동 방향 모드에 재진입한다.

단, popup을 닫은 뒤 생성된 Route가 있는 상태에서 새 지점을 클릭해 연 설정창에도 자동 Route 컨트롤 자체는 보여야 한다.

## 6. Token 0 처리

- Route A 생성 후 잔액이 0이면 성공 상태와 Route A는 유지한다.
- 추가 방향 클릭은 provider 호출 전에 차단한다.
- 같은 popup 안에 `경로 생성 잔여 토큰 0개`와 부족 상태를 표시한다.
- 부족 때문에 예전 popup으로 전환하지 않는다.
- popup을 닫으면 자동 방향 가로채기는 해제한다.

## 7. 시험 보완

사용자가 같은 worktree에서 자신의 브라우저로 직접 확인할 수 있도록 완료 보고에 아래 내용을 빠짐없이 적는다.

1. 실행해야 할 worktree 절대경로
2. 해당 경로에서 실행할 정확한 CLI 명령
3. 접속할 정확한 URL과 실제 사용 포트
4. 별도 Functions·Firebase Emulator·보조 process 실행 필요 여부
5. 필요하다면 각 process의 CLI 명령과 어느 terminal에서 계속 실행 상태로 두어야 하는지
6. 서버 재시작 필요 여부와 기존 process 종료 방법
7. 일반 새로고침으로 충분한지, 강력 새로고침이 필요한지
8. 캐시·Service Worker·로그아웃·Guest 재생성이 필요한 경우에만 정확한 절차
9. 사용자가 수행할 최소 재현 순서와 각 단계의 기대 결과
