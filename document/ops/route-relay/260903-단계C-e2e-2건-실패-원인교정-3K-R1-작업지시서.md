## 2. 실패 ② 「Start 이동 시 anchor 고정 해제」 — Route Token 잔액이 0이다

### 2.1 증거

Playwright error-context 의 DOM 스냅샷:

```text
- status:
  - paragraph: 경로 생성 잔여 토큰 0개 · 경로 토큰 부족
- checkbox "거리와 방향으로 Route 찾기" [checked]
- status: 경로 토큰 부족
- listitem: guest-WHmhhc (나)
```

**갓 만들어진 Guest 인데 잔액이 0이다.** 온보딩 지급(Guest 10)이 일어나지 않았다.

spec 이 기다린 문구는 실제로 존재한다 — `DISTANCE_AUTO_ROUTE_DIRECTION_CLICK_HINT = "도착하고 싶은 도로 위 지점을 클릭하세요"`. 뜨지 않은 이유는 잔액 0 이라 방향 모드가 arm 되지 않고 상태 슬롯이 「경로 토큰 부족」으로 대체됐기 때문이다. **제품 동작은 정상이다** — 토큰 없이 생성을 막는 것은 의도된 계약이다.

### 2.2 원인 사슬 (3K §2.3 과 동일)

1. `playwright.config.ts` 의 `underEmulator` env 블록에 **`VITE_USE_EMULATOR: '1'` 만 있고 `VITE_FUNCTIONS_EMULATOR_HOST` 가 없다.**
2. `VITE_USE_EMULATOR=1` → `firebase.ts` 가 `connectAuthEmulator()` → **ID token 이 에뮬레이터 발급**.
3. `resolveFunctionsHttpUrl()` 은 host 가 없으면 `null` 을 반환하고 `functionsHttpUrl()` 은 **프로덕션으로 조용히 폴백**한다(`functionsEmulatorUrl.ts` 현재 상태 — throw 미적용).
4. 프로덕션 `verifyIdToken()` 이 에뮬레이터 토큰을 거부 → **401** → `ensureRouteTokenOnboardingClient` 실패 → **잔액 0**.
5. 잔액 0 → `routeTokenInsufficient` → 방향 모드 arm 차단 → spec 이 기다리는 문구가 영원히 안 뜸.

npm script 는 `--only auth,firestore,database,functions` 로 **Functions 에뮬레이터를 띄우긴 했다.** 로그에도 `ensureRouteTokenOnboardingHttp` 가 5001 에 초기화됐다. 그러나 앱이 그 주소를 모른다. 3K §2.3.1-2 의 절반(emulators:exec)만 적용되고 나머지 절반(env)이 빠졌다.

### 2.3 수정

**3K §2.3.1 을 그대로 수행한다.** 재서술하지 않고 그 문서를 따른다. 최소 다음 둘은 반드시 포함한다.

1. `playwright.config.ts` `underEmulator` env 에 `VITE_FUNCTIONS_EMULATOR_HOST: '127.0.0.1:5001'` 추가. Functions 에뮬레이터를 띄우지 않는 시험(`test:e2e:ride` 이전 형태 등)과 충돌하지 않도록, **Functions 에뮬레이터가 포함된 실행에서만** 켜지게 조건을 명확히 한다.
2. `functionsEmulatorUrl.ts` — `VITE_USE_EMULATOR === "1"` 인데 `VITE_FUNCTIONS_EMULATOR_HOST` 가 없으면 **프로덕션 폴백 금지, throw**. `resolveFunctionsHttpOrigin()` 의 같은 폴백도 함께 막는다. 이번 사고가 「조용한 폴백」의 비용을 증명했다 — 401 하나가 3단계를 건너 e2e 2건 실패로 나타났다.

## 3. 실패 ① 「3회 연속」 — `readGuestUid` 가 localStorage 를 본다

### 3.1 원인 (확정)

```text
spec:203  expect.poll(... localStorage.key(i).startsWith('firebase:authUser:') ...).not.toBeNull()
→ Timeout 30000ms, Received: null
```

`apps/web/src/` 어디에도 `setPersistence` 호출이 없다. Firebase Web SDK 는 기본적으로 **IndexedDB(`firebaseLocalStorageDb`)** 를 먼저 쓴다. 따라서 `firebase:authUser:*` 키는 **localStorage 에 존재한 적이 없다.** 이 poll 은 무엇을 해도 timeout 이다.

§2 를 고쳐도 이건 그대로 실패한다. 별개 결함이다.

### 3.2 수정

uid 를 브라우저 저장소 구현에 의존해 읽지 않는다. 다음 중 하나를 쓰고, 고른 이유를 주석 한 줄로 남긴다.

- **권장** — IndexedDB `firebaseLocalStorageDb` → object store `firebaseLocalStorage` 에서 `firebase:authUser:` 로 시작하는 key 의 `value.uid` 를 읽는다. 저장소가 바뀌어도 깨지지 않게 **localStorage 도 함께 훑는 fallback** 을 둔다.
- 또는 Auth 에뮬레이터 REST(`/identitytoolkit.googleapis.com/v1/accounts:lookup`)로 조회한다.

**앱 코드에 시험 전용 전역(예: `window.__uid`)을 심지 않는다.** 제품 표면을 시험용으로 오염시키지 않는다.
