## §0 그림에서 보이는 것

이 STEP 은 코드·수치 검산이라 **주행 화면 캡처는 없다.**  
그림 판정은 STEP 2(명칭)·3(거리)·4~6(Quick Camera) 에서 한다.

정적·수치로만 말하면:

- `rear30` 은 카메라가 라이더 **뒤**에서 진행 방향을 본다 → 라벨 "후방"은 구도와 반대다.
- `front30` 은 카메라가 라이더 **앞**에서 뒤를 본다 → 라벨 "전방"도 반대다.
- pitch 80° 에서 거리 5m 를 넣어도 span 이 floor(≈5.59m) 로 클램프되어 **5m 와 floor 의 zoom 이 동일**하다 → 5m 는 죽은 구간이 맞다.
- `tickRideCameraFollow` 는 매 프레임 `jumpTo({ zoom: followZoom })` 을 쓴다 → 사용자 휠 줌은 구조상 즉시 덮인다.

### 좌/우 코드 검산 (그림 미확인 — STEP 2 에서 캡처 필수)

heading=0(북) 기준:

- `leftFlat`: offsetBearing = heading+270 = 서 → 카메라가 라이더 **좌측**. 라벨 "좌측"과 **코드상 일치**.
- `rightFlat`: offsetBearing = heading+90 = 동 → 카메라가 라이더 **우측**. **코드상 일치**.

감리 지시대로 **그림으로 확인하기 전에는 매핑을 바꾸지 않는다.** 반대면 STEP 2 에서 반증 보고.

### §3 거리 floor / pitch 67° 재계산 (필수)

| 항목 | 값 |
|---|---|
| `RIDER_DISPLAY_HEIGHT_M` | 1.593926… |
| `rideHeightSpanMargin(80)` | 3.50652… |
| floor@80 | 5.58914… → ceil(0.5 step) → **minM = 6** |
| floor ≤ 5.0 이 되는 최대 pitch | **67°** (floor 4.9838 → ceilMin **5.0**) |
| `sin²p = (5/h − 0.5)/3.1` | 0.85062 → pitch ≈ **67.26°** |

감리 산식(pitch ≤ ≈67° → floor ≤ 5.0) **일치. 반증 없음.**

## §2 0-1 반증 조건 확인

> "tick 의 zoom 기록을 막았는데도 사용자 줌이 되돌아가면 F5 가 틀린 것이다."

### 이번 STEP 에서 한 것

1. **정적 확인 (실행)**: 팔로우 중 `applyFollowCameraJumpTo` 가 매 tick `zoom: nextZoom` 을 넣는다. `nextZoom` 목표는 `computeRideFollowFraming(…, distanceM: opts.rideCameraDistanceM)`. 사용자 휠이 `map` zoom 만 바꿔도 다음 프레임에 framing zoom 으로 lerp 된다. → **F5 진단 유지.**
2. **역함수 수치**: distance 가 span 을 이길 때(≥floor) zoom↔distance 역산 오차 ≈ 0 (6·10·20·40·60m). 감리 권고 (a) 의 역산은 **수학적으로 가능**.
3. **라이브 휠 샘플 (미실행)**: 주행 세션에서 preset→휠→1초간 `getZoom()` 3회 샘플은 **이 STEP 에서 브라우저 실주행을 돌리지 않았다.**  
   - "zoom 기록을 막고" 반증 실험도 미실시(코드 변경 금지 구간).  
   - **해석**: 현재 증거는 F5 를 **지지**한다. 라이브 3회 샘플·차단 반증은 STEP 6 구현 직전·직후에 캡처로 닫는다.  
   - 만약 STEP 6 에서 휠 줌이 되돌아가지 **않으면** 그때 F5 를 철회한다.

## §5 이견 · 설계안 3건 (권고)

### (a) 줌 비간섭 — **권고: 감리안(거리 역산) + userZoomLocked 플래그**

**권고 구현**

1. 팔로우 중 사용자 zoom 제스처(`wheel` / pinch / Mapbox `zoomstart` 중 사용자 기원) 감지.
2. 제스처 후 `map.getZoom()` 에서 **거리 역산**:
   - `spanM = mpp(zoom + pitchAdj) * safeHeight`
   - `rideCameraDistanceM = max(spanM, floor(pitch))` 로 상태 덮어쓰기  
   - (distance 가 floor 아래면 span=floor 이라 역산이 floor 로 붙음 — 정직함)
3. tick 은 **덮어쓴 거리**로 framing 계속 → 구도(bearing/pitch/offset) 유지, 거리만 사용자 것.
4. Quick Camera / MapViewSheet 칩 **재클릭(preset 적용)** 시에만 기본 거리(5/60 등)로 리셋 + 락 해제.
5. `topDown`/`north`(또는 1번 Route Fit)처럼 `distanceM:0`·fallbackZoom 경로에서는 역산 대신 **앱 `mapZoom` / framing fallback 을 사용자 zoom 으로 동기화**하고 tick 이 그걸 쓰게 한다.

**대안 (비권고)**

- tick 에서 zoom 쓰기만 끄기 → center/bearing 과 zoom 불일치, look-at 깨짐.
- `free` 로 전환 → 팔로우 판타지 상실, 원안 위배.

### (b) rename 매핑 — **권고: 지시 §2 확정안 그대로**

| 기존 | 정정 | 라벨 |
|---|---|---|
| `rear30` | `forward` | 전방 |
| `front30` | `backward` | 후방 |
| `leftFlat` | `left` | 좌측 |
| `rightFlat` | `right` | 우측 |
| 나머지 | 유지 | — |

- `DEFAULT_FOLLOW_MODE`: `"leftFlat"` → `"left"` (구도 동일)
- `RIDE_FOLLOW_CAMERA_MODE`: `"topDown"` 유지
- giant-relay 계측 스크립트 **미수정**
- 좌/우가 화면에서 반전으로 나오면 **매핑 바꾸지 말고 반증 보고**

### (c) 거리 범위 — **권고: max→60 + 밀착 pitch를 67°로 낮춰 5m 개방**

1. **상한**: `RIDE_CAMERA_DISTANCE_MAX_AT_BASE_M` 40 → **60**. 슬라이더·default 도 함수 유도값을 따름.
2. **하한 5m**: min 숫자만 5 로 내리지 **않음**(잘림). 밀착 4방향(`forward/backward/left/right`)의 pitch 를 **67°** 로 내려 floor≈4.98 → ceilMin **5.0**.  
   - 1차 구현값 67°. STEP 3 캡처에서 「밀착감 상실」이면 64~60° 후보를 수행결과에 올려 감리 선택.
3. **1번 Aerial 60m**: `topDown` 에 거리 개념을 넣거나( pitch 0 + distanceM 60 + offset 기반 framing ), Quick Camera 1 의 Aerial 분기만 distance 팔로우를 쓰도록 STEP 5 에서 설계 확정. STEP 1 권고는 **기존 `computeRideFollowFraming` 재사용, pitch 0·distance 60·offsetBearing=baseHeading+180(뒤쪽 상공은 수직에 가깝게)** — 구체 분기는 STEP 5 착수 시 재확인.
4. **6번 북향**: 지시대로 **baseHeading=0 고정인 forward 구도 + 5m**. 기존 `north`(distance 0·bearing 0만)는 MapViewSheet 칩용으로 남기되, Quick Camera 6 은 forward@heading0@5m 로 해석(지시 STEP 5와 동일).

### heading 소스 확정

```text
baseHeading =
  headingFromMove(prev→curr, stepM >= 2)   // 우선
  ?? headingFromRoute(60m ahead × 60 samples)  // CAMERA_BEARING_WINDOW_*
  ?? map.getBearing()
```

근거: `tickRideCameraFollow` L227–237.  
원안 §10 「실제 주행 heading」: **이동 벡터 우선, 부족 시 경로 전방 평균** → 부합. GPS/마커 rotation 단독 사용 아님.
