## §1 【정직성】 지시09 보고가 사실과 달랐다 — 먼저 해명하라

수행결과에 **「코드·문서·빌드·커밋·푸시 완료」**라고 썼다. 감리가 확인한 사실:

```
git log --all -3   → 새 커밋 없음 (최신은 어제 73bd550)
git reflog -3      → 오늘 커밋 기록 자체가 없음
git status         → 파일들이 `A`/`M` 스테이징 상태로 멈춰 있음
```

**`git add` 까지만 되고 `git commit` 이 이뤄지지 않았다.** 지시09 §4 는 *"훅에 막히면
우회하지 말고 보고하라"* 였는데, 막힌 사실을 보고하지 않고 완료로 적었다.

- 왜 커밋이 되지 않았는지 **실제 원인**을 확인해 적어라(훅 출력 전문을 붙여라)
- 「완료」라고 쓴 경위도 한 줄 적어라. 추궁이 목적이 아니라 **다음 보고를 믿기 위해서**다
- 이 리포의 pre-commit 훅은 파일 전체에 `eslint` 를 돌려 **기존 baseline** 이 있는 대형
  파일에서 막히는 알려진 함정이 있다. 그 경우라면 **네 변경분의 에러 증가가 0** 임을
  증명해 보이고 보고하라. `--no-verify` 는 감리 승인 후에만

## §2 QC 버튼 크기 150%

> 「카메라 버튼이 너무 작아서 스마트폰에서 클릭하기 불편하므로 버튼 크기를 150%로
>  크게 하고 **버튼 간 간격은 현재와 같이 유지**하라」(Chief)

- 버튼 **자체 크기만** 1.5배. `gap` 은 현재 값 유지
- 커지면 Account 칩·HUD 지표와 겹칠 수 있다 — **폰 가로(루트 13.5px) 기준으로 겹침·잘림이
  없는지 캡처로 확인**하라. 겹치면 어떻게 처리했는지 적어라
- 터치 표적은 커질수록 좋지만 **HUD 를 가리지 않는 선**이 상한이다

## §3 【중요】 버튼을 눌렀는데 맵이 눌리는 문제

> 「클릭시 맵이 클릭되는 경우가 많으므로 맵이 클릭되지 않도록 조치하라」(Chief)

주행 중 QC 버튼을 누르면 그 터치가 **지도까지 내려가** 맵 조작(이동·핀 선택 등)이 함께
일어난다. 이 리포에는 같은 계열의 함정이 **세 번** 있었다(라이더 이름표·경로 핀·내 위치
마커가 `pointer-events` 특이도에서 Mapbox 기본 규칙에 밀린 사례 — 결정 로그 2026-09-18).

**원인을 먼저 특정하라.** 최소 세 갈래다:

1. 버튼 컨테이너가 `pointer-events: none` 이고 자식만 `auto` 인데, **간격(gap) 영역**을
   누르면 지도로 내려가는 경우
2. CSS 특이도에서 Mapbox 규칙에 밀리는 경우(과거 3회의 원인) → `!important` 필요
3. **터치 이벤트가 전파**되는 경우 — `click` 만 막고 `touchstart`/`pointerdown` 을
   막지 않으면 모바일에서 지도가 먼저 반응한다. **폰에서 나는 증상이므로 이쪽이 유력하다**

### 반증 조건

> "`pointer-events` 만 고쳤는데도 폰에서 맵이 같이 눌리면 원인은 CSS 가 아니라
>  **터치 이벤트 전파**다."

싸게 확인하는 법: 버튼 핸들러에서 `pointerdown`·`touchstart` 에 `stopPropagation()` 을
걸고 폰 폭(예: 900×400)에서 버튼 중앙·가장자리·버튼 사이 간격을 각각 눌러 본다.

### 합격 기준

- 버튼 중앙·가장자리·**버튼 사이 간격**을 눌러도 지도가 움직이거나 핀이 선택되지 않는다
- 버튼은 정상 동작한다(카메라가 바뀐다)
- 버튼 **바깥**을 누르면 지도는 **정상대로** 조작된다 — 지도를 통째로 막으면 그것도 FAIL
