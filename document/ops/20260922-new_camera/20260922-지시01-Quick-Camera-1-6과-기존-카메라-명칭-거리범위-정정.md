## 0. 감리가 이미 조사한 것 — 네 손으로 검산하라

**새 카메라 시스템을 만들지 마라. 요구된 것의 8할은 이미 있다.**

| # | 감리 조사 결과 | 근거 |
|---|---|---|
| F1 | 공통 Camera Controller 가 **이미 존재**한다: `getCameraForFollowMode()` + `computeRideFollowFraming()`. 후자는 `distanceM`(실제 m)·`pitchDeg`·뷰포트로 **zoom 을 역산**한다 — 「5m = 실거리」는 이미 이 함수의 계약이다 | `components/map/rideCameraFollow.ts`, `lib/rideCameraFraming.ts` |
| F2 | `FollowMode` = `free/keep/north/rear30/front30/leftFlat/rightFlat/topDown` — 원안 1~6 과 거의 1:1 대응 | `components/ride/RideRoutePanel.tsx:14` |
| F3 | **명칭이 원안과 반대다.** `rear30`(라벨 "후방") = 카메라가 라이더 뒤에서 진행 방향을 보는 구도 = **원안 2번 「전방」**. `front30`(라벨 "전방") = **원안 3번 「후방」** | `getCameraForFollowMode` |
| F4 | `topDown`·`north` 는 `distanceM: 0` 고정(거리 개념 없음) → **1번 Aerial 60m·6번 북향 5m 는 실제 코드 변경 필요** | 같은 함수 |
| F5 | `tickRideCameraFollow()` 가 **rAF 매 프레임 `map.jumpTo()` 로 zoom 을 다시 쓴다** → 현 구조에서 사용자 휠 줌은 즉시 덮인다 | `rideCameraFollow.ts` 하단 |

## 2. 【STEP 2】 명칭 정정 — 확정안

`30` 은 pitch 30° 시절의 유물이며 현재 pitch 는 80 이다. 이름이 거짓말을 하고 있다.

| 기존 | 정정 | 구도(사실) | 원안 |
|---|---|---|---|
| `rear30` (라벨 "후방") | **`forward`** (라벨 "전방") | 카메라가 라이더 **뒤**, 진행 방향을 본다 | 2번 |
| `front30` (라벨 "전방") | **`backward`** (라벨 "후방") | 카메라가 라이더 **앞**, 지나온 쪽을 본다 | 3번 |
| `leftFlat` | **`left`** (좌측) | 카메라가 라이더 **좌측** | 4번 |
| `rightFlat` | **`right`** (우측) | 카메라가 라이더 **우측** | 5번 |
| `topDown` · `north` · `free` · `keep` | 유지 | — | 1·6번 |

- ⚠ **좌/우도 반드시 실측 검증하라.** 감리는 코드상 `leftFlat` = 라이더 좌측으로 읽었으나
  이는 그림으로 확인하지 않았다. 반대면 **매핑을 바꾸지 말고 반증을 먼저 보고**하라
- 변경 대상은 제품 4파일 + e2e 1개다(F8). `DEFAULT_FOLLOW_MODE`(`leftFlat`)·
  `RIDE_FOLLOW_CAMERA_MODE`(`topDown`)의 **값이 가리키는 구도는 바꾸지 마라** — 이름만 따라간다
- giant-relay 의 `g3~g5-measure.mjs` 는 과거 계측 기록이다. **건드리지 마라**

## 3. 【STEP 3】 거리 범위 정정 — 감리 분석

`rideCameraDistanceRangeM()` 은 하한·상한을 **라이더 전고에서 유도**한다.

- **상한**: `RIDE_CAMERA_DISTANCE_MAX_AT_BASE_M = 40` 은 제품 상수일 뿐이다.
  60m 를 수용하도록 올린다. 슬라이더 상한도 함께 따라간다
- **하한**: `floor = rideHeightSpanMargin(pitch) × 전고`, `margin = 0.5 + 3.1·sin²(pitch)`.
  현재 pitch 80° → margin 3.506 → floor ≈ 5.59m → 눈금 올림 **6.0m**.
  **하한 숫자만 5 로 낮추면 라이더가 프레임에서 잘린다** — 그 값은 물리에서 나온 것이다.
  계산상 **pitch ≤ 약 67° 면 floor ≤ 5.0m** 가 된다(감리 산식: `sin²p ≤ 0.851`).
  → 원안 §12 가 허용한 **구도 조정(pitch)** 으로 5m 를 여는 것이 감리 권고다
- **【필수】 이 67° 를 네 손으로 다시 계산하고, 실제 화면에서 검증하라.**
  감리 산식이 틀렸으면 반증을 먼저 보고하라. 「pitch 를 낮췄더니 밀착감이 사라졌다」면
  그것도 보고 대상이다 — 숫자가 맞아도 그림이 틀리면 실패다
- assert·허용치를 완화해 통과시키지 마라. 실패는 FAIL 로 보고하는 것이 옳은 처신이다
