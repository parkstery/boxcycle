# 카메라 작업 릴레이 — 20260922-new_camera

> **감리(클로드)와 개발팀장(커서)이 이 폴더의 파일로만 통신한다.**
> Chief 는 파일을 옮기지 않는다. 양쪽이 스스로 이 폴더를 읽고 쓴다.

## 1. 파일 이름 규약 (Chief 지정)

```
20260922-지시01-<내용>.md              ← 감리가 쓴다
20260922-지시01수행결과-<내용>.md       ← 개발팀장이 쓴다
20260922-지시01수행결과02-<내용>.md     ← 같은 지시를 재작업했을 때
20260922-지시01수행결과03-<내용>.md     ← 그 다음 재작업
```

- **번호는 지시에 종속된다.** 수행결과는 자기만의 일련번호를 갖지 않는다 —
  `지시09` 에 대한 보고는 반드시 `지시09수행결과` 다
- 재작업이 생기면 **수행결과 뒤에만** `02` · `03` · `04` … 를 붙인다
- 날짜 접두어 `20260922-` 는 이 작업 묶음의 개시일로 **고정**한다(작성일이 아니다)
- `<내용>` 은 무엇에 대한 것인지 사람이 읽고 알 만큼 쓴다

## 2. 진행 방식

```
감리        지시NN 파일 작성
            ↓
개발팀장    이 폴더에서 아직 수행결과가 없는 가장 높은 번호의 지시를 찾아 수행
            → 지시NN수행결과 파일 작성 (캡처 포함)
            ↓
감리        수행결과를 검산 → 승인이면 지시NN+1, 반려면 지시NN수행결과02 를 요구
```

- **개발팀장은 착수 전 이 폴더를 `ls` 하라.** 가장 최근 지시와 그에 대응하는
  수행결과의 유무가 지금 무엇을 할 차례인지 말해 준다
- 승인 없이 다음 지시 번호로 넘어가지 마라. 지시 안의 STEP 게이트도 같다
- 이견·선택지는 수행결과 파일에 쓴다. **Chief 에게 직접 선택을 요청하지 마라**

## 3. 이 작업의 고정 규칙

- `git commit` · `git push` **금지** (`.cursor/rules/github-push-after-work` 의
  「푸시 금지 명시」 예외에 해당한다). 커밋은 승인 후 별도 지시한다
- 감리 수치는 **코드를 고치기 전에** 개발팀장이 다시 잰다. 다르면 반증을 먼저 보고
- **assert PASS 는 합격이 아니라 최소 조건이다.** 수치가 맞아도 그림이 틀리면 실패다
- 이미지는 **폴더 경로를 통째로** 준다 (`.out` 은 gitignore 라 파일 링크가 안 열린다)

## 4. 현재 파일

목록을 여기 고정하지 않는다 — **폴더를 `ls` 하라.** `Chief원안` 은 요구의 기준이고,
`지시NN` 중 대응하는 `지시NN수행결과` 가 없는 가장 높은 번호가 지금 할 일이다.

- **감리**: `*수행결과*` 를 감시 → 검산 → 다음 지시. Chief 호출 불필요.
- **개발팀장**: `node scripts/ops-relay/poll-next.mjs document/ops/20260922-new_camera`
  → `NEXT` 이면 **즉시 착수**(Chief 「계속」 대기 금지). 스킬 `.claude/skills/ops-relay/`,

## 6. 감리가 지키는 것 (2026-09-23 Chief 질책 후 신설)

> 「개발팀장은 뭘 한 것처럼 얘기하는데 화면상으로 확인해보니 바뀐 게 하나도 없다.
>  그런데 너는 뭘 감리하고 있는 거냐」

- **한 라운드 = 화면 변화 한 번.** 조사·승인만 하는 문서 라운드를 연달아 돌리지 않는다
- 수행결과를 읽기 **전에** 감리가 먼저 `git diff --stat -- apps/web/src` 를 본다.
  **0줄이면 보고 내용과 무관하게 반려**한다
- 감리는 **개발팀장의 캡처로 판정한다** — 감리가 앱을 직접 띄우지 않는다(토큰 절약, Chief 지시
  2026-09-23). 그러므로 **캡처 목록을 지시서가 미리 못 박고**, 빠지면 반려한다
