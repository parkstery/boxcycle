## 11-20 3D 주행 FPS 후보 비교

수행 Codex. Mapbox GL JS 3.23.1에서 `jumpTo`와 `setFreeCameraOptions`는 각각 move/zoom 계열 이벤트를 발생시킨다. 이벤트가 지도 갱신을 예약하면 같은 렌더 전에 들어온 두 요청은 한 프레임에 합쳐진다. FreeCamera는 지형 레이캐스트로 중심과 줌을 다시 계산한다.

독립 검수는 Edge에서 GTX 1660, CSS 1580×794, 버퍼 1911×960, Outdoors·Terrain-RGB 1.3배·경로선 조건으로 실행했다. 생산 카메라 추적을 사용했고, 라이더가 계속 그려지는 경우를 모사해 매 rAF에서 repaint를 요청했다. GPU 타이머는 지도 렌더 4회당 1회 표본이다. 각 후보는 10초, FPS는 rAF 간격의 역수다. 지도 호출 시간과 GPU 시간은 겹칠 수 있다. 앞선 `controlled-render.json`은 강제 렌더, 이번 표는 독립 장면에서의 rAF이며 전체 주행 앱과는 별도다.

| 장면 · 후보 | 평균 FPS | 프레임 p95 ms | 지도 평균 / p95 ms | GPU 평균 / p95 ms |
|---|---:|---:|---:|---:|
| QC2 5 km/h 기준 A/B | 20.4 / 20.6 | 70 / 70 | 48.1 / 64.9 · 47.5 / 65.5 | 26.2 / 35.8 · 25.7 / 36.3 |
| QC2 단일 FreeCamera 적용 | 22.8 | 60 | 42.8 / 55.1 | 24.2 / 34.1 |
| QC2 거의 같은 자세 생략 | 23.3 | 60 | 41.6 / 56.9 | 23.9 / 29.5 |
| QC2 30 Hz | 23.3 | 60 | 42.1 / 53.5 | 22.8 / 31.5 |
| QC2 20 Hz | 35.9 | 50.1 | 27.0 / 51.0 | 9.1 / 25.7 |
| 정지 기준 | 21.5 | 60 | 45.7 / 55.1 | 26.0 / 30.6 |
| 정지 · 거의 같은 자세 생략 | 97.7 | 10.1 | 5.4 / 7.5 | 3.1 / 3.8 |
| QC3 25 km/h 방향 변화 기준 | 12.5 | 110 | 74.9 / 99.5 | 35.9 / 49.1 |
| QC3 30 Hz | 12.9 | 110.1 | 75.4 / 108.3 | 37.2 / 57.8 |
| QC3 20 Hz | 13.3 | 100 | 72.9 / 95.7 | 35.1 / 49.9 |

- 단일 적용은 검수 전용으로 복제한 Transform에서 명목 구도와 지형 보정을 계산하고 최종 FreeCamera를 라이브 지도에 한 번 적용했다. 기준 지도 렌더당 약 7회의 갱신 요청을 약 4회로 줄였다. 위치 오차는 해당 표본에서 0.001 mm 미만이었고, 두 카메라 호출의 평균 합계는 약 0.5~0.7 ms였다. 호출을 하나 줄인 뒤에도 매 프레임 지형·소스 및 라벨 배치 처리가 남았다. QC2 기준의 라벨 배치 평균은 15.2~16.5 ms, painter render 평균은 27.5~29.1 ms였다.
- 자세 생략은 검수에서 최종 카메라 위치 1.5 cm, pitch·bearing 0.04°, 줌 0.005 이내를 사용했다. 정지 때 978회 중 971회를 생략했고, 5 km/h에서는 233회 중 10회를 생략했다.
- 20 Hz에서 QC2 실제 카메라 적용은 10초당 196회였다. 평균 화면 FPS가 올랐지만 카메라 위치가 달라지는 간격 p95는 70 → 80 ms, 투영된 라이더 기준점의 세로 범위는 약 2.9 → 7.1 CSS px였다. 카메라 이동이 없는 화면 프레임과 다음 이동이 교차하는 것을 계측으로 확인했다. QC3 방향 변화 구간에서는 기준부터 카메라 적용이 약 13회/초라 상한으로 줄이는 효과가 작았다.
- ego-browser 작업 공간 37에서 약 1초 간격의 rAF 제한이 발생한 회차는 성능 판단에서 제외했다. 편차를 피하기 위해 별도 로컬 Edge에서 같은 장면을 실행했다. 원시 자료와 실행 스크립트는 `tmp/terrain-perf/camera-candidates-edge.json`, `tmp/terrain-perf/run-edge.mjs`에 있다.

로컬 앱은 Firebase 에뮬레이터에서 게스트로 진입해 서울 남산공원길을 수동 5 km/h로 달렸다. Edge GTX 1660·같은 화면 크기, QC2, 개발 빌드 `?perflab=1`, 지형 1.3배·건물 표시 조건으로 첫 10초 계측 창을 비교했다. 20 Hz 프로토타입은 Playwright가 검수 브라우저에만 주입했고 follow pose 적용 앞에서 제한했다.

| 로컬 앱 · 입력 5 km/h | 평균 FPS | 프레임 p95 ms | 지도 평균 / p95 ms | GPU 평균 / p95 ms |
|---|---:|---:|---:|---:|
| 3D 기준 | 5.1 | 249.9 | 148.2 / 179.3 | 60.1 / 77.1 |
| 3D 20 Hz | 5.0 | 250.1 | 149.7 / 189.0 | 60.7 / 81.8 |

20 Hz는 64회 적용, 0회 생략이었다. 앱에서 프레임이 50 ms보다 훨씬 늦게 돌아와 적용 횟수가 줄지 않았다. 수동 3D OFF는 주행을 이어 가면서 바꾼 값이다. 사용자 실센서 주행의 FPS는 재현하지 않았으며, 로컬 에뮬레이터 수치는 해당 입문 코스의 모의 입력 결과다.

판정은 제품 변경 0건. 단일 적용은 소폭 개선했지만 30 FPS에 미달했고, 정지 자세 생략은 이동 중 생략률이 약 4%였다. 20 Hz는 독립 QC2 장면에서 30 FPS를 넘겼으나 앱 병목을 줄이지 못했고 독립 장면의 카메라 정지 간격도 늘었다. 다음 담당 Codex는 같은 앱 장면에서 지형을 유지한 채 라벨 배치와 지형 위 레이어 그리기 비용을 분리한다.

### 제품 반영 · 제자리 레이어 이동 생략

앱 시작부터 실제 순서를 기준으로 제자리 이동을 줄이고 양쪽 모두 경로 선택 후 7초 기다린 검수에서, 기준은 주행 전 idle 0회·초기 로드 유지였다. 후보는 주행 전 idle에 도달하고 초기 로드 종료를 확인했다. Setters나 fade 값을 덮어쓰지 않은 A/B에서 주행 중 강제 전체 배치 51/51 → 0/58프레임, 라벨 배치 34.1 → 5.0 ms, FPS 5.06 → 5.76, 프레임 p95 269.9 → 229.9 ms였다. 후보의 새 배치 완료는 7회였다. 원본 `prod-tiles-*-placement-idle.json`. 7초는 비교용 대기이며 앱 변경에 포함하지 않았다.

후보의 판정 가능한 130프레임 모두에서 앱 소스 6개의 선 값은 같았고 Outdoors 베이스맵 `other:composite`의 선 값은 달라졌다. 첫 프레임은 비교에서 제외했다. 앱 소스의 타일 무효화 요청 32,576건을 생략했어도 베이스맵은 측정 132프레임 모두에서 갱신 대상으로 기록됐다. 소스별 동일 값으로 좁힌 후보 역시 30 FPS와 지형 타일 재사용 목표에 미달했다. 각 1회이므로 평균 FPS 차이의 재현성은 확인하지 않았다.

### 11-21 기존 지도 스타일의 3D 비교

실험용 소스 갱신과 선 캐시 변경을 모두 끈 같은 앱 빌드에서 기본 Outdoors와 기존 주행 버튼으로 전환한 Standard 낮을 비교했다. 첫 Standard 실행은 지도 전체 `isStyleLoaded()`를 요구하는 검수 조건에서 35초 초과로 실패했다. 재시험은 실제 Standard 낮 설정, 3D 건물 옵션과 1.3배 지형 렌더러를 확인해 통과했다. 첫 계측의 시작 중심 위치는 약 20m 달랐다. 동일 위치 비교에서는 시작 중심 차이가 약 0.8m였다. 같은 GTX 1660·QC2·수동 5 km/h로 주행했고 전체 계측의 지형 배율은 1.3이었다.

### 11-22 변경된 베이스맵 선의 타일별 렌더 데이터

수행 Codex. 남산공원길, QC2, 수동 5 km/h, Edge GTX 1660, 800×360/DPR 1.5, Outdoors, 지형 1.3배에서 기존 선 값 계측을 확장했다. 두 회차 모두 비교 가능한 경우에 한해 앱 소스의 동일 선 값 무효화 및 변경 없는 주행선 콜백 무효화를 생략했다. 두 회차에서 동일하게 베이스맵 선 폭·발광 값이 바뀐 레이어를 고르고, SDK의 선 그리기가 사용하는 소스 타일의 렌더 데이터 버킷을 조회했다. 후보는 로드된 타일에 해당 레이어의 렌더 데이터가 전혀 없는 경우에만 선 캐시 무효화를 생략하도록 구성했다.

### 11-22 지형 그리기 안의 레이어별 CPU 시간

기본 1024×1024, 같은 시작 위치, 기존 Outdoors의 계측 장면에서 SDK의 `renderLayer` 진입을 레이어별로 합산했다. 123프레임 동안 지형 그리기 CPU 경과 시간은 평균 40.9 ms, 그 안의 레이어 호출에 들어간 시간은 평균 34.8 ms였다. CPU 측정은 JS에서 호출 전후를 재며 드라이버 대기와 계측 비용도 포함될 수 있다. GPU 타임이나 이전 두 회차의 FPS와 합산하지 않는다.
