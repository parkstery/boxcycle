## 원인과 범위

App.tsx 867 부근 effect가 active→idle 시 persistedRecentNewRoadGeometry(신규 서버 문서가 없으면 [])로 덮어쓴다. handleRecentConquestResult positive는 ref만 갱신하고 state를 안 바꾼다. 새로운 recentNewRoad/current Functions/Rules 변경이 미배포인 환경에서도 표시가 작동해야 한다.

허용: apps/web/src/App.tsx 신규 도로 상태 부분, hooks/useConquest.ts, lib/conquest/repo/firestoreConquest.ts, lib/conquest 내 작은 순수 상태/geometry 모듈과 scripts/conquest 회귀시험. 서버·Rules·계정·주행 저장·기존 스타일 변경 금지. 필요 시 최소 관련 계약시험 수정.

## 구현 완료 조건

1. 주행 종료 직후 후보를 지우지 않고 보존. 양수 서버 결과 newGeometry가 있으면 권위값으로 교체, 없으면 종료 시점 후보를 newMeters 한도 내로 보존. 같은 KST 날짜의 이전 주행은 합치고 다른 날짜는 교체. 중복 콜백은 중복 추가 금지. zero/error/timeout은 해당 후보만 제거하고 이전 최신 날짜 내역 보존. 새 주행·결과창 닫기·지연된 persisted snapshot에서도 확정된 당일 이전 주행을 잃지 않게 한다. 계정 전환은 이전 geometry 노출 방지.
2. 구버전 서버/Rules에서도 새로고침 후 최신 취득일 도로 복원이 필요하다. 기존 conquest chunks.cells[id]=YYYYMMDD + traces.path/day 읽기를 재사용(추가 전체컬렉션/ride query 없이). 최신 유효 취득일을 찾고 그 날짜 trace의 경로 조각 중 해당 날짜 소유 셀인 조각만 강조 후보로 복원. 전체 trace를 신규로 표시 금지. 날짜 없는 trace/잘못된 날짜는 무시. 최신 서버 recent 문서가 있으면 같은/최신 날짜의 권위값 우선, 늦은 이전 날짜가 로컬 최신을 덮지 않게 한다. 기존 함수 loadConquestCellIds 공용 API 유지(내부 추가 함수 허용). 데이터 모델/Rules 수정 금지, 기존 read 예산 내 처리.
3. 순수 helper만 시험하지 말고 React hook/state의 active→idle→late snapshot→positive→다음 주행 전환을 실제 실행하는 회귀시험 추가. 미배포 문서 null, 같은 날 2회, 다음 날, zero/error/timeout, stale snapshot/계정전환, mixed old/new geometry 복원 검증.
4. 현재 기존 도로/마젠타 강조 스타일 유지. 과거 기록은 셀 해상도 기반 복원임을 결과에 명시.

검증: 관련 conquest/map/ride-result 시험, npm run build, npm run lint, git diff --check. 명령/종료코드/통과수/미검증 구분을 03-result-01.md에 기록. 실패 숨기지 말 것. 서버 미배포를 빌드 성공으로 검증했다고 보고하지 말 것.
