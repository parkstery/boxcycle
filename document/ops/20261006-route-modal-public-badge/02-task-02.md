## 현상 (Chief, 실기 확인)
내 경로 → 경로 선택 → 「공개」 클릭: 퍼블릭 등록 창이 **내 경로 창 뒤**에 뜨고 내 경로 창이 남아, 닫기를 따로 눌러야 등록 창이 보인다.

## 요구
1. 「공개」 클릭 → 내 경로 창이 **자동으로 닫히고** 퍼블릭 등록 창이 바로 보인다.
2. 퍼블릭 등록 창에서 **취소**(「취소」 버튼, 바깥 오버레이 클릭, ✕/Esc가 있으면 그것도) → **내 경로 창이 다시 열린다**.
3. **등록 성공** 시에는 내 경로 창을 다시 열지 않는다(종전 동작 유지).

## 구조 (Supervisor 조사 결과)
- 등록 창 상태는 App 이 소유: `App.tsx` ~3029 `onOpenPublicRequest={(route) => setPublicRouteRequestModalRoute(route)}`, ~3185 `<PublicRouteRequestModal onClose=... onSubmit=...>`. 상태 훅 `hooks/usePublicRouteReviewMeta.ts`.
- `PublicRouteRequestModal.tsx`: 성공 경로(~102)도 `props.onClose()` 를 부른다 → **취소와 성공이 같은 콜백**이라 구분이 안 된다.
- 내 경로 창 열림 상태: `RideRoutePanel.tsx` `savedModalOpen`. 기존 `openSavedTabSignal`(nonce) 은 열면서 **「대기」 필터를 강제**한다(쿼터 유도용) — **재사용 금지**.

## 구현 지침
- 요구 1: `SavedRoutesModal.tsx` 에서 `onLoadRoute` 와 같은 패턴으로 `onOpenPublicRequest` 를 감싸 `panel.onOpenPublicRequest(route); onClose();`. prop 이 undefined 면 undefined 그대로(게스트 비활성 버튼 판정 유지).
- 요구 2·3:
  - `PublicRouteRequestModal` 에 선택 prop `onCancel?: () => void` 추가 — 취소 버튼·오버레이·Esc 는 `onCancel ?? onClose`, 성공 경로는 지금처럼 `onClose`.
  - `RideRoutePanel` 에 선택 prop `reopenSavedSignal?: number` 추가 — 값이 바뀌고 >0 이면 `setSavedModalOpen(true)` (필터 강제 없음). 기존 `openSavedTabSignal` 처리와 같은 「이전 값 비교」 패턴 사용(effect 금지 — 주석 참조).
  - App: nonce state 하나, 등록 창 `onCancel` 에서 등록 창 닫기 + nonce 증가 → `reopenSavedSignal` 로 전달.
  - 다시 열린 내 경로 창의 선택·필터·스크롤 복원은 **범위 밖**(초기 상태로 열려도 됨).
- 각 변경에 이유 주석 한 줄(2026-10-06 Chief).
