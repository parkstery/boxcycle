### 2-1. 실패 내역 — 4위상이 **전부 같은 값**이다

```
phase   side   기울기      gap
0       l       8.86°     0.5mm
0       r      54.40°   −11.1mm
0.25    l       8.86°     0.5mm      ← 위상이 달라도 동일
0.25    r      54.40°   −11.1mm
0.5     l       8.86°     0.5mm
0.5     r      54.40°   −11.1mm
0.75    l       8.86°     0.5mm
0.75    r      54.40°   −11.1mm
```

**이것이 진단의 핵심이다.** 위상이 바뀌어도 값이 변하지 않는다는 것은
**상쇄가 정확히 작동한다**는 뜻이다 — 발이 정강이 회전과 무관하게 **기준 자세를
유지**하고 있다. 유도(`R_ankle = (R_leg·R_shin)⁻¹·(R_leg0·R_shin0)`)는 옳았다.

**틀린 것은 전제다.** 나는 *"분해 시점(phase 0.000)에 발바닥이 페달면과 평행하다"* 고
가정했는데, **그 기준 자세에서 이미 왼발 8.86° · 오른발 54.40° 기울어 있다.**

### 2-2. 좌우 편차 45.5° — 여기가 원인일 가능성이 높다

왼발 8.86° 는 오차 수준이지만 오른발 54.40° 는 다른 종류의 문제다. 두 후보:

1. **분해 기준 위상과 앱 IK `phase 0` 의 좌우 대응이 어긋났다.**
   앱 `phase 0` 은 **왼발 BDC · 오른발 TDC** 다. Blender 분해는 `PHASE = "0.000"` 에서
   했는데, `BONE_OF` 좌우 반전(`L→R`)이 걸려 있어 **한쪽만 맞고 반대쪽은 180° 어긋난**
   기준을 쓴 것으로 보인다(왼발만 거의 맞는 것이 그 증거다).
2. **발바닥 법선을 "발 로컬 −Y" 로 가정한 것이 부정확하다.**
   실측하니 밑창 최저 정점이 왼발 x −32…−23, 오른발 x 0…15 로 **뒤꿈치에만 몰려 있다**
   (F25 §4-1 에서도 같았다). 발바닥은 평평하지 않고 뒤꿈치가 가장 낮으므로,
   로컬 −Y 를 법선으로 쓰면 실제 접지면과 다르게 잰다.

**둘 중 무엇인지 확정하지 못했다.** 확정하려면 분해 시점의 발 world 자세를 Blender 에서
직접 찍어 앱 IK phase 0 과 대조해야 한다 — 게이트 실패로 중단했으므로 하지 않았다.

## 4. 발목 회전 유도 과정 (§5 요구)

```
ankle 은 leg_*_shin 의 자식. 라이더 노드는 rest 가 제거돼 순수 translation 이므로(F21)
Mapbox 누적 규칙에서 회전만 곱해진다:

    global(ankle) = R_leg · R_shin · R_ankle

메시는 분해 시점(phase 0.000)의 자세로 구워졌다. 그 자세를 유지하려면

    목표   global(ankle) = R_leg0 · R_shin0
    따라서 R_ankle = (R_leg · R_shin)⁻¹ · (R_leg0 · R_shin0)      (직교 → 역 = 전치)
```

조립·분해는 F22 규약 `R = Ry(e[1])·Rz(e[2])·Rx(e[0])` 그대로. `riderIk.mjs` 에
`mat3ToMapboxEulerDeg` · `mapboxEulerDegToMat3` · `mat3Mul` · `mat3Transpose` 를 추가했다.

**부호는 추측하지 않았다** — 게이트 8·9 가 판정하도록 두었고, 그 결과가 §2-1 이다.
**유도는 맞고 기준이 틀렸다**는 것이 게이트가 알려준 사실이다.

## 6. 반증·이견

### 6-1. 【반증】 "본체 5,521 불변" 은 성립하지 않는다 — **5,513 이 맞다**

지시 §3 은 *"본체 5,521 불변(발이 이동할 뿐)"* 을 합격 기준으로 뒀다. **실측 5,513.**

소스 정점은 **5,477 로 완전히 불변**이고(inflation 1.000), 차이 8 은 **glTF exporter 가
UV·노멀 경계에서 정점을 쪼개는 수**가 노드 구성에 따라 달라진 결과다. 발이 정강이에서
분리되며 파트 경계가 재편됐으니 이 수는 바뀔 수밖에 없다. **부풀림이 아니다**(5,521→5,513 은
오히려 감소). 게이트 기대값을 5,513 으로 갱신했다.

### 6-2. 【판정식 교정】 `remap-palette-uv` 의 "고유 텍셀 ≥ 2" 기준

발이 분리되며 **정강이가 맨살 단색**이 돼 텍셀 1개가 됐고, 기존 assert 가 FAIL 을 냈다.
그러나 원래 잡으려던 결함은 *"팔레트가 아닌 세트 0 의 UV(0,1) 한 점에 전부 몰림"* 이다.
판정식을 **"교체 후 UV(0,1) 잔존 금지"** 로 바로잡았다 — **허용치 완화가 아니라
판정 대상 교정**이다. 근거를 스크립트 주석에 남겼다.

### 6-3. 【자기신고】 회전 이중 적용을 한 번 냈다

이번 분해는 **새 joints(HIP −149.66, 844.52)** 로 했으므로 산출물이 이미 최종 위치인데,
습관대로 `rotate-rider-nodes --deg 5` 를 태워 **62.09mm 어긋났다.** 게이트 5 가 즉시
FAIL 로 잡았고 `--deg 0`(어깨 지정만)으로 고쳤다. **게이트가 없었으면 그대로 올렸을 것이다.**
