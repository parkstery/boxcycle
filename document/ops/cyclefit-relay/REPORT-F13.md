## 6. 이견

### 6-1. 페달축 48.8% — 기준(49~51%)을 0.2%p 밑돈다

원인은 §11 에 이미 "미뤄둔 항목"으로 있는 **접점 밴드 centroid 어긋남**(F11 §8-1)이다.
접점 본이 목표보다 17.6mm 뒤에 잡히면서 비율이 0.2%p 내려간다.
**수평 실측은 좌 3.2 / 우 2.7mm** 로 실질 오차는 F12(2.5/3.4)와 같은 수준이다.
밴드 윈도우를 ±8% → ±3% 로 좁히면 개선되나 §11 범위라 손대지 않았다.

### 6-2. **`ANKLE_UP` 은 37.0 을 유지했다 — 감리 34.8 에 반대한다**

감리 §4-2 는 발목~발바닥이 22.0 → 19.8 로 줄어든다고 봤다. **실측은 22.0 불변이다.**

```
축소 후 rest 실측:  밑창 z 85.01 (고정면, 이동 0.000mm)
                    발목 z 107.01 (본 — 스케일 대상 아님)
                    → 발목~밑창 = 22.0  (F12 와 동일)
```

근거 셋:

1. **사용자 지시가 "바닥면을 기준으로"** 다. 밑창이 고정면이면 그 위 메시만 내려온다.
   발목은 밑창 위 22.0 에 그대로 있다.
2. **발목은 신발이 아니라 다리 IK 관절**(`SHIN` tail)이다. 신발과 함께 줄이면
   정강이 길이가 바뀌어 "정강이 400 불변"(§9)이 깨진다.
3. `ANKLE_UP` 의 정의는 "발목→밑창 + 클릿 15.0" 이고, 앞 항이 22.0 이므로 **37.0** 이다.

이 판단 때문에 BDC 무릎이 감리 예상 22.7° 가 아니라 **24.30°** 가 됐다(표준 25~35° 에
0.7° 미달). **다르게 판단하시면 `ANKLE_UP` 34.8 로 재실행하겠다.**

### 6-3. 밑창 각도가 12.3° 로 커졌다 — 신발 단축의 필연

접점이 발목 앞 93.03 → 80.20 으로 당겨지면서 발목→접점 축이 10.3° → 12.3° 로 선다.
밑창–페달 접점은 유지되지만 뒤꿈치가 더 들린다. `ANKLE_UP` 을 낮춰도 축 각도는
`atan(CONTACT_DROP / ANKLE_BACK)` 이라 **바뀌지 않는다**(높이만 내려간다).
평평하게 하려면 접점 정의나 발 pitch 를 따로 다뤄야 한다 — 지시 범위 밖이라 보고만 한다.

1. **손가락 그립 미구현** — 본이 없어 원리적으로 불가능(§4). 조사만 보고.
2. **페달축 48.8%** — 기준 49~51% 를 0.2%p 밑돎(§6-1).
3. **밑창 각도 12.3°** — "페달 상면에 평평" 기준을 문자대로는 충족하지 못함(§6-3).
4. **BDC 무릎 24.30°** — 표준 25~35° 에 0.7° 미달. 엉덩이 보정 금지라 그대로 뒀다.
5. **안장 물리적 불가능(§2)은 그대로** — 결정 대기 중이므로 렌더에 계속 나타난다.
6. **렌더를 3회 반복했다** — ① 비교안 배율이 1.0 으로 계산되는 버그(이미 연장된 상완을
   기준으로 삼음) ② 팔 각도선이 라이더 뒤편에 그려져 안 보임. 둘 다 스스로 잡았으나
