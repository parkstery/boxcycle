## 1. 감리 진단

### 1-1. 【2】 관절 캡이 없다 — 옛 라이더에는 있다

제품 GLB 와 옛 절차적 라이더를 파싱해 대조했다.

```
옛 절차적 라이더 (관절마다 구형 캡을 자식으로 달고 있다)
   leg_l       100×100×100 (고관절)   86×86×84 (무릎)
   leg_l_shin   72×72×70   (무릎)     52×52×52 (발목)
   arm_l        60×60×60              arm_l_fore  60×60×60

현재 제품 (V2 강체 분해)
   leg_l · leg_l_shin · arm_l · arm_l_fore  →  **본체 메시 1개씩. 캡 0개**
```

**강체 분해는 본체만 잘라 붙였고 관절 채움이 없다.** 그래서 두 세그먼트가 각도로 만나
실루엣에 꺾인 자국만 남고 **관절이 없는 막대처럼 보인다.** 사용자 지적 그대로다.

이건 **664 정점 이음매(§7-4)와는 다른 문제**다. 이음매는 표면 연속성이고, 이건
**관절 부피 자체가 없는 것**이다. 캡을 넣으면 이음매 겹침도 상당히 가려진다.

### 1-2. 【3】 페달이 크랭크의 자식이라 함께 돈다

제품 GLB 실측 — `crank` 노드의 직계 자식 7개 중 **마지막 둘이 페달**이다:

```
crank(idx206) 자식
   … 크랭크암·스핀들 5그룹 …
   idx204  (무명)  mesh160  70×20×50mm     ← 왼 페달 플랫폼
   idx205  (무명)  mesh161  70×20×50mm     ← 오른 페달 플랫폼
```

**이름이 없어 `nodeOverrideNames` 에 넣을 수 없고, `crank` 회전을 그대로 물려받는다.**
실제 페달은 스핀들 베어링으로 자유회전하므로 **항상 수평**이다. 사용자 지적이 맞다.

**해법 — Mapbox 는 회전을 누적한다**(F21 확정, 번들 36066~36071). 페달 노드에
`−crankRotationDeg` 를 주면 부모의 회전이 **정확히 상쇄**된다.

```
global(pedal) = global(crank) × T(스핀들) × R(−crank)
              → 페달은 크랭크를 따라 공전하되 자세는 수평 유지
```

⚠ **성립 조건: 페달 노드의 원점이 스핀들이어야 한다.** 지금은 translation 이 없고
오프셋이 정점에 구워져 있어, 그대로 회전시키면 **제자리에서 돌지 않고 궤도가 틀어진다.**
→ 생성기에서 **노드 translation = 스핀들 위치, 메시는 그 원점 기준 로컬**로 내보내라.

## 2. 지시

### 2-1. 【1】 먼저 커밋한다 — 안전지점을 만들고 시작하라

F24 보고 §4 의 5분할 안을 **채택한다.** GLB 는 **4번에 한 번만** 넣어라(권고 채택).

```
1) fix(rider): 팔레트 UV 세트를 TEXCOORD_0 으로 재지정해 앱 색 복구 (F20)
2) fix(rider): GLB 노드 rest rotation·scale 제거 — 몸통 90° 어긋남·과대 해소 (F21)
3) fix(rider): 앱 IK 회전각의 y·z 성분 뒤바뀜 수정 — 팔다리가 실제로 움직인다 (F22)
4) feat(rider): 무릎 안쪽 교정 + 라이더 5° 전방 회전(안 B) 확정 (F23~F24)   ← GLB 포함
5) docs(ops): F20~F24 지시서·보고서
```

- **`.bak` 7개는 커밋하지 마라.** `.gitignore` 에 추가하되 **범위를 좁혀라** —
  `apps/web/public/rider/prototype/*.bak` (리포 전역 `*.bak` 금지)
- `.pre-F19.bak` 보존 권고 채택 — 지우지 마라
- **push 는 하지 마라.** 사용자가 커밋만 지시했다
- 각 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>` 를 넣어라
- **pre-commit 훅이 막으면 우회하지 마라**(`--no-verify` 금지). 그대로 보고하라

### 2-2. 【3】 페달을 수평으로 유지한다

**생성기(`generate-rider-prototype-glb.mjs`)에서 고쳐라.** 후처리 스크립트가 아니다 —
자전거는 SSoT 파생이므로 재생성 때마다 따라와야 한다.

1. 페달 플랫폼 메시를 **명명 노드 `pedal_l` / `pedal_r`** 로 내보낸다
   - **노드 translation = 페달 스핀들 위치**(크랭크 로컬), **메시 정점은 그 원점 기준**
   - 부모는 지금처럼 `crank`
2. `config.ts` `RIDER_GLB_NODE_OVERRIDE_NAMES` 에 두 이름 추가 (10 → **12개**)
   - feature-state 키 2개 신설 (`pedal-l-rotation` · `pedal-r-rotation` 규약 유지)
3. `glbModelLayer.ts` `model-rotation` match 에 2항 추가 + `setFeatureState` 에 2필드 추가
4. `pose.mjs` 가 **`[0, 0, −crankRotationDeg]`** 를 내보낸다
   - ⚠ 부호는 **렌더로 확인**하라. 상쇄가 맞으면 위상이 바뀌어도 페달면이 수평이다

**좌/우 크랭크는 180° 위상차**가 있다 — 두 페달 모두 같은 `−crankRotationDeg` 로
상쇄되는지 확인하라(부모 각도가 각각 다르면 각각 상쇄값이 다르다). **렌더로 판정하라.**

### 2-3. 【2】 관절 캡을 넣는다

**무릎 2개 · 팔꿈치 2개.** 고관절·발목은 이번 범위가 아니다(몸통·신발에 가려진다).

- 위치: `leg_l_shin` / `leg_r_shin` / `arm_l_fore` / `arm_r_fore` 노드의 **로컬 원점(0,0,0)**
  = 정확히 관절 위치다. 그 노드의 **자식**으로 붙여라
- 크기: **네가 실측해서 정하라.** 옛 라이더는 무릎 86/72mm · 팔꿈치 60mm 였다.
  V2 는 단면이 다르므로 **본체 메시의 관절부 단면 지름을 재서 맞춰라** —
  캡이 살보다 크면 혹처럼 튀어나오고 작으면 안 가려진다
- 색: 팔레트 텍스처를 쓴다. **무릎·팔꿈치 모두 맨살**이므로 UV 를 피부 텍셀
  `(0.0625, 0.5)` = `#bc9179` 로 찍어라(F20 remap 후 세트 0 기준)
- 형상: 저폴리 구(UV sphere 8×6 수준). **정점 예산을 크게 쓰지 마라**
- 구현: `apps/web/scripts/rider-cycle-fit/add-joint-caps.mjs` **재현 가능 스크립트**로
  만들고 파이프라인 순서에 넣어라. **Blender·메시 재분해 금지**

⚠ **정점 수 게이트(5,521)가 바뀐다.** 캡 정점만큼 늘어나는 것이 정상이니
**게이트 기대값을 "5,521 + 캡 정점"으로 갱신하고, 캡 정점 수를 로그로 찍어라.**
본체 5,521 은 그대로여야 한다 — **본체와 캡을 분리해 세라.**

### 2-4. 【4】 이번엔 고치지 말고 **재판정 자료만** 만들어라

페달이 수평이 된 뒤 발–페달이 어떻게 보이는지가 4 의 출발점이다.

- **발–페달 접점 클로즈업** 4위상 각 1장 (측면). 신발 밑창과 페달면이 보이게
- 가능하면 **수치**: 페달면 상단 y 와 신발 밑창 최저 y 의 차(mm), 4위상
- **네 소견**: 남은 어긋남이 (a) 발목 각도 부재인지 (b) 접점 오프셋 값 문제인지
