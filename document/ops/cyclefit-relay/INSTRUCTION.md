## 0. 【중대 정정】 "안장이 물리적으로 불가능하다"는 **틀렸다**

F12 부터 다섯 단계에 걸쳐 "안장을 좌골에 맞추면 시트튜브 상단보다 76.9mm 아래라
불가능하다"고 판단해 왔다. **그 판단이 틀렸다. 사용자가 자전거 렌더를 보고 잡아냈다.**

> 사용자: *"시트튜브를 더 줄일 필요가 뭐가 있지? 시트포스트로 조절하면 높이 조절
> 범위는 얼마든지 좌골에 맞출 수 있을 텐데.. 감리나 개발팀장이 자전거 모델을 이
> 최종 모델이 아닌 **다른 예전 자전거를 건드리고 있을지도 모른다**는 생각이 들어."*

### 0-1. 원인 — `coords.seatTop` 은 **그려지지 않는 유물 필드**다

`generate-rider-prototype-glb.mjs:300-304` 가 명시하고 있다:

```js
// F4-2 이후 **메시로는 그리지 않는다**(시트튜브가 junction 에서 끝나므로).
const seatTop = [...RIG_SEAT_TOP, 0];
void seatTop;   // 메시 미사용 — SSoT 대조·디버깅용으로 보존
```

**실제로 그려지는 시트튜브는 junction 에서 끝난다.** F4-2 에서 사용자가
*"시트튜브 길이는 연결부위까지, 그 이후는 모두 시트포스트"* 로 확정한 그대로다.

```
시트튜브 실제 끝(junction) = (560 − 150) × sin 73.5°  =  y(BB) 393.1
안장 (saddleHeight 479.8)                            =  y(BB) 460.0
                                                        ─────────
                                             노출 시트포스트 66.9mm  ← 정상
```

**안장은 시트튜브 끝보다 66.9mm 위에 있다. 처음부터 문제가 없었다.**
`seatTop` 536.9(= 560 × sin 73.5°)는 F4-2 **이전**에 시트튜브를 560 까지 그리던 시절의
잔재이고, 우리는 **존재하지 않는 튜브와 안장을 비교**하고 있었다.

### 0-2. 책임

당신이 F12 §0-1 에서 이 결론을 올렸고, 감리가 F12·F16·F17 세 번 "독립 확인"했다고 했다.
**셋 다 같은 유물 필드를 봤다.** 감리는 직전 F17 지시서에서 멀쩡한 프레임의 시트튜브를
560 → 450 으로 줄이라고까지 했다 — 사용자가 안 잡았으면 최종 승인 프레임이 훼손됐다.

**이번 정정으로 시트튜브 단축 지시는 전면 철회한다.**

## 2. F17-R1 지시

### 2-1. 프레임은 **최종 모델 그대로** — 한 글자도 바꾸지 마라

| 항목 | 값 | |
|---|---|---|
| `seatTubeLength` | **560** | **불변** (F17 의 450 지시 철회) |
| `SEAT_TUBE_SHORTENING` | 150 | 불변 → junction y 393.1 |
| `seatTubeAngle` | 73.5 | 불변 |
| `saddleSetback` | 20 | 불변 |
| `headTubeLength` · `stack` · `reach` · `crankLength` · `headBot` | | **전부 불변** |

**바꿀 수 있는 것은 `saddleHeight`(= 시트포스트 길이) 하나뿐이다.**

### 2-2. 【1단계】 좌골 높이를 확정하라 — 정의가 갈린다

F12 §4-3 에서 당신이 이미 지적한 모호성이다. **이번에 확실히 정하라.**

| 정의 | 좌골 높이(지면) | `saddleHeight` | 포스트 노출 |
|---|---|---|---|
| 밴드 centroid (F12 채택, 현재값) | 730.5 | **479.8** | 66.9mm |
| 골반 메시 최하점 | 682.3 | **429.5** | 18.7mm |

**둘 다 프레임에 들어간다.** 문제는 "어느 쪽이 실제로 앉은 것처럼 보이는가"다.

- 밴드 centroid(730.5)를 쓰면 **가랑이 부분이 안장을 48mm 관통**한다(F12 §4-3)
- 메시 최하점(682.3)을 쓰면 관통은 없으나 좌골이 안장에 **얹히지 않고 스칠** 수 있다

**판정 기준은 그림이다**(§3). 두 값으로 각각 렌더해 비교하고, **어느 쪽이 자연스러운지
근거와 함께 제안하라.** 필요하면 그 사이 값도 좋다.

### 2-3. 【2단계】 파생 방향을 뒤집어라 — **이게 이번 작업의 본체다**

`apps/web/src/lib/riderPrototype/riderRig.geometry.mjs` 는 지금 **안장이 엉덩이를 정한다**:

```
PELVIS_ROOT = SADDLE_CONTACT + (0.015, 0.06, 0)      ← 사람이 자전거에 맞춰진다
```

사용자 원문(F17): *"힙 높이를 정하고 그 높이에 맞춰서 안장이 놓이도록 시트포스트 길이를
조절하는게 기본적인 자전거 높이 조절 컨셉인데 그걸 사람이 자전거에 맞춘다는게 말이 되나!"*

**뒤집어라:**

```
HIP (−211.28, 836.88) 지면      ← 1차 입력. 라이더 자세가 정한다(F12 확정)
  ↓ 좌골 오프셋 (메시 실측, §2-2 에서 확정)
좌골 높이
  ↓ = 안장 접촉점 높이
  ↓ seatTubeAngle 73.5° · saddleSetback 20 (불변)
saddleHeight (= 시트포스트 길이)   ← 파생
```

- 하드코딩 복제 금지. **SSoT 한 곳**에서 파생
- `geometry.json` 의 `$note_saddle` 파생식 주석도 새 방향으로 갱신
- `generate-rider-prototype-glb.mjs` 와 `riderGlbPedalPose.pose.mjs` 가 같은 SSoT 를
  import 하므로 **함께 따라와야 한다**(F16 §5-1 확인 완료)

### 2-4. 【3단계】 `coords.seatTop` 유물을 정리하라

**이번 사고의 직접 원인이다.** 메시에 쓰이지 않으면서 판단을 오염시켰다.

- 제거하거나, **junction 기준으로 재정의**하거나, 최소한 필드 옆에
  **"메시 미사용·판정에 쓰지 말 것"** 을 `$note` 로 명시하라
- `riderRig.geometry.mjs` 의 `RIG_SEAT_TOP` 도 같이 처리
- **어느 쪽을 택했든 근거를 보고하라**

## 3. 합격 기준 — **그림이 최종 판정이다**

| 항목 | 기준 |
|---|---|
| **엉덩이가 안장에 얹혀 보인다** | 뜨지도, 파묻히지도 않는다 — **렌더로 판정** |
| **시트포스트가 보인다** | junction 위로 노출된 포스트가 그림에 있다 |
| 안장 상면 − 좌골 | **±2mm** |
| 파생 방향 | HIP → 좌골 → 안장 → `saddleHeight`. 역방향 파생이 남아 있으면 실패 |
| 프레임 | `seatTubeLength` 560 등 §2-1 **전부 불변** (`git diff` 로 증명) |
| 발접촉 4위상 | 좌·우 0.0mm 유지 (안장이 바뀌어도 발은 페달에) |
| BDC 무릎 | 25.93° 유지 |
| assert 4종 | 전부 PASS |

**수치가 맞아도 그림에서 엉덩이가 안장에 안 얹혀 있으면 불합격이다.**
