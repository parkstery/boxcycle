## 1. 감리 진단 — 원인을 특정했다

감리가 제품 GLB 를 직접 파싱해 확인한 것이다. **추측이 아니다.**

### 1-1. 【진짜 원인】 메시가 3.1배로 부풀었다

```
원본 V2 라이더        5,477 정점
제품 GLB 라이더 9노드 합계  16,983 정점     ← 3.1배
  torso 9,873 · arm_*_fore 1,544/1,540 · leg_*_shin 901/904 · …
```

**당신 F16 보고서는 "정점 5,477 전수 배분"이라고 했는데 실물은 16,983 이다.**
보고와 산출물이 다르다.

3.1배는 **인덱스 공유가 깨져 삼각형마다 정점이 독립**된 수치다(≈ ×3).
분해 과정에서 메시가 non-indexed 로 재구성되면서 **UV·노멀이 재생성**됐다.

### 1-2. 그래서 색이 뭉갠다

V2 라이더는 **머티리얼 1개 + 128×16 팔레트 아틀라스**로 색을 낸다(원본 확인).
저지·팬츠·피부·신발이 전부 **UV 좌표로 팔레트 텍셀을 찍어** 나온다.

```
팔레트 128px 에 색이 20여 개  →  색 하나가 약 6px
```

**UV 가 6px 만 어긋나도 옆 색으로 새거나 경계에서 뭉갠다.** 정점이 3배로 재생성되는
과정에서 그 정밀도가 깨졌고, 결과가 **전신 살색 단색**이다.

> 참고: 옛 절차적 라이더는 **텍스처 없이 머티리얼 13개의 `baseColorFactor`** 로 색을 낸다.
> 그래서 작게 그려져도 파란 저지·빨간 팬츠가 또렷했다. 우리 쪽이 더 깨지기 쉬운 구조다.

### 1-3. 정상인 것 — 여기는 건드리지 마라

감리가 확인했고 **문제 없다**:

| 항목 | 상태 |
|---|---|
| 노드 10개 · 이름 · 좌/우(±81.4) · 피벗([0,−378.4,0]) | ✔ 정확 |
| 팔레트 텍스처 2장 · 128×16 · `magFilter` NEAREST | ✔ 원본과 동일 |
| UV 범위 0~1 | ✔ |
| `skins` 0 · `animations` 0 | ✔ |
| **몸통이 44.66° 기울어 구워진 것** | ✔ **정상이다** — 생성기도 `torso` 를 기울여 만든다(`generate-rider-prototype-glb.mjs:660~`). 앱은 `torsoRotationDeg [0,0,0]`(Static Fit, sway OFF)이라 회전을 얹지 않는다 |
| 자전거 | ✔ 우리가 만든 최종 프레임이 그대로 나온다 |

**감리가 앞서 "몸통 이중 포즈" 를 의심했으나 틀렸다.** 정정한다.

## 2. F19 지시 — 딱 하나만 고친다

### 2-1. 분해 시 **메시 무결성을 보존하라**

`decompose-v2-rider.py` 가 정점을 복제·재생성하지 않게 고쳐라.

- **정점 수 5,477 유지** — 파트 경계에서 불가피한 복제만 허용(수백 단위)
- **UV(`TEXCOORD_0`)·노멀을 원본 그대로 이어받아라** — 재계산 금지
- 인덱스 공유(indexed primitive) 유지
- Blender `separate` 가 원인이면 다른 방법을 써라. **분해의 목적은 "정점을 어느 노드에
  매달 것인가"뿐이고, 지오메트리는 바뀔 이유가 없다**

방법은 당신이 판단하라. 다만 **원본 정점을 손대지 않는 경로**를 우선 검토하라
(예: 원본 primitive 를 유지한 채 노드별로 인덱스 부분집합만 참조).

### 2-2. 검증 — 이번엔 정점 수를 합격 기준에 넣는다

제품 이식 전, 후보 GLB 를 파싱해 **로그에 찍어라**:

| # | 검사 | 기대값 |
|---|---|---|
| 1 | **라이더 9노드 정점 합계** | **5,477** (±수백) ← **이번 핵심 지표** |
| 2 | UV 범위 · 고유 UV 개수 | 원본(721개)과 같은 수준 |
| 3 | 노멀 | 원본 그대로(재계산 흔적 없음) |
| 4 | 노드 10개 · 좌/우 · 피벗 | F18 과 동일 유지 |
| 5 | `skins`/`animations` | 0 / 0 |
| 6 | 팔레트 텍스처 2장 · 128×16 | 유지 |

**1번이 3배로 나오면 고쳐지지 않은 것이다. 이식하지 말고 보고하라.**

### 2-3. 판정은 **앱 화면**에서 한다 — Blender 렌더가 아니다

이번 사고의 교훈이다. 열네 단계 동안 Blender 에서 발–페달 0.0mm 를 맞췄지만
**앱에서는 라이더가 200~250px 로 그려진다.** 그 크기에서 보이는 건
**실루엣 · 색 · "사람이 자전거를 탄다"는 인상**뿐이다.

- **앱 스크린샷을 실제 게임 카메라 거리에서** 찍어라(스크린샷 확대 금지)
- **파란 저지 · 빨간 팬츠 · 흰 신발이 보이는가** — 이것이 이번 합격 판정이다
- 옛 절차적 라이더(`.pre-F15.bak`)와 **나란히 비교**하라. 사용자 기준이 그것이다
