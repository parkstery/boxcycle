## 1. 감리 예상값 검산

### 1-1. 【반증】 「밖으로 나온 정점 18~23 · 최대 돌출 118.9~162.0mm」는 재현되지 않았다

**현상·원인 진단은 맞다.** 스텁은 실재하고 회전하면서 반바지 밖으로 드러난다.
**수치만 재현되지 않았고, 그 이유는 「보이는가」를 재는 방법이 다르기 때문이다.**

세 가지 방법을 차례로 시도했고 **전부 그림과 어긋났다.** 기록을 남긴다:

| 시도 | 결과 | 왜 틀렸나 |
|---|---|---|
| 광선 짝수·홀수(parity) | 271정점 · 65.2mm | `torso` 는 **닫힌 메시가 아니다**(경계 edge 108 · 비매니폴드 24). 게다가 원본 V2 는 **살갗 위에 옷 껍질이 겹친 다층 메시**라 안쪽 껍질 내부가 «밖»으로 나온다. 봉합 후 자가검산 정확도 **60/96** |
| 광선 탈출(escape ray), 전 구면 | 29정점 · 42.3mm | **땅 밑에서 올려다보는 시선**까지 «보인다»로 센다 |
| 표면 거리 여유(inset 5mm) | 뚜껑 0mm² | 눈에 띄는 초승달을 **0 으로** 보고했다 |

→ **대리 지표를 버리고 픽셀을 셌다.** 실제 게임 카메라 배율(**3.9mm/px**, F34 실측)과
고도각(`RIDE_CAMERA_PITCH_CLOSE = 80` → **시선 고도각 10°**)으로 오프스크린 래스터해
문제 삼각형이 **화면에 몇 픽셀 나오는지** 직접 센다. 사람이 보는 것과 같은 단위다.

```
스텁 노출   F34 제품 909px  →  F35 후보 0px      (36카메라 × 8위상 최악값)
```

⚠ 이 과정에서 **내 계측이 두 번 거짓 0 을 냈다.** 뚜껑 판정에 `y > 0` 을 걸었더니
절단면을 관절 평면에 정확히 놓았을 때(y == 0) 뚜껑이 통째로 빠졌고, 관절 아래로 자르면
또 빠졌다. 두 번 다 **PASS 로 보일 뻔했다.** 소스 주석에 박아뒀다.

### 1-3. 【환산식 차이】 「저지 41.8mm」는 오차가 아니라 **다른 공식**이다

감리 41.8 / 17.2 / 20.9 ↔ 내 실측 44.9 / 18.4 / 22.4 — **비가 전부 0.9306 으로 일정하다.**

```
감리 = √(2A)            (직각이등변 환산)
나·F34 = √(4A/√3)       (정삼각형 환산)      √(2A)/√(4A/√3) = 0.9306
```

**면적은 같다.** 목표 「≤30mm」를 어느 환산으로 읽느냐만 정하면 된다. F34 가 정삼각형
환산을 썼으므로 **정삼각형으로 통일**했다. 그 기준으로 저지는 **44.9 → 21.8mm** 다.

### 1-4. 【반증】 허리 단차의 원인은 삼각형 크기가 아니다 — **반바지가 별개 껍질이다**

감리 §1-3: *"41.8mm 저지와 17.2mm 반바지가 만나는 경계일 가능성이 크다."*
**두 색 삼각형은 edge 를 하나도 공유하지 않는다.** 연결 성분으로 갈라보니:

```
torso 껍질 20개 중
  껍질0  삼각형 1,728  y −114~201mm   반바지 100%   ← **완전히 별개의 닫힌 껍질**(경계 edge 0)
  껍질1  삼각형 1,344  y  −48~436mm   피부 816 + 저지 528
```

반바지는 몸통 위에 **덧입혀진 독립 껍질**이고, 몸통 껍질 밖으로 얼마나 나와 있는지가
곧 실루엣 단차다. **실측(torso 로컬 y 대역별, 몸통 껍질 표면까지 최단거리):**

| y 대역(mm) | 중앙값 | 최대 |
|---|---|---|
| 60~80 | 4.1 | 7.9 |
| 120~140 | 15.7 | 20.1 |
| 140~160 | 25.3 | 38.8 |
| 180~200 | 28.1 | **76.8** |
| **허리대 y ≥ 150 종합** | **22.2mm** | **76.8mm** |

**저지를 아무리 잘게 쪼개도 이 22.2mm 는 그대로다.** 실제로 세분화 후 그림이 안 변했다
(§0-3). 고치려면 반바지 껍질을 몸통 쪽으로 당기거나 윗단을 저지 밑으로 넣어야 한다 → §5-2.

### 1-5. 【정정】 게이트 13 을 「같은 방식으로 `ankle_*` 도」 적용하면 안 된다

지시 §1-2 는 `leg_*_shin ↔ leg_*` · `ankle_* ↔ leg_*_shin` 도 같은 방식으로 검사하라 했다.
실측 결과:

- **`leg_*_shin` 은 스텁이 애초에 없다** — 로컬 y 범위 −303.6 ~ **−39.6mm**, y>0 정점 **0개**.
  검사는 넣었으나 항상 0 이다(무해)
- **`ankle_*` 에 같은 잣대를 대면 190/190 이 «관통»으로 잡힌다.** F31 이 발 메시를
  «밑창 법선 = 로컬 −Y»로 정렬해 놨으므로 `ankle_*` 의 로컬 y>0 은 «관절 위»가 아니라
  **신발 윗면**이다(190정점, y −23.2 ~ +40.6). 보이는 게 정상이다
  → **축이 다른 세그먼트를 스텁 규칙에서 제외**하고 이유를 소스에 남겼다

## 2. 한 일

### 2-1. `clip-node-mesh.mjs` (신규) — 평면 클리핑 + 절단면 뚜껑

정점을 «지우면» 경계가 톱니로 남는다. **평면 클리핑**을 한다 — 걸친 삼각형은 평면 위에
새 정점을 만들어 다시 삼각형화하고(edge 당 한 번만 만들어 링이 벌어지지 않게), 생긴
경계 루프마다 **중심 팬 뚜껑**을 덮는다.

```
leg_l · leg_r  각각
  정점 535 → 529   삼각형 1,024 → 1,012
  잘린 정점 168 (원래 y 최대 +96.8mm) · 버린 삼각형 272 · 걸친 삼각형 120
  뚜껑 **2루프** 120삼각형   ← 살 껍질 + 반바지 껍질, 예상대로 둘 다 막혔다
```

뚜껑 UV 는 링 정점의 **최빈 UV** 를 쓴다(평균을 내면 팔레트 텍셀 경계를 넘어 엉뚱한 색이 된다).

### 2-2. 절단 높이 — **로컬 y = +10.0mm** (근거를 수치로 남긴다)

감리 지시는 «+10~20mm». **−40mm 부터 +30mm 까지 8단계를 실제로 잘라 픽셀로 쟀다:**

| 절단면 y | 스텁 노출 | **절단 뚜껑 노출** |
|---|---|---|
| (자르기 전 +96.8) | **909px** | 59px |
| −40mm | 0px | 391px |
| −20mm | 0px | 319px |
| 0mm | 0px | 295px |
| **+10mm** | **0px** | **293px** ← 최소 |
| +20mm | 0px | 302px |
| +30mm | 0px | 321px |

→ **+10mm 채택.** 스텁을 없애면서 **절단면 노출이 최소**이고, 감리가 지정한 범위 안이다.
회전 전 위상에서 **틈(구멍)은 생기지 않는다** — 8위상 × 36카메라에서 뚜껑 너머로
속이 비치는 지점 없음. **고관절 캡은 필요 없었다.**

### 2-3. 【미해결·기준선】 절단면 293px 은 **0 으로 만들 수 없다**

위 표대로 어느 높이로 잘라도 293~391px 이 남는다. 원인은 절단 높이가 아니라
**반바지가 고관절 뒤쪽을 덮지 못한다**는 것이다. 잘라내기 전에는 스텁 본체가 그 자리를
메우고 있었을 뿐이고, 그래서 «갑옷»으로 보였다.

**허용치를 늘려 통과시키지 않았다.** 대신 **기준선 상수**로 고정해 커지면 실패하게 했다:

```js
LEG_STUB_MAX_PX = 0     // 이번 지시의 정본
LEG_CAP_MAX_PX  = 293   // 해결 못 한 것을 «숨기지 않고 고정»
ARM_STUB_MAX_PX = 211   // F36 이월
```
