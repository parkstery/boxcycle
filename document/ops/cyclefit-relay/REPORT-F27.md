## 1. 【반증】 어긋남은 **180°가 아니라 90°** 다

감리 §1-1 은 *"차이 345.0mm = 2×172.5 = 크랭크 지름 → 정확히 180°. +180° 를 더하면
8건 전부 0.0mm"* 라 했다. **노드 계층을 실제로 합성해 재보니 다르다.**

```
실측 차이   8건 전부 **244.0mm**          (감리 주장 345.0)
+180° 적용  8건 전부 **243.95mm**          ← 전혀 해결되지 않는다
244.0 = 172.5 × √2                        ← 크랭크 반경의 **90° 현**
```

| phase | side | GLB world (mm) | pedalWorld (mm) |
|---|---|---|---|
| 0 | l | [−172.5, 270.5, 74] (9시) | [0, 98, 74] (6시) |
| 0.25 | l | [0, 443, 74] (12시) | [−172.5, 270.5, 74] (9시) |

**일관되게 GLB 가 앱보다 90° 앞선다.**

### 1-1. 원인과 정확한 보정값 — 유도해서 확정했다

`generate-rider-prototype-glb.mjs:574` 가 `crank.rotation.z = π/2` 로 rest 를 둔다
(fit_ik 주석: *"cycle-only.glb rest 크랭크 = 3시-9시 수평"*). **Mapbox 는 override 를
누적하므로 그 rest 가 살아 있다.**

```
crank world = Rz(90 + θ)
GLB pedal_l = (−C·cos θ,  BB.y − C·sin θ)
앱 pedalWorld(l) = ( C·sin cr,  BB.y − C·cos cr)
두 식이 같으려면  sin θ = cos cr,  cos θ = −sin cr   →   **θ = cr + 90°**
```

**적용**: `crankRotationDeg = −phase·360 **+ 90**`.
페달 상쇄는 `−crankRotationDeg` 그대로라 새 값(+90 포함)을 자동으로 따라간다 —
*"적용된 크랭크 회전의 정확한 음수"* 라는 §2-1 요구를 유지한다.

**정방향 검산: 4위상 × 좌우 8건 전부 0.000mm.**

### 1-2. 감리 판단 중 **옳았던 것**

- **"페달과 IK 목표가 어긋나 있다"** — 사실이다. 크기만 달랐다
- **"어떤 게이트도 렌더 페달과 IK 페달을 대조하지 않았다"** — 정확하다. 그래서 게이트 10 을 만들었다
- **"F18 crank 병합 이후 줄곧"** — rest `+90°z` 는 그때 들어왔다

## 3. 발목 절대 수평 — 밑창 법선 실측값과 유도

### 3-1. 밑창 법선 실측 (§2-3-1) — **−Y 가정은 틀렸다**

GLB `NORMAL` accessor 에서 **아래를 향하는 면**(로컬 하위 45mm · `n.y < −0.25`)의 가중 평균:

```
ankle_l  [−0.4011, −0.9136, −0.0672]   → 로컬 −Y 에서 **24.00°** 벗어남 (42정점)
ankle_r  [−0.1087, −0.9897, −0.0930]   → 로컬 −Y 에서  **8.23°** 벗어남 (71정점)
```

좌우가 다른 이유는 §1-2 감리 설명대로다 — **분해가 좌 BDC · 우 TDC 한 시점**에서 이뤄져
두 발의 발목 각도가 애초에 다르다.

### 3-2. 유도 — 절대 기준으로 바꿨다

```
R_target = 밑창 법선을 세계 +Y 로, 발끝(로컬 +x)을 세계 +x 로 보내는 정규직교 회전
           [F S N] · [f s n]ᵀ      (n = −실측법선, f = +x 에서 n 성분 제거, s = n×f)
R_ankle  = (R_leg · R_shin)⁻¹ · R_target
```

**F26 의 "분해 시점 자세 유지"를 버렸다** — 감리 §1-2 지적대로 그 전제가 틀렸다.

### 3-3. 결과 — 크게 좋아졌으나 미달

|---|---|---|

**남은 문제 2건 (내 소견)**

1. **기울기가 위상마다 0~10.5° 로 변한다.** 절대 기준이면 전 위상 0° 여야 한다.
   `soleLevelTarget` 이 발끝을 세계 +x 로 고정하는데, 다리가 z 방향으로도 기울어
   `R_leg·R_shin` 의 역이 yaw 성분까지 완전히 상쇄하지 못하는 것으로 보인다.
2. **gap 이 전부 음수(−8.5 ~ −21.9mm)** — 밑창이 페달면보다 **일관되게 아래로 파고든다.**

   가정 사이에 계통 오차가 있다는 뜻인데, §4 가 `ANKLE_UP` 변경을 금지해 손대지 않았다.
   **게이트 9 를 통과시키려면 이 값의 재검토가 필요해 보인다 — 감리 판단을 구한다.**
