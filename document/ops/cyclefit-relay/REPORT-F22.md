## 2. 감리 진단 검산 — **3건 전부 일치. 반증 없음**

### 2-1. `riderIk.mjs:109` 성분 뒤바꿈 — 일치

번들 `rotationYZX`(`:36044`)를 직접 열었다:

```js
identity(out); rotateY(out, out, r[1]); rotateZ(out, out, r[2]); rotateX(out, out, r[0]);
//  →  R = Ry(r[1]) · Rz(r[2]) · Rx(r[0])   즉 배열은 [x, y, z]
```

코드 주석의 *"[pitch(x), roll(z), yaw(y)]"* 가 **틀렸고**, 그 전제로 `[ex, ez, ey]` 를
반환해 **y·z 가 맞바뀌어 있었다.** 감리 지적 그대로다.

### 2-2. 왕복 검산 실패 — 일치 (수치까지)

```
restToDirRotationDeg([0.7071, −0.7071, 0])   45° 앞 스윙
  수정 전 반환 [0.00, 45.00, 0.00]   ← 감리 주장 [0, 45, 0] 과 정확히 일치
         R·rest = [0.0000, −1.0000, 0.0000]  오차 0.765367   **무회전**
  수정 후 반환 [0.00,  0.00, 45.00]
         R·rest = [0.7071, −0.7071, 0.0000]  오차 0.000000   PASS
```

**Y 는 팔다리의 rest 축(−Y) 자신이라 제자리 스핀** — 감리 §1-2 설명이 맞다.

### 2-3. 실제 pose 출력이 Y 지배적 — 일치

| | 수정 전 | 수정 후 |
|---|---|---|
| `armLRotationDeg` | [−1.37, **52.55**, −0.68] | [−2.26, 1.12, **52.54**] |
| `armLForeRotationDeg` | [1.08, **9.94**, 0.09] | [1.10, −0.10, **9.94**] |
| `legRRotationDeg` | [0.63, **21.99**, 0.12] | [0.68, −0.13, **21.99**] |
| `legRShinRotationDeg` | [−2.50, **−25.79**, 0.57] | [−2.78, −0.64, **−25.79**] |

감리가 인용한 `armL [−1.37, 52.55, −0.68]` 과 소수점까지 일치한다. 수정 후 **큰 성분이
index 1(Y) → index 2(Z, 시상면)** 로 이동했다 — 자전거를 옆에서 볼 때 팔다리가 도는 축이다.

### 2-4. 감리 §2-1 추출식 — 손계산으로 유도해 확인했다

`R = Ry(b)·Rz(c)·Rx(a)` 를 전개하면

```
R[1][0] = sin c                  → c = asin(R[1][0])
R[1][1] = cos c·cos a            → a = atan2(−R[1][2], R[1][1])
R[1][2] = −cos c·sin a
R[0][0] = cos b·cos c            → b = atan2(−R[2][0], R[0][0])
R[2][0] = −sin b·cos c
```

**감리 식 그대로다.** 짐벌(|R[1][0]|≈1 → cos c≈0)에서는 a·b 가 축퇴하므로
`b = 0`, `a = atan2(R[2][1], R[2][2])` 로 처리했다(전개식에서 `R[2][1]=sin a`,
`R[2][2]=cos a` 임을 확인).

행렬 인덱스는 **`R[행][열]`, 열벡터 규약 `v' = R·v`** 로 확정했다 — 기존 코드의
`m11..m33` 과 같은 규약이라 그대로 확장했다.

### 2-5. 옛 라이더 baked pose (§1-3 ④) — **확인하지 않았다**

지시 §4·§5 가 옛 라이더를 재생성하지 말라고 했고, 이번 판정에 불필요해 조사하지 않았다.
**감리 수치를 검산 없이 인용하지 않겠다** — 미확인 항목으로 남긴다.
