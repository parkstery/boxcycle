## 1. 규칙 — 감리가 지킨다

### 1-1. 【필수】 진단에 **반증 조건**을 붙인다

지시서를 쓰기 전에 이 문장을 완성하지 못하면 **아직 지시할 때가 아니다.**

```
"__를 고쳤는데도 현상이 남으면 내 진단이 틀린 것이다."
그 반증을 **가장 싸게 확인하는 방법**은 __이고, 개발팀장이 **본작업 전에 먼저** 한다.
```

F34 라면: *"반바지를 4배 세분했는데도 갑옷이면 삼각형 크기가 아니다.
파이프라인 전에 오프스크린 1장으로 확인"* → **한 사이클 대신 5분.**

### 1-2. 【필수】 「보이는가」는 **픽셀**로 판정한다

정점 수·mm 지표는 F35 에서 세 번 그림과 어긋났다(광선 parity · escape ray · 표면거리).
**게임 카메라 배율(3.9mm/px)로 래스터해 픽셀을 센다.** 사람이 보는 것과 같은 단위다.
`offscreen-raster.mjs` 가 그 도구다.

### 1-3. 【필수】 보고서 첫 절은 **UAG(사용자 수용 게이트)** 다

기술 게이트 13/13 인데 사용자가 "그대로"인 일이 반복됐다. 순서를 뒤집는다.

```
UAG   사용자가 말한 현상 그대로를 인용 · BEFORE/AFTER 픽셀 · PASS/FAIL
      ↓
기술 게이트 1~N
```

**기술 게이트가 전부 PASS 여도 UAG 가 FAIL 이면 FAIL 이다.**

### 1-4. 【필수】 감리가 **먼저** 전수 육안 점검한다

사용자 지적은 **확인**이지 **발견**이 아니어야 한다(2026-08-07 질책).
매 보고 후 감리가 앱 렌더를 직접 열어 결함 목록을 만들고, 그중 무엇을 이번에 할지 고른다.

### 1-5. 지시서는 **40줄 상한**

근거·이력은 별도 파일로 링크한다. 자기반성·설득 문단을 쓰지 마라 —
**행동을 바꾸는 것은 게이트지 반성문이 아니다.**

## 2. 도구 — 계측은 코드를 새로 쓰지 말고 부른다

`apps/web/scripts/rider-cycle-fit/inspect.mjs` (F36 신설 예정)

```
node inspect.mjs node <이름>          노드 변환(matrix||TRS 양쪽) · 부모 체인 합성
node inspect.mjs mesh <이름>          정점·삼각형·AABB·색별 분포·삼각형 한 변
node inspect.mjs pose <phase>         전 노드 회전각 + 월드 관절 위치
node inspect.mjs pixels <노드> [위상] 게임 카메라 배율에서 몇 픽셀 보이는가
node inspect.mjs penetrate <A> <B>    A 가 B 를 뚫는가 (픽셀)
```

**감리도 개발팀장도 이것을 쓴다.** 같은 숫자를 보므로 §0 의 3번이 사라진다.

⚠ **환산 규약 통일**: 삼각형 한 변 = `√(4A/√3)`(정삼각형). 직각이등변 환산 금지.

## 3. 역할 — 바꾸지 않는다

```
사용자   "무엇이 잘못 보이는가" (현상)          ← 파일명 몰라도 된다
감리     "어디가 왜 잘못됐는가" + 반증조건 + 지시 + UAG 판정
개발팀장 구현 + 기술 게이트 + 그림
```

**개발팀장이 감리 숫자를 다시 재는 규율은 유지한다** — 감리 오진 9건이 전부 그렇게 잡혔다.
독립성은 「다른 제품」이 아니라 **「산출물을 다시 재는 것」** 에서 나온다.
