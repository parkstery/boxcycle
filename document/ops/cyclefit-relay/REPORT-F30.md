## 1. 밑창 면 특정 — 감리 방법을 그대로 적용했고, **관문에서 막혔다**

F29 에서 페달 판에 쓴 방법(삼각형별 법선·면적 → 아래쪽 면 군집 → 최대 면적 군집)을
발 메시에 그대로 적용했다.

```
=== ankle_l — 아래쪽 면 군집(면적순) ===
   33230mm²  법선 [ 0.1588, −0.9843, −0.0765]   ← 최대 군집
    5248mm²  법선 [ 0.0023, −0.1063,  0.9943]
   ▶ S 평균 8.11mm · 중앙값 27.68 · 범위 −23.22…40.61   (정점 8)

=== ankle_r — 아래쪽 면 군집(면적순) ===
   19097mm²  법선 [ 0.7808, −0.4824,  0.3971]   ← 최대 군집. **45° 이상 기운 면이다**
   14133mm²  법선 [ 0.7209, −0.5665,  0.3993]
   ▶ S −22.00mm (범위 폭 0 — 평면은 정확히 잡혔다)
```

### 정합성 관문 — **둘 다 실패**

| 관문 | 기준 | 실측 | |
|---|---|---|---|
| `S` 좌우 편차 | ≤ 2mm | 좌 8.11 · 우 −22.00 → **30.11mm** | ✘ |
| `S` 발 두께 자릿수(30mm 대) | 정합 | 평균 **−6.9mm** | ✘ |

**§3-1 지시대로 고치지 않고 멈췄다.**

## 2. 【근본 원인】 좌우 발 메시의 **자세가 완전히 다르다** — 자산 문제다

`ankle_*` 메시 로컬 AABB 를 직접 대조했다:

```
ankle_l   x[−32.4 … 218.8]  y[−30.4 …  61.8]  z[−45.7 … 49.8]   크기 251.2 ×  92.2 ×  95.5mm
ankle_r   x[−51.3 … 146.5]  y[−47.8 … 194.7]  z[−55.5 … 48.0]   크기 197.8 × **242.5** × 103.5mm
```

**좌우가 대칭이면 z 부호만 반대이고 x·y 범위는 같아야 한다.** 실제로는

- **왼발**: x 로 251mm 뻗고 높이 92mm → **발이 눕혀져 있다**
- **오른발**: 높이 **242.5mm** → **발이 세로로 서 있다**

원인은 명확하다. 분해가 **phase 0.000 한 시점**에서 이뤄졌고 그때 **왼발 BDC · 오른발 TDC**
였다. `ankle_*` 는 부모(`SHIN`) 정렬을 물려받는데(F26 §5-1 설계), **좌우 정강이 각도가
46.3° 다르므로** 발 로컬 자세도 그만큼 벌어진 채 구워졌다.

### 2-1. 그래서 이 방법으로는 좌우 `S` 가 같아질 수 없다

`S` 는 **발목 원점에서 밑창 평면까지의 수직거리**로, 강체 불변량이다. 그런데 **발이
로컬 좌표계 안에서 서로 다른 자세로 저장돼 있으면** 밑창 면 자체가 다른 방향을 향하고,
"아래를 향하는 면" 군집도 다른 것을 잡는다 — 오른발 최대 군집 법선이
`[0.78, −0.48, 0.40]`(45° 이상 기움)인 것이 그 증거다. **그건 밑창이 아니라 발 옆·등면이다.**

**F28 §2-1 에서 올린 소견 2번("`SOLE_NORMAL` 이 좌우 다른 면을 잡았을 가능성")이 맞았고,
그 뿌리가 계측이 아니라 분해였다.**

## 3. 해법 — 분해 단계에서 발을 **밑창 기준으로 정렬**한다

`decompose-v2-rider.py` 의 `PIVOT["ankle_*"]` 는 현재 **`SHIN` 방향으로 정렬**한다
(F26 §5-1: *"부모와 같은 회전으로 맞춰 ankle 이 부모 로컬에서 identity 가 되게"*).
그 선택이 좌우 비대칭을 만들었다.

```
현재   PIVOT["ankle_l"] = ("FOOT_" + BL, "SHIN_" + BL)      ← 정강이 축으로 정렬
제안   ankle 메시를 **밑창 법선이 로컬 −Y** 가 되도록 정렬한다
       (Blender 에서 FOOT 정점군의 아래쪽 면 법선을 구해 −Z(Blender) 로 회전)
```

이러면 **좌우 모두 `SOLE_NORMAL = (0,−1,0)`** 이 되고 `S` 도 같아진다. 그리고 앱 쪽
`SOLE_NORMAL` 상수도 필요 없어져 코드가 단순해진다.

**대안**(감리 F28 §6 의 안 B): 분해를 **좌우 같은 위상**에서 두 번 해 각 발이 페달에
닿은 자세로 굽는다. 정확하지만 파이프라인을 두 번 태워야 한다.

**나는 위쪽(밑창 정렬)을 권한다** — 한 번의 분해로 끝나고, `ankle` 은 어차피 앱이
절대 회전을 걸므로 부모 정렬을 물려받을 이유가 없다.

⚠ **어느 쪽도 분해 파이프라인 6단계를 다시 태워야 한다.** 지시 범위를 넘으므로
착수하지 않았다.

## 5. 실패·미완 전수

1. **§3-1 발목 미완** — 정합성 관문 실패. **다섯 단계 연속**이다(F26~F30)
2. **제품 이식·촬영 못 함** — 밑창–페달 판정 자료 여전히 없음
3. **§3-2 광택 시험 미착수** — 조건부 지시라 손대지 않았다
4. **F26~F30 발목 변경분 미커밋** — 게이트 미통과
5. 관절 캡은 지시대로 손대지 않았다(F31 범위)

## 6. 이견

**§3-1 의 방법 자체에는 이견이 없다.** 페달 판에서 검증된 방법이고 구현도 그대로 했다.
다만 **그 방법이 통하려면 입력(발 메시)이 좌우 대칭이어야 하는데 그렇지 않았다.**

감리가 §3-1 에 **정합성 관문 2개를 걸어둔 것이 정확히 작동했다** — 관문이 없었으면
`ANKLE_UP = 3.06mm` 라는 엉터리 값이 들어갔을 것이다(현재 37.0).

### 다음 수 — 권고

**§3 의 "밑창 기준 정렬"로 분해를 한 번 더 태우는 것.** 이번 실패로 **원인이 계측이
아니라 자산임이 확정**됐으므로, 같은 방법을 다시 시도하는 것은 무의미하다.

작업량은 F26 과 같다(분해 → 파이프라인 6단계 → 게이트). **다만 이번엔 무엇을 고쳐야
하는지 알고 시작한다** — `PIVOT["ankle_*"]` 의 정렬 기준 한 줄이다.
