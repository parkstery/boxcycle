### 【핵심】 앱 색이 안 나오는 진짜 원인 — 특정 완료

**UV 정밀도 문제가 아니다. "작은 팔레트 텍스처 + 밉맵" 조합 자체다.**

```
V2 라이더 : 머티리얼 1개 + 128×16 팔레트 아틀라스 · minFilter 9984(밉맵)
옛 라이더 : 머티리얼 25개 + baseColorFactor 단색 · 텍스처 0
```

앱에서 라이더는 **약 130px**. 팔레트는 색 하나가 **6px** 이라 밉맵 한 단계만 내려가도
인접 색이 섞여 **평균색(살색)** 이 된다. Blender 는 밉맵 없이 원본 해상도로 샘플링하므로
정상으로 보였다 — **같은 GLB 인데 렌더러에 따라 다르게 나온다.**

**해법 후보 (다음 지시의 결정 사항)**

| 안 | 내용 | 평가 |
|---|---|---|
| **A** | 팔레트 텍셀을 **정점 색 `COLOR_0`** 으로 굽는다 | Mapbox 가 읽는 것 실측 확인. **밉맵과 무관해 확실**. 텍스처를 아예 뺄 수 있다 |
| **B** | 팔레트를 NEAREST 로 **2048×256 업스케일** | 색 블록이 커져 밉맵에 강해진다. **가장 간단**(이미지 교체 1회) |
| C | `minFilter` 를 NEAREST 로 | glTF 상 가능하나 Mapbox 존중 여부 불확실 |

**감리 의견: B 를 먼저(30분), 안 되면 A.** A 가 근본이지만 B 가 압도적으로 싸다.

## 2-1. 【필독】 앱 라이더와 V2 라이더는 **다른 자산**이다 (2026-08-02)

이걸 모르면 "GLB 굽어서 앱에 올려라"가 **옛 모델 재생성**으로 끝난다. 실제로 F15 에서
감리가 그렇게 지시해 사고가 났다.

| | 앱 라이더 | **F1~F14 에서 만진 라이더** |
|---|---|---|
| 자산 | `apps/web/public/rider/prototype/rider-lowpoly.glb` | `stylized_cyclist_v2_lod0.glb` |
| 생성 | `generate-rider-prototype-glb.mjs` (절차적) | Blender 제작물 + `fit_ik.py` |
| 구조 | **명명 노드 10개** | **스킨드 아마추어 23본** |
| 구동 | Mapbox `setFeatureState` 노드 회전 | Blender 포즈 |

앱이 요구하는 노드 10개(`config.ts` `RIDER_GLB_NODE_OVERRIDE_NAMES`):
`crank` `torso` `leg_l` `leg_l_shin` `leg_r` `leg_r_shin` `arm_l` `arm_l_fore` `arm_r` `arm_r_fore`.
회전각은 `riderGlbPedalPose.pose.mjs` 가 계산한다. **본·스키닝·애니메이션 클립을 안 쓴다.**

**목표는 절차적 라이더를 버리고 V2 를 앉히는 것이다.** 이식 방법은 **강체 분해** —
V2 메시를 본 가중치로 잘라 위 이름의 노드에 강체로 매단다. V2 는 이미 사실상 강체
바인딩이라(손 100% `HAND_*`, 발 432정점 전부 `FOOT_*`) 실현 가능하다.

**주의**: `riderGlbPedalPose.pose.mjs` 의 IK 는 **옛 절차적 라이더의 사지 길이**를
전제한다. V2 실측(허벅지 378.40 · 정강이 352.00 · 상완 334.83 · 전완 212.84)으로
맞추지 않으면 **앱에서 발이 페달에서 떨어진다** — Blender 에서 F1~F14 로 잡은 문제가
그대로 재발한다.

**자전거는 이미 연결돼 있다** — 생성기가 `geometry.json`(SSoT)에서 파생하므로
`RTW_RIDER=0` 로 자전거만 재생성하면 프레임·안장이 반영된다.

## 4. 작업 규율 — 반복된 실패에서 나온 것

이 규칙들은 전부 **실제로 사고가 나서** 만들어졌다. 지키지 않으면 같은 사고가 반복된다.

### 4-1. 렌더 assert 4종 — 절대 완화하지 마라

`render-all.py`에 있다. 어긋나면 `RuntimeError`로 렌더를 중단시킨다.

| assert | 막는 사고 |
|---|---|
| `frameAssertions` | **구프레임 GLB로 렌더** (F6에서 발생 — 사용자 승인 프레임이 회귀) |
| `crankPhaseAssertions` | **위상 어긋남** (F5 — 두 발이 수평이라 판정 불가) |
| `footContactAssertions` | **발이 안 닿는데 렌더 성공** (F6·F8 세 번 반복) |
| `jointsFreshness` | **낡은 joints 재사용** (F8 — 7/30자 파일로 렌더) |

**실패를 우회하려고 허용치를 늘리지 마라.** F9에서 개발팀장이 assert를 완화하지 않고

### 4-1b. 【F10-R1 최대 교훈】 계측이 보는 장면과 렌더가 보는 장면이 다를 수 있다

라이더 GLB는 `Pedal_Loop` 액션을 활성 상태로 들고 온다. `render()`는 렌더 직전 씬을
프레임 평가하는데, **그때 그 애니메이션이 우리가 세운 IK 포즈를 덮었다.**

```
apply_phase 직후   발 최저 z = 103.12   ← 계측이 본 값
렌더 1회 뒤        발 최저 z = 271.47   ← 이미지가 본 값
```

**F5·F6·F8·F9 네 번의 "계산 0mm ↔ 렌더 미달"이 전부 이것 하나였다.**
`arm.animation_data_clear()`로 끊었다(`render-all.py`).

**규율**: assert가 PASS인데 그림이 이상하면 **assert의 허용치를 의심하기 전에
"둘이 같은 장면을 보고 있는가"를 먼저 확인하라.** 외부 자산(GLB)은 액션·NLA·드라이버·
컨스트레인트를 몰래 들고 온다.

- 수치가 목표에 닿아도 **그림이 이상하면 이상하다고 쓴다**
- 감리는 렌더를 **직접 열어 보고** 판정한다. 로그만 읽고 합격을 주지 마라

### 4-6. 모델 계층화

- 설계 판단(프레임·IK·좌표계·SSoT 파생) → **Opus 직접**
- 기계 작업(파일 집계·해시 대조·아카이빙) → `impl-simple` 위임
- 확정 사양 구현 → `impl-standard` 위임
- 50줄 미만은 직접. 위임은 큰 덩어리로 한 번에
- `REPORT.md`에 **모델 사용 내역 한 줄** 기록

### 4-7. 금지 기본값

`git commit`·`push`·제품 GLB(`apps/web/public/rider/prototype/rider-lowpoly.glb`)
덮어쓰기는 **지시서가 명시적으로 허용할 때만.** GLB 생성은 항상 `RTW_GLB_OUT`으로

## 8. 개발팀장 작업 프로세스 — **이 순서를 유지하라**

지금까지 F9~F17-R1 열 단계가 이 순서로 굴러갔다. 다음 창도 그대로 하면 된다.

```
1. INSTRUCTION.md 를 읽는다            ← 사용자가 "읽고 그대로 수행해"라고만 입력한다
2. 감리 수치를 **먼저 검산**한다        ← 감리가 F6~F8·F12·F16 에서 오진 4건을 냈다
3. 실측이 감리와 다르면 **반증을 먼저 보고**한다(코드 고치기 전에)
4. 구현 → 렌더 → **그림을 직접 열어 본다**  ← §4-5b 사용자 질책의 핵심
5. REPORT.md 를 쓴다:
     §0 「그림에서 보이는 것」  ← 반드시 수치보다 먼저. 이상하면 이상하다고 쓴다
     감리 예상값 검산 결과 · 실측 전수 · 미완/실패 전수 · 이견
6. 기존 REPORT.md → REPORT-<이전지시번호>.md 로 보존
7. INSTRUCTION.md 의 `상태:` 를 `보고완료` 로 변경
8. 커밋·push 는 **하지 않는다** — 사용자 승인 후 감리가 별도 지시
```

**보고 시 렌더 이미지는 폴더 경로를 통째로 준다.** 개별 파일 링크는 `.out` 이
gitignore 라 클릭해도 열리지 않는다(2026-08-02 사용자 지적, `file:///` 도 실패).
