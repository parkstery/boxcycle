## 3. 감리 진단 검산 — **반증 1건**

### 3-1. 【반증】 페달 노드는 이미 스핀들 원점이다 — 메시 재출력이 불필요했다

감리 §1-2 는 *"지금은 translation 이 없고 오프셋이 정점에 구워져 있어, 그대로 회전시키면
제자리에서 돌지 않고 궤도가 틀어진다"* 며 **생성기에서 메시를 원점 기준으로 다시 내보내라**
고 했다. **실측은 반대다.**

```
제품 GLB 페달 노드 (matrix 형식)
  idx204  matrix = 단위행렬 + translation [0, +172.5, +74.0]   ← 이미 스핀들 위치
  idx205  matrix = 단위행렬 + translation [0, −172.5, −74.0]
  메시 AABB  x[−35…35] y[−10…10] z[−25…25]                     ← 이미 원점 중심
```

`box()` 가 position 을 노드 translation 으로 쓰고 정점은 원점 기준으로 만들기 때문이다.
→ **정점·구조를 손댈 필요가 없었고, 이름만 주면 됐다.** 지시 §2-2 의 1번 항목 중
"메시 정점을 원점 기준으로" 부분은 **이미 충족돼 있었다.**

(`matrix` 형식이어도 override 는 정상 작동한다 — 번들 `:36432` 가 `matrix || TRS` 로
`localMatrix` 를 만들고, override 는 그 뒤에 post-multiply 된다.)

### 3-2. 나머지는 일치

| 감리 주장 | 실측 | |
|---|---|---|
| 페달이 `crank` 자식이라 함께 돈다 | `crank` 직계 자식 7개 중 마지막 둘 | ✔ |
| 이름이 없어 `nodeOverrideNames` 에 못 넣는다 | 무명 노드였다 | ✔ |
| 페달 플랫폼 70×20×50mm | 동일 | ✔ |
| 옛 라이더 캡: 무릎 86×86×84 · 팔꿈치 60×60×60 | 동일(정점 165 / 117) | ✔ |
| 현재 제품에 캡 0개 | 본체 메시 1개씩뿐 | ✔ |
| Mapbox 누적이므로 `−crankRotationDeg` 로 상쇄 | **렌더로 확인 — 수평 유지** | ✔ |

**좌·우 상쇄값 확인**(§2-2 요구): 좌우 크랭크암은 180° 위상차가 있지만 **`crank` 노드
하나가 둘을 함께 돌린다.** 두 페달의 부모 회전이 동일하므로 **상쇄값도 같다**
(`[0, 0, −crankRotationDeg]`). 렌더에서 양쪽 다 수평인 것으로 확인했다.

**부호**: `+crankRotationDeg` 가 아니라 **`−`** 가 맞다(렌더 확인). 상쇄가 성립하면
위상이 바뀌어도 페달면이 수평을 유지한다 — p1·p3 에서 크랭크 각도가 다른데 둘 다 수평이다.

## 4. 【§2-4】 발–페달 재판정 자료 + 소견

### 4-1. 수치 (정강이 로컬, 발목 = 원점, +x 전방)

```
앱 IK 가정   ANKLE_UP 37.0mm 아래 · ANKLE_BACK 93.03mm 앞  = 페달축 위치
페달 플랫폼  두께 20mm → 상면은 축보다 10mm 위 = 발목 아래 27.0mm

메시 실측 (발바닥)
  y < 최저+10mm  x −33.6 … −25.4   중앙 −29.5      ← 뒤꿈치만
  y < 최저+30mm  x −33.6 … 214.1   중앙  90.2      ← 발바닥 전체
  최저점 y = 발목 아래 28.3mm (뒤꿈치)
```

| 축 | 값 | 판정 |
|---|---|---|
| **수평** | 발바닥 전체 중앙 x **90.2** vs `ANKLE_BACK` **93.03** → **차 2.8mm** | **거의 정확** |
| **수직(뒤꿈치)** | 뒤꿈치 28.3mm vs 페달 상면 27.0mm → **1.3mm** 파고듦 | **거의 정확** |
| **발바닥 기울기** | 뒤꿈치 y −380.3 · 발끝(x 214) 은 그보다 **위** | **✘ 여기가 문제다** |

### 4-2. 소견 — **(a) 발목 각도 부재다. (b) 접점 오프셋 값 문제가 아니다**

접점 오프셋 두 값(`ANKLE_BACK` 93.03 · `ANKLE_UP` 37.0)은 **실측과 2.8mm · 1.3mm 로
사실상 맞다.** 그런데도 발이 따로 노는 것은 **발바닥 면이 페달면과 평행하지 않기** 때문이다.

V2 는 발이 정강이에 **강체로 붙어 있고 발목 관절이 없다**(HANDOFF §7-4 "발목·손목이
강체에 흡수됨"). 정강이가 위상마다 기울면 **발도 통째로 같이 기울어**, 페달면(이제 수평)과
발바닥이 어긋나 **뒤꿈치만 닿거나 발끝만 닿는다.**

**따라서 4 를 해결하려면 `ankle_l`/`ankle_r` 노드를 추가해 발을 별도 세그먼트로 만들고,
발바닥이 항상 페달면과 평행하도록 회전을 걸어야 한다** — 페달 수평 상쇄와 같은 원리다.
HANDOFF §7-4 가 *"Mapbox 제약이 아니라 우리 계약이다. `nodeOverrideNames` 는 상한 없는
배열"* 이라 적어둔 그 작업이고, 이번에 노드를 10 → 12 로 늘려봤으니 **경로도 확인됐다.**

⚠ 다만 **메시 분해가 필요하다**(발을 정강이에서 잘라내야 한다). 이번 지시의 "Blender·메시
재분해 금지" 범위를 넘으므로 **손대지 않았다.** 비용 판단은 감리·사용자 몫이다.
