## 만들 것
`apps/web/scripts/account-deletion/account-deletion-emulator.e2e.mjs`(신설, 유지되는 시험) — 에뮬레이터(auth·firestore·database·functions) 위에서 **HTTP 로 직접** 서버 함수를 부른다(Google 팝업 재인증은 헤드리스로 못 하므로 Auth 에뮬레이터 이메일 계정으로 최근 로그인 토큰을 만든다).
실행 명령은 기존 `scripts/e2e/run-with-functions-emulator.mjs` 래퍼로, `apps/web/package.json` 에 `test:e2e:account-deletion` 스크립트를 추가해도 된다(이 한 줄은 허용).

### 시나리오
1. 사용자 A(이메일 계정)·B 생성. A 데이터 시드(Admin/REST owner): `users/{A}`(nickname·stripeSubscriptionId 없음), `nicknames/{key}`(ownerUid=A), `savedRoutes`×2, `rides`×2, `conquest/{A}`+`chunks`·`traces`, `routeTokenLedger`(userId=A), `publicRouteRequests`(applicantUid=A), `routePublications`(applicantUid=A), `livePresence/{A}`, `trails/{t}/members/{A}`, RTDB `trails/{t}/motion/{A}`. B 에도 savedRoutes·users 시드.
2. A 토큰으로 POST `deleteAccountHttp` `{ confirmPhrase: "탈퇴" }` → 200 `{ result: { ok: true } }`.
3. 검증: A 의 위 문서 전부 없음 · `routePublications` 는 **남아 있고** `applicantUid==""`·`publisherDeleted==true` · `nicknames/{key}` 없음 · RTDB motion 노드 없음 · Auth 에 A 없음 · **B 데이터는 그대로**.
4. 거부 케이스: (a) 토큰 없음 401 (b) 확인 문구 틀림 400 (c) 익명(게스트) 토큰 → failed-precondition (d) auth_time 이 5분 넘은 토큰 → failed-precondition `requires-recent-login`(에뮬레이터에서 오래된 auth_time 토큰을 만들 수 없으면 사유 기록하고 생략) (e) 같은 사용자 두 번째 호출 → 이미 삭제된 계정이라 401 — 데이터 손상 없음.
