# 계정 탈퇴 — 계획 (2026-10-06, 코드 작성 없음)

## 1. 목표
로그인 사용자가 앱 안에서 스스로 계정을 삭제한다. 개인 데이터는 지우고, 다른 사용자와 공유된 공용 자산은 **익명화**해 남긴다. 결제(구독)는 먼저 해지한다.

## 2. 사용자 데이터 위치 (조사 결과)
| 저장소 | 경로 | 탈퇴 처리(제안) |
|---|---|---|
| Firebase Auth | 계정 | **삭제**(마지막 단계) |
| Firestore | `users/{uid}` (닉네임·등급·이어달리기 슬롯·칼로리 프로필 등) | 삭제 |
| | `nicknames/{key}` | 삭제(닉네임 재사용 가능) |
| | `savedRoutes` (userId) | 삭제 |
| | `rides` (userId) | 삭제 — 단 집계 통계에 쓰였으면 집계값은 유지 |
| | `conquest/{uid}` + `chunks`·`traces` | 삭제 |
| | `pioneerChunks` (최초 정복자 기록 — 공용 세계 지도) | **익명화**(uid → 「탈퇴한 라이더」) — 결정 필요 |
| | `publicRouteRequests` (신청자) | 대기 중은 철회·삭제, 처리 완료분 삭제 |
| | `routePublications` (내가 등록한 퍼블릭 경로) | **결정 필요**: 유지+익명화 / 비공개 전환 / 삭제 |
| | `routeTokenLedger` (토큰 원장) | 결정 필요(회계 기록이면 익명화 보존) |

| Stripe | 구독(`subscriptionCore`·`stripeWebhookHttp`) | **즉시 해지** 후 진행. 결제 기록은 Stripe 쪽 보관(법정 보존) |

※ `firestore.rules` 상 `users` 는 `allow delete: if false` — 클라이언트 직접 삭제 불가. 서버(Cloud Functions, Admin SDK)에서 처리해야 한다.

## 3. 구조
1. **서버 함수 `deleteAccountHttp`(callable/HTTPS, 인증 필수)** — 한 곳에서 순서대로:
   1) 요청자 = 토큰 uid 확인, **최근 로그인(5분 이내) 확인**(Firebase 정책: 계정 삭제는 최근 인증 필요)
   2) Stripe 구독 해지(활성 시)
   3) 라이브 흔적(presence·members·RTDB) 삭제 → 다른 사용자 화면에서 즉시 사라지게
   4) 개인 문서 일괄 삭제(배치·페이지 단위, 실패 시 재시도 가능하게 멱등)
   5) 공용 자산 익명화(결정 결과대로)
   6) 마지막에 Auth 계정 삭제
   - 중간 실패 시 「탈퇴 진행 중」 표식을 `users/{uid}` 대신 별도 `accountDeletions/{uid}` 에 남겨 재실행 가능하게
2. **클라이언트**: 사용자 정보 시트(UserInfoSheet) 맨 아래 「계정 탈퇴」 → 경고 화면(지워지는 것/남는 것 목록) → 닉네임 입력 확인 → Google 재인증 → 서버 호출 → 로그아웃·로컬 정리 → 첫 화면.
3. **게스트(익명) 계정**: 서버 데이터가 적다. 같은 함수로 처리하거나 「기기에서 데이터 지우기」로 단순화 — 결정 필요.
4. 진행 중인 주행·Trail 이 있으면 탈퇴 버튼 비활성(먼저 종료).

## 4. 검증 계획
- 에뮬레이터 e2e: 사용자 A 데이터 시드(경로·주행·정복·퍼블릭 등록·presence) → 탈퇴 → 각 컬렉션에 A 의 uid 가 남지 않음 · 공용 자산은 익명 표기 · Auth 계정 없음 · 사용자 B 화면에서 A 흔적 사라짐.
- 단위: 삭제 대상 목록(컬렉션별 쿼리) 계약 테스트 — 새 컬렉션이 생기면 이 목록을 갱신하지 않으면 실패하도록(「탈퇴 누락」 방지 게이트).
- 재인증 없이 호출 → 거부, 남의 uid → 거부, 두 번 호출 → 안전(멱등).

## 5. 작업 순서(승인 후)
1) 정책 결정 반영 → 2) 서버 함수 + 단위 계약 → 3) Rules 확인(클라이언트 직접 삭제 경로는 열지 않음) → 4) UI → 5) e2e → 6) Chief 배포(functions 포함) → 7) 개인정보처리방침·이용약관 문구 갱신.

## 6. Chief 결정 필요
1. **퍼블릭 경로**(내가 등록한 routePublications): ① 유지·등록자 익명화(추천 — 다른 라이더의 주행 기록·활동이 걸려 있음) ② 비공개 전환 ③ 삭제
2. **정복 지도의 최초 정복(pioneer) 기록**: ① 익명화 유지(추천 — 세계 지도 일관성) ② 삭제
3. **즉시 삭제 vs 유예 기간**: ① 즉시(추천 — 단순) ② 7~30일 유예 후 삭제(그 사이 로그인하면 복구)
4. **게스트 계정**: ① 같은 탈퇴 기능 ② 「이 기기 데이터 지우기」로 단순화
5. **토큰 원장(routeTokenLedger)**: 익명화 보존 / 삭제
