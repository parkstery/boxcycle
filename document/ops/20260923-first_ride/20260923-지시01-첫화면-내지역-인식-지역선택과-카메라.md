## §0 이 라운드의 한 줄

> 첫 사용자가 지도를 열었을 때 **「여기 내가 아는 곳인데」** 가 성립하게 만든다.
> 경로 생성(Ready Ride)은 **이 라운드가 아니다** — 지시02 다.

화면 변화는 **좌하단 카드 + 지도 카메라** 둘이다. 그 밖의 표면을 건드리지 마라.

## §2 구현

### 2.1 컴포넌트

**신규**: `apps/web/src/components/ride/LocalFirstEntryCard.tsx` + `.css`
**배선**: `App.tsx` 에서 `firstRideIntroCard` 가 렌더되던 자리(약 `App.tsx:1910`)를 이 카드로 교체한다.
게이트는 기존 `firstRideIntroVisible` 를 **그대로 재사용**한다 — 새 게이트를 만들지 마라
(`NextRideCard` 와 동시에 뜨면 안 되는 성질이 거기 이미 들어 있다).

`FirstRideIntroCard.tsx` 는 **지우지 마라.** 새 카드 안에서 입문 코스 줄로 흡수하거나,
그대로 렌더하고 위에 지역 블록을 얹거나 — 어느 쪽이든 좋다. 다만 **입문 경로 시작 버튼의
동작(`enterBasicHub`)은 한 글자도 바꾸지 마라.**

### 2.2 카드의 3상태

| 상태 | 화면 | 다음 동작 |
|---|---|---|
| **S0 지역 미정** | 「어디에서 첫 라이딩을 할까요?」 + `[지역 선택]` `[현재 위치]` + 「또는 입문 경로로 시작」 줄 | 두 버튼 중 하나 |
| **S1 지역 확정** | 「**{지명}** · 여기서 첫 Ready Ride」 + `[다시 고르기]` + 입문 경로 줄 유지 | (지시02 에서 생성 버튼이 붙는다) |
| **S2 위치 실패** | 「위치를 확인하지 못했습니다 — 지역을 직접 고르세요」 + `[지역 선택]` (실패 사유 한 줄) | 지역 선택으로 폴백 |

S1 에는 **아직 「Ready Ride 시작」 버튼을 달지 마라.** 누르면 아무 일도 안 일어나는 버튼은
이 라운드의 결과가 아니다. 자리만 비워 두고 지시02 에서 채운다.

### 2.3 `[지역 선택]`

- 기존 지명 검색 패널(`placeSearchOpen` / `PlaceSearchPanel` / `MenuPlaceSearch`)을 **연다**
- 결과를 고르면: ① 카메라 이동(§2.5) ② 카드가 S1 로 ③ 패널 닫기
- 기존 지명 검색의 **본래 용도(메뉴에서 여는 검색)가 깨지면 안 된다.** 호출자에 따라
  「고른 결과를 어디로 보낼지」만 달라져야 한다

### 2.4 `[현재 위치]` — 권한은 여기서만

```
클릭 → navigator.geolocation.getCurrentPosition(성공, 실패, { timeout: 8000, maximumAge: 600000 })
```

- **클릭 전에는 절대 호출하지 않는다.** 마운트·프리페치·「미리 물어보기」 전부 금지
- `navigator.geolocation` 이 없으면 버튼을 **비활성**이 아니라 **미표시**로 하고 S0 를 지역 선택 단독으로 그린다
- 실패·거부·타임아웃(8초) → **S2**. 앱이 멈추거나 로딩이 남아 있으면 안 된다
- 성공하면 좌표를 **지역 단위로 일반화**해서 쓴다 — 역지오코딩으로 **도시/행정구역 이름**을 얻어
  그것을 지명으로 표시한다. **상세 주소·번지를 화면에 쓰지 마라**(실행계획 §3.1)
- 좌표를 로그·분석 이벤트·Firestore 에 쓰지 마라. 화면과 카메라에만 쓴다

### 2.5 카메라 — 「내가 아는 곳」으로 보이는 줌

- `setExternalCameraJump({ lngLat, zoom, requestId })`, `requestId` 는 기존 `cameraJumpSeqRef` 증가 방식 그대로
- 함께 `setFollowMode("free")` · `setActiveQuickCamera(null)` — `NextRideCard` 가 하는 것과 같다
- **줌은 하드코딩 14 로 두지 말고 이 라운드에서 정하라.** 판정 기준은 하나다:
  **폰 가로(740×300)에서 그 화면에 지명 라벨(동·구·시)이 읽히는가.**
  후보 `12 / 13 / 14` 를 같은 도시에서 찍어 비교 캡처를 내고, 고른 값과 이유를 한 줄로 적어라
- 사용자가 지도를 직접 움직인 뒤에는 **다시 점프하지 마라**(`NextRideCard` 의 rideId 1회 가드와 같은 성질 —
  지역 선택 1회당 점프 1회)

### 2.6 선택한 지역의 보존

```
localStorage["rtw.localFirst.region"] = { name, lngLat, zoom, source: "search" | "geolocation", at }
```

- **읽기·쓰기 전부 `try/catch`.** 사생활 보호 모드·차단 환경에서 throw 하거나 빈 값이 온다.
  없으면 S0 로 정상 렌더돼야 한다
- 다음 접속에 값이 있으면 **S1 로 시작**한다(카메라도 그 자리에서 연다)
- 이것이 지시02(Ready Ride 생성)의 **출발점 입력**이 된다. 키 이름을 바꾸려면 감리에 먼저 올려라

### 2.7 터치 (이 리포에서 네 번 반복된 함정)

카드 컨테이너는 `pointer-events: auto`, `onPointerDown`·`onTouchStart` 에서
`stopPropagation()` + `preventDefault()`. **카드를 눌러도 지도가 끌려가면 안 된다.**

## §4 회귀로 깨지 말아야 할 것

1. **이전 주행이 있는 사용자**는 `NextRideCard` 가 그대로 뜬다 — 새 카드가 그 자리를 뺏으면 안 된다
2. 메뉴의 **지명 검색**이 종전대로 동작한다(그 결과가 이 카드에 잘못 꽂히면 안 된다)
3. **입문 경로 시작**이 종전대로 `enterBasicHub` 로 진입한다
4. 주행 시작 후(`riding`) 이 카드는 사라진다. 미니맵·HUD·RouteDock 과 겹치지 않는다
5. Guest(익명 인증)에서도 동작한다 — **인증 전에는 이 카드가 뜨지 않는다**(기존 `user` 가드 유지)

**권한 프롬프트 게이트 — 자가 검산을 붙여 숫자로 증명하라.**
`getCurrentPosition` 호출을 세는 계수기를 임시로 감싸고 다음을 보고한다.

| 시점 | 기대 | 실측 |
|---|---|---|
| 앱 로드 ~ 카드 S0 표시까지 `getCurrentPosition` 호출 수 | **0** | |
| `[현재 위치]` 1회 클릭 후 호출 수 | **1** | |
| `[지역 선택]` 만 눌렀을 때 호출 수 | **0** | |

> ⚠ 「0 이 나왔다」만 쓰면 반려한다. **계수기가 실제로 세고 있음을 먼저 증명하라** —
> 클릭 시 1 로 올라가는 행이 같은 표에 있어야 0 이 의미를 갖는다.
> 항상 0 을 반환하는 계측은 게이트가 아니라 **자동 통과 장치**다.

`localStorage` 보존 검산:

| 항목 | 실측 |
|---|---|
