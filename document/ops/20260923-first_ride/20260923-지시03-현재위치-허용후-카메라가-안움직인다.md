## §1 증상 (Chief 실기, 배포본 `b15339c`)

> 「현재 위치를 선택하면 허용 여부를 물어온다. **허용을 클릭하면 현재 위치로 이동을 해야 하는데
>  이동하지 않는다. 새로 고침을 하면 나의 현재 위치로 이동된다.**」

핵심: **새로고침하면 이동한다** = 좌표는 `localStorage` 에 정상 저장됐다
= `onConfirmRegion` → `applyLocalFirstRegion` 이 실행됐고 `writeLocalFirstRegion` 도 됐다는 뜻이다.
**저장은 되는데 그 순간의 카메라 점프만 화면에 반영되지 않는다.**

## §2 감리가 읽어 둔 것 (출발점 — 여기서부터 시작하라)

| 위치 | 내용 |
|---|---|
| `App.tsx` `applyLocalFirstRegion` (약 1967행) | `setLocalFirstRegion` → `writeLocalFirstRegion` → `setExternalCameraJump({lngLat, zoom, requestId})`. **검색·현재위치 두 경로가 이 함수를 공유한다** |
| `App.tsx` 복원 효과 (약 2014행) | `firstRideIntroVisible && localFirstRegion` 일 때 `localFirstFramedAtRef` 가드로 1회 점프. **새로고침이 동작하는 건 이 경로다** |
| `MapView.tsx` (3756행) | `if (!map || !mapLoaded || !externalCameraJump) return;` → `map.stop()` → `flyTo/fitBounds`. deps `[externalCameraJump, mapLoaded, prefersReducedMotion]` |
| `LocalFirstEntryCard.tsx` `handleUseCurrentLocation` | `getCurrentPosition` 성공 → **`await fetchMapboxReverseGeocodeRegionLabel(...)`** → `onConfirmRegion(...)` |

**두 경로의 유일한 구조적 차이는 「동기 vs 비동기」다.**
지명 검색은 사용자 클릭 → 곧바로 확정. 현재 위치는 권한 프롬프트(수 초) → 역지오코딩 await → 확정.
그 사이에 다른 카메라 주체가 끼어들 시간이 있다.

## §3 먼저 원인을 확정하라. 고치지 마라 (STEP 1)

**추측으로 고치지 마라.** 아래를 계측해 **어디서 끊기는지 한 줄로 확정**한 뒤 보고하고 STEP 2 로 간다.

| # | 확인할 것 | 방법 |
|---|---|---|
| C1 | `applyLocalFirstRegion` 이 실제로 호출되는가, 그때 `region` 값은? | 임시 로그 |
| C2 | `setExternalCameraJump` 가 **새 requestId** 로 dispatch 되는가 | 임시 로그 |
| C3 | `MapView` 의 소비 효과가 **실행되는가**, 아니면 `!mapLoaded` 등 가드에서 빠지는가 | 가드 각각을 로그로 구분 |
| C4 | `flyTo` 가 호출된 뒤 **누가 카메라를 되돌리는가** — `map.on('movestart'/'moveend')` 로 이동 전후 center 를 찍어라 | 다른 카메라 주체(팔로우·QuickCamera·초기 프레이밍)가 덮는지 |
| C5 | 카드가 **S1 으로 바뀌는가**(「○○ · 여기서 첫 Ready Ride」) | 바뀐다면 상태는 정상이고 지도만 문제 |

재현 방법(실기 없이):
- Playwright `context.grantPermissions(['geolocation'])` + `setGeolocation({latitude, longitude})` 로
  **성공 콜백 경로**를 태운다
- 권한 프롬프트의 체감 지연을 흉내 내려면 `getCurrentPosition` 을 **의도적으로 2~3초 지연**시켜
  비동기 간격을 벌려라 — 증상이 타이밍 경합이면 여기서 재현된다
- 역지오코딩도 실제로 네트워크를 타므로 **느린 응답**(예: 1.5초)을 함께 시험하라

> ⚠ **재현하지 못한 채 고치지 마라.** 재현이 안 되면 그 사실을 보고하라 — 그때는 Chief 실기에서
> 로그를 받는 쪽으로 방향을 바꾼다. 「아마 이것일 것이다」로 코드를 고치면 같은 증상이 남는다.

## §4 고친다 (STEP 2 — 원인 확정 후)

원인에 따라 고치되, **다음 원칙을 지켜라.**

- **두 경로가 같은 함수를 공유하는 구조를 깨지 마라.** 현재 위치 전용 우회로를 새로 만들지 마라
- 카메라 주체가 경합한다면 **점프가 이기게** 하라 — 다만 기존 주체(주행 팔로우·QuickCamera·
  NextRide 앵커)의 동작을 바꾸지 마라. 첫 화면 idle 구간에 한정한다
- 비동기 완료 시점에 컴포넌트가 사라졌거나 `mapLoaded` 가 아직이면, **점프를 버리지 말고
  조건이 갖춰질 때 적용**되게 하라(새로고침이 동작한다는 건 복원 경로가 그 일을 한다는 뜻이다)
- `localFirstFramedAtRef` 가드를 없애지 마라 — 사용자가 지도를 움직인 뒤 재점프하는 회귀가 난다

## §5 회귀로 깨지 말아야 할 것

1. **지명 검색 경로**의 카메라 이동(종전대로)
2. **새로고침 복원** 경로(지금 유일하게 동작하는 경로다 — 이걸 깨면 더 나빠진다)
3. 권한 **거부·타임아웃** 시 S2 폴백
4. 주행 중 카메라·QuickCamera 1~6·NextRide 앵커 점프
5. 첫 화면 권한 프롬프트 0회(`getCurrentPosition` 계수 로드 0 / 클릭 1) — 계측기는 dev 가드 안에 있다

# B. 폐합 실패가 막다른 골목이다 (Chief 실기 — 배포본)

## §B1 증상

카드에 「**이 지역에서는 순환 경로를 찾지 못했습니다**」 + `[다시]` · `[지역 다시 고르기]` 만 남는다.
사용자는 **달릴 것을 아무것도 받지 못한 채 또 선택을 강요**당한다.

> 「순환경로를 찾지 못했다고 또 다음 질문을 묻는 것은 UX 측면에서 좋지 않다.
>  **순환경로가 아닌 경로를 제시하는 게 좋고, 다른 경로를 선택할 기회도 동시에 주는 게 필요하다.**」(Chief)

## §B2 ⚠ 지시02 규칙의 정정

지시02 §2 E4 는 「폐합 실패 시 편도로 **조용히** 낙하하지 마라」였다. 그 취지(사용자를 속이지 마라)는
유지하되, **결과를 안 주는 것은 더 나쁘다**는 Chief 판단으로 다음과 같이 바꾼다.

> **원칙: 결과 없이 되묻지 않는다.** 항상 **달릴 수 있는 경로 하나**를 내놓고,
> 그것이 순환이 아니면 **그 사실을 말해 주고**, 마음에 안 들면 **바꿀 수 있게** 한다.

「조용히」가 금지된 것이지 「편도」가 금지된 것이 아니다.

## §B3 구현

### 서버

- `searchReadyLoopRoute` 가 폐합 후보를 못 찾으면 **실패로 끝내지 말고 편도 대안을 만든다**
- 편도 대안은 **기존 `searchDistanceAutoRoute` 를 재사용**하라. 새 알고리즘을 만들지 마라 —
  방위 자동 표본 중 가장 점수가 좋은 방위를 골라 그 함수에 넘기면 된다
- 응답에 **`closed: boolean`**(또는 동등한 플래그)을 실어 클라이언트가 순환/편도를 구분하게 하라
- 편도조차 못 만들면 그때는 실패다(도로 없음 등). 그 경우만 실패 문구를 쓴다
- 호출 예산 13회를 넘기지 마라. 폐합 시도에서 이미 5회를 썼다면 남은 예산 안에서 편도를 만든다

### 클라이언트 — 카드

성공(순환):
```
○○ · 여기서 첫 Ready Ride
[Ready Ride 시작]  [다른 경로]  [다시 고르기]
```

폐합 실패 → 편도 대안:
```
○○ · 여기서 첫 Ready Ride
순환 경로를 찾지 못해 편도 경로를 만들었어요
[Ready Ride 시작]  [다른 경로]  [다시 고르기]
```

- **경로는 이미 지도에 그려져 있어야 한다.** 문구만 다르고 사용자가 할 수 있는 일은 같다
- **`[다른 경로]`** 는 방위를 바꿔 **다음 후보**를 만든다(같은 결과를 반복해 내놓지 마라 —
  직전에 쓴 시작 방위를 제외하고 다음 표본을 쓴다). 누를 때마다 다른 경로가 나와야 한다
- `[다시]`(재시도) 라는 이름을 쓰지 마라 — 실패를 전제한 말이다. **`[다른 경로]`** 다
- 진짜 실패(편도도 불가)일 때만 지금의 실패 문구 + `[다시]` · `[지역 다시 고르기]` 를 쓴다

### 토큰

**이 라운드에서도 토큰을 건드리지 마라**(지시02 정정 유지). `[다른 경로]` 가 기존 규칙대로
토큰을 쓰는 것은 그대로 둔다 — Chief 의 「무제한」 결정은 별도 라운드에서 적용한다.
