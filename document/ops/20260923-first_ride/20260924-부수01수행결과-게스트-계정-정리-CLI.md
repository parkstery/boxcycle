# 부수01 수행결과 — 게스트(익명) 계정 정리 CLI

담당: 개발팀장(Claude) · 2026-09-24

## 1. 배경

테스트 반복으로 Firebase Auth 에 익명(Guest) 계정이 다수 누적됨. 입문자 첫 경험 테스트를 방해하므로,
익명 계정 전부와 그 Firestore 귀속 데이터를 지우는 관리용 CLI 를 만든다(Google 등 provider 실계정은 제외).

## 2. 만든 파일

- `functions/src/purgeGuestUsersCore.ts` — 판정·조사·삭제 로직 본체
- `functions/src/cliPurgeGuestUsers.ts` — CLI 진입점(기존 `cliPurgeDiscardableRides.ts` 구조 모방: `arg()`/`hasFlag()` 파서, `initFirebaseAdminForCli`, `JSON.stringify` 요약 로그)

## 3. 등재한 npm 스크립트

- `functions/package.json` → `"admin:purge-guest-users": "npm run build && node lib/cliPurgeGuestUsers.js"`
- 루트 `package.json` → `"admin:purge-guest-users": "npm --prefix functions run admin:purge-guest-users --"`

## 4. 익명 판정 · 제외 규칙

- 익명 판정: `user.providerData.length === 0 && !user.email && !user.phoneNumber` 셋 다 만족해야 포함.
- custom claims 에 `/admin/i` 매치 키가 truthy 로 있으면 무조건 제외(조사 로그에 제외 목록을 별도 출력).
- 실행 직전 안전장치: 삭제 대상 각 uid 를 `auth.getUser()` 로 재조회해 `isAnonymousUserRecord()` 재검증. 하나라도 실패하면 **그 uid 를 로그에 남기고 즉시 프로세스를 중단**(판정 로직 결함으로 간주, provider 계정 오염 방지).

## 5. 삭제 대상 Firestore 경로 확정 목록과 근거

`functions/src` 전체와 `firestore.rules` 를 읽고 uid 귀속 경로를 확인했다.

### 5.1 삭제 대상 (`--yes` 시 실제로 지움)

| 경로 | uid 연결 근거 |
|---|---|
| `users/{uid}` | 문서 id = uid (`firestore.rules` `match /users/{userId}`) |
| `conquest/{uid}` | `conquestOnRideCreated.ts:123` `db.doc(\`conquest/${userId}\`)` |
| `conquest/{uid}/chunks/*` | `cliAuditConquest.ts:89` |
| `conquest/{uid}/traces/*` | `cliAuditConquest.ts:95` |
| `rides` where `userId==uid` | `firestore.rules` `match /rides/{rideId}` — `resource.data.userId` |
| `savedRoutes` where `userId==uid` | `firestore.rules` `match /savedRoutes/{routeId}` |
| `routeTokenLedger` where `userId==uid` | `routeTokenCore.ts` 문서 id 는 idempotencyKey 해시(uid 아님) — `data.userId` 필드로 조회 |
| `livePresence/{uid}` | 문서 id = uid (`firestore.rules` `match /livePresence/{userId}`) |
| `openTrailListings` where `hostUid==uid` | 문서 id = trailId, `hostUid` 필드로 조회. Trailhead 목록 항목(ephemeral) — 다른 사용자의 개인 데이터를 침범하지 않음 |
| `trails/{trailId}/members/{uid}` | 문서 id = uid(`firestore.rules` `match /trails/{trailId}/members/{userId}`) — collection group `members` 스캔 후 부모 경로가 `trails/*` 인 것만 구분 |
| `publicationSessions/{publicationId}/members/{uid}` | 동일 규칙, `firestore.rules` `match /publicationSessions/{publicationId}/members/{userId}` — subcollection 이름이 `trails/*/members` 와 같은 `members` 라 한 번의 collection group 스캔에서 부모 컬렉션명(`trails` vs `publicationSessions`)으로 분리 |
| `trails/{trailId}/livePublicationRides/{uid}` | 문서 id = uid, collection group `livePublicationRides` |
| `publicRouteRequests` where `applicantUid==uid` | `firestore.rules` `match /publicRouteRequests/{requestId}` |

### 5.2 확인만 하고 삭제하지 않는 것(보고 전용, `REPORT-ONLY` 라벨)

- **`routePublications`** — 공개 경로. 익명 사용자가 만든 것이 있으면 다른 사용자 화면에 영향이 가므로
  지우지 않고 개수만 보고한다. `savedRoutes(userId==uid)` → 그 문서 id(routeId) 로 `routePublications.routeId in [...]`
  역참조해 개수를 센다. **실제로는 rules 상 익명(`tier: 'anonymous'`)은 `publicRouteRequests` 조차
  생성할 수 없다(`userTierAllowsPublicRoute()` 가 `registered_free|registered_paid|admin` 만 허용)** —
  실행 결과도 전원 `routePublicationsOwned=0` 으로 이 구조적 제약과 일치한다.
- **`trails/{trailId}` 문서 자체**(`hostUid==uid`) — 지우면 그 trailId 를 참조하는 다른 참가자의
  `members`/`livePublicationRides` 서브컬렉션이 고아가 된다(문서 하나 지운다고 서브컬렉션이 같이 지워지지
  않는 Firestore 특성 + 다른 실사용자 영향 가능성). 개수만 `trailsHostedReportOnly` 로 보고.
- **`publicationPresence/{publicationId}`** — 문서 id 가 publicationId(경로 단위 집계)이지 uid 가 아니라서
  애초에 uid 로 귀속되지 않는다. 대상에서 제외.

## 7. 사용법

```bash
# 조사만(기본, 아무것도 안 지움)
npm run admin:purge-guest-users

# 실제 삭제 — 전체
npm run admin:purge-guest-users -- --yes

# 실제 삭제 — 50건 제한
npm run admin:purge-guest-users -- --yes --limit=50

# 서비스 계정 파일 지정
npm run admin:purge-guest-users -- --serviceAccount=/abs/path.json
```

`--yes` 실행 시 uid 단위로 `[DELETE] uid=... ok — firestore N건 삭제` 로그를 남기고, 마지막에
`{ authDeleted, firestoreDocsDeleted, failed }` 합계를 출력한다. 실패한 uid 는 중단하지 않고 계속 진행 후
목록으로 별도 출력한다. 실행 전 대상 uid 목록은 항상
`document/ops/20260923-first_ride/.out/guest-purge/<timestamp>_{dry-run|delete}.json` 로 저장된다.

## 9. 남은 판단(감리 몫)

- `trails/{trailId}` 문서 자체(guest 가 host, 88건) 를 어떻게 할지 — 그대로 두면 폐쇄된 Trailhead 로 남고,
  지우면 다른 실사용자의 서브컬렉션이 고아가 될 수 있음. 이번 CLI 는 건드리지 않음.
  필요하면 별도 CLI(`admin:cleanup-orphan-trails` 류)로 후속 처리 권장.
