## §3 구현

### 3.1 서버 — `distanceAutoRouteCore.ts` 확장

지금 계약은 **방위(`bearingDeg`)를 사용자가 준다**는 전제다. Ready Ride 는 그걸 안 받는다.

**① 방위 자동 선택**
`bearingDeg` 를 **선택 인자**로 만들고, 없으면 시작 방위를 **균등 표본**으로 훑어라
(예: 0°/72°/144°/216°/288° — 개수는 호출 예산 안에서 네가 정하고 근거를 적어라).
기존 `AUTO_ROUTE_BEARING_OFFSETS_DEG`(±30°) 는 **주어진 방위의 미세 조정**이므로 역할이 다르다.
둘을 섞지 마라.

**② 폐합(출발 = 도착)**
Directions 는 왕복을 직접 만들지 않는다. **waypoint 를 태워 되돌아오게** 하라 —
서버는 이미 `waypoints` 를 파싱해 넘긴다(`functions/src/index.ts` `parseWaypoints`).

- 최소 형태: `start → W1 → W2 → start` (삼각). 목표 거리 D 에 대해 W 는 **D/3 안팎**의 반경에
  방위를 벌려 배치한다. 4점(사각)도 후보로 허용
- **같은 길로 되돌아오는 형태(out-and-back)는 폐합으로 치지 마라** — 왕복 접힘은 중복 100% 다.
  최소한 「갔다 다른 길로 온다」여야 한다. 자기 중복 비율을 **수치로 보고**하라(§6)
- 폐합 실패 시(예산 내 후보 없음) **편도로 조용히 낙하하지 마라.** 실패를 실패로 보고하고,
  사용자에게는 「이 지역에서는 순환 경로를 찾지 못했습니다」로 노출하라

**③ 거리 허용 오차**
목표 3km 기준 **±20%**(기존 `MAX_DISTANCE_ERROR_RATIO`)를 그대로 쓴다. 폐합에서는 정확 절단
(`clipRouteGeometryToTargetMeters`)이 시작점으로 돌아오는 성질을 깨뜨릴 수 있다 —
**절단으로 폐합을 깨지 마라.** 어느 쪽을 우선했는지 보고에 명시하라

**④ 알고리즘 버전**
`AUTO_ROUTE_ALGORITHM_VERSION` 을 올려라(예: `4A-ready-loop`). 지금 값 `3I-shortfall` 을 그대로 두지 마라

### 3.2 출발점 — 지역 중심은 도로 위가 아니다

`rtw.localFirst.region.lngLat` 는 행정구역 중심점이라 **건물 한가운데일 수 있다.**
기존 계약의 `targetRoadPoint` 개념(클릭점 → 도로 스냅)을 재사용해 **가장 가까운 주행 가능 도로**로
스냅한 뒤 출발점으로 삼아라. 스냅 전후 좌표와 이격 m 를 보고하라.

### 3.3 클라이언트 — S1 카드에 버튼을 채운다

- S1 에 **「Ready Ride 시작」** + 거리 선택(**3 km 기본**, 2/5/10)
- 생성 중에는 진행 표시. **8초를 넘기면** 「경로를 찾는 중입니다」를 유지하되 취소 가능하게 하라
- 성공: 생성된 Route 를 지도에 그리고 **기존 주행 준비 흐름(Go 게이트)에 그대로 얹어라.**
  새 시작 경로를 만들지 마라 — 센서 준비 게이트·Go 계약을 우회하면 안 된다
- 실패: 카드 안에서 사유 한 줄 + `[다시]` · `[지역 다시 고르기]`. 지도를 비우지 마라
- 카피: 「Ready Ride 시작」 · 「3 km」 · 「다른 거리」. 음차·번역 금지

### 3.4 Token (E5)

첫 Ready Ride 1건은 차감하지 않는다. 다만 **무한 재생성은 막아야 한다** —
같은 지역에서의 **재생성 2번째부터는 기존 Token 규칙을 그대로 적용**하라.
어디서 「첫 1건」을 판정했는지(클라이언트 상태인지 서버인지) 보고에 적어라.
서버 규칙을 우회하는 클라이언트 플래그는 **금지**다.

## §4 회귀로 깨지 말아야 할 것

1. 기존 **거리·방향 자동 Route**(사용자가 지도를 클릭해 방향을 주는 흐름)가 그대로 동작한다 —
   `bearingDeg` 를 선택 인자로 바꾸면서 기존 호출을 깨뜨리기 쉽다. **두 경로 모두 캡처로 증명하라**
2. Route Token 차감이 기존 흐름에서 종전과 같다(첫 Ready Ride 만 예외)
3. 지시01 의 S0/S1/S2 와 입문 경로 병존이 그대로다
4. Go 게이트·센서 준비 흐름 불변

## §6 수치 보고

**좌표 6곳 이상**에서 돌려라. 국내 3(도심·주택가·외곽) + 해외 3(유럽·북미·아시아 타도시).

| 좌표(지명) | 목표 | 생성 성공 | 실거리 | 오차% | 자기중복% | 프로바이더 호출 수 | 폐합 여부 |
|---|---|---|---|---|---|---|---|
| … | 3km | | | | | | |

- **자기 중복%** = 경로가 자기 자신과 겹친 구간 길이 / 전체 길이. 계산식을 보고에 적어라
- **호출 수는 13 이하**여야 한다. 넘으면 그 좌표를 실패로 적어라
- 출발점 스냅: 지역 중심 → 도로 스냅 이격 m
- 시작 방위 표본 개수와 그 근거 한 줄

> ⚠ **성공률만 쓰지 마라.** 실패한 좌표가 왜 실패했는지(도로 없음 / 예산 초과 / 폐합 불가)를
> 구분해 적어라. 「6/6 성공」만 있고 실패 분류가 없으면 반려한다.
