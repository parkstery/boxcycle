# A. 첫 화면 중심이 강남에 고정돼 있다

## §A1 문제

`MapView.tsx:1016 DEFAULT_CENTER = [127.035, 37.505]` — 강남이다.
위치를 거부하거나 지역을 안 고른 사용자는 **원주에 있어도 강남에서 시작**한다.
줌은 지시06 에서 13 으로 고쳤으니 **중심만** 남았다.

## §A2 감리 결정 (다르게 원하면 정정한다)

> **마지막 주행 위치 → 없으면 기존 기본(강남).**

- 재방문자에게 가장 자연스럽다 — 어제 달리던 곳에서 다시 연다
- 첫 사용자는 지금과 똑같다(회귀 없음)
- 국가 추정·IP 측위 같은 것은 **하지 마라**. 새 외부 의존을 들이지 않는다

## §A3 구현

- 마지막 주행 위치의 출처는 **이미 있는 것**을 써라 — `NextRideCard` 가 쓰는 재개 앵커,
  `rides` 의 마지막 종료점, 또는 `rtw.localFirst.region` 중 **가장 싸게 얻어지는 것**.
  무엇을 골랐는지와 이유를 보고서에 한 줄
- **우선순위**: `localFirstRegion`(사용자가 고른 지역) > 마지막 주행 위치 > 기존 기본
- 지도를 한 번 띄운 뒤에는 재점프하지 않는다(지시01 의 1회 가드와 같은 성질)
- 주행 카메라·Quick Camera·NextRide 앵커에 **영향이 가면 안 된다**

# C. 주행 결과에 「새 도로 +N km」를 세운다

## §C1 배경

Claim 연동(지시08)으로 **안 달린 길을 우선 제안**하게 됐다. 그런데 사용자는 자기가
**새 도로를 얼마나 땄는지** 결과 화면에서 또렷이 보지 못한다. 핵심 판타지의 보상 표면이다.

데이터는 **이미 서버에 있다** — `rides/{id}.conquestResult.newMeters`.

## §C2 구현

- `RideSummarySheet` 에서 **「새 도로 +N km」를 오늘 거리와 나란히 세운다**
- 지시 09 이전에도 한 줄로 존재했다면, **위계를 올리는 것**이 이번 일이다
- **0 일 때는 표시하지 마라**(기존 규칙: 50m 미만 미표시). 0 노출은 실패감만 준다
- 집계가 늦게 도착하면(서버 트리거) **자리를 비워 두고 도착하면 채워라.** 「0 km」로 먼저
  보여 주고 나중에 바꾸지 마라 — 사용자는 첫 숫자를 기억한다
- 시트는 이미 컴팩트하다(4줄). **줄 수를 늘리지 마라** — 기존 요소의 위계를 바꿔라

## §C3 캡처

| # | 파일 | 확인 |
|---|---|---|
| C1 | `03-summary-new-road.png` | 새 도로가 있는 주행의 결과 시트 |
| C2 | `04-summary-zero.png` | 새 도로 0(전부 이미 달린 길) — **표시되지 않는다** |

# B. LF-4 관측 — 기존 Ride 기록만으로 산출한다

## §B1 범위를 좁힌다

> 「측정 구현은 **기존 Ride 기록으로 가능한 항목부터** 재사용한다.」
> — [260907 실행계획 §5](../../260907-RTW-도로망-성취경험-실행계획.md)

**이번 라운드에서 클라이언트에 새 이벤트를 심지 마라.** 새 이벤트는 보관 기간·접근 권한·
개인정보 정리가 선행돼야 한다. 지금은 **이미 쌓인 데이터를 읽는 집계 스크립트**만 만든다.

## §B2 만들 것

`functions/src/cliRideMetrics.ts` — 기존 `cli*.ts` 구조를 그대로 모방.
등재: `admin:ride-metrics`

산출 지표(전부 `rides` + `users` 로 계산 가능한 것만):

| 지표 | 정의 |
|---|---|
| 첫 주행 완료율 | 계정 중 유효 Ride 를 1건 이상 남긴 비율 |
| **72시간 내 2번째 주행률** | 첫 유효 Ride 이후 72시간 안에 두 번째 유효 Ride 가 있는 계정 비율 |
| 다른 날 재사용 | 첫 Ride 와 **다른 현지 날짜**에 유효 Ride 가 있는 계정 비율 |
| 신규 도로 Claim 비율 | `conquestResult.newMeters` 합 / 총 주행 거리 |
| 주행당 평균 신규 도로 km | — |

- **유효 Ride 의 정의는 기존 것을 써라**(`rideRecordPolicy` 의 최소 거리·시간). 새로 정하지 마라
- 익명(Guest)과 provider 계정을 **나눠서** 내라 — 오늘 371개를 지웠으므로 표본이 얕다는 것도 함께 적어라
- 출력은 표 + JSON(`.out/jisi09/ride-metrics.json`)
- **개인정보 금지**: 좌표·주소·이메일을 출력하지 마라. uid 는 집계에만 쓰고 목록으로 뱉지 마라

## §B3 실행

조사 전용이다. **읽기만 한다.** 쓰기·삭제 경로를 만들지 마라.
실제로 한 번 돌려서 **현재 숫자**를 보고서에 넣어라(표본이 작으면 작다고 적어라).
