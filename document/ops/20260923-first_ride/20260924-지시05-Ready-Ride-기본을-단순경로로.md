## §1 Chief 결정 (이 라운드의 근거)

> 「거리가 짧을 때 순환경로를 만든다는 것 자체가 쉽지 않은 일이다.
>  **순환경로에 목매지 말고 단순 경로로 진행하라.**」(Chief, 2026-09-24)

지시04 실측이 이 판단을 뒷받침한다 — **폐합 성공률 논현동 10% · 서울 0% · 수도권 20곳 5%**.
즉 지금 구조는 **호출 예산 5회를 써서 95% 실패한 뒤에야** 편도로 내려간다.

**그리고 이 앱은 실내 주행이다. 출발지로 돌아올 이유가 없다.** 폐합을 기본으로 잡은 것은
감리의 판단 착오였다(실행계획 Q3). 뒤집는다.

## §2 바뀌는 계약

| 항목 | 종전 | **이번 라운드** |
|---|---|---|
| Ready Ride 기본 | 폐합(출발=도착) 시도 → 실패 시 편도 | **처음부터 단순 경로(편도)** |
| 폐합 | 기본 동작 | **기본에서 제외.** 코드는 지우지 말고 호출하지 않는다 |
| 실패 문구 | 「순환 경로를 찾지 못해 편도 경로를 만들었어요」 | **삭제**(§4) |
| 호출 예산 | 폐합 5회 + 편도 | 편도에 전부 쓴다 |

## §3 구현

### 서버

- Ready Ride 요청의 기본 경로를 **`searchDistanceAutoRoute`(단순 경로)** 로 바꾼다.
  이미 존재하고 클릭 방식이 쓰는 검증된 함수다 — **새 알고리즘을 만들지 마라**
- 방위는 지금처럼 **자동 표본**으로 고른다(클릭이 없으므로). 표본 개수·선택 방식은
  편도 기준으로 다시 잡아도 좋다 — 바꿨다면 근거를 수치로 적어라
- `closeLoop` 파라미터와 `searchReadyLoopRoute` 는 **삭제하지 마라.** 클라이언트가
  기본으로 보내지 않을 뿐이다(나중에 「순환 경로」를 선택지로 되살릴 수 있게)
- V1~V3 기하 검사(지시04)는 그대로 통과해야 한다

### 클라이언트

- 「Ready Ride 시작」이 **단순 경로**를 만든다. 거리 선택(2/3/5/10 km)은 그대로
- **실패 사과 문구를 없앤다.** 편도가 기본이므로 설명할 것이 없다 —
  경로가 나오면 그냥 나온 것이다
- `[다른 경로]` 는 유지한다(직전 방위 제외, 지시03에서 만든 것)
- 진짜 실패(도로 없음 등)일 때만 실패 문구를 쓴다

## §4 카피

지시03에서 넣은 「순환 경로를 찾지 못해 편도 경로를 만들었어요」 **한 줄을 제거**한다.
성공 시 카드는 지역명과 거리만 말한다. 금지어·용어는 Ontology 를 따른다(「Ready Ride」는
영문 그대로, 조사 붙임).

## §5 성공 기준 — **숫자가 게이트다**

캡처가 아니라 **실측 성공률**로 판정한다.

| 항목 | 기준 |
|---|---|
| 수도권 20곳 × 3 km 생성 성공률 | **≥ 90%** |
| 논현동 5곳 × 2 km·3 km | **≥ 90%** |
| 거리 오차 | 목표 대비 ±20% 이내 |
| 프로바이더 호출 수 | 좌표당 **13 이하** |
| V1~V3 위반으로 버려진 후보 | 보고에 건수와 사유 |

⚠ **측정은 실제 Mapbox 호출로만 한다.** synthetic·인터셉트 측정은 **인정하지 않는다** —
지시02의 「성공 6/8」이 synthetic이었고 실측은 5%였다. 같은 일을 반복하지 마라.
지시04가 쓴 실측 스크립트(`.out/jisi04/*.mjs`)를 재사용하라.

**기준 미달이면 그 사실을 그대로 보고하라.** 숫자를 맞추려고 측정 방법을 바꾸지 마라.
