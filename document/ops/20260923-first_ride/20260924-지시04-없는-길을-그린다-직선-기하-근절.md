## §1 증상

Ready Ride 편도 폴백이 **도로가 아닌 직선**을 경로로 내놓는다.
Chief 실기 캡처: 마포구에서 출발한 경로가 **한강을 직선으로 가로질러** 영등포구까지 이어진다.
RouteDock 경유지도 「마포구 월드컵로…」 → 「영등포구 안양남…」로, 강 건너로 찍혀 있다.

> 「경로를 탐색 못하면 이 녀석은 **없는 길을 만들어 내는 못된 짓**을 하는 경향이 있어.
>  **전에도 이런 짓을 하더라고.**」(Chief)

**재발하는 부류다.** 이번 한 건을 고치는 것으로 끝내지 마라 — §4 의 불변식이 이 라운드의 본체다.

## §2 이미 배제된 가설 (다시 파지 마라)

| 가설 | 판정 |
|---|---|
| 하네스 가짜 Mapbox(`fetchHarnessFakeDirections`)가 프로덕션에서 켜졌다 | **배제.** `resolveHarnessActive` 는 `FUNCTIONS_EMULATOR==="true"` AND projectId`demo-rtw-route-token` AND `RTW_ROUTE_TOKEN_HARNESS==="1"` 세 조건 AND(fail-closed). 프로덕션에서 켜질 수 없다 |
| Mapbox 토큰 누락으로 가짜로 낙하 | **배제.** 토큰이 없으면 `fetchDirectionsRoute` 가 `failed-precondition` 을 **throw** 한다. 낙하 경로가 없다 |

## §3 STEP 1 — 원인을 서버 증거로 확정하라 (고치기 전에)

**어디서 직선이 만들어지는지 데이터로 잡아라.** 추측 금지.

가장 값싼 판별식: **좌표 개수**다. 3 km 실도로 경로는 수백 점이다. 직선은 2~수 점이다.

| # | 확인 | 방법 |
|---|---|---|
| D1 | 편도 폴백이 Directions 를 **실제로 호출**했는가 | 호출 URL·응답 상태·소요시간 로그 |
| D2 | 응답 geometry 의 **좌표 개수**와 총 연장 | 로그. 여기서 2~수 점이면 provider 응답 자체가 직선 |
| D3 | 서버가 클라이언트로 내보내는 geometry 의 좌표 개수 | D2 와 다르면 **서버 내부 가공**(절단·병합·캐시)이 범인 |
| D4 | 클라이언트가 지도에 그리는 좌표 개수 | D3 와 다르면 클라이언트 파싱·렌더가 범인 |
| D5 | `writeCache`/`readCache` 왕복에서 geometry 가 보존되는가 | `geometryJson` 직렬화·역직렬화 손실 여부 |
| D6 | 폐합(성공) 경로에서도 같은 일이 생기는가 | 편도 전용 문제인지 공통 문제인지 가른다 |

- **실제 운영 백엔드를 쳐라.** 인터셉트·synthetic 으로는 이 결함을 재현할 수 없다 —
  지시02·03 의 캡처가 전부 인터셉트였기 때문에 이 결함이 두 라운드를 통과했다
- 재현 좌표는 Chief 캡처와 같은 **마포구 월드컵로 일대, 목표 3 km** 를 쓴다
- 원인을 **한 줄로 확정**해 보고한 뒤 STEP 2 로 간다

## §4 STEP 2 — 불변식을 세워라 (이 라운드의 본체)

원인을 고치는 것과 **별개로**, 없는 길이 다시는 사용자 화면에 나가지 못하게 막는다.

### 서버 — 경로를 내보내기 전 검사

`distanceAutoRouteCore.ts` 에 **경로 타당성 검사**를 넣고, 성공 응답 직전에 **반드시** 통과시켜라.

| 검사 | 기준 | 위반 시 |
|---|---|---|
| V1 좌표 밀도 | 총 연장 대비 좌표 수가 비정상적으로 적으면 도로 경로가 아니다. 기준값은 **네가 실측으로 정하고 근거를 적어라**(실제 cycling 응답 여러 건의 점/km 분포를 재라) | 그 후보를 **버린다** |
| V2 최장 직선 구간 | 인접 두 좌표 사이 거리가 **임계값 초과**면 도로가 아니다. 임계값도 실측 근거로 정하라(교외 직선도로가 있으니 과하게 조이지 마라) | 그 후보를 **버린다** |
| V3 출발점 정합 | geometry 첫 점이 요청 start 에서 지나치게 멀면 잘못된 응답이다 | 버린다 |

- **검사에 걸리면 조용히 다른 후보로 넘어가고, 모든 후보가 걸리면 정직하게 실패**시켜라.
  없는 길을 내보내느니 실패가 낫다 — 이건 지시03 의 「막다른 골목 금지」보다 우선한다
- 검사 결과를 진단 로그에 남겨라(몇 개 후보가 왜 버려졌는지)
- **기존 클릭 기반 경로에도 같은 검사를 적용하라.** Chief 가 「전에도」라고 한 이상
  Ready Ride 전용 문제로 보지 마라

### 단위 시험 (필수)

`functions` 에 시험을 추가하라. 최소 세 건:
1. 실제 cycling 응답 샘플(좌표 다수) → **통과**
2. 직선 2점 geometry → **거부**
3. 한강 횡단 같은 장거리 단일 구간이 낀 geometry → **거부**

> ⚠ 시험 데이터를 직선으로만 만들지 마라. **통과해야 할 진짜 경로 샘플**이 없으면
> 기준이 과도하게 조여져 정상 경로까지 버리는 반대 사고가 난다.

## §5 회귀로 깨지 말아야 할 것

1. 정상 지역(강남·홍대 등)에서 **폐합 3 km 가 종전대로** 생성된다 — V1~V3 에 걸리지 않아야 한다

4. 프로바이더 호출 예산 13회
