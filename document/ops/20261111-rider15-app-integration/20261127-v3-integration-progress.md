# rider15 V3.0 앱 이식 검증 현황

2026-11-27 · 수행 Codex · 상태: 화면 확인 및 기본 모델 전환 대기

## 완료

- V3.0_lite 세 파일을 후보 `20261127-160608-8767e93a`에 등록하고 원본·복사본 SHA-256을 전달 manifest와 대조했다. 자산 `ca759223`, DEV 연결 `d336821e`.
- 기본 활성 모델은 rider14를 유지한다. DEV `?riderModel=rider15`에서 새 후보를 사용한다. rider15 선택 시 만세 자산 경로만 후보를 가리키며, 추가 상체 동작이나 주행 조건별 자세 전환은 구현 범위에서 제외했다.
- rider15 전용 시험 16/16, 기존 rider-preserve 시험 63/63, TypeScript 및 변경 파일 ESLint 통과. Node 시험은 이미지 텍스처를 제거한 대체 경로를 사용하므로 실제 화면 확인을 대체하지 않는다.
- 실제 브라우저 벤치에서 rider.glb 및 rider-lod2.glb를 불러와 리그 ready 상태를 확인했다. 입문 경로 게스트 주행 상태 진입도 확인했다.
- 벤치 입력 제한을 3명에서 30명으로 확장했다. 줌 22·30명·30프레임 측정의 화면 전체 드로우콜 평균 208, 삼각형 평균 640330이 표시됐다. 지도와 라이더를 합친 값이며 모델 단독 비용이나 프레임 시간은 아니다.

## 미완료 및 한계

- 주행 화면 캡처 2회와 벤치 캡처가 시간 초과되어 모델 외형, 접지, 색상, LOD 전환의 시각적 합격 여부를 판정하지 못했다. Chief 확인 필요.
- 30프레임 호출이 브라우저 동기 제한시간을 넘어 나중에 완료됐다. 프레임 시간, rider14 대비값, 혼합 LOD 및 실제 휴대폰 성능은 측정하지 못했다. 현재 앱은 줌으로 전체 라이더의 LOD를 정하므로 기존 벤치만으로 혼합 LOD 시험은 할 수 없다.
- 화면 승인 전 기본 모델을 rider15로 바꾸지 않았다. 자세 조건 및 만세 등 상체 모션 기능 설정은 Chief 지시대로 이식 후 별도 작업이다.
- 전달 문서의 클립당 크랭크 2회전 설명과 달리, 실제 Hoods 첫~마지막 키 표본 재생은 1회전이었다. 차체 롤은 약 ±1°였다.

## 재개

개발 서버의 `http://127.0.0.1:5000/?riderModel=rider15`에서 입문 경로 → 주행 시작 후 후보의 크기·방향·접지·색상과 줌 전환을 확인한다. 문제와 성능을 조사하고 Chief의 명시적 화면 승인 후 기본 모델 전환, 회귀 검증, 결과 갱신과 단계 커밋을 진행한다. 배포는 별도 지시가 필요하다.
