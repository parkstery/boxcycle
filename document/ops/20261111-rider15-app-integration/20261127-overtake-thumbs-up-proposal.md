# 추월 동행에게 엄지척 — 제안

Codex · 2026-11-27. 제안만 작성, 앱·서버 구현 없음.

권장 흐름: 같은 Trail·같은 방향의 동행이 뒤에서 앞으로 지나가면 화면에 잠시 `OO님에게 👍` 단추를 표시한다. 한 번 누르면 내 라이더가 그 사람 쪽으로 엄지척하고, 상대에게 `내 닉네임 👍`를 짧게 표시한다. 자동 발신은 기본으로 하지 않는다. 경로·카메라 조작과 겹치지 않는 가로 화면 위치는 시안 후 결정한다.

- 추월 판단은 지도 직선거리가 아니라 같은 경로의 표시 진행거리 차이를 사용. 뒤2m 이하→앞2m 이상 전환과 상대속도 양수를 확인하되, 처음 합류·순간 위치 보정·반대 방향·낡은 패킷은 제외. 한 사람/한 추월당1회, 후보 유효시간8초·동일 상대 재노출30초를 초기 제안값으로 둔다. 실제 샘플로 조정할 값이다.
- 여러 명이면 가장 최근 실제로 옆을 지나간 한 명을 이름과 함께 표시하고 클릭 순간 대상uid·주행 세션을 고정한다. 사용자가 누르는 사이 다른 사람으로 대상이 바뀌지 않도록 한다.
- GLB 실제 조사: LookThumb_Left/LookThumb_Right 각 약2.708초 클립 존재. 현 주행 리그는 제스처 호출 인터페이스가 없어 추가 연결 필요. Hoods에서 상체 제스처와 하체 페달 위상을 분리해 손·발 접점을 검증한다. 좌우 통과 위치가 식별될 때 해당 클립을 선택하고, 같은 경로 중앙에 겹쳐 옆을 특정할 수 없으면 방향을 임의 단정하지 않는다.
- 우선 로컬 후보 단추/애니메이션 프리뷰로 사용성 확인. 그 다음 상대가 볼 수 있도록 이벤트 전송을 구현. 로컬 재생만으로 전송됐다고 표시하지 않는다.
- 전송은 위치 패킷과 별도의 짧은 유효기간 이벤트(eventId·senderUid·targetUid·ride/session·type·sentAt·expiresAt). 같은 eventId는1회만, 재접속 시 만료 인사는 재생하지 않는다. 기존 RTDB 경로 재사용 여부·Rules·신원 검증·쓰기 제한·읽기 범위/비용은 별도 설계·Chief 결정 후 구현한다.
- 급커브/일시정지/종료/동작 자산 미로딩이면 손을 갑자기 떼지 않게 처리한다. 동작이 지연되면 상황이 지난 뒤 늦게 실행하지 않고, 전달 알림만 쓸지 기준을 정한다.

근거: peerRidersDrive.ts의 id·speedMps·displayDistM, preservedRiderHandle.ts의 현 공용 표면, rider-gestures.glb JSON 애니메이션 목록 직접 확인. 통신·추월 재생 회귀를 추가할 경우 peer-sync 스킬로 로그 재현부터 고정한다.
