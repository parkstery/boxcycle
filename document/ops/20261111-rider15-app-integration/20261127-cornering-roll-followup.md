# 전신 기울기 급변·좁은 커브 반경 재조정

Codex · 2026-11-27. Chief: 테이퍼/전신 기울기가 훅 변하고 이전과 차이가 안 느껴짐, 회전 반경도 작아 보임.

## 원인과 조정

이전 코드는 공간 곡률 연속성만 검사했고 시간상 전신 롤의 속도·가속도는 제한하지 않았다. 진입80ms/복귀120ms 지수 추종은 목표35도에 대해100ms 만에 약25도 기울 수 있다. 공간 테이퍼가 있어도 좁은 커브·높은 속도·낮은FPS에서는 빠른 변화가 남는다. 90도 꼭짓점의 실제 표시 반경도 수치 측정3.186m로 작았다.

- 공간 테이퍼 반폭6.75→13.5m. 90도 중앙 표시 반경약6.37m. 20km/h 전환시간1.917→3.817초, 커브 중앙 기울기약34.2→18.7도, 표시 방향 오차0.59→0.29도. 코너 안쪽 편차1.79→3.58m이므로 좁은 도로 화면에서 추가 확인 필요.
- 몸과 자전거 전체 롤에 임계 감쇠 추종을 적용하되 속도30도/s·가속도120도/s²로 제한.120Hz 이하 시간 간격으로 적분하여6/15/30/60FPS에서도 점진적으로 변한다. 단순히 기울기 상한만 낮추지는 않았다(35도 유지).
- MapView의 기존100ms 상한 dt를 각속도 계산에 쓰면 실제 프레임이 그보다 길 때 각속도를 과대평가한다. 본인·동행·페이서 방향/롤에는 별도 실제 프레임 시간(탭 복귀 안전상한500ms)을 전달. 다른 기존 dt 소비자는100ms 상한 유지.
- 지형 회전·GLB·통신·주행 속도/거리 계약 변경 없음. 표시 궤적을 넓힌 수정이며 자동 감속은 하지 않는다.

## 검증과 남은 확인

수정 전 기울기 속도/가속도 제한 회귀와6m 이상 반경 회귀가 실패함을 재현했다. 관련 커브/geo/이정표/지형27/27 PASS, 빌드 PASS, 변경 lint 오류0(기존 MapView 경고10), diff 검사 PASS. 빠른 복귀를 요구하던 기존 단언은 초기0.2초에 절반 미만·이후 수렴·점진적 복귀 기준으로 변경했다.

localhost:5000에서 제공하는 riderTurn 모듈 HTTP200·반폭13.5/롤 속도 제한30 코드 포함 확인. 실제 사용자 탭·운영 배포 여부는 확인하지 못했고 테스트 주소 질문은 답 대기. 이번 화면 자연스러움은 미검증. ego-browser skill 안내는 읽었으나 브라우저 조작·화면 확인은 수행하지 않았다.

Chief: http://localhost:5000/ 새로고침 후 같은 좌우 커브를20/30km/h로 비교. 진입→중앙→복귀가1~수초에 걸쳐 보이는지, 넓어진 궤적이 좁은 도로에서 과하게 안쪽으로 들어가지 않는지 확인. 이 후속 수정은 미커밋·미배포.
