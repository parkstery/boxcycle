## 0. 새 세션이 알아야 할 전부

2026-09-18 밤, 주행 화면 하단에 표고 그래프 대신 **「고도 데이터를 불러오지 못했습니다」** 만 표시되는 증상이 보고됐다.
「오늘 작업 중 표고 연동 코드를 날려먹은 것 아니냐」는 의심이 있었으나 **회귀가 아니다.** 원인 규명은 끝났고, 이 문서는 **조치만** 남긴 것이다. 원인 재조사 불필요.

---

## 1. 확정된 원인

Open-Meteo 고도 API가 **일일 요청 한도를 초과**해 429를 반환하고 있었다.

```
$ curl "https://api.open-meteo.com/v1/elevation?latitude=37.5665,37.5666&longitude=126.9780,126.9781"
HTTP 429
{"reason":"Daily API request limit exceeded. Please try again tomorrow.","error":true}
```

근거:
- 2026-09-17 이후 `fetchRouteElevations.ts` · `useRouteElevationProfile.ts` · `roadElevationCoach.ts` · `coachElevationFromRoute.ts` 커밋 **0건** (`git log --since` 확인). 코드는 손대지 않았다.
- `routeGeometry` 는 `useRouteWorkspace` 의 상태값이라 레퍼런스가 안정적이다 — effect 재실행 폭주는 아니다.

### 한도를 태운 주범

Open-Meteo 를 가로채는 e2e 스펙은 **`apps/web/e2e/hud-distance-elevation-shots.spec.ts` 단 하나**(`stubElevation`, 해당 파일 474행 부근)뿐이다.
경로를 설정하는 **나머지 스펙 29개 / 전체 36개**는 실제 API 를 때린다.

- `ROUTE_ELEVATION_SAMPLE_COUNT = 72` (`apps/web/src/lib/fetchRouteElevations.ts`)
- Open-Meteo 는 좌표 수만큼 호출로 계산 → **주행 테스트 1회 = 72 콜**
- 2026-09-18 하루 동안 `ride-continuation`(7) · `phase-c` · `ride-summary` · `next-ride` · `distance-auto-route` · `hud-shots` · `touch-targets` 를 수십 회 반복 실행했다.

한도는 **UTC 00:00 = KST 09:00** 에 리셋된다.

### 증상이 회귀처럼 보인 이유

`fetchElevationsForCoords` (`apps/web/src/lib/fetchRouteElevations.ts:44`) 가
`if (!response.ok) throw new Error("elevation request failed")` — 429든 네트워크 오류든 **구분 없이** 같은 에러를 던지고,
`MapView.tsx:3763` 이 그걸 전부 「고도 데이터를 불러오지 못했습니다」 한 줄로 표시한다.

## 2. 해야 할 일

### A. e2e 전역 스텁 (최우선 — 재발 방지의 핵심)

`hud-distance-elevation-shots.spec.ts` 의 `stubElevation` 과 같은 방식(요청된 `latitude` 콤마 개수만큼 합성 표고 배열 반환)을
**모든 e2e 스펙에 자동 적용**되는 공용 픽스처/전역 설정으로 올린다. 테스트가 다시는 실 API 를 소모하지 않게 한다.

주의:
- `hud-distance-elevation-shots.spec.ts` 는 시나리오별(A/B/…) 합성 곡선을 쓴다. **기존 스펙의 시나리오 스텁이 전역 스텁에 덮이거나 무력화되지 않도록** 우선순위를 확인할 것.
- 가로챌 대상은 고도 API 뿐 아니라 **`openMeteoWeather.ts` 의 forecast API**(`https://api.open-meteo.com/v1/forecast`)도 같은 일일 한도를 공유한다. 함께 스텁할 것.
- 축퇴 방어: 스텁이 실제로 걸렸는지(요청이 실 네트워크로 나가지 않았는지) 한 개 이상의 스펙에서 확인할 것. 스텁이 조용히 안 걸려도 테스트는 초록으로 통과한다.

### B. routeSig 캐시

같은 경로를 다시 열 때 재요청하지 않도록 `sessionStorage` 캐시를 넣는다.
키는 `routeElevationSignature(geometry)` 를 그대로 쓴다 (`fetchRouteElevations.ts` 에 이미 있음).
개발 중 새로고침마다 72콜이 나가는 것을 막는 목적.

### C. 429 전용 메시지

`fetchElevationsForCoords` 에서 `response.status === 429` 를 분리해,
UI 에 「고도 API 일일 한도 초과 — 내일 다시 시도됩니다」 류로 표시한다.
다음에 같은 일이 생겼을 때 코드 회귀로 오해하지 않게 하는 것이 목적.

### D. (chief 판단 대기) Mapbox Terrain 폴백

Open-Meteo 실패 시 이미 존재하는 Mapbox Terrain DEM (`TERRAIN_SOURCE_ID = "boxcycle-dem"`, `MapView.tsx:1708`) 의
`map.queryTerrainElevation()` 으로 대체하는 폴백.

트레이드오프 — **지시 없이 착수하지 말 것**:
- 데이터 소스가 바뀌어 고도값과 코칭 수치가 달라진다.
- 로드된 타일 범위에서만 동작한다.

## 4. 검증

- 전역 스텁 적용 후 전체 e2e 를 1회 돌리고, 그 동안 실 Open-Meteo 로 나간 요청이 **0건**임을 확인한다.
- 한도가 리셋된 뒤(KST 09:00 이후) 실제 주행에서 표고 그래프가 다시 그려지는지 육안 확인.
- 테스트 주행 경로는 **200m 이하** (chief 지시 — 테스트 시간 단축).
