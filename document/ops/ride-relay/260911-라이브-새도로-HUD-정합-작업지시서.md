## 0. 역할

- **개발팀장(구현 에이전트):** 아래 결함을 고치고, 수용 기준 증거와 함께 제출한다.
- **수퍼바이저(이 세션):** 코드·시험 증거로 수용표만 판정한다. 구현을 대신하지 않는다.
- **Chief:** 최종 사용자. 3회 실패 또는 PASS 시에만 보고한다.

## 1. 현재 증상 (Chief 실측)

1. 하드 새로고침 후 주행: 「새 도로」칸은 보이나 **값이 `+0.00`에 고정**되고 거리(예: 0.05 km)와 함께 증가하지 않음.
2. 이전 회귀: 표시 지연(~37초/50m), 시작 순간 깜빡임 후 소멸, 거리와 새 도로 수치 불일치(셀×30m).

## 2. 제품 수용 기준 (전부 필수)

| ID | 기준 | 증거 |
|---|---|---|
| A1 | 주행 시작 후 **5초 이내**에 「새 도로」칸이 나타남(무장) | 단위/수동 절차 + 가능하면 로그·캡처 |
| A2 | **미보유(새) 도로**만 달릴 때: 세션 거리와 새 도로 km가 **소수 2자리·근접**(허용 |Δ| ≤ 0.02 km 또는 ≤ 20 m) | `computeLiveNewRoadFromRoute` 시험 + 시나리오 |

## 3. 의심 원인 (조사 후 확정·수정)

우선 확인할 것:

1. `ownedAtStart` 스냅샷이 **과대**(전 맵 소유로 잡혀 항상 0)인지.
2. `traveledMeters`/`fromMeters`가 세션 거리와 어긋나 셀 구간이 비는지.
3. `sessionArmed` 이후 갱신 주기가 traveled 변화를 반영하는지.
4. HUD 단위/포맷이 km인데 값이 미터로 들어가거나 반대인지.

**금지:** 증상만 가리는 UI 트릭(가짜로 거리 복사해 새 도로에 넣기). 서버 Claim과 같은 **미보유 셀 경로 미터**가 진실이다. 다만 라이브는 낙관 표시이므로 CF 한도 전 값일 수 있다.
