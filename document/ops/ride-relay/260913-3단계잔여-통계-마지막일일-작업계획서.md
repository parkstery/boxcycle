## 2. 현황(계획 근거)

- `RIDE-IN-RIDE-HIERARCHY-3`(PR #17)는 `main2` 병합·Hosting 배포 완료. 「마저」= **회귀 확인 + 발견 시 핫픽스**, 3단계 UI 재설계 아님.
- 통계는 주간·월간·연간 탭만 있음(`RideStatsPeriod`). 「최근 주행」은 **접는 목록**이며 통계 카드에 **마지막 1건 요약·오늘(일일) 집계**가 없다.
- 4·5(`RIDE-RETURN-EXPERIMENT-4` 등)는 **폐기**. PR #18은 이미 닫힘. 재개 금지.

## 3. 구현 범위

### 3.1 G2 — 3단계 잔여

1. Hosting https://boxcycle-dc2df.web.app 또는 로컬 `main2`에서 3단계 표면 스모크(입문 로드 → ready → Go → riding).
2. 회귀 FAIL이 있으면 **최소 수정**만. 범위 확대·GLB·Conquest·nextRideTarget 금지.
3. 이상 없으면 보고에 「잔여 결함 0」과 스모크 증거.

### 3.2 G3 — 통계: 마지막 주행 · 일일 주행

표면: `UserInfoSheet` 통계 블록(주간/월간/연간 **근처**, 사용자가 탭 없이 읽히게).

| 항목 | 정의 | 표시(최소) |
|---|---|---|
| **마지막 주행** | `endedAt` 최신 **유효** Ride 1건(폐기 기준은 기존 `isDiscardableRideRecord` / 목록과 동일) | 거리(km)·경과 시간·종료 시각(또는 상대). 없으면 「없음」 |
| **일일 주행** | 기기 **로컬 달력 오늘 00:00 ~ 내일 00:00** 구간의 집계 | 횟수·거리·시간(기존 주간 카드와 같은 축). 0건이면 0 표시 |

구현 지침:

- `rideStatsAggregate.ts`(또는 인접 순수 모듈)에 `day` 구간·`pickLastRide`/`aggregateToday` 등 **순수 함수** 추가. UI만 복제 금지.
- 기존 `statsSessions` / `recentSessions` 데이터 재사용. 신규 Firestore 스키마·외부 분석 금지.
- Ontology: Room/Lobby/course UI 금지. km 표기는 기존 `formatRideDistanceKmNumber` 등 팀 포맷 우선.
- 「최근 주행」접기 목록은 유지(제거하지 말 것). 통계의 마지막 주행과 역할이 겹쳐도 됨 — 통계는 **요약 1행**, 목록은 **다건·액션**.

### 3.3 금지

Journey · Conquest 인정 변경 · nextRideTarget 파생 · 카메라 전면 교체 · 라이더 GLB/Modelling · 4·5 재방문/유료 · 6A 센서 칩 대규모 이동 · 머지/배포.
