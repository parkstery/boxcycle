## 1. 왜 지금인가 — 루프가 끊기는 지점

핵심 판타지 「Ride = Claim」은 **달린 길이 쌓이는 것**인데, 지금은 한 번 달리면 거기서 끝난다. 다음 구간을 이으려면 사용자가 지도를 다시 잡고 출발점을 처음부터 다시 찍어야 한다.

거리·방향 자동 Route 는 3F-C-R1 로 「클릭한 곳에서 끝나는 경로」를 만들 수 있게 됐다. 이제 그 끝이 **다음 출발점**이 되어야 루프가 닫힌다.

### 1.1 코드로 확인된 현황 (추정 아님)

| 확인 항목 | 결과 | 근거 |
|---|---|---|
| 자동 Route 가 앱의 표준 Route 로 적용되는가 | **적용된다** — `start`·`end`·`geometry`·`distance`·`summary` 를 표준 state 에 넣고 `resetRide()` 한다 | `App.tsx:1505-1515` `onApplyRoute` |
| 주행 종료 시 종료점이 다음 Start 로 승계되는가 | **승계되지 않는다** — 종료 경로에 `setStartLngLat` 호출이 없다 | `hooks/useRideEndAndPersistence.ts` |
| 「다음 주행」 카드가 있는가 | **없다** — 문자열이 web 소스에 존재하지 않는다 | `apps/web/src/` 전수 검색 |
| RIDE-CONTINUE-1 진행 상태 | **실행 대기** (제품 결정만 확정) | [document/README.md](../../README.md) 색인 |

**루프가 끊기는 지점은 「주행 종료 → 다음 출발점」 한 곳이다.** 자동 Route 생성부터 주행 시작까지는 이미 표준 경로를 타고 있다.

## 2. 단계 A — 현행 실동작 확인 (먼저 보고, 구현 전)

이미 되는 것을 다시 만들지 않기 위해, 아래 3건을 **실제로 눌러 보고** 화면 증거와 함께 보고한다. 코드만 읽고 추정하지 않는다.

1. 자동 Route 생성 직후 `Go` 로 주행이 시작되는가. `rideStatus` 가 `running` 이 되는가.
2. 자동 Route 를 「내 경로로 저장」하면 SavedRoute 로 남는가. `profile`·거리·geometry 가 생성값과 일치하는가.
3. 주행을 끝낸 직후 `startLngLat` 은 무엇인가. 결과 시트에서 다음 행동으로 갈 수 있는 경로가 있는가.

이 보고 뒤에 단계 B 로 넘어간다. 1·2 가 이미 정상이면 그 범위는 건드리지 않는다.

## 3. 단계 B — RIDE-CONTINUE-1 본체

[260829 지시서](260829-다음-주행-이어달리기-작업지시서.md) 의 §6 단계 A~C 를 **그 문서 그대로** 수행한다. 순서를 바꾸지 않는다.

- 단계 A: 완주 표시 통일(`isRouteCompletion`), SavedRoute 진행률 transaction max, 중복 저장 시 상태 보존
- 단계 B: 실제 Ride anchor(`sessionStartLngLat`·`sessionEndLngLat`) 순수 함수 + Firestore 확장 + legacy null fallback
- 단계 C: 모든 유효 Ride 결과 시트, 다음 출발점 표시

진행률 신뢰성을 먼저 고친 뒤 카드를 만든다는 원칙을 유지한다.

## 4. 단계 C — 자동 Route 결합 (이 R1 의 신규 조항)

### 4.1 260829 §3.3 갱신

260829 §3.3 은 자동 Route 가 지도 팝업으로 들어오기 전에 작성됐다. 3항을 다음으로 **대체**한다.

> ~~3. 출발점은 `S` 로 고정하고 사용자는 도착점·경유지만 선택한다.~~
>
> **3. 출발점은 `S` 로 고정한다. 사용자는 ① 도착점·경유지를 직접 찍거나 ② 그 자리에서 거리·방향 자동 Route 로 다음 구간을 생성한다. 두 경로 모두 동등한 1급 진입이다.**

나머지 1·2·4·5·6 항은 그대로 유지한다. 특히 **6항(사용자가 출발점을 직접 바꾸면 일반 Route 생성으로 전환)** 은 자동 Route 진입에도 똑같이 적용된다.

### 4.2 결합 계약

1. **Start 고정** — 자동 Route 팝업이 「이 지점에서 새 경로」로 열리면 Start 는 직전 Ride 의 `sessionEndLngLat` 으로 고정된다. 사용자가 Start 를 옮기면 고정이 풀리고 일반 자동 Route 로 전환된다.
2. **직전 값 승계** — 목표 거리와 이동수단은 **직전 주행에서 쓴 값**을 기본값으로 채운다. 매번 다시 고르게 하지 않는다. 사용자가 바꾸면 그 값이 다음 구간의 기본값이 된다.
3. **Token 정책 불변** — 자동 Route 1회 생성 = Token 1개. 이어 달리기라고 면제하지 않는다. 3F-C-R1 §3.1 의 「거리 조정 재탐색 1회 무료」는 그대로 적용된다.
4. **`offered` 동작 불변** — 도로거리가 목표를 넘으면 3F-C-R1 의 `offered` 고지·고스트 마커·거리 조정 원클릭이 이 진입에서도 똑같이 동작한다.
5. **이전 결합 정리** — Publication·Trail·loaded SavedRoute 결합 상태를 정리한다(260829 §3.3-2). 이전 SavedRoute geometry 를 **수정하지 않는다.**
6. **연속 누적** — N 번째 구간도 같은 방식으로 반복 가능해야 한다. 구간마다 별개의 Ride 로 기록되며, 앞 구간을 덮어쓰지 않는다.

### 4.3 하지 않는 것

- `Journey` 용어·새 데이터 모델을 이번에 확정하지 않는다(260829 결정 유지). 연속 구간을 묶는 상위 개체는 만들지 않는다.
- 자동 Route 를 주행 종료 시 **자동으로** 생성하지 않는다. 항상 사용자가 눌러서 시작한다.
- 이어 달리기 전용 Token 할인·보너스를 신설하지 않는다.

## 5. 시험

1. **루프 3회 연속** — 자동 Route 생성 → 주행 → 종료 → 그 종료점에서 다시 자동 Route 생성을, 끊김 없이 **3회 반복**하는 e2e 를 만든다. 각 회차마다 다음을 assert 한다.
   - 새 Start == 직전 Ride 의 `sessionEndLngLat`
   - 목표 거리·이동수단이 직전 값으로 채워져 있음
   - Token 이 회차당 정확히 1개 차감
   - 이전 구간의 Ride·SavedRoute 가 변경되지 않음
2. **`ride-verify` Skill** 로 진입 시퀀스 회귀를 고정한다.
3. 260829 §4.4(진행률 단조 증가)·§4.5(중복 SavedRoute 상태 보존) 순수 함수 시험.
4. Start 를 사용자가 옮기면 고정이 풀리고 일반 Route 로 전환되는 분기 시험.
5. legacy Ride(anchor 필드 없음)에서 「이 지점에서 새 경로」가 조용히 비활성화되고 크래시하지 않는지 시험.
6. 기존 자동 Route 시험 전량 회귀 유지:

```text
npm -w boxcycle-web run test:distance-auto-route
npm -w boxcycle-web run test:distance-auto-route-replay
npm -w boxcycle-web run test:route-token
npm -w boxcycle-web run test:e2e:ride
npm --prefix functions run build
npm -w boxcycle-web run build
```
