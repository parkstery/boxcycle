## 1. 개발팀장에게 내리는 지시

**주행 결과 시트를 ‘오늘 몇 km 탔는가’에서 ‘이번에 어떤 길을 달렸고 내 도로망에 얼마가 더해졌는가’까지 전달하는 화면으로 개편한다.** 현재 종료·저장·재개 계약을 보존하면서, 해당 Ride의 서버 인정 결과와 이번 세션의 궤적을 결합한다.

이번 PR에서 아래 네 가지를 완료한다.

1. 결과 화면의 새 도로 값을 **해당 서버 Ride 문서**에 귀속시킨다.
2. 이번 세션 궤적을 종료 시점에 고정해 결과 시트 안에 시각화한다.
3. 집계 대기·0·오류·저장 실패를 구분하고 운동 통계와 다음 행동을 유지한다.
4. 결과 화면 및 기존 이어 달리기 회귀를 검증하고 화면 증거를 제출한다.

**지금은 선행 0단계부터 착수한다.** 0B의 검증된 결과 모델·ID 연결·구독 API를 인계받은 뒤 이 문서의 화면 구현에 들어간다. 아래 §2·§4의 데이터 요구사항은 유지하되 0B에서 구현한 기능을 재개발하지 않는다. 0B 완료 시 해당 절을 실제 API 소비 지시로 갱신한다. 브랜치 기준점과 미커밋 변경을 확인하며, 종전 3~5일 추정은 0B 이후 UI 범위로 재산정한다.

## 3. 화면 계약

### 3.1 정상 집계 완료 화면

읽는 순서는 아래와 같다. 수치는 설명용 예시다.

```text
주행 결과                                      닫기

새 도로 +0.8 km
이번에 달린 길이 내 도로망에 더해졌어요

[이번 세션 궤적 + 주변의 기존 도로망 미리보기]
 굵은 선: 이번에 달린 길   가는 선: 내 도로망

오늘 1.2 km · 08:00 · 평균 9.0 km/h · 36 kcal
전체 진행 31% → 43%                 (해당 경로만)
다음 출발점 안내                    (유효 anchor만)

[기존 새 경로 연결 액션]             (기존 조건 유지)
경로 이름 / 내 경로로 저장           (기존 보조 기능)
```

- 새 도로 값과 미리보기가 중심이며 오늘 운동 통계도 첫 화면에서 읽힌다. 주소·경로 이름은 줄바꿈/말줄임 처리한다.
- 기존 `aria-label="주행 결과"`, 전체 진행 및 주행 진입 계약을 유지한다. 변경이 필요하면 하네스 계약과 spec을 함께 수정한다.
- 기존 ‘지금 새 경로 연결’/‘끝점에서 새 경로’, 저장·중복 저장·쿼터 오류 처리를 보존한다. 1단계에서는 신규 ‘이어 달리기’ CTA를 별도로 만들지 않는다.
- 닫기는 기존 idle 복귀와 NextRideCard 노출을 유지한다. 시트가 열리거나 서버 집계가 도착했다는 이유로 Route 준비·주행 시작을 자동 실행하지 않는다.
- 확정 새 도로가 50m 미만이면 기존 0 수치 미표시 원칙에 맞춰 숫자 hero를 숨기고 오늘 운동 거리 중심으로 전환한다. 양수이면 ‘새 도로가 조금 더해졌어요’, 0이면 ‘오늘의 주행을 마쳤어요’로 표현한다. 0의 이유를 중복·한도 중 하나로 추측하지 않는다.
- 지역 전체 정복률·미확정 배지·토큰·예상 도착 시간은 추가하지 않는다.

### 3.2 미리보기의 정확한 의미

미리보기는 **이번에 달린 길**이다. 새 도로로 인정된 부분만의 geometry라고 표시하지 않는다. 서버 trace의 path와 `newMeters`는 서로 다른 정보이며, 중복/한도 때문에 전체 path 길이와 새 도로 거리가 다를 수 있다.

- `fromMeters = 세션 시작 offset`, `toMeters = 종료 누적 위치`의 실제 구간만 사용한다. 전체 계획 경로 또는 재개 이전 구간을 이번 주행처럼 그리지 않는다.
- 종료 후 Route workspace가 비워지기 전에 geometry를 복사해 고정한다. 이후 다른 경로 선택·비동기 지명 조회·카메라 이동이 결과를 바꾸지 않는다.
- **추가 Mapbox 인스턴스 없이 SVG 궤적 미리보기**를 기본 구현으로 한다. 좌표를 투영해 종횡비를 유지하고 여백 안에 fit한다. 북쪽 위, 경위도 축척 보정, 날짜변경선 횡단, 수직/수평·짧은 선·빈 좌표·비정상 좌표를 처리한다. 지원 불가능한 입력은 텍스트 폴백을 쓴다.
- 실제 좌표의 선만 그린다. 가짜 도로·건물·새 지도를 생성하지 않는다. 배경지도 없는 도로망 미리보기라는 성격을 유지한다.
- 기존 내 도로망은 이미 로드된 traces 중 이번 주행 bounds 주변만 클리핑한다. 세계 전체를 fit하지 않는다. 아직 로드되지 않았거나 오류이면 이번 궤적만 보이고 그 사실을 표시한다.
- 현재 Ride의 서버 trace가 도착해도 이번 궤적을 기존 배경에 이중으로 넣지 않는다. 결과 표시가 열려 있는 동안 주변 데이터 갱신으로 구도가 뛰지 않게 한다.
- 기존 색상 BlueViolet `#8A2BE2`를 유지한다. 이번 주행은 굵기·glow, 기존 도로망은 가는 선으로 구분한다. 양쪽에 범례를 붙이며 색만으로 정보를 구분하지 않는다.
- geometry가 없으면 ‘이번 주행의 경로 미리보기를 표시할 수 없어요’와 통계/가능한 다음 행동을 보여 준다. anchor 하나에서 경로를 추정하지 않는다.
- 영구 누적값이나 기존 trace를 로컬에서 쓰거나 합산하지 않는다. 서버 집계 전 라이브 선을 ‘영구 저장 완료’라고 표기하지 않는다.

## 4. 집계·저장 상태 계약

### 4.1 진실의 원천

새 도로 수치는 **해당 `rides/{serverRideId}.conquestResult.newMeters`**만 사용한다. 계정 누적 증분, 클라이언트 셀 차집합, trace 길이로 대체하지 않는다. 다른 탭·직전 Ride 집계가 현재 결과에 섞이면 실패다.

현재 `RideEndResult.recordId`는 로컬 ID다. 저장 응답으로 얻은 서버 ID를 로컬 ID와 연결한다. 필요한 타입 확장은 표시용 메모리 상태로 우선 구현하고, 신규 Firestore 필드·컬렉션·인덱스·Rules·마이그레이션을 만들지 않는다.

### 4.2 상태별 표현

| 상태 | 진입 근거 | 표시/행동 |
|---|---|---|
| 저장 중 | 유효 로컬 결과 생성, 서버 ID 미확정 | 운동 통계·미리보기 즉시 표시. ‘주행 기록 저장 중…’. 서버 저장 완료를 약속하지 않음 |
| 집계 중 | 서버 ID 있음, 유효 conquest payload 있음, 해당 결과 아직 없음 | ‘새 도로 확인 중…’. 나머지 화면·닫기/기존 다음 행동 사용 가능 |
| 집계 완료 | 유효한 해당 Ride 결과 존재 | §3의 양수/50m 미만/0 표현. `null`·필드 없음은 0이 아님 |
| 확인 지연 | 집계 대기 15초 경과 | ‘새 도로 확인이 늦어지고 있어요’. 열려 있는 동안 60초까지 구독, 이후 해제하고 ‘다시 확인’ 제공 |
| 조회 실패 | 권한·네트워크 등 구독 오류 또는 유효하지 않은 수치 | ‘새 도로를 확인하지 못했어요’ + ‘다시 확인’. 동일 문서만 다시 구독 |
| 서버 저장 실패/불가 | 쓰기 reject 또는 서버 ID 획득 불가 | ‘서버 저장을 확인하지 못했어요’. 로컬 결과 유지. 원격 저장 완료/영구 인정 완료 카피 금지 |
| 집계 대상 없음 | 생성된 payload가 없거나 알려진 유효성 조건 불충족 | ‘새 도로 집계를 확인할 수 없는 주행이에요’. 운동 통계·가능한 다음 행동 유지 |

15초/60초는 UI 대기 정책이며 서버 처리 SLA나 인정 판정이 아니다. ‘다시 확인’은 **읽기만** 재시도한다. 현재 저장이 `addDoc` 기반이므로 새 문서 생성 재시도로 중복 Ride를 만들지 않는다. 서버 쓰기 재시도·멱등성 재설계가 필요하면 후속 과제로 분리한다.

서버 함수는 일부 잘못된 payload에서 결과 없이 반환한다. 결과 부재를 곧바로 거절·0·완료로 해석하지 않는다. UI에서 판별할 수 없는 경우 확인 지연/실패로 남긴다.

### 4.3 수명·경합

- 구독 키는 `(uid, 로컬 recordId, serverRideId)`로 연결한다. 동시에 열린 결과에 대한 문서 구독은 최대 1개다.
- 시트 닫힘·새 결과 생성·로그아웃·계정 변경·unmount 시 구독과 timer를 정리한다. 늦은 저장 응답·snapshot이 시트를 다시 열거나 새 결과를 덮지 않게 한다.
- 재시도마다 이전 구독을 해제한다. 반복 polling, 전체 Ride 목록 조회, 전체 traces 재조회는 추가하지 않는다.
- 저장/진행률 갱신/집계의 성공은 서로 다른 상태다. `anchorLngLat` 존재만으로 ‘서버에 다음 출발점 저장 완료’를 표기하지 않는다. 서버 저장 확인 전에는 ‘여기서 다음 주행을 준비할 수 있어요’처럼 표현한다.
- 결과 view model은 문자열을 역파싱하지 않는다. 유한한 0 이상 수치만 받아 km 표기 정책을 적용한다.

## 5. 작업 순서와 책임

1. **개발팀장 — 기준선 확보:** 브랜치/HEAD·작업 트리·관련 선행 수정 확인. 기존 build, next-ride, selector 계약 및 대상 e2e의 실패·skip을 기록한다. 기존 실패와 이번 회귀를 구분한다.
2. **데이터 연결 담당 — 종료 스냅샷:** 로컬/서버 ID 연결, 세션 geometry, 저장 상태, 결과 구독 수명 구현. 기존 인정 payload·offset·진행률 저장 규칙 유지.
3. **UI 담당 — 미리보기와 상태 표시:** SVG 투영/클리핑 순수 로직, 결과 컴포넌트·CSS 구현. App에는 연결 코드만 둔다.
4. **개발팀장 — 통합:** 상태별 화면과 CTA 계약 검토. 기존 결과 구독/누적 차감 표시의 중복 사용 제거.
5. **검증 담당 — 수용표 실행:** 결정적 데이터 시험 → emulator 통합 → 반응형 화면 확인 순으로 수행하고 보고한다.

담당자는 한 사람이 겸임할 수 있다. 구현 순서는 위 의존성을 따른다. 배포·실제 사용자 대상 데이터 조작은 이 작업의 완료 조건이 아니다.

| A5 | 31%부터 43%까지 재개 후 종료 | 선은 이번 12% 구간만. 오늘 거리 offset 차감, 전체 진행 31→43 유지 |
| A6 | 저장 후 결과 늦게 도착, 직후 새 Ride 결과 또는 계정 전환 | 이전 값·geometry·지명 혼입 없음. 구독/timer 정리 |
| A7 | 조회 오류·15초/60초 지연·다시 확인 | 정해진 상태 전이. 서버 문서 중복 생성 없이 동일 문서 읽기 |
| A8 | 서버 저장 실패 및 geometry 없는 유효 Ride | 저장 완료 주장 없음. 기존 로컬 기록 유지, 미리보기 폴백, 가능한 CTA만 |
| A9 | SavedRoute 미완주·완주 / ad-hoc / Publication | 기존 결과·저장·연결 동작 유지. 완주 98% 기준·쿼터·중복 저장 처리 불변 |
| A10 | 결과 닫기 → 다음 주행 카드 → 재개 준비 | reload 없이 카드 노출. 준비까지만 진행하고 Go/센서 준비 게이트 유지 |
| A11 | 세션 미리보기와 새 도로가 다른 길이 | 범례는 ‘이번에 달린 길’. 전체 궤적을 새 도로로 주장하지 않음 |
| A12 | 1920×1080, 390×844, 844×390, 690×275 | 가로 스크롤/잘림/CTA 겹침 없음. 낮은 화면은 시트 내부 스크롤로 모든 액션 접근 |
| A13 | 긴 이름·200% 텍스트 확대·키보드·reduced motion | 읽기와 닫기/액션 가능. focus 이탈 방지·닫은 뒤 적절한 focus 복귀. 움직임 감소 설정 준수 |
| A14 | 무효/폐기 Ride | 기존 결과 노출 정책 유지. 새로운 빈 성취 화면 생성 없음 |
| A15 | 많은 기존 traces·수직/수평·날짜변경선·비정상 좌표 | 미리보기 bounds/투영 정상 또는 명시적 폴백. 원본 데이터 미변경 |

저높이 화면에서는 미리보기 높이를 줄이고 통계·상태·주 액션을 우선한다. 터치 액션은 최소 44px 높이를 확보한다. SVG에는 접근 가능한 제목/설명을 제공하고 숫자 갱신은 `aria-live="polite"`로 한 번 전달한다.

## 7. 검증 명령과 증거

저장소 루트에서 실행:

```powershell
npm run build
npm --prefix apps/web run test:next-ride
npm --prefix apps/web run test:e2e:ride
npm --prefix apps/web run test:e2e:ride-continuation
```

`apps/web`를 작업 디렉터리로 실행:

```powershell
node scripts/ride-verify/verify-selectors.mjs
```

- 신규 순수 시험: 상태 전이·문서 귀속·오래된 응답 무시·offset 세션 구간·투영/클리핑 경계. 기존 하네스 패턴을 따라 추가하고 실제 명령을 보고서에 남긴다.
- 신규 통합 시험: 서버 Ride 저장→ID 연결→지연된 `conquestResult` 수신→현재 시트 갱신. 0·오류·이전 결과 경합을 결정적으로 재현한다. emulator 전용 seed로 상태를 주입할 수 있으나 이 시험을 실제 CF 인정 알고리즘 검증이라고 부르지 않는다.
- 기존 emulator launcher를 재사용한다. `RIDE_VERIFY_LIVE=1`만 켜 실제 Firebase에 붙이거나 인증/센서 gate를 제품 코드에서 우회하지 않는다.
- 접근성/배치 변경으로 selector가 달라지면 정적 계약과 e2e를 함께 수정한다. 단언을 삭제하거나 skip해서 통과시키지 않는다.
- 브라우저/Playwright가 5분간 유의미하게 진전 없으면 중단하고 서버·포트·프로세스·로그를 점검한다. headless·단일 worker·기존 서버 재사용 등 다른 경로로 전환한다. 실행되지 않은 필수 검증은 BLOCK으로 보고한다.
- 미리보기는 화면용 복사본을 주변 범위로 클리핑·단순화하고 총 렌더 점 수를 5,000 이하로 제한한다. 10만 점 fixture에서 결과 준비 200ms 이내를 목표로 측정 환경과 시간을 기록한다. 초과하면 단순화/캐시로 보완한다. 운동·인정 원본에는 적용하지 않는다.
- 결과를 10회 열고 닫은 뒤 활성 결과 구독과 timer는 0, 열려 있을 때 결과 구독 최대 1임을 계측으로 확인한다. 추가 지도 인스턴스·Directions·역지오코딩 요청 0을 확인한다.
- 화면 증거는 정상 양수·대기·0·오류·재개 구간을 포함하고 위 4개 viewport를 커버한다. 최소 한 번은 emulator의 실제 종료 흐름을 통해 촬영한다. fixture 화면만으로 통합 PASS를 선언하지 않는다.
