## 1. 생명주기와 실패 분기

결과 화면은 **Conquest 완료를 기다리지 않는다.** 종료 스냅샷이 유효하면 즉시 표시하고, 이후 비동기 축은 각각 상태를 갱신한다.

```
[경로/입력 준비] -> Go -> running/paused
        |
        v
[종료 스냅샷 고정]  <- rAF metrics·geometry·offset·profile·연결 ID를 동기 구간에서 복사
        |
        +- discard(<=100m 또는 <=5s) -> 결과 없음 · 저장 없음 · idle
        |
        v
[즉시 결과 표시]  <- RideEndResult / 확장 ViewModel (낙관)
        |
        +--- 축 A: Ride 저장 (local -> Firestore addDoc)
        +--- 축 B: SavedRoute 진행률 (local 낙관 -> FS transaction max)
        +--- 축 C: Conquest 확인 (CF -> rides/{serverRideId}.conquestResult)
```

### 1.1 단계별 계약

| 단계 | 입력 | 성공 시 | 실패/지연 시 |
|---|---|---|---|
| 종료 스냅샷 | `rideMetrics`(누적), `startOffsetMetersRef`, workspace geometry/distance/profile, loaded SavedRoute refs | `StoredRideSession` + `RideEndResult` 생성, `summaryVisible` | discard면 결과 null |
| 즉시 표시 | 유효 `RideEndResult` | 결과 시트 오픈. Conquest/서버 ID 미확정이어도 표시 | 표시를 Conquest에 직렬 대기 **금지** |
| 축 A Ride 저장 | 스냅샷 + conquest payload | `serverRideId` 확정·로컬 연결 | 로컬 기록 유지. 「저장 완료」 카피 금지 |
| 축 B 진행률 | `progressToSave`, SavedRoute id | 서버 max 반영으로 결과/카드 정정 | 축 A와 독립. 낙관값은 유지하되 확정 아님 |
| 축 C Conquest | `rides/{serverRideId}` 문서 | `conquestResult.newMeters` 등 해당 Ride만 UI 반영 | pending/unknown != 0. 계정 누적 폴백 금지 |

### 1.2 실패 분기 (요약)

1. **저장 실패·진행률 실패·집계 지연**은 서로 다른 상태로 전달한다.
2. 늦은 비동기 응답은 **owner uid + 결과 키(localRecordId 또는 serverRideId)** 가 활성 결과와 일치할 때만 적용한다.
3. 시트 닫기·새 결과·계정 전환·unmount 시 구독/timer를 해제한다. 이전 응답이 시트를 다시 열지 않는다.
4. `addDoc` 재호출은 다른 문서를 만든다. **조회 재시도 != Ride 재생성.**

- **legacy:** 매핑 없는 과거 기록은 시간·거리 유사성만으로 합치거나 삭제하지 않는다.
- **계정:** uid가 다르면 결과·목록에 적용·업로드하지 않는다.

## 4. 비동기 상태 전이표

세 축은 **독립**이다. 한쪽 성공으로 다른 쪽 성공을 주장하지 않는다.

### 4.1 축 A — Ride 저장

| 상태 | 의미 |
|---|---|
| `idle` | 종료 전 |
| `local_saved` | localStorage·recent에 localRecordId로 존재 |
| `saving` | `saveRideSessionToFirestore` 진행 |
| `saved` | serverRideId 확정·연결됨 |
| `save_failed` | 예외. 로컬 유지 |
| `discarded` | 정책상 미저장 |

- **입력:** 종료 스냅샷, uid, trail/publication/route 링크, conquest payload(optional)
- **부수효과:** CF 트리거(마일리지·토큰·정복·activity), heat 낙관
- **실패 시 보존:** 로컬 `StoredRideSession`, 결과 시트의 exercise/session
- **재시도:** 동일 스냅샷의 **조회/표시**만. 무단 `addDoc` 재생성 금지(멱등 재설계는 별도 범위)

### 4.2 축 B — SavedRoute 진행률

| 상태 | 의미 |
|---|---|
| `n/a` | SavedRoute 없는 주행 |
| `optimistic` | 클라 `setSavedRoutes` max 반영 |
| `confirmed` | FS transaction 결과 반영 |
| `progress_failed` | warn 후 낙관값 잔류(확정 아님) |

- **입력:** `progressToSave = max(completionRatio, previousProgressRatio)`, 완주 시 promote
- **부수효과:** next-ride 카드·resume 후보
- **실패 시 보존:** 낙관 progress · 서버 max 규칙 유지
- **재시도:** 동일 routeId에 progress write만(낮은 값으로 되돌리지 않음)

### 4.3 축 C — Conquest 확인

| 상태 | 의미 |
|---|---|
| `not_applicable` | payload 없음·discard |
| `pending` | 저장됨·결과 필드 없음(대기) |
| `confirmed` | `conquestResult` 유효 숫자 |
| `zero` | 확정 0 (중복·한도 등) |
| `error` | 조회 실패·NaN/음수/타입 오류 |
| `unknown` | 구독 전/해제 |

- **입력:** `rides/{serverRideId}.conquestResult`
- **부수효과:** 결과 시트 「새 도로」 수치만. `conquest/{uid}` 페인트는 계정 통계로 유지
- **실패 시 보존:** exercise 거리·pending 표시. **totalMeters-baseline 폴백 금지**
- **재시도:** 동일 serverRideId 문서만

## 6. 거리 계약 보완

거리 종류 번호는 [거리 카탈로그(record)](../../archive/260907-RTW-거리-종류-코드표현.md)를 따른다.

### 6.1 Conquest 미터 구분

| 심볼 | 의미 | SoT |
|---|---|---|
| `creditMeters` | 서버가 계산한 **인정 예산**(속도·티어·일일 쿼터 clamp) | CF 트랜잭션 지역 변수 |
| `conquestResult.creditedMeters` | 예산 중 **실제로 셀 순회에 소비한 인정분** (`consumedTotal`) | `rides/{id}.conquestResult` |
| `conquestResult.newMeters` | **해당 Ride의 신규 도로 거리**(이미 소유한 셀 제외) | 동상 — **결과 UI 원천** |
| `conquest/{uid}.totalMeters` | **계정 누적** 내 도로망 거리 | 계정 통계·페인트. 결과 차분 원천 금지 |

예시: 세션 3.0km · 일일 잔여로 credit 2.0km · 절반이 기존 소유 셀 → `creditedMeters≈2.0km`, `newMeters≈1.0km`, 계정 `totalMeters`는 +1.0km.

### 6.2 세 길이는 같지 않다

1. **이번 운동 거리** `sessionDistanceMeters` = virtual − offset
2. **이번 세션이 따른 geometry 구간 길이** ≈ endMeters − startMeters (haversine 합)
3. **신규 도로 미터** `conquestResult.newMeters`

중복 셀·한도·Directions vs geometry 차이로 수치가 갈린다. 같은 이름 `distanceMeters`라도 맥락 SoT를 따른다. **일괄 rename/마이그레이션으로 통일하지 않는다.**

### 6.3 progressRatio 분모

| 용도 | 분모 | 코드 |
|---|---|---|
| live/peer·session anchor ratio | geometry 길이 우선 | `computeRouteProgressRatio` |
| 종료 `completionRatio`·resume offset | `routeDistanceMeters` (Directions) | end hook, `resumeOffsetMetersFrom` |
| 카드 resume 좌표 | geometry × `lastProgressRatio` | `resumeAnchorForRoute` |

저장 진행률(비율)을 geometry에 곱해 좌표를 얻을 때와, Directions 미터로 offset를 만들 때는 **변환 계약을 명시**해야 한다(F2). Route 거리 출처: Directions 응답 / clip 결과 / 저장 스냅샷(`SavedRoute.distanceMeters`)을 섞어 쓰지 않는다.

### 6.4 「오늘 거리」

결과·HUD의 「오늘 N km」는 **현재 결과 시트가 가리키는 이번 세션** `sessionDistanceMeters` 표시다. **당일 모든 Ride 합계가 아니다.** 계정 마일리지(`users.mileageTotalMeters`)와도 다르다.

| identity | uid, localRecordId, serverRideId? | 동일 주행 연결. 늦은 응답은 키 일치 시만 |
