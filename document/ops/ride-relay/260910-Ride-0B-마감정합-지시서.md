## 1. 검수 판정 (요약)

독립 확인: `test:e2e:deadline-watchdog` 4 PASS; `test:next-ride` 149 PASS / 0 FAIL / 4 TODO.  
`persistRideEndCore` production 위임·Mapbox style stub(주행 성공 강제 아님)·emulator CF `conquestResult` 경로는 진전으로 인정한다.

**0B 완료 불가.** 제출 C1~C14 표가 원지시서 §6 의미를 바꿔 붙였다.

| 제출 라벨 | 실제 내용 | 원 §6 의미 |

| e2e C1~C5 | 이어 달리기/완주/ad-hoc/legacy 시나리오 | 로컬↔서버 ID, late list, legacy/계정, dual-length, 세션 offset |

## 2. 작업 순서

### M1. 번호 충돌 제거

- `ride-continuation.spec.ts` 등 이어 달리기 전용 시험 제목에서 §6 번호 재사용을 중단한다. 예: `RC1`…`RC5`, `RC13`, `CF-LIVE` 등.
- 제출·PROGRESS·매트릭스에는 **원지시서 §6 C1~C14만** PASS/FAIL/BLOCK/TODO로 쓴다.
- CF 실제 집계 증거는 `EMU-CF` 또는 `R5-CF` 행으로 분리한다. C14에 넣지 않는다.

### M2. 원 C1~C14 정합 표 (필수 산출)

각 행에 **시험 파일·케이스명·production 호출·명령·exit code**를 연결한다.

- 이미 있는 unit/N2/S1 증거로 채울 수 있으면 재구현하지 말고 링크만 한다.
- 원 C14(종료 샘플 vs stale UI)는 N2 `persistRideEndCore` 증거로 연결 가능한지 확인하고, 가능하면 PASS로 고정한다.
- 원 C13은 현재 e2e(이름 변경 후)를 유지한다.
- 원 C1~C3, C8, C11, C12 등 빈칸은 기존 production 시험이 있으면 매핑, 없으면 **최소 추가**만 한다. 새 UI/1단계 작업 금지.
