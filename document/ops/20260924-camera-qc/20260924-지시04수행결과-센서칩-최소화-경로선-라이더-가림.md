## B. 경로선이 라이더를 관통한다 — 먼저 처리

### 원인 (한 줄)

**레이어 순서(draw order) 문제다, depth 문제가 아니다.** 라이더(`preservedRiderLayer`, custom
`renderingMode:"3d"`)는 최초 생성 시 style 레이어 배열의 맨 위에 얹히지만, 경로선(`route`)·
내 도로망(`conquest-traces` 계열)·활동 오버레이(`activity-world` 계열)는 각자 필요할 때마다
`addLayer(beforeId 없음)` 또는 `moveLayer(top)`(예: `moveActivityWorldLayersToTop`)로 **스스로를
다시 최상단으로 끌어올리며** 라이더보다 위로 올라간다. Mapbox 의 2D line/fill 레이어는 커스텀
3D 레이어가 쓴 depth 를 읽지 않고 **style 레이어 배열 순서(painter's algorithm)만으로 앞뒤가
정해지므로**, 나중에 그려진 쪽(=배열에서 더 위)이 무조건 이긴다. 그래서 route 가 다시 추가되거나
conquest/activity 레이어가 top 으로 옮겨질 때마다 라이더 위로 올라와 몸통·헬멧을 가른다.

### D1~D4 확인

| # | 확인 | 결과 |
|---|---|---|
| D1 | 그리는 순서 | 라이더는 **한 번만** top 에 얹히고 그 뒤로는 순서를 지키지 않는다. route/conquest/activity 는 각자 반복적으로 top 으로 이동 — 시간이 지날수록 라이더가 밀려 내려간다 |
| D2 | depth test/write | `renderingMode:"3d"`·three.js `WebGLRenderer`(공유 `gl` 컨텍스트)가 자체적으로 depth 를 쓰지만, **2D line/fill 레이어는 그 depth 를 아예 읽지 않는다** — 3D↔3D(건물 등)에는 영향 없고, 3D↔2D 는 순서로만 결정. 즉 D2 는 원인이 아니다 |
| D3 | 어떤 선이 문제인가 | `route`(경로, 빨강)·`boxcycle-conquest-live-line`(진행 칠하기)·`boxcycle-conquest-traces-*`(내 도로망) 전부 같은 성질 — 전부 2D line 레이어라 순서 싸움에 함께 걸린다 |
| D4 | 카메라 각도 의존성 | **각도 자체는 원인이 아니다.** 화면에서 라이더 실루엣과 선의 스크린 좌표가 겹치기만 하면 어느 각도에서도 재현된다. QC1(상공 aerial, pitch 0)은 라이더가 작게 보여 겹칠 확률이 낮을 뿐, 근접 시점(QC2~QC6, pitch 80)에서는 라이더가 크게 잡혀 겹침이 자주 생긴다. Chief 가 재현한 QC3(=`backward`, 후방)이 대표 사례 |

### 택한 해법 — **①** (라이더가 선을 가리게 한다)

`preservedRiderLayer.ts` `ensureRiderPreservedLayer` — 이 함수는 이미 **매 프레임** 호출된다
(`MapView.tsx` RAF 루프). 라이더 레이어가 이미 있으면, 매 호출마다 `map.getStyle().layers`의
**맨 끝 id** 가 라이더 자신인지 확인하고 아니면 `map.moveLayer(id)`(beforeId 없음 = 맨 위로)로
되돌린다. route/conquest/activity 가 자기들끼리 top 을 다투며 라이더를 밀어내도, **다음 프레임
(16ms 이내)에 라이더가 곧바로 되찾아** 항상 선 위에 그려진다 — 즉 라이더가 선을 가린다.

②(겹치는 구간만 옅게)로 가지 않은 이유: ①이 구조적으로 불가능한 지점을 찾지 못했다. depth
공유 문제가 아니라 순서 문제였고, 이 코드베이스는 이미 `moveActivityWorldLayersToTop` 같은
"매번 자기 레이어를 top 으로 되돌리는" 동일 패턴을 쓰고 있어 라이더에도 그대로 적용 가능했다.

### 회귀 확인 (코드 검산 — §B4)

- **내 도로망(보라) 렌더·궤적 3색·LOD 광채**: `CONQUEST_ORDERED_LAYERS`(halo·traces·live·live-glow)
  끼리의 상대 순서는 `orderConquestLayers`가 그대로 관리 — 이번 변경은 그 그룹 전체를 라이더보다
  아래로 미는 것뿐, 그룹 **내부** 순서·불투명도 로직은 건드리지 않았다
- **경로선·진행 칠하기**: `route`/`CONQUEST_LIVE_*` 레이어 자체(소스·페인트·폭)는 무변경. 라이더와
  안 겹치는 화면에서는 이전과 동일하게 보인다
- **미니맵**: 별도 Mapbox 인스턴스(다른 map 객체) — `ensureRiderPreservedLayer`는 `layerByMap`
  WeakMap 으로 map 인스턴스별로 독립 동작해 미니맵에는 라이더 커스텀 레이어 자체가 없다(영향 없음)
- **peer 라이더·네임태그**: peer 도 같은 커스텀 레이어(`specs` 배열)로 그려져 함께 top 으로 유지된다.
  네임태그는 `mapboxgl.Marker`(DOM 오버레이)라 GL 레이어 순서와 무관 — 항상 캔버스 위
- **3D 건물 occlusion**: 건물(fill-extrusion)과 라이더 사이의 앞뒤는 실제 depth buffer 공유로
  결정되는 것으로 보이며(3D↔3D), 이번 변경은 라이더의 style-array 위치만 옮길 뿐 depth 기록/테스트
  방식을 바꾸지 않았다 — 다만 **실기로 직접 보지 못했으니 아래 확인 지점에 포함**

### Chief 확인 지점

- **어디**: 주행 중(경로/내 도로망 라인이 보이는 상태) 카메라 2~6번(QC2 forward·QC3 backward·
  QC4 left·QC5 right·QC6) 중 라이더가 화면에 크게 잡히는 시점. **QC3(후방)이 원래 재현 각도**
- **조건**: 경로선(빨강)이나 내 도로망(보라)이 라이더 발밑/몸통 근처를 지나가는 순간 — 이전에는
  선이 몸통·헬멧을 가르며 위로 보였는데, 이제는 라이더가 선을 덮어야 정상
- **위험 지점(솔직히)**: (1) 3D 건물이 있는 각도에서 「건물 뒤로 라이더가 사라지는」 기존 occlusion이
  깨지지 않는지 — 위 이유로 이론상 무관해야 하나 실기 미확인. (2) 매 프레임 `getStyle().layers`
  읽기 자체는 순서가 이미 맞으면 `moveLayer`를 호출하지 않아 비용이 작지만, route/conquest/activity
  가 자주 top 으로 재이동하는 상황(경로 갱신이 잦을 때)이라면 프레임마다 되돌리는 핑퐁이 반복될 수
  있다 — 성능 이슈로 체감되면 이 지점부터 의심할 것. (3) QC1(상공 aerial)처럼 라이더가 아주 작게
  보이는 각도에서는 라벨/POI 텍스트도 라이더보다 아래로 깔리게 된다 — 라이더 발밑 지명이 잠깐
  가려질 수 있으나 실기 전 판단은 Chief 몫으로 남긴다

## A. 초기 화면 센서 칩 — LED 만 남긴 최소형

### 처리

`RouteDock.tsx` — `stage === "idle"`(경로 없는 첫 화면)일 때, 기존에 있던 **주행 중 접힘의
캐럿+LED 패턴을 그대로 재사용**한다(D7, 새 CSS 없음):

- `preRouteCollapsed = stage === "idle" && Boolean(cadence)`
- 텍스트 칩(`[ ● SENSOR ]`)은 숨기고, 캐럿(`route-dock__caret`)의 셰브런 아이콘 자리에
  LED(`route-dock__caret-led`, 기존 `hud-cadence__led` 클래스 그대로 재사용)만 남긴다
- **클릭 동작은 토글이 아니라 `cadence.onOpen()` 직결**로 바꿨다(§A3 "동작은 그대로" 요구) —
  idle 에서 캐럿을 펼쳐 봐야 빈 목록("지도를 탭해 출발·도착 설정")뿐이라 펼침 대신 곧바로 센서
  시트를 연다. 경유지가 하나라도 잡히면(`stage`가 idle 을 벗어나면) 즉시 원래 캐럿(펼치기/접기)
  + 텍스트 칩 조합으로 되돌아간다 — ready-to-start·setup·riding·paused 는 전부 무변경
- LED 상태 표현(미연결 흰색·검색 중 흰색 깜빡임·연결됨 초록)은 `cadenceChipView`를 그대로
  호출해 그리므로 **로직 변경 없음**
- `RouteDock.css`: `.route-dock-anchor--caret-only` 클래스를 추가해 `.route-dock-anchor--ride-collapsed`
  와 같은 "body 폭 0" 규칙을 공유 — dock 전체 폭이 캐럿 폭(0.93rem)만 남는다
- 44px 터치 타깃: 캐럿의 기존 `min-height:44px` 규칙이 그대로 적용된다(별도 CSS 추가 없음) —
  다만 이 값은 이 라운드 이전부터 폰 가로(루트 13.5px)에서 실측 약 37px 이라는 기존 이슈가
  있다(`touch-targets-44.spec.ts` 주석, Chief 판단 대기 — 이번 라운드가 만든 문제 아님, 손대지 않음)

### Chief 확인 지점

- **어디**: 주행 시작 전(로그인 직후 첫 화면), 좌하단 RouteDock 자리. 이전엔 `[ > ● SENSOR ]`가
  보였는데 이제는 캐럿 폭 안에 LED 점 하나만 보여야 한다
- **조건**: 경로·핀을 아직 하나도 안 찍은 상태(=idle). 지도를 탭해 출발점을 찍는 순간 원래
  캐럿+텍스트 칩 형태로 돌아간다(의도된 동작)
