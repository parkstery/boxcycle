## §1 무엇을 바꿨는지

`MapView.tsx:3929` 근처 표고 오버레이에서 「시점 Nm」·「종점 Nm」(`.elevation-overlay__meta`)의
**세로 위치**를 그래프 박스 **맨 위**(허공)에서 화면 하단 **코칭 멘트 줄**
(`.hud-coach`/`.map-hud__bc`, `MapHud.css`)과 같은 높이로 옮겼다. 가로(좌=시점, 우=종점)는
그대로다.

- `MapView.css` `.elevation-overlay__meta`: 그래프 박스 상단의 in-flow 행 → `position: absolute;
  bottom: calc(var(--hud-pad-bottom, 0.65rem) + 0.2rem)` 로 화면 최하단 근처에 절대배치.
  `.hud-coach`/`.map-hud__bc`가 쓰는 것과 **같은 계산식**을 그대로 복제했다 — 다만 `MapHud`는
  `MapView`의 형제 컴포넌트(DOM 트리상 남남)라 `--hud-pad-bottom` 커스텀 프로퍼티가 상속되지
  않는다. 이미 같은 상황을 겪은 `PlaceSearchPanel.css`(`var(--hud-pad-top, 0.65rem)`)의 리터럴
  폴백 선례를 그대로 따랐다.
- `.elevation-overlay__plot`: 메타 행이 더 이상 그래프 위 공간을 안 먹으므로 높이를
  `calc(100% - 1rem)` → `calc(100% - 0.3rem)` 로 넓혔다(그래프가 패널 높이를 더 쓴다. 전부
  안 쓴 이유는 §5 참고). **`.elevation-overlay` 자체의 폭·높이(120px)는 건드리지 않았다** —
  패널 rect 는 불변.
- `MapView.tsx`: `elevationUi.marker.yPct < 20` 이면 붙던 `elevation-overlay__progress--below`
  (점 아래로 뒤집기)를 **제거**했다. 이유는 §3.

## §2 Chief 가 어디서 확인하면 되는가

- **자리**: 주행 중(또는 입문 코스 로드 후 일시정지 전이라도 `elevationUi`가 뜬 상태) 화면
  하단, 표고 그래프 패널(중앙 하단) 바로 아래 줄. 「시점 N m」이 왼쪽, 코칭 멘트가 가운데,
  「종점 N m」이 오른쪽 — 한 줄 띠로 보여야 한다.
- **뜨는 조건**: `elevationUi`(경로 있고 표고 로드 완료)가 있을 때 항상 같은 높이. **코칭 멘트는
  주행 시작(`riding`) 또는 일시정지(`paused`) 상태에서만** 뜨므로(`showCoach` 조건, `MapHud.tsx`
  291행), 주행 전(코스만 로드한 idle 상태)에는 시점/종점만 그 높이에 있고 코칭 멘트 자리는
  비어 있다 — 이때도 시점/종점 높이가 그대로인지 보면 "코칭 멘트 없을 때도 같은 높이" 요구를
  확인할 수 있다.
- **끄고 보기**: MENU(좌상단 RTW) → 설정 → 「코칭 배너」 체크 해제 → 주행 시작. 코칭 멘트 없이
  시점/종점만 그 높이에 뜨는 상태를 바로 재현할 수 있다.

## §3 3939행 뒤집기 로직을 어떻게 처리했는가

원래 로직: 표고 그래프 최고점 부근(`yPct < 20`)에서는 「N% covered」 배지를 점 위로 띄울 여백이
부족해 **그래프 박스 맨 위에 있던** 시점/종점 메타 행을 침범했다 — 그래서 점 아래로 뒤집었다.

이번 변경으로 메타 행이 그래프 박스 밖(화면 최하단, 코칭 높이)으로 완전히 옮겨갔으므로,
**침범할 대상 자체가 사라졌다.** 그래서 `yPct < 20 ? "--below" : ""` 분기와
`.elevation-overlay__progress--below { --elev-label-y: 60% }` 규칙을 **삭제**했다(죽은 코드
방치 금지 — 지시서 §3 명시 사항). 관련 위치 3곳의 주석도 갱신·정정했다:

1. `MapView.tsx` 3939행 주석 — 새 설계로 재작성.
2. `MapView.css` — `--below` 규칙 자리에 제거 이유를 남겼다.
3. `MapView.css` 종점 깃발 위 주석(구 라인 1090-1095) — 이 주석은 **원래도 실제 코드와 안
   맞았다**("위로 띄우면(-100%)... 반드시 -50%(가운데)를 유지한다"고 적혀 있었는데 실제
   `.elevation-overlay__finish`의 transform 값은 이미 `-100%`였다). 메타 행 침범이라는 전제가
   사라진 김에 함께 정정했다 — 남은 진짜 이유("깃대 밑동이 종점에 앉도록")는 그대로 뒀다.

기존 e2e 회귀 스펙(`hud-distance-elevation-shots.spec.ts`)이 시나리오 B(초반이 경로 최고점)에서
`--below` 클래스가 **붙어야 한다**고 단언하고 있어 그대로 두면 이번 변경으로 **깨진다** —
스펙 자체를 "`--below`가 더 이상 붙지 않아야 한다"로 갱신했다(§4). **이 스펙은 캡처 중단
지시로 실행하지 않았다** — 소스만 고쳤고 `npx playwright test` 는 돌리지 않았다.

## §4 §6 요구 수치 — 계산치(실측 아님, 중요)

캡처를 생략하라는 지시로 **브라우저 실측은 하지 못했다.** 대신 코드에 실제로 존재하는 값
(`index.css` 루트 폰트 13.5px·`line-height:1.5`, `MapHud.css`의 `--hud-pad`/`--hud-pad-bottom`
공식, 내가 쓴 `.elevation-overlay__meta` 패딩/폰트)을 그대로 대입해 손으로 계산했다. 폰 가로
근사 뷰포트 **740×300**(지시서 §5 D 기준) 가정:

| 항목 | 계산값 | 판정 |
|---|---:|---|
| 표고 패널 rect (w×h) | 변경 없음(414.4×120px, `.elevation-overlay` 규칙 자체를 안 건드림) | 늘지 않음 — **git diff 로 확인 가능**(해당 규칙 diff 없음) |
| 시점/종점 세로 중심 vs 코칭 멘트 세로 중심 차이 | **약 2.2px**(740px 폭 기준. 650~900px 범위에서 약 0.9~3.3px) | 0에 근접 — 폴백 리터럴(0.65rem)과 실제 clamp 값의 미세한 차이가 원인, 실측 시 브라우저 렌더 오차 별도 존재 |
| 「N% covered」 배지 최소 간격 | **약 +6.7px**(0.3rem 여유 반영 후, 경로 최저점 부근 최악 케이스) | 겹치지 않음(양수) — 단, 손계산이라 확정 아님(§5 이견) |
| 코칭 멘트 최장 시 좌우 간격 | 실제 문구 최장("Relax your grip. No white knuckles.", 36자) 기준 약 **+29px** 여유. `.map-hud__bc`의 CSS `max-width` 이론 상한(30rem/70% 중 작은 값)까지 늘어나는 극단값이면 **겹칠 수 있음**(이론상 마이너스) — 단 `phraseManifest.ts`의 실제 문구가 그 상한에 도달하지 않아 실사용 중 발생 가능성은 낮다 | 실사용 안전, 이론적 여지는 §5에 명시 |

## §5 이견·불확실 구간 (솔직하게 — 캡처로 확정 못 함)

1. **모두 계산치다.** `line-height`가 `inline-flex` 컨테이너 높이에 정확히 어떻게 반영되는지,
   폰트 렌더링 실제 glyph box 등은 브라우저마다 미세하게 다를 수 있다. "0에 가깝다"·"안 겹친다"
   판정은 CSS 선언값을 손으로 대입한 결과지, `getBoundingClientRect()` 실측이 아니다.
2. **배지-메타 간격이 타이트했다.** 처음 계획(그래프가 패널 높이 100%를 그대로 씀)으로 계산하면
   최악 케이스(진행점이 경로 최저점 근처) 여유가 **약 3px** 로 빠듯해, `.elevation-overlay__plot`
   높이를 `100%`가 아니라 `calc(100% - 0.3rem)`으로 약간 줄여 여유를 키웠다(§1). 즉 그래프가
   패널 높이를 "완전히"는 안 쓴다 — 지시서는 "높이를 늘리지 마라"였지 "100% 채워라"는 아니었으므로
   범위 안이라 판단했지만, **실기로 안 봤으니 확신은 아니다.**
3. **코칭 멘트 최장 시 겹침은 이론적으로 가능**하다(§4). 실제 문구 풀은 안전하지만, `.map-hud__bc`의
   `max-width`(변경 안 함, MapHud.css 소유)가 이론상 시점/종점 위치까지 닿을 수 있다는 계산
   결과는 남긴다 — Chief 가 실기에서 코칭 멘트가 뜬 채로 시점·종점과의 간격을 한 번 보면 좋겠다.
4. **경로 미리보기 선(지도 위 빨강 선)·Mapbox 저작권/스케일바와의 겹침은 확인하지 않았다** —
   경로 형태·카메라 각도에 따라 달라지는 지오메트리라 코드만으로 계산할 수 없다. 캡처 생략
   지시로 실기 확인이 필요하다.
5. `.elevation-overlay__meta`의 폰트 크기(0.72rem)는 바꾸지 않았다 — D1("m" 단위 반복 정리)을
   검토했으나, 시점/종점이 화면 양 끝에 떨어져 있어 단위를 한쪽에만 남기면 반대쪽 숫자의
   의미가 끊긴다고 판단해 **둘 다 유지**했다(지시서도 "지우지는 마라"를 재확인).

## §7 깨질 수 있는 곳 (솔직하게)

- **§5-2, 5-3** — 배지/코칭 멘트와의 간격이 계산상 여유는 있지만 실기 확인 없이 타이트한
  구간을 CSS 상수(0.65rem 폴백·0.3rem 플롯 여유)로만 방어했다. 실기에서 만약 겹치면, 가장
  먼저 의심할 곳은 이 두 상수다.
- **`--hud-pad-bottom` 폴백(0.65rem)** — 실제 `clamp(0.45rem, 1.4vw, 0.85rem)` 값과 화면 폭에
  따라 최대 ±0.2rem(~2.7px) 어긋난다. 뷰포트가 이례적으로 넓거나 좁으면(예: 태블릿 가로) 시점/
  종점과 코칭 멘트의 세로 정렬이 계산치보다 더 벌어질 수 있다.
- **그래프 곡선·진행점 렌더링** — `.elevation-overlay__plot` 높이를 늘려(0.7rem 만큼 더 사용)
  세로 스케일이 예전보다 약간 커졌다. 표고 굴곡이 시각적으로 더 도드라져 보일 수 있다 —
  데이터나 좌표 계산은 안 바꿨지만 "그림이 달라 보인다"는 점은 미리 밝혀 둔다.
- **모델 사용**: Claude Sonnet 5(본 세션), 서브에이전트 위임 없이 직접 구현·계산했다.
