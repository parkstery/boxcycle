# 지시01 — 관리자 지표 서버 함수

2026-10-23 · task · 담당 Claude impl-standard · 감리 Claude · 계약 [01-plan.md](01-plan.md) · 보고 `03-result-01.md`

범위: `functions/` 만. `apps/web` 는 다른 실행자가 동시에 고친다 — 건드리지 않는다.

1. `functions/src/cliRideMetrics.ts` 의 계산 부분(Auth 코호트 적재·rides 스캔·사용자별 집계·비율 계산)을 새 `functions/src/rideMetricsCore.ts` 로 옮긴다. **순수 집계 함수**(입력: 사용자→코호트 맵, ride 행 목록, 제외 uid 집합, 기준 시각 → 출력: 계약의 `metrics`·`recent`)와 **적재 함수**(admin SDK 로 읽기)를 나눈다. CLI 는 이 코어를 써서 **지금과 같은 출력**을 낸다(제외 목록 없이 — CLI 옵션 `--exclude-internal` 이 있으면 제외 적용).
2. 새 `functions/src/adminDashboard.ts` 에 `getAdminDashboard` — 기존 `adminPromoteSavedRoute.ts` 의 인증·권한 확인 방식과 `index.ts` 의 `onRequest`(region·invoker public·CORS) 형식을 그대로 따른다. GET 만. 제외 uid = `config/routeReviewers.uids` ∪ `config/adminDashboard.excludeUids`(문서 없으면 빈 목록). 가입 시각은 Auth `metadata.creationTime`. 처리 안 된 신청 수는 `publicRouteRequests` 의 `status == "pending"` count. `index.ts` 에서 export.
3. 시험: 순수 집계 함수에 가짜 데이터로 — 비율 계산, 분모 0 → null, 제외 uid 빠짐, KST 날짜 경계(15:00 UTC 전후), 폐기 기준 미만 주행 빠짐. 기존 functions 시험 방식(`functions/package.json` 의 test)을 따라 등록한다.
4. 금지: Firestore 규칙·기존 함수 동작 변경, 운영 데이터 쓰기, 배포, git commit/push/stash/checkout/restore/clean/worktree.

검사(functions 폴더): `npm test` 전체 통과, `npm run build` 통과. 보고에 계약과 다른 점이 있으면 적는다.
