# 쓰기 장부 — 나머지 950회 분류와 L9 제안

작성 2026-11-04 Supervisor Claude Code(Opus 5.5) 직접 · 상태: **측정 완료, L9 A·B Chief 승인·구현(11-04)** · [작업 입구](README.md) · 재현 도구 [classify-writes.cjs](tools/classify-writes.cjs)

## 결론

- 「나머지 950회는 500m 경로의 서버 집계」라는 추정은 **대부분 틀렸다**. 서버 집계는 약 270~320회다.
- 진짜 큰 덩어리는 **접속 신호(하트비트)**다. 공개 경로 주행 1시간에 470~630회로, L4로 줄인 위치 저장 300회보다 많다(코드 주기로 계산, 공개 주행 실측은 아니다).
- 주행의 84%(시간 기준 89%)는 공개 경로가 아닌 주행이다. 이 주행은 위치 저장을 전혀 안 하고, 하트비트와 **없는 문서를 지우는 호출**만 나간다.

## 보고서 정정

- **`netStats`가 없으면 옛 화면이라는 판정은 틀렸다.** `routeEnabled`는 `sharedRidePublicationId`가 있어야 참이고, 공개 경로가 아닌 주행은 최신 화면이어도 `netStats`를 남기지 않는다. 판정은 `publicationId`가 있는 주행으로만 한다.
- 12:21 공개 경로 재주행으로 `netStats`가 처음 남았다. 4초 줄기는 재현되지 않아 아침 구간 원인은 **미확정**이다 → [L4 설계 문서](02-design-l4.md) 끝.
- `read-net-stats.cjs`는 색인 부족으로 실패해서 코드로 거르도록 고쳤다. 운영 색인은 추가하지 않았다.

## 별건 — 지운 게스트 기록이 되살아남 (11-04 12:12)

관전 브라우저의 새 게스트 `aPbTo3`가 12:12:53~55에 주행 50건(종료 10-29~11-01)을 올렸다. 트리거 약 250회, 읽기 급증의 시작이다.

- 경로: `useRecentRideSessions` — 서버에 이 uid의 주행이 0건이고 브라우저에 기록이 있으면 무조건 올린다. 기록이 어느 계정 것인지 확인하지 않는다.
- 영향: 그 게스트의 마일리지 51,074m·주행 50회가 전부 이 기록이다. `conquestResult.tier`가 없어 순위 점수는 안 올랐다.
- 추정: 11-03 게스트 전부 삭제 뒤 브라우저가 새 익명 uid를 받았고, 지워지지 않은 로컬 기록이 올라갔다(이전 uid는 확인하지 못했다). 게스트 자동 정리 뒤 돌아온 사용자도 같은 경로를 탄다.
- 수정(Chief 승인): 로컬 기록에 `ownerUid`를 찍고, 내가 만들었고 서버에 없는 기록만 올린다. 게스트→Google 연결은 uid가 그대로라 같은 계정으로 처리된다. 주인 표시 전의 옛 기록은 올리지 않고 화면에만 남는다.
- `aPbTo3` 50건은 수정본 배포 뒤 지운다(먼저 지우면 옛 코드가 서버 0건을 보고 다시 올린다). 스냅샷 `.out/private-guest-lifecycle/rides-aPbTo3-20261104/`, 도구 [purge-resurrected-rides.cjs](tools/purge-resurrected-rides.cjs). `worldActivity.recentRideCount30d` +50은 되돌리지 않았다(줄어드는 경로가 없는 누적값).

## 3D 뷰와 읽기·쓰기 (Chief 질문)

`enable3D`는 카메라·지도 코드(`MapView`·`rideCameraFollow`·`CameraViewMenu`·`MapHud`·`App`)에만 쓰인다. 지형은 Mapbox 타일(`mapbox.terrain-rgb`)이고 Firestore·RTDB 코드에 닿지 않는다. 위치 저장 박자는 100ms 타이머라 화면 프레임과 무관하다. 다만 보내는 속도 값은 프레임 기반 샘플러가 만들므로, 3D로 프레임이 크게 떨어질 때 속도 변화 쓰기가 달라지는지는 **측정하지 않았다**. 12:18 주행의 56회·26회 차이가 3D 때문인지 추월 때문인지도 가르지 못했다.
