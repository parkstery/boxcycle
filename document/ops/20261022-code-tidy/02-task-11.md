## 1. ref 동기화 효과 압축

`MapView` 본문(약 822–1114행)에 아래 꼴의 효과가 수십 개 반복된다.

```ts
useEffect(() => {
  someRef.current = some;
}, [some]);
```

- 새 훅 `apps/web/src/components/map/useAssignRef.ts`: `export function useAssignRef<T>(ref: { current: T }, value: T): void { useEffect(() => { ref.current = value; }, [ref, value]); }`
- **본문이 정확히 「ref.current = 값」 한 줄이고 의존성이 그 값 하나뿐인** 효과만 `useAssignRef(someRef, some);` 로 바꾼다. **같은 자리**에서 바꾼다 — 효과 실행 순서가 선언 순서이므로 위치를 옮기지 않는다.
- ref 선언(`useRef(...)`)과 초기값은 그대로 둔다. 본문이 두 줄 이상이거나 조건·다른 의존성이 있는 효과는 건드리지 않는다.
- `useLayoutEffect` 는 바꾸지 않는다.

## 2. 파일 위쪽 보조 함수 분리

`MapView` 컴포넌트 밖의 최상위 함수(약 134–560행: `createFixedScaleBoxControl`, `isMapAttachedToContainer`, `mountSelfLocationMarker`, reduced-motion 구독 3종, `syncLiveSelfRiderVisual`, auto-route 클릭 디버그 마커 2종 등)를 성격별 새 파일로 옮긴다(예: `mapViewControls.ts`, `mapViewSelfRider.ts`, `mapViewReducedMotion.ts`). 본문은 한 글자도 바꾸지 않고 옮긴다. `MapView.tsx` 에서 이미 export 되던 이름이 있으면 `MapView.tsx` 에서 계속 같은 이름으로 다시 내보낸다.

- `components/` 는 앱 계층이라 `dep-layers.json` 수정은 필요 없다.
- 소스 문자열을 읽는 계약 시험(`scripts/**/*contract*.test.*` 에서 `MapView.tsx` 를 `readFileSync` 하는 것)이 있으면, 옮긴 함수의 문자열을 그 시험이 찾는지 먼저 확인하고, 찾는다면 **그 함수는 옮기지 말고** 보고에 적는다(시험을 고치지 않는다).
