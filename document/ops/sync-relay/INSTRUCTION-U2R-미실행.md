## 1. 고칠 것 — **red dot 이 route 밑으로 내려간다**

### 1-0. 보존

```
현재 INSTRUCTION.md → document/ops/sync-relay/INSTRUCTION-U2.md 로 복사
U2-tick-baseline.json · U2-tick-after.json 은 덮어쓰지 마라
```

### 1-1. 무엇이 깨졌나

`moveActivityWorldLayersToTop` 은 이제 **활동 레이어 8종의 존재 시그니처**가 바뀔 때만
`moveLayer` 한다 (`MapView.tsx:217-219`). 그런데 이 함수가 존재하는 이유는 주석 그대로다 —

```
/** Activity World dot·line — `route`·coverage 위로
    (route effect 가 dot 뒤에 addLayer 되는 회귀 방지) */
```

```
코스를 불러오면
   MapView.tsx:1817   route effect 가 route 레이어를 **위에** addLayer 한다
   MapView.tsx:1830   곧바로 moveActivityWorldLayersToTop(map) 를 부른다  ← 복구 의도
   그러나 route 추가는 활동 레이어 8종의 **존재 여부**를 바꾸지 않는다
   → 시그니처가 같아 early return → **아무 일도 하지 않는다**

시그니처 초기화는 style.load(:1599) 한 곳뿐인데
   **코스 로드는 style.load 를 동반하지 않는다**
```

**결과: 주행 중 코스 로드·전환 시 red dot·heat 가 route 선 아래로 깔린다.**
이 함수가 막으려던 바로 그 회귀다. red dot 은 이 리포에서 여러 번 문제가 됐던 영역이다.

### 1-2. 어떻게 고치나 — 방향만

```
① 「무엇이 바뀌면 다시 올려야 하는가」를 다시 정의하라
   활동 레이어의 존재 여부만으로는 부족하다.
   **위에 무엇이 얹혔는지**가 바뀌면 다시 올려야 한다 —
   예: map.getStyle().layers 의 순서에서 활동 레이어들의 위치(index)가 내려갔는지
   비용이 걱정되면 route·coverage 처럼 위에 얹힐 수 있는 레이어만 좁혀 봐도 된다

② 되돌려서 「매번 moveLayer」로 가지는 마라
   그건 U-2 가 없앤 부하다. 조건을 옳게 만드는 것이 답이다

③ lastActivityWorldLayerSig 가 **모듈 전역**이다
   맵 인스턴스가 재생성·리마운트되면 상태가 남는다. 맵에 매어라
```

### 1-3. 시험을 반드시 붙여라 — 이번 회귀는 시험이 없어서 통과했다

```
R1  주행 중 코스 로드·전환 (style.load 없이) 뒤
    활동 레이어(red dot·heat)가 route 선 **위**에 있는가
    판정은 눈이 아니라 map.getStyle().layers 의 **인덱스 비교**로 하라
R2  style.reload 후 복구 — U-2 의 T3 가 안 한 것이다. 이번엔 실제로 넣어라
R3  U-2 가 얻은 이득이 유지되는가 — 경로 A emit 0 · fracA 0
```

## 2. 최종 코드로 다시 재고, 사람 눈으로 확인한다

### 2-1. 계측을 최종 코드로

U-2 의 after JSON 은 `33b369c` **직전** 측정이라고 본인이 밝혔다. 최종 코드로 다시 내라.
→ `U2R-tick-after.json` (기존 두 파일은 그대로 두어라)

### 2-2. 프레임 지표는 **이 하네스로 판정하지 마라**

```
관측 사실   rAF p50 이 수정 전 83.3ms · 후 66.7ms — 헤드리스에서 12~15fps 다
            그래서 「16.7ms 초과 발생률」이 전후 모두 1.0 이다
결론        T2 는 「미달」이 아니라 **이 환경에서 측정 불가**다
            발생률을 통과 기준으로 계속 쓰지 마라
```

대신 **부하가 실제로 사라졌음**을 보이는 지표로 판정하라 — 경로 A emit, moveToTop 호출 수,
`syncActivityWorldLayersOnMap` 총 소요 시간 합(30초 중 몇 ms를 썼는지). 이건 환경과 무관하다.

### 2-3. 사람 눈 확인용 — **실제 브라우저 화면**

지금 틱이 사라졌는지 판정할 수 있는 것은 사용자뿐이다. 확인을 도와라.

```
헤드리스 말고 **실제 브라우저 창**으로 주행 화면을 띄우는 방법을 보고서에 적어라
   (npm 스크립트 한 줄이면 된다. 거리 1m·팔로우로 바로 들어가는 경로면 더 좋다)
가능하면 수정 전/후 화면 녹화 또는 연속 스크린샷을 U2R-shots/ 에 남겨라
```
