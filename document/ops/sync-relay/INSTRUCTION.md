## 0. S3A 판정 — **수용 6/6 PASS. 채택**

`S3A-summary.json` 재계산으로 수치 일치를 확인했다. `publishQueueMs` p50 4,520 → **22 ms**,
`inFlightMax` 10 → **1**, `A_firstOutOfOrder` 77 → **0**, cap 히트 22.8 % → **0 %**.
`PublicationSharedPresence` 수신 배선 수정과 `rideJoinPresenceBurst` 경유 통일도 근거가 타당하고
이견에 정직하게 밝혔다. **RTDB 구독 방식은 그대로이므로 금지 위반이 아니다.**

### 0-1. 감리 정정 2건 (Chief 지적)

**(가) `publishQueueMs × 속도`를 화면 오차와 동일시한 것은 과장이었다.**
37.7 m / 115.9 m 는 **발행 스냅샷이 얼마나 낡았는가**이지 사용자가 보는 어긋남이 아니다.
수신 측 외삽이 일부를 보상한다. **화면 오차는 아직 측정된 적이 없다. 그것이 이번 지시다.**

**(나) 외삽 점유율만으로 패킷 간격의 원인을 확정한 것도 성급했다.**
「점유 51.3 % → 간격 328 ms」는 균등 분포를 가정한 역산일 뿐이다.
이번에는 **간격을 직접 측정**하고, 원인은 단정하지 않는다.

### 0-2. 감리 자책 3건째 — 반증 조건이 나빴다

S3A §2-3 이 건 문턱은 **`extrapolate` 점유 50 %** 였는데, 점유율은 위치 정확도의 프록시가 아니다.
실제 지표(cap 히트 0 %, ahead max 3,356 → 840 ms, 외삽 오차 max 3.85 → **1.45 m**)는 모두
개선됐다. 네가 규칙대로 「해당함」으로 보고한 것은 옳다. **규칙이 나빴다.**

## 1. 이번 지시의 성격 — **측정만 한다**

```
제품 코드를 변경하지 않는다
발견한 문제를 즉석에서 고치지 않는다 — 발견하면 기록하고 멈춘다
```

허용되는 변경은 **측정 스크립트·e2e spec·집계 스크립트뿐**이다
(`apps/web/e2e/**` · `apps/web/scripts/peer-sync/**`). `apps/web/src/**` 는 **한 줄도 건드리지 마라.**

내부 지표(`publishQueueMs` 등)는 **이번 판정의 근거가 아니다.** 참고로만 병기한다.
판정은 **A 의 실제 위치와 B 화면 위치의 미터 오차** 하나로 한다.

## 2. 측정

### 2-1. 무엇을 재는가

| 기호 | 값 | 출처 (이미 존재 — 신규 계측 금지) |
|---|---|---|
| **A_auth** | A 의 rAF 원본 거리 | `sampleVirtualDistanceM()` · pt1 `authDist` |
| A_snap | A 의 경로 투영 거리 | pt2 `dist` (①−② 확인용) |
| **B_disp** | B 화면에 그려진 peer 거리 | pt6 `displayDistM` |
| B_newest | B 가 수용한 최신 스냅샷 | pt5 / 버퍼 `newest.distM` |

**판정은 `A_auth` 대 `B_disp`** — 사용자가 보는 것과 진짜 위치다.
스케일 게이트만 `B_newest` 를 쓴다(승인된 정의 그대로).

### 2-2. 시나리오 2종

| 케이스 | 조건 | 판정 |
|---|---|---|
| **z15-cruise** | 30 km/h 정속, **Δ(A_auth) ≥ 100 m** 이고 **창 ≥ 20 s** | **판정 대상** |
| **z15-depart** | 0 → 30 km/h 램프 전 구간 + 이후 정속으로 위 전제 충족까지 | **판정 대상** |

- **z13(저줌)은 이번 판정에서 제외**한다. D-2 미수정이라 실패가 예정돼 있고 S3B 사안이다.
  측정은 해서 **기록만** 남겨라(판정표에 올리지 마라).
- 주행 거리는 `A_geoLen`(≈1,029 m) 아래에서 끝내라. **D-8 clamp 구간에 들어가지 마라.**

### 2-3. 유효성 가드 (하나라도 위반이면 그 케이스는 「판정 유보」)

```
① 앞 2 초 폐기        HANDOFF §5 F-1 (visibility 초기 시각 0) 회피. 폐기했음을 보고에 명시
② 전제 충족          Δ(A_auth) ≥ 100 m  AND  창 ≥ 20 s
③ 겹침 비율 ≥ 0.7     s1-metrics.mjs 의 minOverlapRatio (S3-DIAG-R2 에서 정정 완료)
④ D_eff 천장 미접촉   maxDelayMs = 3000 으로 탐색. 천장에 붙으면 「판정 유보」 — 완화 금지
⑤ 시계 보정          before·after 각 1 회 기록. |after − before| > 100 ms 면 선형 보간하고
                     보간했음을 명시. 보정값 미기재 시 그 수치는 무효
```

`D_eff` 는 신호가 멈추면 무의미해진다(S2 에서 이미 겪었다). ④ 는 그 재발 방지 장치다.

## 3. 판정 — 승인된 기준 2 개만 쓴다

새 기준을 만들지 마라. 둘 다 `HANDOFF.md` 에 이미 승인돼 있다.

### 3-1. 스케일 게이트 (HANDOFF §3)

```
전제    Δ(A_auth) ≥ 100 m  AND  창 ≥ 20 s
게이트  |Δ(A_auth) − Δ(B_newest)| / Δ(A_auth) ≤ 0.1        (시간 이동에 불변)
        참고 — S1 z15-cruise 는 48 % 이탈로 FAIL 이었다
```

### 3-2. 정확도 예산 (HANDOFF §4)

```
A_auth 대 B_disp
  D_eff              ≤ 350 ms
  residual RMSE      ≤ 1.0 m   @30 km/h
  residual max       ≤ 2.5 m
```

### 3-3. 판정 — **범위를 한정한다**

```
z15-cruise · z15-depart 두 케이스가 3-1 과 3-2 를 모두 통과
   →  「S3A 대상인 z15 위치 불일치 종결」
하나라도 미달                    →  미종결 (부분 성공 아님)
「판정 유보」가 하나라도 남으면    →  미종결 · 재측정 필요
```

⚠ **PASS 를 「멀티라이더 위치 동기화 결함 종결」로 쓰지 마라.**
z13(저줌)은 §2-2 대로 판정에서 제외했고 **D-2 는 아직 미수정**이다. D-1 도 남아 있다.
전체 결함의 종결 여부는 **S3B 완료 뒤에 판단**한다.

보고서·커밋 메시지에 쓸 수 있는 표현은 **「S3A 대상인 z15 위치 불일치 종결」** 까지다.
