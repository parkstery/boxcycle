## 1. 결함 ① 로컬 투영이 매 프레임 화면 정중앙으로 스냅한다

감리가 `S44R5-manifest.json` 을 직접 계산한 결과다.

```
localScreenX 표본 28   →  정확히 640.0 이 17 개
나머지 11 개            →  643.8 · 645.0 · 645.1 · 645.7 · 646.3 · 646.4
640.0 은 화면 정중앙이다 (폭 1280)
```

상대 좌표가 그 토글을 그대로 따라간다.

```
프레임   local     상대X     변화
 001    645.7    −96.8     −9.1
 002    640.0    −94.3     +2.5
 003    645.0   −100.4     −6.1
 004    640.0    −97.5     +2.9
```

**방향 전환 23 회의 주성분이 peer 가 아니라 이 토글이다.** peer 절대 X 는 552 → 541 로 매끄럽다.

### 1-1. 감리가 코드에서 확인한 것 — 여기서부터 보라

`peerJitterCapture.ts:412-414` 에서 peer·local·ahead 는 **같은 `map` 으로 같은 순간에** 투영된다.

```ts
const peer  = projectLngLat(map, input.lng, input.lat);
const local = projectLngLat(map, input.localLng, input.localLat);
```

**따라서 프레임 안에서 카메라 상태가 어긋난 것은 아니다.** 그렇다면 남는 후보는 이것이다.

```
카메라가 따라가는 self 위치와 getPeerSyncSelfDistM() 이 **서로 다른 소스·다른 시점**이라
카메라가 수렴한 프레임에서만 project(local) 이 정확히 중앙이 된다
```

**이 가설을 확인하라.** 맞으면 두 소스를 일치시키거나, 최소한 어느 쪽이 화면에 실제로 그려지는
마커인지 확정하라.

### 1-2. 【필수】 그려지는 위치와 일치하는지 증명하라

Chief 가 S4-4R3 에서 지적한 문제가 그대로 남아 있다 —
**`map.project` 로 계산한 값이 실제로 그려지는 마커 위치와 같다는 증거가 없다.**

```
증명 방법   같은 프레임의 스크린샷에서 마커의 실제 픽셀 위치를 읽어
            localScreenX · peerScreenX 와 대조하라
            (마커 색·모양으로 픽셀을 찾거나, 렌더가 쓰는 좌표를 직접 계측에 흘려라)
```

**대조가 서기 전에는 이 좌표로 어떤 판정도 하지 마라.**

## 2. 결함 ② 진행축 값이 여러 프레임 동안 얼어붙는다

```
relSPx 고유값   13 / 28
동결 구간       9 프레임 연속 7.74  ·  7 프레임 연속 7.28
```

같은 구간에서 상대 X 는 −96.7 ↔ −104.5 로 계속 움직인다. **입력이 변하는데 출력이 안 변한다.**

얼어붙은 값은 부호가 뒤집힐 수 없다 — **반전 10 회는 과소 집계다.**

### 2-1. 어디가 원인인지 먼저 가려라

```
후보 A   매니페스트가 프레임값이 아니라 **최근 반전 이벤트의 값**을 실어 나른다 (보고 버그)
후보 B   판정기의 û 창(UHAT_HALF_WINDOW = 12)이 29 프레임 창에서 양끝 clamp 로
         거의 같은 창을 공유해 값이 정체된다 (계산 버그)
```

**A 인지 B 인지 먼저 확정하고 적어라.** 고치는 방법이 다르다.

### 2-2. 자가 검산을 붙여라

```
입력(상대 화면 변위)이 프레임마다 다르면 출력(relSPx)도 프레임마다 달라야 한다
합성 로그로 시험을 세워라 — 동결이 재발하면 시험이 실패해야 한다
```
