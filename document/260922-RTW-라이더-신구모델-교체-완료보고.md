## 0. 한 장 요약

2026-09-21, BOXCYCLE 앱의 라이더 3D 모델이 **절차적 저폴리 모델(`rider-lowpoly.glb`)에서 Blender 제작 고품질 모델(`rider.glb`, 후보 `20260921-041426-cd81398e`)로 교체 완료**되었습니다.

핵심은 "GLB 파일 교체"가 아니라 **렌더 경로 자체의 교체**입니다. 구형은 Mapbox 네이티브 `model` 레이어가 14개 명명 노드를 feature-state로 회전시키는 방식이었고, 신규 모델에는 그 노드 계약이 존재하지 않습니다. 그래서 파일만 덮어쓰면 "모델은 보이지만 페달링이 멈추는" 상태가 됩니다. 이를 피하기 위해 **Mapbox Custom Layer(Three.js 직접 렌더링) + 런타임 DQS 스키닝**이라는 별도 모드(`preserved`)를 신설하고, 구형 경로(`glb` 모드)는 손대지 않고 그대로 보존했습니다.

| | 구형 | 신규 |
|---|---|---|
| 파일 | `rider-lowpoly.glb` | `rider.glb` (후보 `20260921-041426-cd81398e`) |
| 제작 | 절차적 생성 스크립트(실린더·박스 조립) | Blender 모델링(Modelling 프로젝트 s5 릴리스) |
| 삼각형 | 23,842 | 52,434 (+119.9%) |
| 렌더 | Mapbox `model` 소스 + 노드 회전 | Mapbox Custom Layer + Three.js + DQS |
| 관절 표현 | 강체 14노드 분절 | 연속 외피 + 정점 가중치 블렌딩 |
| 모드명 | `glb` | **`preserved` (현재 기본값)** |

## 6. 이전 교체 시도가 중단된 이유 (2026-09-20)

**시도한 방식**: 신규 모델의 연속 관절 외피를 앱의 14노드 계약에 맞추기 위해 **강체 14조각으로 절단**하고, 절단으로 생긴 틈을 **피벗 중심 구(球)**로 메우는 방식.

**실패 원인 — 구조적 한계**:

- 관절이 인접 사지보다 굵게 부풀어 보임: **어깨 72.3 mm / 상완 53.8 mm = 1.34배**, 팔꿈치 **1.39배**, 무릎 **1.38배**
- 원인은 기하학적으로 불가피함: 틈을 메우는 구의 반경은 `R = √(절단면반경² + 피벗거리²)` 이므로, **절단면이 피벗에서 멀수록 구가 구조적으로 커집니다**. 어깨는 절단면이 피벗에서 72.1 mm 떨어져 있어 가장 심했습니다.
- 강체 2세그먼트로는 관절 테이퍼(가늘어짐)를 재현할 수 없다는 판단
- 별건으로 위상 부호 버그(`−phase·2π` vs 하네스 `+phase`)로 위상 90°에서 **235 mm 어긋남** 발견

**결론**: 사용자 지시로 단계 B를 중단하고, **"자르지 않는다"**는 방향 전환 — 이미 존재하던 DQS(이중 사원수 스키닝) 변형을 앱 런타임에서 재현하는 방식으로 전면 재설계했습니다. 이 결정이 이번 성공의 분기점입니다.

### 10.2 새 모델을 받았을 때 먼저 확인할 것

1. **메시 이름이 이전 후보와 같은가?** 다르면 `RIG.groups`·`GUIDE_MESH`를 전부 다시 매핑해야 합니다(신규 모델은 210개 중 140개가 `Mesh_N` 자동명이므로 이름이 쉽게 어긋납니다).

5. 노드 계층이 평면인가 계층인가 — 계층 모델이면 `glb` 모드 노드 계약 재사용을 검토할 수 있습니다.

### 10.3 불변식·금지사항 (기존 문서에서 확정된 규칙)

**노드 계약(구형 유지 시)**: 14노드, 전부 `RiderBike` 직속 구조, rest = 로컬 −Y, crank 제외 회전 identity, `skins 0` / `animations 0`, 노드 scale 전부 1.

**좌우 규약**: `_l` = **+Z**, `_r` = **−Z**. "신규 모델의 +Z 쪽 부위 → `*_l` 노드, −Z 쪽 → `*_r` 노드로 귀속한다." / "**미러링하지 않는다**(와인딩·노멀이 뒤집힌다). 소스 모델의 R/L 라벨을 따라가지 않는다."

**좌표계·축**: m 단위 / +X 진행 / +Y 위 / +Z 라이더 왼쪽. Blender→glTF 축 변환을 **두 번 적용 금지**. 구형 소스의 L/R 본 이름을 새 모델 좌우에 그대로 대입 금지.

**스케일**: "체형을 임의로 늘이거나 줄이지 않는다." GLB 자체 크기 변경 금지(**스케일은 레이어가 담당**). 노드 오프셋은 rig 상수와 반드시 일치 — "한쪽만 바꾸면 IK와 메시가 어긋난다."

**제품 GLB 해시 불변**: `rider-lowpoly.glb`(`a9d0d6716c…`)는 최종 승인 전까지 변경 금지, 매 단계 재해시 확인. 감사 FAIL 조건에 포함.

**후보 재승인**: candidateId = `YYYYMMDD-HHmmss-<shortInputHash>` (KST). 입력·변환 코드·export 설정이 바뀌면 **새 ID 사용**. 최종 검토 후 재export 금지(byte-for-byte 복사만). "**이전 후보의 해시 검증·단계 완료·승인을 새 입력에 승계하지 않는다.**"

**절대 하지 않는 것(원문 전문)**:

- 제품 GLB를 최종 승인 전 건드리는 것
- 테스트·검증 기준을 통과시키려고 느슨하게 바꾸는 것
- 체형을 늘이거나 줄이는 것 · GLB 자체 크기 변경
- 미러링으로 좌우를 맞추는 것
- `git reset --hard` · 사용자 작업트리 stash/checkout/삭제 · 저장소 전체 reset
- `--no-verify`로 훅 우회
- 계획서와 코드가 다를 때 코드를 임의로 고치는 것(차이를 보고할 것)
- Draco에 `quantize`를 함께 거는 것(Mapbox 3.23.1이 `KHR_mesh_quantization` 미지원)
- 승인 후 후보를 다시 export하는 것
- `strip-node-rest.mjs`를 un-pose에 쓰는 것
- export 후 후처리로 정점을 회전시켜 rest를 만드는 것
- 분해 대상 3개 외의 메시를 BLEND에서 가져오는 것
