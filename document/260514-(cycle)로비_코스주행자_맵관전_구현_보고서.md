# 로비「코스 주행자 현황 맵에서 보기」기능 구현 보고서

**문서 접두어:** `260514-(cycle)`  
**대상 기능:** 같은 로비(방)에 있는 사용자가 **공식 코스를 주행 중**일 때, 주행하지 않는 사용자의 지도에 **다른 주행자 위치(점)**와 **코스 노선**을 표시하는 기능.  
**구현 위치:** `apps/web` (React + Mapbox GL + Firebase Firestore)  
**배포 전제:** Firestore 보안 규칙에 `rooms/{roomId}/liveCourseRides` 경로가 포함되어 있어야 하며, 변경 후 `firebase deploy --only firestore` 로 배포해야 한다.

---

## 1. 기능 개요

### 1.1 목적

- 로비에 머물며 지도를 보는 사용자가, **같은 방(`roomId`)에서 현재 코스를 주행 중인 다른 사용자**의 대략적인 위치와 코스 형상을 한눈에 파악할 수 있게 한다.
- 기존 **입문 허브 동행(`coursePresence`)**은 같은 코스에 입장한 멤버 간 **정밀 좌표 공유**에 가깝다. 본 기능은 **방 단위**로 “누가 어떤 코스를 얼마나 탔는지”만 가볍게 공유한다.

### 1.2 사용자 경험(UX)

| 역할 | 조건 | 지도에 나타나는 것 |
|------|------|---------------------|
| **발행자(주행 중)** | 로비 참가 + 주행 중(running/paused) + 공식 코스 ID + 경로 geometry | Firestore에 **진행률 스냅샷**만 주기적으로 기록 |
| **관전자(주행 전)** | 로비 참가 + 주행 idle | 같은 방의 스냅샷 구독 → 코스 geometry는 **로컬/코스 API로 로드** → **빨간 노선 + 흰 글로우**, **빨간 원 + 흰 글로우**로 표시 |

### 1.3 기존 동행 UI와의 관계

- `CourseSharedPresence` + `peerMarkers`는 **DOM 스프라이트 마커**로 동행 라이더를 표시한다.
- 관전 쪽은 **Mapbox GeoJSON `circle` + `line`** 전용 레이어로 그려 **캐릭터가 아닌 작은 점**으로 구분한다.
- 동일 UID가 동행 마커에 이미 있으면(`excludePeerIds`) 관전 점에서 **제외**하여 이중 표시를 막는다.

## 2. 설계 원칙(데이터 부담 최소화)

1. **Firestore에는 geometry를 넣지 않는다.**  
   코스 노선은 클라이언트가 `courseId`로 이미 가지고 있거나, `courses` 문서/내장 허브 데이터에서 **한 번 로드**한다.

2. **실시간 필드는 최소화:** `courseId`, `progressRatio`(0~1), `displayName`(선택), `lastSeenAt`.

3. **쓰기 빈도 제한:** 약 **4초마다** 한 번 `setDoc(merge)` (`LOBBY_LIVE_COURSE_RIDE_WRITE_INTERVAL_MS = 4000`).  
   가상 주행 거리는 매 프레임 갱신되지만, **ref로 최신값만 읽고** effect 의존성에 넣지 않아 **interval 재시작 남발을 방지**한다.

4. **신선도 판정:** 로비 멤버와 동일하게 `firestoreLobby` 의 `lastSeenAt` → ms 변환 후, `isMemberRecentlySeen` / `LOBBY_STALE_MS`(기본 240초)로 **오래된 스냅샷은 표시 대상에서 제외**한다.

## 3. Firestore 데이터 모델

### 3.1 경로

```
rooms/{roomId}/liveCourseRides/{userId}
```

- `roomId`: `sanitizeRoomId` 적용(허용 문자 패턴 불일 시 `default` 등 정책에 따름).
- 문서 ID = 주행자 Firebase Auth `uid`(본인 문서만 쓰기).

### 3.2 필드(쓰기 시)

| 필드 | 타입 | 설명 |
|------|------|------|
| `courseId` | string | `basicActiveHubCourseId ?? activeOfficialCourseId` 에 해당하는 코스 ID |
| `progressRatio` | number | `0 ≤ value ≤ 1`, `virtualDistanceMeters / routeDistanceMeters` (후자 0이면 0) |
| `displayName` | string | `getPresenceDisplayName(user)` — 규칙상 길이 80 이하 |
| `lastSeenAt` | serverTimestamp | 갱신 시각 |

### 3.3 생명주기

- 주행 중 조건을 만족하면 **즉시 1회 write** 후 **4초 interval**로 반복.
- effect cleanup 또는 코스/geometry 부재 시 **`deleteDoc`** 으로 문서 제거(고아 문서 방지).

### 3.4 보안 규칙(`firestore.rules`)

- **read:** 로그인 사용자 전원(`isSignedIn`) — 방 단위 격리는 클라이언트가 `roomId`로 구독 경로를 제한하는 패턴(추가 서버 검증이 필요하면 Cloud Functions 등으로 강화 가능).
- **create/update:** 본인 `userId` 만, 키는 `courseId`, `progressRatio`, `lastSeenAt` 필수 + `displayName` 선택, `courseId` 길이·`progressRatio` 범위 검증.
- **delete:** 본인만.

## 4. 클라이언트 모듈 구성

### 4.1 `lib/firestoreLobbyLiveCourseRides.ts`

- **`subscribeLobbyLiveCourseRides(roomId, onChange, onError)`**  
  컬렉션 스냅샷 → `LobbyLiveCourseRideRow[]` 로 정규화(잘못된 필드 문서는 스킵).

- **`mergeLobbyLiveCourseRideSnapshot(user, roomId, { courseId, progressRatio })`**  
  `setDoc(..., { merge: true })`.

- **`deleteLobbyLiveCourseRide(uid, roomId)`**  
  문서 삭제.

- **`isLobbyLiveCourseRideRowFresh(row)`**  
  `lastSeenAtMs` 기준 최근 접속 여부.

### 4.2 `hooks/useLobbyLiveCourseRidePublisher.ts`

**역할:** 발행자 측 주기적 스냅샷 기록.

**활성화 조건(`App.tsx`에서 전달):**

- Firebase 설정됨 + 사용자 존재 + `lobbyParticipationEnabled`
- `rideStatus !== "idle"` (running 또는 paused 포함)
- `basicActiveHubCourseId ?? activeOfficialCourseId` 존재
- `routeGeometry.coordinates` 존재

**구현 포인트:**

- `virtualDistanceMeters` / `routeDistanceMeters`는 **ref**에 매 렌더 갱신 → interval 콜백에서 최신 비율 계산.
- `useEffect` 의존성은 `[enabled, roomId, user?.uid, courseId, routeGeometry]` 로 제한해 **거리 변화마다 effect 재실행하지 않음**.

### 4.3 `hooks/useLobbyLiveCourseRideSpectatorOverlay.ts`

**역할:** 관전자 측 데이터 가공 → `MapView`용 `spectatorDots`, `spectatorRouteGeometries`.

**활성화 조건(`App.tsx`):**

- `configured && user && lobbyParticipationEnabled && rideStatus === "idle"`

**구독:** `subscribeLobbyLiveCourseRides` — 비활성/자기/동행 중복 UID 필터.

**geometry 로드:**

- `BASIC_SHARED_HUB_IDS` 에 포함되면 **`getBasicHubCoursePayload`**(내장).
- 그 외 **`fetchCourseRoutePayload`**(Firestore `courses/{id}`).

**상태 캐시:** `geomByCourseRef: Map<courseId, loading | ready | missing>`  
비활성 시 맵 클리어 + `geomEpoch` 로 파생 메모 재계산.

**좌표 복원:**

- 노선 길이 `lineStringLengthMeters(geometry)` 에 대해  
  `getPointOnRouteByDistance(geometry, progressRatio * len)` 으로 **경로 상의 대표 점** 산출.

**노선 LOD:**

- `lib/geoDecimate.ts` 의 `maxLineStringVerticesForMapZoom(mapZoom)` 으로 상한 결정.
- `decimateLineStringVertices` 로 균등 스텝 샘플링, **끝점 유지**.
- 코스별 **한 줄만** 관전 레이어에 넣기 위해 `courseId` 단위로 중복 제거.

**타입 export:** `LobbySpectatorDot { id, lngLat }` — `MapView` import 용.

### 4.4 `lib/geoDecimate.ts`

- **`maxLineStringVerticesForMapZoom(zoom)`**  
  줌 구간별 상한: 8 이하 20점 → … → 14 초과 160점.

- **`decimateLineStringVertices(geometry, maxVertices)`**  
  꼭짓점 수가 많을 때만 스텝으로 희석.

## 5. 지도 표현(`components/MapView.tsx`)

### 5.1 소스 ID

| 소스 ID | 용도 |
|---------|------|
| `boxcycle-lobby-spectator-routes` | 관전용 노선 FeatureCollection |
| `boxcycle-lobby-spectator-dots` | 관전용 라이더 점 FeatureCollection |

### 5.2 레이어 ID 및 순서

- 사용자 본인 경로 레이어 `route`가 있으면 **`beforeId = "route"`** 로 삽입해, **관전 레이어가 사용자 경로 아래**에 오도록 한다.
- **노선:**  
  1. `boxcycle-lobby-spectator-routes-glow` — 흰색, 두껍게, `line-blur` 로 글로우  
  2. `boxcycle-lobby-spectator-routes-line` — `#dc2626` 코어 라인  
- **라이더:**  
  1. `boxcycle-lobby-spectator-dots-glow` — 흰색 큰 원 + `circle-blur`  
  2. `boxcycle-lobby-spectator-dots-circle` — `#dc2626` 채움 + 흰 `circle-stroke`

### 5.3 동기화 함수 `syncLobbySpectatorLayers(map, dots, routes)`

- `map.isStyleLoaded()` 가 아니면 즉시 return.
- 소스 최초 생성 시 위 레이어들을 추가하고, 이후에는 **`setData`만** 갱신.
- **구버전 마이그레이션:** 글로우 레이어가 없고 코어 레이어만 있는 경우, 글로우를 코어 **아래**에 한 번 삽입.

### 5.4 `MapView` 와 `App` 연결

- props: `lobbySpectatorDots`, `lobbySpectatorRoutes`.
- 렌더마다 `lobbySpectatorDataRef` 에 최신 배열을 넣고, **`style.load`** 시에도 `syncLobbySpectatorLayers` 호출해 스타일 리로드 후 깨짐을 방지.
- 별도 `useEffect([mapLoaded, lobbySpectatorDots, lobbySpectatorRoutes])` 로 데이터 변경 시 동기화.

## 7. 한계·주의사항

1. **진행률과 실제 지도 geometry 정합**  
   비율은 `routeDistanceMeters`(Directions 요약 거리)와 가상 거리 비율이며, **선형으로 샘플링된 코스 polyline 길이**와 미세하게 어긋날 수 있다. 필요 시 동일 기준(예: polyline 누적 길이)으로 통일하는 개선 여지가 있다.

2. **규칙상 read 범위**  
   현재는 “로그인한 사용자면 모든 방의 `liveCourseRides` 문서를 읽을 수 있는” 규칙이다. 방 엄격 격리가 필요하면 **커스텀 클레임·Functions proxy·서브컬렉션 규칙 강화** 등을 검토해야 한다.

3. **퍼블릭 코스 geometry**  
   `fetchCourseRoutePayload` 가 실패하면 해당 코스는 `missing` 처리되어 **점/선이 안 그려질 수 있다.**

4. **동시 주행자 수**  
   코스 수만큼 geometry를 캐시하므로, 한 방에 서로 다른 코스가 매우 많으면 **클라이언트 메모리·Firestore 스냅샷 크기**가 늘어난다.
