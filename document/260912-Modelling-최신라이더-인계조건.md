## 4. GLB 인수 조건과 앱 변환 조건

**원본 인수 시:** GLB 파싱·재가져오기 가능, 외부 이미지/버퍼가 있다면 빠짐없이 전달, 좌표 유효, Blender와 형상·재질 대응, 라이더/자전거 구분 가능. `skin`, animation clip, 앱의 14개 노드는 **필수 아님**. 현재 저장 자세·축·단위를 기록하며 형상을 임의로 rest 자세로 바꿔 전달하지 않는다.

**앱 후보에서:** `crank`, `pedal_l/r`, `torso`, `leg_l/r`, `leg_l/r_shin`, `ankle_l/r`, `arm_l/r`, `arm_l/r_fore`의 14개 명명 노드와 정확한 부모/피벗/rest 계약을 구성한다. m / +X 진행 / +Y 위 / +Z 라이더 왼쪽을 기준으로 변환한다. 이 작업과 8위상 페달 검증은 boxcycle 책임이다.

## 5. 수신 후 순서

아래 ✅는 **appearance_preserved_lod / `20260913-162030-d32f2fc2`에 대한 과거 실행 기록**이다. 최신 natural_joint_skin은 전달 기록만 갱신했으며, 후속 사용자 진행 요청 시 1·3·4를 새 입력으로 수행하고 2의 도구 적합성을 확인한다.

1. ✅ 연결 창구에서 받은 **정확한 릴리스 경로·해시**와 상태를 확인한다. 작업 중 파일 또는 구형 GLB를 대신 선택하지 않는다.
2. ✅ 최신 파일 목록을 명시적으로 받도록 입력 등록 도구를 확장한다. `register-modelling-baseline.mjs`는 `--release`·`--rider-glb`·`--rider-blend`·`--source-task`·`--evidence`·`--legacy`·`--blender` 명시 인자를 받으며, Blender 조사기는 manifest의 `selectedRiderBlend`를 따른다. 폴더 자동 탐색은 넣지 않는다. 기존 fit 입력은 `--legacy`로 따로 지정한다.
3. ✅ 새 원본·현행 제품·실행 도구의 사본과 해시를 고정하고 새 candidateId를 발급한다. 기존 후보 manifest는 변경하지 않는다. 제품 및 rig가 9월 11일 이후 바뀌었는지도 확인한다.
4. ✅ 최신 blend/GLB의 메시·그룹·본·계층·치수·재질을 다시 조사하고 새 단계 0 이미지와 보고서를 만든다. 소매/상완 축과 손 위치의 수치·시각 검증도 이 릴리스에 연결한다.
5. 새 기준선 그림 검토 후 A(부위/앵커) → B(정적 결합) → C(페달) → D(앱 후보) → E(교체) 순서로 진행한다. 승인은 해당 candidateId와 단계에 기록한다.

최신 natural_joint_skin의 인계 기록 갱신을 완료했으며 **후속 사용자 진행 요청 대기**다. 목둘레 미완료 항목을 추적하고, 새 외피의 운동 연결 방식을 검토해야 한다. 이번 갱신에서 제품 파일과 이전 후보 manifest는 변경하지 않았다.
