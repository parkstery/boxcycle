## 1. 결론과 이번 작업 범위

완성된 외형을 보존하려면 **14개 강체 조각으로 절단하는 방식의 추가 보정보다, 원본 메시를 유지하는 변형·렌더 경로를 먼저 소규모로 검증**하는 것이 합리적이다. 이는 성공이 확인된 구현이 아니라 다음 실험의 우선순위다. 제품 GLB·앱 코드·rig 상수는 이번 검토에서 변경하지 않았다.

사용자 요청은 먼저 상태 확인과 계획 수립이다. STEP-P/P2/P3/B의 명령·STOP·CLI 위임 지시는 이전 작업의 이력으로 읽었으며 재실행 지시로 취급하지 않았다. Claude CLI에 별도 작업을 전달하지 않았다.

현재 브랜치 `rider/20260919-natural-joint-skin`, HEAD `2027e8f577f2a5a0a4758eec3a063b3e9dc91219`. 기존 결정 로그 수정, 미추적 Python 6개·문서·`0` 파일을 보존한다. 검토에는 현재 브랜치를 사용한다. 구현 시작 시 별도 작업 디렉터리의 `codex/rider-shape-preserving` 브랜치로 분리하고, 필요한 원본·검증 도구만 목록과 해시를 남겨 복사한다. 기존 미커밋 작업을 옮기거나 일괄 커밋하지 않는다.

## 3. 실패 원인과 증거 신뢰도

모델러의 `인계_수정_검증.md`는 연결된 외피에 혼합 가중치가 필요하며 Guide 그룹 자체는 완성된 skin binding이 아니라고 명시한다. **완성된 것은 외형이며 앱 애니메이션 연결까지 완성된 파일은 아니다.**

앱 `glbModelLayer.ts`는 Mapbox model layer의 14개 노드에 회전을 준다. `riderGlbPedalPose.pose.mjs`는 기존 치수와 −Y rest 기반 IK를 사용한다. 이 계약을 새 연속 외피에 그대로 강제하면서 절단·캡·구가 필요해졌고, 원형 실루엣이 바뀌었다.

기존 `modelling-threequarter.png`와 `final/renders/CHECK-090-06-threequarter.png`를 직접 열어 어깨 돌출·팔꿈치 경계·무릎 구형 돌출을 확인했다. 서로 포즈가 달라 정량 비교나 새 승인 자료로 사용할 수는 없다. 중단 보고의 반경비 1.34~1.39와 접촉 오차는 **과거 계측값**으로 취급하며 이번 독립 재계측값으로 주장하지 않는다.

검증의 문제도 별도로 존재한다.

- 제품을 대상으로 `verify-rider-glb.mjs` 재실행: `self is not defined`로 종료코드 1. 낡은 AABB 범위와 TS 파사드의 상수 문자열 파싱도 소스에서 확인했다. 제품 불량의 증거가 아니라 검사기 보수 필요의 증거다.
- `verify-fit.mjs` 재실행: 종료코드 0, 경고 2개. 기본값이 옛 `v2_4_cyclefit/ik-joints-v2.json`을 읽으므로 새 모델의 접촉 통과 증거가 아니다.
- `segment-penetration.mjs:134`는 `primitives[0]`만 읽는다. 복수 재질 후보의 전체 형상 검사로 사용할 수 없다.
- 앱 위상은 `-phase * 2π`. 과거 감사 화면의 반대 부호 및 무효 수치 목록은 중단 보고 §3을 따른다. 수정됐다는 파일도 재사용 전 앱과 같은 위상/좌우/축 검증을 통과해야 한다.
- 기존 candidateId가 여러 변형 산출물에 공통 사용되어 manifest만으로 최종 후보를 특정할 수 없다. 이후에는 GLB·변형 코드·rig·렌더 코드가 바뀔 때 새 ID와 해시를 발급한다.

## 4. 경로 선택

| 경로 | 형상 보존 가능성 | 비용·불확실성 | 권고 |
|---|---|---|---|
| 구·원통 관절을 계속 보정 | 관절 외형 변경이 계속 필요 | 앱 변경은 작으나 반복 모델링 비용 큼 | 추가 반복 중단 |
| 원본 + 기존 뷰어의 DQS를 별도 렌더 경로에서 사용 | 절단 없이 연속 외피 유지 가능 | 지도 결합·성능 실증 필요 | 작은 실험 우선 |
| 완전한 전신 rig/GPU DQS 새 제작 | 장기 표현력 높음 | 새 가중치·셰이더·검증 범위 큼 | 최소 실험 성공 후 필요한 부분만 |

외부 뷰어 `pedal_rig_viewer_wheelfix.html`의 `prepLeg`·`bakeWeights`·`solveLeg`·`updateSkin`에 다리 IK와 CPU DQS가 구현되어 있다. `updateSkin`은 정점과 법선을 함께 갱신한다. **팔 전체의 가동 rig가 이미 완성됐다고 해석하지 않는다.** 최초 실험은 몸통·팔·손을 원본 자세로 고정하고 다리·크랭크·발·휠만 움직여, 가장 문제가 컸던 어깨 절단을 없앤다. 상체 흔들림은 기준선 후 별도 평가한다.

이는 Three.js의 기본 스키닝에 넣기만 하면 같은 결과가 된다는 뜻이 아니다. 현재 DQS의 가중치·부호 정렬·bind 변환·법선 처리를 함께 재사용하고 원래 뷰어와 대조해야 한다.

Mapbox는 model layer에서 skin/morph/glTF animation을 지원하지 않으며 custom layer + Three.js를 대안으로 안내한다([공식 모델 문서](https://docs.mapbox.com/style-spec/guides/using-3d-models/), [공식 예제](https://docs.mapbox.com/mapbox-gl-js/example/add-3d-model/), 2026-09-20 확인). 다만 [globe 문서](https://docs.mapbox.com/mapbox-gl-js/guides/globe/)는 custom layer 미지원이라고 명시한다. **실제 스타일의 projection·주행 중 terrain을 첫 실험에서 확인하며, 앱 전체를 Mercator로 바꾸는 조치를 자동 채택하지 않는다.** terrain 접지·깊이·가림·그림자·스타일 재로딩은 기존 model layer와 자동으로 같아지지 않는다.

## 5. 실행 순서와 중단 기준

### 0 — 입력과 대조군 고정

- 새 작업 디렉터리·후보 ID에 s5, s6, 뷰어, rig 데이터, 관절 좌표, 관련 코드의 해시를 기록한다. 제품과 기존 실패 후보는 읽기 전용 대조군으로 둔다.
- s5를 기본 입력으로 시작한다. s6는 원본과 재질별 월드 삼각형·법선·그룹 귀속이 동등함을 확인한 경우에만 최적화 입력으로 승격한다. "43 draw calls"를 임의의 절대 합격선으로 삼지 않는다.
- 동일 카메라·배율·조명·원본 자세에서 현재 제품/신규 원본 기준선을 확보한다. 이미지에 후보 ID·해시·단계·미승인 표시를 넣는다.

### 1 — 가장 작은 형상 보존 실험

- 독립 프리뷰에서 원본 상체는 유지하고 기존 뷰어 다리 DQS를 모듈로 추출한다. 모델 재생성·관절 캡 추가 없이 동작시킨다.
- 정적 자세에서 원본 외형과 접점을 먼저 검증한 후, 8위상과 0/360° 연결부를 검증한다. 좌우 180°와 90/270° 부호 시험은 필수다.
- 기준 pose 복원 오차, 전체 primitive 수·삼각형 수·재질 보존, 손/안장/클릿/페달 접촉, 휠 중심·법선, 오금·반바지의 기존 결함을 기록한다. 원래 결함과 변환으로 추가된 결함을 구분한다.
- 기존 앱 상수와 새 모델 수치를 섞지 않는다. BB 267.0/270.5mm 충돌은 자산별 rig 계약으로 해결하며 외형을 맞추려고 자전거만 3.5mm 띄우지 않는다.
- **중단 기준:** 절단·구 추가 없이 원본 자세를 복원할 수 없거나, DQS로 새 찢김이 생기면 지도 이식을 시작하지 않는다. 원인 한 건을 특정하고 새 후보에서 검증한다. 포괄적인 반경 조정 반복으로 돌아가지 않는다.

### 2 — 지도 결합 타당성 실험

- 제한된 개발용 전환 옵션으로 라이더 1명만 표시한다. 실제 projection 및 terrain 조건부터 기록한다. 지도 구조 변경이 필요하면 비용과 대안을 먼저 제시한다.
- 경위도·방향·전체 린·현재 페달 phase를 전달하는 얇은 경계를 만든다. MapView의 기존 센서 RPM/정지/reduced-motion/동행 phase 입력을 유지한다. 구 rig의 Euler 회전을 새 rig에 재사용하지 않는다.
- 이동·회전·지형 높이·오르막/내리막·카메라 확대/축소·깊이 가림·스타일 재로드·컨텍스트 복구·제거/재진입을 확인한다. 그림자와 조명 차이를 숨기지 않고 대조한다.
- 1/10/실제 지원 최대 동행 수에서 기존 제품 대비 CPU/GPU 시간·p95 프레임 시간·메모리·전송 크기를 측정한다. 데스크톱과 저사양 목표 기기 조건을 적고, 최소 목표 30fps(p95 프레임 시간 33.3ms 이하)를 잠정 기준으로 둔다. 기존 앱도 미달이면 모델 비용을 분리 측정한다.
- **비용 통제:** 첫 실험은 1회로 제한해 형상·지도·성능 증거를 낸다. 실패 원인 없이 전신 rig/GPU 최적화/모델 수정으로 범위를 넓히지 않는다. CPU DQS가 병목이라는 실측이 있을 때 GPU 변형 또는 위상 캐시를 비교한다.

### 3 — 앱 연결과 공통 검증

- 성공한 렌더 방식과 자산별 rig 계약을 설계·결정 로그에 확정한 뒤 제품 코드에 연결한다. 구 렌더 방식으로 즉시 되돌리는 옵션을 유지한다.
- preview와 앱은 같은 변형 함수를 import한다. 검사기는 모든 primitive를 읽고, 현재 제품과 신규 후보를 구별하는 계약을 사용한다. 낡은 검사기 통과를 위해 기대 범위만 넓히지 않는다.
- 다리·접촉 자동 검증과 실제 이미지 검토를 함께 실시한다. 실제 화면 배율뿐 아니라 확대 상태에서도 관절 돌출·찢김이 없어야 한다. 작은 배율은 결함을 면제하는 근거가 아니다.
- `ride-verify`로 Guest 인증→Route 선택→running, 정지/재시작, 동행 표시를 확인한다. peerMotion 알고리즘은 변경 범위에 넣지 않는다.

### 4 — 검토한 결과 그대로 교체

- 사용자가 검토한 후보의 이미지·동영상·GLB와 변형 코드/rig 버전의 묶음을 확정한다. 새 렌더 경로에서는 GLB 해시 하나만으로 동일 결과를 보장할 수 없다.
- 스킬의 정적 fit/페달/제품 승인 게이트를 따른다. 렌더 구조가 바뀌면 14노드 전용 promote를 무조건 실행하지 않고 새 계약에 맞는 검증·승격 절차를 먼저 만든다. 승인 후 재수출·재생성 없이 동일 바이트를 배치한다.
- 기존 파일/renderer 전환으로 복구 가능한 상태에서 URL 캐시 갱신·빌드·최종 실행 검증을 한다. 배포는 별도 실제 요청 범위에 따른다.

## 6. 재사용과 제외

재사용: 입력 해시·P2/P3 대조 기록·원본 rig 좌표·뷰어 DQS·휠 보정·노드/재질 목록·문제 재현 이미지. 각 자료는 실제 입력과 맞는지 확인 후 쓴다.

최종 모델로 재사용하지 않음: 구/돔 캡 후보, 파묻기·원통 반복 실험, 부호 오류가 있는 위상별 PASS 표. `.out` 안 사본 검사기의 수정 사항은 필요한 부분만 리뷰해 정식 도구로 옮기며 통째로 복사하지 않는다.

현재 판정: **계획 수립 완료. 원본 보존 경로의 구현 가능성은 아직 실험 전이며, 제품 교체 완료 또는 성공 보장은 아님.** 다음 산출물은 새 완성 모델이 아니라 원본 보존 프리뷰와 지도 결합의 작은 검증 결과다.
