# 맵 확대·축소 뷰 덜컹거림 원인 및 해결 보고서

**문서 접두**: `260517-` (YYMMDD)  
**대상**: `apps/web` — Mapbox GL 기반 `MapView`, 맵 뷰 시트 `MapViewSheet`  
**관련 커밋**: `034b704` (요약: 줌 동기화 루프 제거, `zoomend` 전환, `mapZoom` 적용 rAF 합치기, 시트 ±1 버튼)

---

## 1. 현상

- 맵 우측 상단 **Mapbox 기본 NavigationControl**의 `+` / `−` 또는 **휠·핀치 줌** 시, 카메라가 부드럽게 이어지지 않고 **끊기거나 미세하게 흔들리는(덜컹거리는)** 느낌이 난다.
- **맵 뷰 시트**의 줌 슬라이더를 빠르게 움직일 때도 유사하게 불안정해 보일 수 있다.
- UI에 표시되는 줌 숫자와 실제 맵 줌이 잠깐 어긋나거나, 클릭(또는 한 스텝)당 **기대와 다른 변화량**으로 느껴질 수 있다.

---

## 2. 원인 분석

### 2.1 이중 제어 루프 (핵심)

앱은 맵의 줌 레벨을 **React 상태 `mapZoom`**으로 들고 있고, `MapView`는 다음 두 경로를 동시에 사용하고 있었다.

| 경로 | 동작 |
|------|------|
| **맵 → 부모** | `map.on("zoom", …)` 에서 **애니메이션 중에도 매 프레임** `map.getZoom()`을 `toFixed(1)` 반올림 후 `onMapZoom` → `setMapZoom` |
| **부모 → 맵** | `useEffect([mapZoom])` 에서 `Math.abs(map.getZoom() - mapZoom) < 0.05`가 아니면 **`map.zoomTo(mapZoom, { duration: 0 })`** |

Mapbox가 NavigationControl·휠 등으로 **이미 줌 애니메이션을 수행 중**인데, 중간 프레임마다 React가 새 `mapZoom`을 받아 리렌더되고, 이펙트가 다시 `zoomTo`로 맞추면 **내부 애니메이션과 외부 `zoomTo`가 서로 덮어쓰기**를 반복한다. 그 결과가 사용자에게는 **떨림·덜컹임**으로 인지된다.

### 2.2 `zoom` 이벤트의 특성

Mapbox GL JS에서 `zoom` 이벤트는 줌 레벨이 바뀌는 **과정 전체**에서 발생한다. 반면 사용자가 기대하는 “한 번의 줌 조작”의 끝은 **`zoomend`**(또는 `moveend`)에 가깝다. 과정마다 상위 상태를 갱신하면 **불필요한 리렌더와 재동기화**가 폭증한다.

### 2.3 슬라이더와의 결합

맵 뷰 시트의 `<input type="range" step={0.1}>` `onChange`는 포인터 이동 중 **연속적인 `setMapZoom` 호출**을 유발한다. 위 이펙트와 맞물리면 같은 프레임에 여러 번 `zoomTo`가 예약될 수 있어, 슬라이더 조작 시에도 **거친 움직임**이 날 수 있다.

### 2.4 “비율이 일정하지 않다”는 체감

- 루프로 인해 **실제 맵 줌**과 **UI 숫자**가 순간적으로 어긋난다.
- `toFixed(1)` 반올림이 중간값에 겹치면 **같은 제스처라도 표시·적용 단위가 들쭉날쭉**해 보일 수 있다.

## 3. 해결 방안 (적용 내용)

### 3.1 맵 → 부모: `zoom` → `zoomend`

- `map.on("zoom", …)` 를 제거하고 **`map.on("zoomend", …)`** 에서만 `onMapZoom(map.getZoom().toFixed(1))` 호출.
- **한 번의 줌 제스처가 끝난 뒤** 부모 상태를 맞추어, 애니메이션 중 React가 `zoomTo`로 끼어들 여지를 줄인다.

### 3.2 초기 동기화

- `map.on("load", …)` 안에서 `setMapLoaded(true)`와 함께 **초기 `getZoom()`을 부모에 반영**하여, 기본 맵 줌과 앱 상태가 어긋나지 않게 한다.

### 3.3 부모 → 맵: `requestAnimationFrame` 합치기

- `mapZoom` prop이 짧은 간격으로 여러 번 바뀔 때(슬라이더 등), **`requestAnimationFrame`으로 한 프레임에 한 번만** `zoomTo`를 호출하도록 합친다.
- 이펙트 cleanup에서 `cancelAnimationFrame`으로 정리해, 언마운트·의존성 변경 시 누수·중복 호출을 방지한다.

### 3.4 UI: 이산 ±1 버튼 (맵 뷰 시트)

- 슬라이더만으로는 “한 클릭당 1레벨”이 보장되지 않아 체감이 달라질 수 있으므로, 시트에 **`−` / `+` (1.0 단계, 3~20 클램프)** 버튼을 추가해 **확대·축소 스텝을 명시적으로 고정**했다.
- Mapbox NavigationControl과 유사한 **정수 스텝 기대**를 시트에서도 맞출 수 있다.

## 5. 한계 및 추가 검토 (선택)

- **`zoomend`만 사용**하면 줌이 끝나기 전까지 시트의 숫자 readout은 **약간 늦게** 따라갈 수 있다. (대신 떨림은 줄어든다.)
- **주행 중 카메라 follow** 등 다른 코드 경로에서 `jumpTo`/`easeTo`로 줌을 건드리는 경우, 동일한 “부모 `mapZoom`과의 일치” 정책이 필요한지 별도 점검할 수 있다.
- 휠 줌을 **연속적으로** 빠르게 할 때는 `zoomend`가 제스처마다 여전히 여러 번 발생하므로, 필요 시 **디바운스(예: 50~100ms)** 를 `onMapZoom` 쪽에 추가하는 것도 후보다.
