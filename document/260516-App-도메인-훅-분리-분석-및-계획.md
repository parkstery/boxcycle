## 1. 현황 요약

- **파일:** `apps/web/src/App.tsx`
- **규모(대략):** 2,100+ 줄, 단일 `export default function App()` 안에 **상태·이펙트·핸들러·JSX**가 모두 집중됨.
- **이미 분리된 훅:** `useLobbyRoomSession`, `useLobbyLiveCourseRidePublisher`, `useLobbyLiveCourseRideSpectatorOverlay`, `useVirtualRideSession`, `useRideUiStage`, `useRideArrivalAutoEnd`, `useRideCoachingMedia`, `useRideFeedbackPreferences`, `useBleCrankRpm`, `useRideMapillaryStreet`, `useDocumentVisibility` 등 — **라이딩·로비 일부**는 모듈화되어 있으나 **오케스트레이션은 전부 App**에 남음.

- `handleEndRide` ↔ `loadedSavedRouteIdRef`, `lastEndedWasAdhoc`, `user`, `roomId`, `profile`, 경로 상태 — **J와 I·E가 한꺼번에 묶이기 쉬움**. 1차에서는 **EndRide만 별 훅** 또는 **“ride persistence” 서브모듈**로 빼는 것이 안전.
- `generateRoute` ↔ `user`, `rideStatus`, 경로 상태 — **E**에 두되 `user`는 인자로 주입.
- `enterBasicHub` ↔ `deleteCoursePresence`, `basicActiveHubCourseId`, `routeGeometry` — **F**가 **E**의 일부 setter에 의존.

## 3. 목표 아키텍처(안)

```
App.tsx                    ← 얇게: 훅 조합 + JSX + stage → props 매핑만
├── hooks/useAppAuth.ts           (B)
├── hooks/useAppRoom.ts           (C) — optional: C+D 병합 시 mapHudRidePresence는 selector
├── hooks/useRoutePlanning.ts     (E) + generate/clear (F의 enter는 콜백 주입 또는 F에서 반환)
├── hooks/useOfficialCourses.ts   (F) — 또는 useRoutePlanning 하위
├── hooks/useSavedRoutesState.ts  (G)
├── hooks/usePublicRouteReview.ts (H)
├── hooks/useRideSessionActions.ts(I + J의 end-ride 진입점) — 단계적으로 분할 가능
└── lib/appSessionKeys.ts   (A) — 순수 함수·상수만
```

**원칙:** 첫 PR부터 `App` 동작 동일(회귀 최소). **한 PR = 한 도메인 또는 A+B 같은 소형 묶음.**

## 4. 단계별 실행 계획(권장 순서)

### Phase 0 — 준비 (코드 변경 거의 없음)

- [ ] `App.tsx` 내 **섹션 주석** 정리(도메인별 `// ----- Auth -----` 등) — 선택.
- [ ] 본 문서를 팀 기준 문서로 고정.

### Phase 1 — 무상태 추출 (리스크 최저)

- [ ] `lib/appSessionKeys.ts` (또는 `lib/appConstants.ts`): `POST_SIGNOUT_*`, `B_JOURNEY_*`, `read*` , `MAP_STYLE_OPTIONS` 이동.
- [ ] `formatElapsedFromMs`, `isBenignAuthPopupCancel` → `lib/rideFormat.ts` 또는 기존 `lib` 유틸에 합류.

### Phase 2 — `useAppRoom` (C)

- [ ] `roomId`, `roomDraft`, `applyRoomFromDraft`, `popstate` effect.
- [ ] 반환: `{ roomId, setRoomId, roomDraft, setRoomDraft, applyRoomFromDraft }`.

### Phase 3 — `useAppAuth` (B)

- [ ] `user`, `authInitialized`, `fsSync`, `busy`, `error`, post-signout 플래그, `authSheetOpen`, `authPickCardHidden`.
- [ ] `onAuthStateChanged` 구독, 닉네임·게스트·Google·서비스 종료 핸들러.
- [ ] **주의:** `setUser`를 다른 훅에 넘길 때 **한 소스**만 유지(리프트 상태는 App에 두고 훅은 setter만 받는 패턴 권장).

### Phase 4 — `useRoutePlanning` (E)

- [ ] 핀·WP·`profile`, `routeGeometry`, `routeLoading`, `generateRoute`, `handleClearPins`, 역지오코딩 effects.
- [ ] 입력: `user`, `rideLocked` 또는 `rideStatus`, `FUNCTIONS_REGION`.
- [ ] 출력: `RideRoutePanel` / `MapView`에 넘기는 props 묶음.

### Phase 5 — `useOfficialCoursesCatalog` + 허브 액션 (F 일부)

- [ ] `publishedPublicCourses*`, `refreshPublishedPublicCourseCatalog`, `enterBasicHub`, `leaveBasicHub` 및 관련 `useEffect`(geometry 매칭 등).
- [ ] 가능하면 **E의 setter**를 ref 또는 콜백으로 주입해 순환 방지.

### Phase 6 — `useSavedRoutesWorkspace` (G)

- [ ] `savedRoutes`, 로드/마이그레이션 effects, CRUD 핸들러.
- [ ] `user`, `configured` 의존 명시.

### Phase 7 — `usePublicRouteReviewMeta` (H)

- [ ] `refreshPublicRouteMeta`, 심사 큐 카운트, `pendingPublicRouteIds`.

### Phase 8 — 주행 종료·기록 (J 중 핵심)

- [ ] `handleEndRide` 및 `loadedSavedRoute*` ref, `lastEndedWasAdhoc` — **가장 큰 덩어리**이므로 `useRideEndAndPersistence` 단일 훅으로 먼저 분리 후, 필요 시 하위로 쪼갬.
- [ ] `handleEndRideRef` 패턴 유지(도착 자동 종료 훅과의 연결).

### Phase 9 — `App.tsx` 슬림화 검증

- [ ] 목표: `App.tsx` **~800줄 이하**(JSX+와이어링)를 1차 목표로 두고, 이후에도 줄이기.
- [ ] 수동 스모크: 게이트 → 게스트 → 입문 코스 → 주행 종료 → 저장 경로 → 로그아웃.

## 5. 테스트·회귀 방지

- **수동:** 위 Phase 9 시나리오 + 방 전환(`RoomSwitcher`) + 퍼블릭 코스 로드.
- **자동:** 현재 E2E가 없다면 Phase 4 이후 **최소 1개** Vitest(예: `sanitizeRoomId` + room reducer) 또는 스토리북은 선택.

---

## 6. 리스크·비권장 사항

- **한 번에 전부 이동:** 리뷰 불가·회귀 추적 어려움 → **금지 권고**.
- **Context 남용:** 초기에는 `useX()` 반환 객체를 App에서만 조합하고, **React Context는** 여러 화면에서 동일 상태가 필요해질 때만 도입.
- **`useEffect` 의존 배열:** 이동 시 누락으로 인한 **한 번 덜 도는 버그** 주의 — 이동 전후로 동일 동작 확인.
