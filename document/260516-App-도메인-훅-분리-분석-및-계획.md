**교차 의존(주의):**

- `handleEndRide` ↔ `loadedSavedRouteIdRef`, `lastEndedWasAdhoc`, `user`, `roomId`, `profile`, 경로 상태 — **J와 I·E가 한꺼번에 묶이기 쉬움**. 1차에서는 **EndRide만 별 훅** 또는 **“ride persistence” 서브모듈**로 빼는 것이 안전.
- `generateRoute` ↔ `user`, `rideStatus`, 경로 상태 — **E**에 두되 `user`는 인자로 주입.
- `enterBasicHub`(훅 `useOfficialCoursesHub`) ↔ `deleteCoursePresence`, `basicActiveHubCourseId`, `routeGeometry` — **F**가 **E**의 일부 setter·`enterBasicHubArtifactsRef`에 의존.

## 3. 목표 아키텍처(안)

```
App.tsx                    ← 얇게: 훅 조합 + JSX + stage → props 매핑만
├── hooks/useAppAuth.ts           (B)
├── hooks/useAppRoom.ts           (C) — optional: C+D 병합 시 mapHudRidePresence는 selector
├── hooks/useRoutePlanning.ts     (E) + generate/clear
├── hooks/useRecentRideSessions.ts (J) — 최근 주행 로컬 상태 + Firestore 동기·백필 effect
├── hooks/useOfficialCoursesHub.ts (F) — 카탈로그·지문·입문 허브; 입문 진입 시 E setter·`enterBasicHubArtifactsRef` 주입
├── hooks/useSavedRoutesWorkspace.ts (G) — 저장 경로·ad-hoc 저장 컨텍스트·로드된 경로 ref
├── hooks/usePublicRouteReviewMeta.ts (H) — 심사 메타·요청 모달; `MenuPanel`의 카탈로그 동시 새로고침은 `App`에서 `onPublicRouteReviewQueueChanged`로 오케스트레이션
├── hooks/useRideEndAndPersistence.ts (J 핵심) — `handleEndRide`·Firestore ride·격상·역지오코딩; `loadedSavedRoute*`·`lastEndedWasAdhoc` 상태는 G 훅에 유지
├── hooks/useRideSessionActions.ts(I + J의 나머지) — 단계적으로 분할 가능
└── lib/appSessionKeys.ts   (A) — 순수 함수·상수만
```

**원칙:** 첫 PR부터 `App` 동작 동일(회귀 최소). **한 PR = 한 도메인 또는 A+B 같은 소형 묶음.**

## 6. 리스크·비권장 사항

- **한 번에 전부 이동:** 리뷰 불가·회귀 추적 어려움 → **금지 권고**.
- **Context 남용:** 초기에는 `useX()` 반환 객체를 App에서만 조합하고, **React Context는** 여러 화면에서 동일 상태가 필요해질 때만 도입.
- **`useEffect` 의존 배열:** 이동 시 누락으로 인한 **한 번 덜 도는 버그** 주의 — 이동 전후로 동일 동작 확인.
