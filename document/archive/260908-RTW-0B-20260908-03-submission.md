### Fix 2: R1/F2 Semantics (Historical Meaning)

**Problem (Codex -02)**: 
- progressToSave mixed geometry-based progressRatioForResume with previousProgressRatio (old routeDistanceMeters-based)
- nextRideTarget compares lastProgressRatio to 0.98, but lastProgressRatio was geometry-based
- Historical data: lastProgressRatio was routeDistanceMeters-based (completionRatio)

**Solution**:
1. Restore `progressToSave = max(completionRatio, previousProgressRatio)`
2. completionRatio: routeDistanceMeters-based (motion-offset, 완주 판정, 0.98 비교)
3. lastProgressRatio저장: routeDistanceMeters-based (historical meaning)
4. resumeAnchorForRoute: boundary adapter (routeDistanceMeters offset → geometry coordinate)

**Locations**:
- Save: `apps/web/src/hooks/useRideEndAndPersistence.ts` L148-153, L193-195
- Resume adapter: `apps/web/src/lib/nextRideTarget.ts` L69-90

**Code**:
```typescript
// Save (useRideEndAndPersistence.ts L148-153)
const completionRatio =
  routeDistanceMeters > 0
    ? Math.max(0, Math.min(1, rideMetrics.virtualDistanceMeters / routeDistanceMeters))
    : 0;
const progressToSave = Math.max(completionRatio, previousProgressRatio);

// Resume adapter (nextRideTarget.ts L85-90)
const routeDistMeters = Number.isFinite(route.distanceMeters) ? route.distanceMeters : geoLen;
const offsetMeters = clamp01(route.lastProgressRatio) * routeDistMeters;
// Convert routeDistanceMeters offset to geometry coordinate
const geoRatio = geoLen > 0 ? offsetMeters / geoLen : 0;
const geoMeters = geoRatio * geoLen;
return getPointOnRouteByDistance(route.geometry, geoMeters);
```
