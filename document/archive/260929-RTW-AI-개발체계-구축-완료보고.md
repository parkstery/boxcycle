## 3. 실제 handoff 예

Codex가 [지시 01](ops/20260929-ai-development-system/02-task-01.md)에 “결과 파일 하나만 작성”을 명시했다. Cursor CLI가 이를 읽고 [결과 01](ops/20260929-ai-development-system/03-result-01.md)을 작성했다. Codex가 Git 상태와 내용을 대조해 [검수 01](ops/20260929-ai-development-system/04-review-01.md)에 PASS를 기록했다. Chief의 중간 복사·붙여넣기는 없었다.

## 4. Windows PowerShell 실행 방법

저장소 `C:\20.HDev\boxcycle`에서 다음처럼 실행한다.

```powershell
agent -p --workspace 'C:\20.HDev\boxcycle' 'document/ops/<묶음>/<지시파일>을 읽고 지정 범위만 수행한 뒤 지정 결과 파일을 작성하세요.'
$LASTEXITCODE
```

`-p`는 비대화식 출력, `--workspace`는 작업 디렉터리 지정이다. `$LASTEXITCODE`로 성공 여부를 확인하고, 결과 파일과 `git diff`를 별도로 검수한다. 이 환경에서 `agent --version`은 `2026.09.26-dd393fe`였다. `agent --help`에서 `--worktree [name]`, `--worktree-base <branch>`, `--output-format text|json|stream-json` 지원도 확인했다. 별도 worktree 실행과 PowerShell 백그라운드·로그 리다이렉션은 이번 왕복 시험 범위 밖이므로 성공을 주장하지 않는다.

## 5. Chief가 할 일

요구를 Codex에 전달하고, 아키텍처·데이터·비용·공용 계약·의미·큰 범위 변경의 승인 요청이 올 때 결정한다. 작업 중에는 [상태판](../ops/PROGRESS.md)을 확인하고, Codex가 검수한 단위 결과와 최종 완료를 확인한다.

## 6. 동작 검증

Cursor CLI는 같은 지시를 읽고 결과 파일 하나를 작성한 뒤 종료 코드 `0`으로 끝났다. 결과의 파일 경로·범위·기존 Git 변경 구분·파일 존재 확인·빌드 미실행 이유가 지시와 일치했다. Codex가 diff와 `git diff --check`를 확인했다. 제한된 첫 실행은 `uv_os_get_passwd returned ENOMEM`으로 실패했고, 권한이 허용된 실행 환경에서 정상 동작했다.

## 7. 남은 문제

- 작업 폴더 상태 갱신과 Cursor CLI 실행은 아직 사람이 또는 Supervisor가 명시적으로 수행한다. 자동 스케줄러는 만들지 않았다.
- 제한된 실행 환경에서는 CLI가 위 시스템 오류로 실패할 수 있다. 실행 환경·종료 코드·출력을 확인해야 한다.
- 기존 `.claude/commands`와 종료된 묶음 내부 문서에는 당시의 담당자·대기 규칙이 기록으로 남아 있다. 새 작업의 활성 지시로 해석하지 않는다.
