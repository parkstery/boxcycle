## 3. 단계별 작업

### 3-1. 프레임 확정 (F1~F4)

| 단계 | 내용 |
|---|---|
| F1 | 제너레이터 하드코딩 제거 — `geometry.json` → GLB 파생으로 전환 |
| F3 | 헤드튜브 **130 → 85** (사용자가 렌더 보고 확정) |
| F4 | 시트튜브 junction 단축 · 시트포스트 축 정렬(73.5°) · 헤드셋 회색 띠 제거 |

### 3-2. 검증 하네스 (F7~F9)

렌더 파이프라인에 **assert 4종**을 넣어 사고를 기계적으로 차단했다.

| assert | 막는 사고 |
|---|---|
| `frameAssertions` | 구프레임 GLB 로 렌더 (F6 에서 실제 발생) |
| `crankPhaseAssertions` | 크랭크–발 위상 어긋남 (F5) |
| `footContactAssertions` | 발이 안 닿는데 렌더 성공 (F6·F8·F9 세 번 반복) |
| `jointsFreshness` | 낡은 joints 재사용 (F8 — 7/30자 파일로 렌더) |

**허용치를 완화해 실패를 우회하지 않는다**는 규율을 세웠고, F9 에서 개발팀장이 이를
지켜 FAIL 로 보고한 것이 이후 원인 규명의 출발점이 됐다.

### 3-3. 발–페달 접촉 해결 (F10-R1) — 원인 3건

네 번(F5·F6·F8·F9) 반복된 **"계산상 오차 0mm 인데 렌더에서는 안 닿음"** 의 정체.

**① 두 층의 좌/우 라벨이 반대였다**

`export-ik-joints-v2.mjs` 의 `hipL`(Blender y −81.4)과 rider 본 `THIGH_L`(y +81.4)이
서로 **반대편**이라, `aim_bone` 이 다리를 **몸 반대편 무릎으로 조준**했다.

```
본 L → joints kneeL  410.41  (허벅지 378.40 초과 → 도달 불가)
본 L → joints kneeR  378.40  ← 정답 짝
```

이 모델로 F9 실측 관절 좌표 6개가 **자유 상수 없이** 전부 재현됐다.

**② 발 뼈가 71.6mm 짧고 축이 41.8mm 편심돼 있었다**

접점 정의에 **좌표별 median** 을 쓴 것이 원인. median 은 강체변환에 equivariant 하지
않아 밴드 중심에서 벗어난다. **centroid** 로 교체해 메시↔본 0.00mm 를 보장했다.

**③ 【결정타】 라이더 GLB 내장 애니메이션이 렌더마다 IK 포즈를 덮어썼다**

GLB 가 `Pedal_Loop` 액션을 활성 상태로 들고 오며, `render()` 직전 프레임 평가에서
우리가 세운 포즈를 덮었다.

```
apply_phase 직후   발 최저 z = 103.12   ← 계측이 본 값
렌더 1회 뒤        발 최저 z = 271.47   ← 이미지가 본 값
```

**계측은 우리 포즈를, 이미지는 GLB 애니메이션을 보고 있었다.**
`animation_data_clear()` 로 끊었다. 네 번의 사고가 이것 하나로 설명된다.

### 3-4. 페달 위치 정상화 (F11)

페달축이 **발끝 바로 밑(발길이의 99%)** 이었다. 사용자가 렌더를 보고 지적했다.
`ANKLE_BACK` 217.94 → 93.03 으로 접점을 **발 중심**으로 옮기고, 라이더를 +x 로
**124.9mm 평행이동**했다. 손 오차 40.05 → 0mm 는 부수 효과.

> **발견**: 시트각 73.5° 와 "페달이 발끝 밑"은 **같은 사실**이었다.
> 73.5° 에 대응하는 페달 위치가 정확히 98.7% 다.

### 3-5. 자세 교정 (F12) — 사용자 질책

> **"감리, 개발팀장은 그림을 이해하지 못하고 숫자만 보고 있다."**

발접촉 0.0mm·손 0mm·페달축 49.1% 를 주고받는 동안 **라이더가 앞으로 엎어져 있는 것을
양쪽 다 못 봤다.** 사용자가 렌더 한 장 보고 즉시 지적했다.

BDC 발바닥을 축으로 상체를 **10° 후방 회전**(`PELVIS` 로컬 X −10°)한 결과:

| | F11 | **F12** |
|---|---|---|
| 몸통각(렌더 실측) | 34.66° | **44.66°** |
| BDC 무릎 | 10.06° | **25.93°** |

**접점 수치를 소수점까지 맞추는 동안 자세가 통째로 틀려 있었다.**

### 3-6. 디테일 (F13~F14)

- **팔**: 상완 274.67 → **334.83**(+21.9%). 팔꿈치 굽힘 4.54° → **10.00°**, 손 오차 0mm
- **신발 −10%**: 지시대로 축소했으나 접점이 발길이의 50% 로 정의돼 있어 발이 짧아지자
  접점이 발목 쪽으로 12.83mm 당겨졌다. 발목→밑창 축이 13.31° → 15.34° 로 서서 뒤꿈치가
  들렸다. **사용자가 지시한 적 없는 변화라 F14 에서 전면 취소**
- **손가락**: 리그에 `FINGER`/`THUMB` 계열 본이 **0개**. `HAND_L/R` 단일 본에 가중치
  1.000 으로 묶여 있어 **포즈로는 원리적으로 불가능**. 미구현

### 3-7. 앱 이식 (F15~F17, 진행 중)

**F15 에서 감리가 지시를 잘못 내려 옛 절차적 라이더를 앱에 올리는 사고**가 났다.
사용자가 즉시 지적했고 F16 에서 되돌렸다.

**핵심 구조 발견 — 앱 라이더와 작업 대상 라이더는 다른 자산이다:**

| | 앱 라이더 | F1~F14 작업 대상 |
|---|---|---|
| 자산 | `rider-lowpoly.glb` (절차적 생성) | `stylized_cyclist_v2_lod0.glb` |
| 구조 | **명명 노드 10개** | **스킨드 아마추어 23본** |
| 구동 | Mapbox `setFeatureState` 노드 회전 | Blender 포즈 |

앱은 `crank`·`torso`·`leg_l`·`leg_l_shin`·`leg_r`·`leg_r_shin`·`arm_l`·`arm_l_fore`·
`arm_r`·`arm_r_fore` 10개 glTF 노드를 매 프레임 회전시킨다. **본·스키닝을 쓰지 않는다.**

**해법은 강체 분해(rigid part decomposition)** — V2 메시를 본 가중치로 잘라 위 이름의
노드에 강체로 매단다. F16 에서 실증했다:

- 전 정점 5,477개 중 **85.98% 가 단일 본 가중치 1.0**. 블렌딩 664개는 전부 관절 이음매
- 산출 GLB: 노드 9개 · skins 0 · animations 0. 자식 원점이 정확히 `[0, −부모길이, 0]`
- 좌/우 매핑: **앱 `_l` 노드에 V2 `_R` 본**을 붙인다(§3-3 ① 과 같은 규칙)

## 4. 작업 규율 — 전부 실제 사고에서 나왔다

| 규율 | 계기 |
|---|---|
| **assert 허용치를 완화해 실패를 우회하지 마라** | F9 |
| **좌표계 두 개(지면원점·BB원점, 차 270.5mm)를 섞지 마라** | F6~F8 감리 오답 999.3 |
| **SSoT → 메시 단방향.** 메시에 맞춰 `geometry.json` 고치지 마라 | F1·F6 |
| **각 단계 결과는 이미지와 함께 사용자 승인 후 다음 단계로** | F2 |

| **파생 부작용을 "지시 범위 밖"이라고 흘려보내지 마라** | F13 신발 각도 |
| **역계산 결과는 반드시 정방향으로 검산하라** | F6~F8 |
| **확정값 조항이 대전제를 이길 수 없다** | **F12~F16 안장 5단계 지연** |

### 4-1. 감리가 크게 틀린 2건 (개발팀장이 실측으로 반증)

1. **"허벅지가 29mm 짧다"** — 실측 430.00mm 로 반증. 감리 모델은 자유 상수 1개로 오차
   2개를 맞춘 것이었고, 좌우 반전 모델은 관절 좌표 6개를 상수 없이 전부 맞췄다
2. **"좌골이 950.5"** — 그건 `SADDLE_CONTACT` 앵커였다. 실측 좌골은 762.01 로
   **188.5mm 아래**. 이 혼동이 "시트포스트 53mm 단축" 오답을 만들었다

**두 번 다 개발팀장의 반증이 옳았다.** 감리 수치를 검산하는 것이 개발팀장 업무의
일부라는 규율이 작동한 결과다.

## 5. 미해결 항목

### 5-1. 시트튜브 단축 (F17 진행 중) — **다섯 단계를 끌어온 문제**

좌골 높이 730.5(지면) = 460.0(BB)에 안장이 놓여야 하는데, 시트튜브 상단 `seatTop` 이
**536.9** 라 **76.9mm 초과**한다. 시트포스트를 다 밀어넣어도 닿지 않는다.

F12~F16 내내 "안장이 물리적으로 불가능 — 사용자 결정 대기"로 분류했으나,
**정체는 시트튜브가 길다는 것 하나였다.** 사용자 지시로 종결:

> *"힙 높이를 정하고 그 높이에 맞춰서 안장이 놓이도록 시트포스트 길이를 조절하는게
> 기본적인 자전거 높이 조절 컨셉인데 그걸 사람이 자전거에 맞춘다는게 말이 되나!"*

`HANDOFF §1 원칙`에 답이 처음부터 적혀 있었으나, §2 확정값 조항("프레임은 사용자 최종
승인 — 절대 건드리지 마라")에 눌려 원칙을 적용하지 못했다.

**F17 조치**: `seatTubeLength` 560 → **450**(권장). 파생 방향도 정상화한다 —
`riderRig.geometry.mjs` 가 `PELVIS_ROOT = SADDLE_CONTACT + …` 로 **안장이 엉덩이를
정하고** 있었다. **HIP → 좌골 → 안장 → `saddleHeight`** 로 뒤집는다.
