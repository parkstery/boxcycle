## 1차 — "80km 달리고 멈추면 인정해야 하지 않나"

100km 경로를 80km 달리고 멈추면(4시간 운동) 아무 기록도 안 남는다면 큰 박탈감이다. 반드시 인정해야 한다. 단 **무엇을 인정하느냐를 분리**해야 한다.

| 항목 | 80km 중단 시 |
|---|---|
| 운동 거리·칼로리·누적 거리 | ✅ 인정 |
| 정복(Claim)·Pioneer | ✅ 실제 달린 구간만 인정 |
| 미션(100km 완주)·Route 완주·Creator 업적 | ❌ 미인정 |

즉 **운동 기록과 게임 목표를 분리**한다. Route는 "진행률"을 가져야 한다(████████░░ 80% → 다음에 80km부터 이어서 주행). 장거리 라이더에게 매우 중요. Pioneer는 80km까지 실제 처음 통과했으므로 개척자 인정 가능, "이 Route 최초 완주" 타이틀만 완주해야 부여. 장거리 Route는 '프로젝트'가 되어야 한다("서울→부산 42% → 이번 주말에 이어서"). 현실에서도 서울→부산·미국 횡단을 하루에 안 끝낸다 — RTW도 같은 철학.

**추천 구조**: 운동 기록 즉시 확정 / Claim·Pioneer 실제 구간까지 즉시 / Route는 미완료 저장 / 언제든 이어서 주행 / 완주 뱃지는 100%에만.

## 2차 — "5km 중 500m, 최소 인정 기준 필요하지 않나"

최소 기준은 필요하지만 **절대 거리만으로 판단하면 안 된다**(5km의 500m=10% vs 100km의 500m=0.5%는 의미가 다르다).

- **운동 기록(Health)**: 매우 낮은 기준(500m 또는 3분) — 실수 시작·즉시 종료만 걸러냄.
- **Route 진행(Game)**: 더 엄격(2km 이상 또는 20% 이상) … 하지만 **더 단순한 기준 추천**: Route를 이어서 탈 수 있다면 최소 인정 거리 자체가 크게 중요하지 않다. 7km·15km 달렸어도 진행률로 저장하면 된다. Claim·통계는 실제 달린 만큼 즉시 반영.

**막아야 할 진짜 대상**: 100개 Route를 만들고 각각 100m만 달려 진행중 Route만 잔뜩 만드는 악용. 그래서 **미완료 Route 저장에만 기준**(1km 미만 또는 10% 미만이면 이어달리기 저장 안 하고 폐기, 그 이상이면 진행 저장)을 두는 게 낫다.

## 3차 — "미완료 경로 쿼터(5~10개)를 두면 어떤가"

**"최소 인정 거리"보다 "미완료 Route 개수 제한"이 훨씬 좋은 해결책**이다. 사용자 행동을 자연스럽게 유도하기 때문.

**Active Route(진행 중 경로) 쿼터**: 무료 5개 / 유료 20개. 새 Route를 만들려는데 진행중이 꽉 차면 "이어서 주행 / 삭제" 중 선택 강제.

장점: ① 미완료 양산 방지 ② 장거리 Route 허용(서울→부산 62%를 몇 달 보관) ③ 심리("4/5가 되면 이것부터 끝내야겠다" — 게임의 정석).

**자동 정리**: 90일 진행 없으면 삭제 확인 또는 Archive 이동. **단 운동 기록(누적·Claim·Pioneer·칼로리)은 Route를 삭제해도 유지** — 삭제되는 것은 Route 자체뿐.

**즐겨찾는 프로젝트**: ⭐서울 한 바퀴 42% / ⭐제주 일주 18% / ⭐국도5호선 81% — 단순 미완료 목록이 아니라 개인의 장기 프로젝트.

**최종**: 장거리는 여러 번에 나눠 완료 / 운동·Claim은 실제 달린 만큼 즉시 축적 / 미완료 Route는 제한된 개수만 유지 / 새 경로를 원하면 기존을 완료하거나 삭제. 데이터 관리가 쉽고 무분별한 경로 생성을 자연스럽게 억제하며 장거리 프로젝트를 지원.
