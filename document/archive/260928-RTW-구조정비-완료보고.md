## 2. 이번에 쓴 방법 — 다음에도 이대로

### 2.1 뽑을 것을 고르는 기준

**「컴포넌트 생명주기와 무관하고, 자기들끼리만 참조하는 묶음」**만 골랐다.
React 상태도 지도 구독도 모르는 코드는 떼어내도 배선이 늘지 않는다.

거꾸로 **고르지 않은 것**: 가변 `ref` 를 다른 곳과 공유하는 코드. 그것은 자리 옮기기가
아니라 배선 변경이고, 틀려도 `tsc` 와 계약이 못 잡는다(§4).

### 2.2 한 번에 하나 · 매번 게이트

단계마다 **네 개를 전부** 돌렸다. 하나라도 빼먹으면 다음 단계에서 원인 후보가 두 배가 된다.

```
apps/web  $ npx tsc -b                 타입
apps/web  $ npm run test:next-ride     계약 331건
루트      $ npm run check:dep          방향·순환
apps/web  $ npx eslint <바뀐 파일>      0 error 유지
```

그리고 **chief 실기 확인**을 단계마다 받았다. 라이더 렌더·팝업은 헤드리스로 확인할 수
없다(구조 감사 P3) — 계약이 닿는 한계가 거기까지다.

### 2.3 도구

- **파일 이동은 `scripts/move-lib-files.mjs`** — `git mv` + 상대경로 재계산 + 자가 검산(M0).
  손으로 옮기지 마라. 이 도구는 **문자열 경로로 옛 파일명을 가리키는 곳**(계약 시험·하네스)도
  찾아서 알려준다 — 그게 `tsc` 가 못 잡는 자리다.
- **게이트를 고쳤으면 `node scripts/verify-gates-alive.mjs`** — 작업 트리가 깨끗해야 돈다.
- **`noUnusedLocals: true` 를 쓴다.** 새 파일에 import 블록을 통째로 복사해 넣고 `tsc -b` 가
  못 쓰는 것을 일러주게 하면, import 정리가 추측이 아니라 기계 작업이 된다.

## 3. 이번에 값을 치른 함정 — **다음 사람이 반드시 읽을 것**

### 3.1 코드를 옮기면 그 코드를 겨누던 계약이 죽는다 (4건 발생)

가장 중요한 교훈이다. 옮긴 코드에 걸려 있던 계약을 따라 옮기지 않으면
**시험은 초록인데 아무것도 막지 않는 상태**가 된다.

| 계약 | 그대로 뒀다면 |
|---|---|
| `preserved-layer-contract` — 동행 네임태그 경로 | `MapView.tsx` 를 보므로 **영영 못 찾아 red** (그나마 시끄럽게 실패) |
| `distance-auto-route-contract` — `buildPickPopup` 슬라이스 | `indexOf` 가 −1 → `slice(-1)` 이 **한 글자만** 남겨 **모든 `doesNotMatch` 가 통과** |
| `conquest-emphasis-contract` — 흰 테두리 금지 | 「그 파일엔 없으니 통과」 → **테두리가 부활해도 초록** |
| `rider-detail-lod-contract` 일부 | 같은 종류 |

**규칙** — 옮길 때마다:
1. 옮기는 코드의 식별자로 `scripts/`·`e2e/` 를 grep 한다
2. 걸리면 **새 파일을 보도록 고친다**
3. `doesNotMatch`·`slice(indexOf(...))` 류는 **못 찾으면 죽는 가드**를 함께 넣는다
4. **깨뜨려 확인한다** — 실제로 금지 문자열을 심어 red 가 되는지 본다(A-4 에서 9→8 pass 확인)

### 3.2 「이왕 하는 김에」가 동작 변경이다

A-5b 에서 마커 정리 범위를 그대로 옮겼다 — 출발·도착·장소 검색·경유지만 지우고
**재개점은 건드리지 않는다**(자기 effect 가 지운다). 「이왕이면 재개점도」 하면 그건
이동이 아니다. 의존성 배열도 늘리지 않았다(정리 함수는 `ref` 로 받았다).

### 3.3 import 정리 스크립트가 파일을 망가뜨렸다

A-3 에서 import 블록을 통째로 재구성하는 스크립트가 **블록 사이에 끼어 있던 상수 선언을
같이 지웠다.** 커밋에서 되돌린 뒤 `tsc` 가 짚어준 줄만 손으로 지우는 방식으로 다시 했다.
**import 블록을 통째로 다시 쓰지 마라** — 진단이 가리키는 줄만 지워라.

### 3.4 pre-commit 훅은 파일 전체에 eslint 를 돌린다

기존 error 가 있는 파일을 한 줄만 고쳐도 커밋이 막힌다(`usePublicationCatalogHub.ts`).
**원본 대비 증가가 0인지 `git stash` 로 대조**하고, 그때만 `--no-verify` 를 **승인받아** 쓴다.

### 3.5 heredoc 을 파이프 뒤에 붙이면 git 이 멈춘다

`git commit -F- ... | tail <<'EOF'` 는 heredoc 이 `tail` 에 붙어 git 이 입력을 못 받고 멈춘다.
**커밋 메시지는 파일로 쓰고 `-F <파일>`** 로 넘겨라.

## 4. 왜 여기서 멈췄나 — 남은 것의 성격

「자리만 옮기기」가 통하지 않는 지점에 도달했다. **억지로 밀면 이득보다 위험이 크다.**

### 4.1 주행 카메라 (A-5c, 착수 안 함)

카메라 상태가 **가변 ref 여럿을 rAF 주행 루프와 공유**한다.

| ref | 사용 |
|---|---|
| `suppressCameraFollowUntilRef` | 8곳 |
| `cameraSmoothRef` | 7곳 |
| `mapZoomRef` | 7곳 |
| `rideCameraDistanceMRef` | 5곳 |

그중 일부가 **rAF 루프 안**이다. 훅으로 뽑으려면 ref 를 통째로 넘기거나(결합은 그대로)
**루프를 함께 옮겨야** 하는데, 그 루프가 **동행 렌더 경로**다.

### 4.2 `App.tsx` 2,954줄

측정: import 160줄 · **훅 호출 105개** · JSX 543줄(이미 컴포넌트로 잘 쪼개져 각 1회 사용) ·
나머지 약 2,250줄이 상태·핸들러·effect. **조립 지점이라 크기가 본질적이다.**
덩어리를 들어내는 방식으로는 줄지 않고, 훅을 기능 단위로 묶는 일 — 4.1 과 같은 위험 — 이 필요하다.

> **다음에 이걸 열려면**: ① 먼저 rAF 루프의 계약 시험을 만들어 동작을 고정하고
> ② 카메라 상태를 한 객체로 모으고 ③ 그다음에 훅으로 뽑는다. ①이 없으면 하지 마라.
