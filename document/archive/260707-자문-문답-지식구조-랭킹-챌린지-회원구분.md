## 1. 지식 구조 — "문서 정리가 아니라 지식의 구조를 바꿔라"

지금 가장 필요한 것은 문서 정리가 아니라 지식의 구조다. 노트 내용 자체는 훌륭하고 제품 철학부터 수익모델까지 머릿속에 거의 다 들어 있다. 문제는 전부 의식의 흐름으로 연결돼 있다는 점(RTW → Trail → Public Route → Token → Badge → Ranking → Weather → Pioneer → Premium…). 이 상태로는 시간이 지나면 본인도 잊는다.

**Obsidian이 실패한 이유**: Obsidian은 구조를 만들어 주는 프로그램이 아니라, 이미 구조가 있는 사람에게 최고의 도구다. 지금은 생각→노트→노트가 계속 늘어나 "RTW = 120개의 md 파일"이 되고, 다시 안 보게 된다.

**RTW는 문서가 아니라 설계도여야 한다** — 프로그램 아키텍처가 아닌 "제품 아키텍처"를 권한다:

```
RTW
├── ① Core Fantasy   왜 존재하는가만 (실내에서 → 현실 세계를 달린다 → 영토를 얻는다 → 세계를 탐험한다)
├── ② Gameplay       라이딩→Route→Trail→Public/Official Route→Conquest→Mission→Badge→Event→Ranking (게임 규칙 전부)
├── ③ World          Mapbox→Weather→Day/Night→Mapillary→3D→Camera→Road→Conquest Layer
├── ④ Social         Trail→Red Dot→Rider→Chat→Voice to Text→Friend
├── ⑤ Economy        Token→Route Upload→Premium→Cosmetic→Avatar
├── ⑥ Backend        Firebase→Oracle→Cloudflare→Realtime→Auth→Sync
├── ⑦ UI             Ride Screen→Map→HUD→Statistics→Popup→Animation
└── ⑧ Roadmap        Done / Doing / Next / Someday
```

모든 기능은 반드시 상태를 가진다(예: Trail ✅ 완료 · Sync ⚠ 개선 필요 · Weather 💡 아이디어 · Ranking 🚧 개발 중). 이 표 하나로 프로젝트 상태를 알 수 있다.

**Feature Card**(가장 추천): 기능마다 A4 반 페이지 — 목적 / 현재 상태 / 남은 문제 / 관련 기능. 이 카드가 RTW의 최소 단위.

**RTW Bible**: 절대 구현 이야기를 쓰지 않는 문서. "왜 존재하는가? 누구를 위한 앱인가? 왜 Zwift가 아닌가? 왜 Token·Public Route·Claim·Trail이 존재하는가?" 이 질문들의 답만. 5년 후에도 안 변하는 문서.

**추천 폴더**: `00_BIBLE / 01_FEATURES / 02_IMPLEMENTATION / 03_ROADMAP / 04_DECISIONS(왜 z16인가, 왜 Google을 버렸나…) / 05_IDEAS(아무 생각이나)`

**위키 제안**: 노트는 프로젝트 기록이 아니라 창업자의 머릿속이다. 위키의 최소 단위는 날짜가 아니라 기능(Feature). 기능마다 6항목 유지 — 목적(Why) / 사용자 경험(UX) / 규칙(Rules) / 구현(Implementation) / 현재 상태(Status) / 관련 기능(Related). 의식의 흐름은 05_IDEAS에 자유롭게 적고, 검토가 끝난 내용만 Feature 문서로 승격. 필요한 것은 새 노트 추가가 아니라 '아이디어 → 기능 → 구현 → 완료'로 승격되는 일관된 지식 관리 체계다.

## 2. 영역별 랭킹 — 행정경계 데이터

행정경계는 OSM 도로 데이터와 별개의 데이터가 맞다. 하지만 생각만큼 큰 문제는 아니다 — 언제, 어떻게 계산하느냐가 중요하다.

- **OSM에는 행정경계도 들어 있다** (도로·건물·하천·공원·철도·행정경계·우편번호·토지 이용).
- **매번 계산하면 비용이 크다**: 10km 주행 = 도로 셀 500개 × "이 좌표는 어디지?(서울?강남?역삼동?)" — 사용자가 많아지면 부담.
- **RTW는 GPS 앱이 아니라 이미 도로를 알고 있다**: Road ID(예: R123456)에 country/province/city/district를 **미리 붙여놓으면** 주행 중 계산이 없다. 이 작업은 OSM 업데이트 시 단 한 번(도로↔행정경계 교차→행정코드 부여→저장).
- **데이터 크기는 작다**: 전 세계 국가 경계 몇 MB, 시/군/구까지 수백 MB~1-2GB. 진짜 문제는 크기가 아니라 **행정구역이 바뀐다는 것**(분리·통합·신설) — 1년에 몇 번 업데이트하면 된다.
- **더 큰 질문**: 왜 행정경계여야 하나? "우리 동네 1등"의 재미라면, 도로 기반 랭킹(한강 자전거길 1위, 국도 5호선 Top Explorer)이나 지도 타일(z8~z10) 기준도 가능 — 그러면 행정경계 관리가 아예 불필요.
- **추천: 혼합 전략** — ① 공식 지역(행정경계): "서울 15위, 강원도 3위" 직관적 표현용. ② 게임 지역(타일): Conquest·Heatmap·Chunk·서버 계산·캐싱용(사용자는 존재를 모름). **보여주는 것은 행정구역, 계산하는 것은 타일** — 행정경계 판정은 도로 데이터 구축 시 1회만 수행하고 도로에 행정코드를 붙여 재사용. 전 세계 대상이어도 런타임 비용이 매우 작다.

## 3. 일일·주간 챌린지

**챌린지를 속도 경쟁으로 만들면 안 된다** — 센서 없는 사용자, 스마트롤러 없는 사용자, 기종·저항 차이로 공정한 레이스가 성립하지 않는다. 답은 "속도"가 아니라 **"탐험"**.

4가지 축:
1. **탐험형**(가장 중요): 오늘 새 도로 3km 개척 / 이번 주 새 도로 20km / 새 동네 하나 완성 / 새 퍼블릭 루트 2개 / 아무도 안 달린 공식 루트 완주 — 센서 유무와 무관하게 공정.
2. **여행형**(RTW만 가능): 이번 주는 파리(개선문·에펠탑·몽마르트) → Paris Explorer 뱃지. 다음 주 런던·서울·뉴욕·제주.
3. **지역 정복형**: 이번 주 원주시 정복 이벤트 — 가장 많은 새 도로 / 정복률 15% 달성.
4. **공식 Route 이벤트**: 운영자 선정 국도 7호선, 하루 완주자 100명 달성 시 전원 뱃지.

추가 아이디어: **세계가 하나의 캔버스**(회원들이 도로를 따라 TOKYO·2026·하트를 함께 그림 — RTW만 가능), **City Completion**(원주시 오늘 5%→이번 달 25%→100% — 게임성 최강), 날씨 연동(Rain Rider·Indoor Hero·Snow Escape), **Featured Route/Today's Creator**(매일 퍼블릭 루트 1개 선정, Creator에게 뱃지 — Route 제작 동기부여).

적합성 평가: 탐험·도시 정복·여행·공식 Route ★★★★★ / 퍼블릭 Route·협동·예술 ★★★★☆ / **속도 레이스 ★★☆☆☆**.

제안: 매일 오전 9시 "오늘의 도시" 공개 — 그 안에서 새 도로 최다 개척 / 공식 루트 완주 / 정복률 상승. "누가 가장 빨리"가 아니라 **"오늘은 어디를 탐험했는가"**를 중심에 — Ride the World와 자연스럽게 연결.

## 4. 회원 구분 — 무료/유료/프리미엄

**RTW는 콘텐츠를 파는 서비스가 아니라 '축적'을 파는 서비스다.** Zwift는 새 월드·그래픽·코스를 계속 만들어야 하지만, RTW는 내가 달린 흔적·만든 루트·개척한 도로·쌓은 정복률 자체가 콘텐츠 — 사용자가 만든 자산이 핵심. 그래서 무료 회원을 너무 제한하면 안 된다.

**추천: 2단계만** (Free / Supporter). 프리미엄은 나중에. Free→Pro→Premium 3단계는 대부분 Pro도 Premium도 애매해지고 가입률만 떨어진다.

- **무료 = 게임 전부**: 공식·퍼블릭 루트, Trail, Conquest, Pioneer, 뱃지, 미션, 이벤트, 랭킹, 날씨, Route 생성·저장(제한), 기본 아바타.
- **유료 = 편의·표현·분석**: ①상세 통계(요일·월·도시·국가별, 히트맵) ②아바타(자전거·헬멧·의상·이펙트) ③영토 표현(색·테두리·광택·애니메이션) ④Route 관리(무료 20개 → 무제한) ⑤비공개 Trail·친구 초대 ⑥음성→텍스트(둘만의 Trail — 거의 유료 전용).

**구글 스트리트뷰 유료화는 추천하지 않는다**: 사용자는 월 2만원이면 "그 돈이면 Zwift 쓰지"라고 생각한다. 스트리트뷰는 RTW의 핵심도 아니고 철학을 흐린다. 정말 요청이 많아지는 시점에 "RTW Explorer" 같은 별도 고가 상품으로 — 운영비가 계속 발생하는 기능이기 때문.

Premium이라면 오히려 **AI 기능**(운동 분석 "지난주보다 지구력 향상", 코스 추천, "이번 달 원주시 상위 3%"), **정복 지도 내보내기**(8K PNG, "2026년 내가 달린 세계" 포스터 — 사람들이 돈을 낸다), **Creator Dashboard**(조회수·완주자·좋아요·인기 순위·Heat Map), **Cloud**(모든 기록 10년 영구 저장, RTW 기록집 자동 생성 — RTW 철학과 맞음).

**결론**: 지금 단계 최중요 지표는 유료 전환율보다 **네트워크 효과**. 사용자가 많아질수록 퍼블릭 루트·Trail·Pioneer·랭킹·정복 데이터의 가치가 커진다. 핵심 루프(달리기→정복→개척→랭킹)는 전부 무료로 유지하고, 유료는 "더 깊게·더 편하게·더 멋지게"에 집중 — 무료 사용자가 많아질수록 유료 회원의 가치도 커지는 구조.
