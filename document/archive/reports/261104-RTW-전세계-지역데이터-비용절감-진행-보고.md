## 1. 요약

- 전세계 서비스용 데이터 구조의 방향을 확정했고, 그 기반인 위치 판정 모듈을 만들었다. 아직 어떤 기능도 이 모듈을 쓰지 않는다.
- 비용 점검에서 사용자 수의 제곱으로 커지는 구조 셋을 찾아 없앴다. 순위는 누적 점수 방식으로 바꿔 배포했다.
- 유럽 RTDB 인스턴스를 만들었지만 앱은 아직 접속하지 않는다(비용 0).
- **열린 문제 하나**: 주행 중 Firestore 위치 저장이 일부 구간에서 12초가 아니라 4초로 나간다. 원인 미확정. 진단 기록을 배포했고, Chief 재주행 기록을 기다린다.

## 4. 측정으로 알게 된 것

- 2026-11-04 2인 실주행 1시간: 읽기 3.8천, 쓰기 1,633. 위치 저장 681회 중 522회(77%)가 1초 안 연속 저장이었다(L4b로 수정).
- 12초 줄기는 실제로 보인다. 같은 시간대에 4초 줄기가 구간으로 나타난다.
- 예상 비용표(1만 명 월 $13,000~26,000 → $1,500~2,900)는 미국 단가와 가정으로 계산했고, 위치 저장을 시간당 900회로 잡아 가속이 잦은 주행에서는 낮게 잡힌 값이다. 서울 Firestore 단가는 확인하지 못했다.

## 6. 재개 방법

실행 폴더 `C:\20.HDev\boxcycle`. 스크립트는 모두 운영 읽기 전용이고 `document/ops/20261103-cost-squeeze/tools/`에 있다. 시각은 UTC(KST−9).

```
node document/ops/20261103-cost-squeeze/tools/read-net-stats.cjs C:/20.HDev/boxcycle/functions 10
node document/ops/20261103-cost-squeeze/tools/mon-writes.cjs C:/20.HDev/boxcycle/functions <시작 UTC> <끝 UTC>
node document/ops/20261103-cost-squeeze/tools/log-gaps.cjs C:/20.HDev/boxcycle/functions <시작 UTC> <끝 UTC>
```

판정: `publicationId`가 있는 주행만 본다. 공개 경로가 아닌 주행은 최신 화면이어도 `netStats`를 남기지 않는다(11-04 정정, [쓰기 장부](../../ops/20261103-cost-squeeze/03-write-ledger.md)). 공개 주행에 `netStats`가 없으면 그 기기는 옛 화면이다. `disconnected`·`noAck`·`staleAck` 중 큰 값이 4초 구간의 이유다.

## 7. 주의 사항

- 유럽 RTDB Rules는 별도 배포다. `firebase.json`이 기본 인스턴스만 안다(HANDOFF 「잊지 말 것」).
- 작업 트리에 다른 사람의 미커밋 화면 변경이 있다. Hosting은 `git archive` 격리 빌드로 배포한다.
- 새 복합 쿼리는 에뮬레이터가 색인 부족을 못 잡는다. 운영에 빈 쿼리로 검사한다(`lb-index-probe.cjs`).
- `leaderboardCore.ts`의 옛 훑기 경로와 임시 캐시 상수는 코드에 남아 있다(동등성 시험이 쓴다). 운영 경로에서는 쓰지 않는다.
- 탈퇴자의 개척 이용 합계는 소유자 쪽에서 줄지 않는다(G3-1 남은 위험).
- `rides.startedAt`이 운영에서 전부 null이다. 의도 여부 미확인.
- 순위 센서 조건은 출시 전 true 복구(`LEADERBOARD_SENSOR_ONLY`, 체크리스트 §6) 그대로다.
- `test:e2e:peer-s1`은 Functions 에뮬레이터를 띄우지 않아 끝까지 돌지 못했다. L4 두 창 e2e는 미완이고 Chief 실주행으로 대체했다.
