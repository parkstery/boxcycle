## 문제

가까운 줌에서 라이더 렌더 비용의 75–84 % 가 CPU 다리 DQS(`PreservedRiderRig.updateSkin`) — 다리 6메시 약 4,200 정점을 매 프레임·라이더마다 CPU 로 섞고 `position`/`normal` 을 GPU 로 다시 올렸다.

## 수정

- 같은 수식을 정점 셰이더로(`lib/riderPrototype/riderGpuSkin.ts` — 순수 JS `skinVertexDQ` 와 GLSL 을 한 파일에). CPU 는 IK 와 4 본 듀얼 쿼터니언만 계산해 유니폼 `uSkinDQ[8]` 로 넘긴다. 정점 버퍼는 휴지값 고정, 재업로드 없음.
- 좌·우 다리는 서로 다른 유니폼이 필요해 다리 머티리얼만 좌·우 복제(컬러 키트·흔들림 주입·캐시 키 `rider-sway-v1:skin-gpu` 동일 적용). 주입 순서 스킨 → 흔들림.
- 스위치 `?skin=cpu|gpu`(`riderSkinMode.ts`), 기본 gpu. GPU 조건(정점 유니폼 ≥ 128, highp ≥ 23 bit) 미달·셰이더 컴파일 실패(`onShaderError`) 시 자동 cpu. perflab 상단 `스킨 gpu/cpu`, JSON `skinMode`.
- LOD2(줌 < 19)·s5 모델은 영향 없음.

## 검증

| | 결과 |
|---|---|
| JS 함수 = 기존 CPU 경로 (8위상·전 정점) | 위치 ≤ 6e-8 m, 법선 방향 ≈ 1e-6° |
| 화면 cpu vs gpu (4위상, 헤드리스) | 픽셀 차 0 / 1,344,000 |
| PC GTX 1660 운영, 파리 줌 22, 3명 | 라이더 2.36–2.60 → **0.39–0.42 ms/프레임**, GPU 타이머 7.2 → 5.1–5.5 ms |
| 폰 Adreno 730 운영 `?skin=gpu` | 정상(`skinMode: gpu`, 자세 비율 83 → 13 %, 떨림 0) |
| G2 배포 후 쿼리 없이 | `skin: gpu`, PC 70.7 fps |

## 틀렸던 것·교훈

1. 법선 비교 기준이 float32 저장 길이 오차를 `acos` 에 넣어 0.016° 로 부풀렸다 → 방향 비교로 바로잡음(Developer 발견).
2. **폰 cpu/gpu A/B 측정 요청은 실익이 없었다.** 폰은 GPU 타이머를 지원하지 않아 fps 비교가 잡음에 묻히고, 먼 줌(LOD2)에서 재면 다리 계산 자체가 없어 차이가 0 이다. 동등성·PC 실측·폰 정상 동작으로 결정에 충분했다. Chief 에게 반복 측정(폰 → Keep → PC 붙여넣기)을 시킨 것은 Supervisor 판단 실수.

## 다시 문제되면

- 다리 모양이 이상하다 → `?skin=cpu` 로 같은 장면 비교. cpu 에서도 같으면 리그 문제, gpu 에서만이면 셰이더(`riderGpuSkin.ts`) — 시험 `scripts/rider-preserve/rider-gpu-skin.test.ts`.
- 특정 기기에서 라이더가 안 보인다 → perflab `스킨` 이 cpu 로 내려갔는지(셰이더 실패 폴백) 확인.
- 되돌리기: `readRiderSkinModeSearch` 기본을 cpu 로 한 줄.
- 실행 중 cpu → gpu 전환(`setSkinMode("gpu")` 를 생성 뒤 처음 호출)은 새 복제 머티리얼에 흔들림·키트가 안 붙는다 — 앱은 생성 시 결정만 쓰므로 무관, 그 기능이 필요해지면 보완.
