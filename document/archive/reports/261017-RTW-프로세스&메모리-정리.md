## 배경

AI 개발 작업(빌드·e2e·브라우저·여러 에이전트 동시 실행) 중 메모리 부족이 반복됐다. 그래서 chief 가 2026-10-17 아침에 불필요한 프로세스를 직접 모두 내리고 메모리를 최대로 확보했다. 그리고 그 상태를 **기준점**으로 저장해 두었다가, 다음 작업 전에도 같은 상태로 되돌리도록 지시했다. 이 정리는 앞으로도 작업 전에 미리 하는 조치로 계속한다.

## chief 지시

1. 현재 프로세스를 확인해 별도로 저장하라. 이것이 앞으로의 기준점이다.
2. 「메모리 정리해」라고 하면 이 기준대로 정리하라.
3. 권한 문제 등으로 정리하지 못한 것은 보고하라.

### 2. 정리 스크립트 — `cleanup.ps1`

| 실행 | 동작 |
|---|---|
| `pwsh -NoProfile -File "$env:USERPROFILE\.claude\process-baseline\cleanup.ps1"` | 미리보기. 기준점에 없는 프로세스·서비스를 목록으로만 출력 |
| 같은 명령 + `-Apply` | 실제 정리. 정리 전후 여유 메모리와 실패 목록 출력 |

- **판정 기준:** 프로세스 **이름**이 기준점에 없으면 정리 대상이다. 서비스는 기준점에서 실행 중이 아니었던 서비스가 대상이다.
- **종료 방식:** 창이 있는 앱은 먼저 정상 종료를 요청하고, 3초 안에 닫히지 않으면 강제로 끈다. 서비스는 `Stop-Service` 로 멈춘다.
- **끄지 않는 것:** 정리를 실행하는 체인(Claude → 터미널 → 셸), Windows 필수 프로세스(svchost, explorer, dwm, lsass 등), node(MCP·개발 서버), git, 작업 관리자.

|---|---:|---:|---:|---:|
| 미리보기(스크립트 검증) | 0 | 0 | 10,427 MB | — |
| 「메모리 정리해」 `-Apply` | 0 | 0 | 10,447 → 10,438 MB | 0 |

기준점을 저장한 직후라 정리할 대상이 없었다. 스크립트가 정상 동작한다는 것과 실패 보고 경로가 작동한다는 것까지 확인했다.

## 한계

- **이름 기준이다.** 기준점에 이미 있던 이름(node, svchost 등)은 개수가 늘어도 정리 대상이 아니다. 그런 이유로 메모리가 부족해지면 이름별 개수까지 비교하도록 보완한다.
- **서비스 정지는 관리자 권한이 필요한 경우가 많다.** 이런 서비스는 실패 목록에 나오고, chief 에게 보고한다.
- 기준점에 없는 앱은 열려 있으면 꺼진다. 저장하지 않은 작업이 있으면 정리 전에 저장해야 한다.

## 운영 절차

1. chief 가 「메모리 정리해」라고 지시하면 그 자체를 승인으로 보고, 미리보기 → `-Apply` 를 바로 실행한다.
2. 보고에는 정리 전후 여유 메모리와 정리하지 못한 항목·이유만 담는다.
3. 기준점을 바꾸라는 지시가 있으면 `baseline.json` 을 다시 캡처하고, 이전 파일은 날짜를 붙여 보존한다.
4. 빌드·e2e·브라우저가 멈추는 등 메모리 부족 증상이 보이면 Claude 가 먼저 정리를 제안한다.
