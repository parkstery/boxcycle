### 2.1 R1 — F2 end/resume distance conversion adapter

**문제**: End persistence는 `routeDistanceMeters` (Directions API) 기준으로 ratio 저장, Resume은 `geometryLength` 기준으로 meters 계산 → dual-length fixture에서 불일치.

**해결**: Adapter 구현 — ratio 저장/복원 시 **같은 denominator (geometry)** 사용.

#### Product change (commit `10b36d1`)

**File**: `apps/web/src/hooks/useRideEndAndPersistence.ts` line 148-156

```typescript
// F2: ratio 저장 denominator = geometry 길이 (resume adapter 계약)
// End persistence와 resume 계산이 같은 기준을 쓰도록 통일.
// routeDistanceMeters는 exercise distance/completion threshold 축에서만 사용 (0A catalog SoT 유지).
const geoLen = routeGeometry ? lineStringLengthMeters(routeGeometry) : 0;
const progressDenom = geoLen > 0 ? geoLen : routeDistanceMeters > 0 ? routeDistanceMeters : 0;
const completionRatio =
  progressDenom > 0
    ? Math.max(0, Math.min(1, rideMetrics.virtualDistanceMeters / progressDenom))
    : 0;
```

**Rationale**:
- End persistence: `completionRatio = virtualDistanceMeters / geoLen`
- Resume (App.tsx): `resumeOffsetMetersFrom(ratio, geoLen)` (already from commit `1535007`)
- Exercise distance / completion threshold: still use `routeDistanceMeters` (0A catalog SoT 유지)

#### Dual-length fixture proof (commit `10b36d1`)

**File**: `apps/web/scripts/ride-result/ride-result-f2-card-resume.test.ts` line 98-130

**Scenario**: Directions API says 1000m, actual geometry is 1200m, ride ended at 500m.

**OLD BUG**:
```typescript
const savedRatio = 500 / 1000; // 0.5 (wrong denominator)
const resumeMeters = 0.5 * 1200; // 600 (WRONG!)
```

**FIX**:
```typescript
const progressDenom = geoLen > 0 ? geoLen : routeDistanceMeters > 0 ? routeDistanceMeters : 0;
const savedRatio = 500 / 1200; // 0.417 (correct denominator)
const resumeMeters = 0.417 * 1200; // 500 (CORRECT!)
```

**Test code**:
```typescript
it("R1 ADAPTER PROOF: dual-length (routeDistance=1000, geo=1200, end 500 → resume 500 NOT 600)", () => {
  const geoLen = 1200;
  const routeDistanceMeters = 1000;
  const endOffset = 500;
  
  const progressDenom = geoLen > 0 ? geoLen : routeDistanceMeters > 0 ? routeDistanceMeters : 0;
  const savedRatio = endOffset / progressDenom; // 500/1200 = 0.417
  
  const resumeMeters = resumeOffsetMetersFrom(savedRatio, geoLen);
  
  // PASS: resume should be ~500, NOT 600
  assert.ok(Math.abs(resumeMeters - endOffset) < 1);
  
  // FAIL example (old bug)
  const buggyRatio = endOffset / routeDistanceMeters; // 500/1000 = 0.5
  const buggyResume = resumeOffsetMetersFrom(buggyRatio, geoLen); // 600
  assert.ok(Math.abs(buggyResume - endOffset) > 50);
});
```

### 2.4 R4 — F3 conquest

**요구사항**:
- Absence ≠ confirmed 0
- No `Number()` coercion of invalid types
- C8/C9/C12 tied to real parser/subscription

#### Product change (commit `6764551`)

**File**: `apps/web/src/lib/rideConquestResult.ts` line 50-91

**Before**:
```typescript
const newMeters = Number(raw.newMeters ?? 0); // coerced any value
```

**After**:
```typescript
// R4: no Number() coercion — only accept actual numbers
const newMetersRaw = raw.newMeters;
if (typeof newMetersRaw !== "number") {
  // Absence or wrong type → "none" (not confirmed 0)
  return EMPTY_CONQUEST_RESULT;
}
```

**Parsing logic**:
- Absence (missing field) → `{ status: "none", newMeters: 0 }`
- Explicit `0` → `{ status: "confirmed_zero", newMeters: 0 }`
- Positive number → `{ status: "positive", newMeters: N }`
- Strings ("123"), null, undefined → reject (return "none")
- NaN, Infinity, negative → `{ status: "error", newMeters: 0 }`

**Rationale**: Prevents CF bugs (e.g. returning string "5000" instead of number 5000) from silently coercing to valid results.

**C8/C9 verification**: Real parser/subscription (unit tests 112 PASS).
