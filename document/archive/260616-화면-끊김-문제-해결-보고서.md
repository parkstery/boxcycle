## 0. 한 줄 결론

> **증상은 “캐릭터 아트”가 아니라 “위치·카메라 갱신 주기” 불일치였다.**  
> 동행은 Firestore 스냅샷 + React props(200ms)로 **점프**했고, 본인 마커·팔로우 카메라도 같은 throttle에 묶여 **추적 모드에서만** 화면 전체가 툭툭 끊겨 보였다.  
> 해결: **(1) 동행 → `liveCourseRides` 진행률 + rAF 보간**, **(2) 본인 마커 → rAF `sampleLiveLngLat`**, **(3) 팔로우 카메라 → 동일 rAF 루프**.

## 1. 증상

| 구분 | 관찰 |
|------|------|
| 동행 캐릭터 | 가만히 있다가 한 번에 **툭** 이동 후 다시 멈춤 |
| 본인 캐릭터 | free 모드보다 추적 모드에서 더 끊김; 약 **0.2~0.3초** 간격 계단감 |
| 카메라 | **전방·후방·북향 등 팔로우 ON** → 화면 전환 툭툭; **free** → 캐릭터만 보면 부드러움 |
| 오해 | GLB / iso2d 스프라이트 품질 문제로 착각 — **아트 교체로는 해결 불가** |

## 2. 근본 원인 (3층)

### 2.1 동행 라이더 — 네트워크·좌표 소스

**Before**

```
Firestore livePresence (lat/lng)
  → 4~12초 throttle, 40m 이동 임계, 소수 3자리 반올림(~100m 격자)
  → React props 갱신
  → peerRidersDrive lerp (~0.34s) 후 정지
  → 체감: 멈춤 → 툭 → 멈춤
```

**원인**

- `CourseSharedPresence`가 `globalPeerPositionsByUid`(livePresence 좌표)만 사용
- 발행측 `GLOBAL_LIVE_PRESENCE_MIN_MOVE_METERS = 40`, `METRICS_UI_MS`와 무관하게 **저빈도·저정밀** 좌표
- 클라이언트 lerp는 **갱신 사이 dead reckoning 없음**

**After (`1562ceb`)**

- 동일 코스 **`liveCourseRides.progressRatio`** + 로컬 `routeGeometry`로 경로 위 점 계산 (본인 `liveForMap`과 동일 계열)
- `peerRidersDrive`: progress **속도 extrapolation** + rAF 매 프레임
- publish 간격 완화: progress min write 8s→5s, max 25s→12s, delta 1.2%→0.8%

---

### 2.2 본인 캐릭터 — React 200ms throttle

**Before**

```
useVirtualRideSession rAF (매 ~16ms)
  → virtualDistanceRef 적분
  → setState는 METRICS_UI_MS=200 마다만
  → App liveForMap → MapView props liveLngLat
  → useEffect setLngLat(liveMarker)
  → 마커: 200ms 점프
```

**원인**

- rAF마다 `setState` 금지 주석·설계 — **HUD 숫자용 throttle이 맵 마커까지 전파**
- 동행은 rAF에서 DOM 직접 갱신 → **본인만 끊김**

**After (`670d306`)**

- `sampleLiveLngLat()`: rAF 루프 ref에서 **throttle 없이** 경로 위 좌표 샘플
- MapView rAF tick: 마커 `setLngLat` + 방향·페달 (`syncLiveSelfRiderVisual`)
- React `liveLngLat` props: 마커 **생성/제거·닉네임·HUD** 용도만 유지

---

### 2.3 팔로우 카메라 — props에 묶인 jumpTo

**Before**

```
마커: rAF sampleLiveLngLat (~16ms)  ← 부드러움
카메라: useEffect(liveLngLat)       ← 200ms 타깃 점프
  → jumpTo(damped) but 목표점 자체가 계단
  → free: 카메라 고정 → 부드러움
  → follow: 지도만 툭툭
```

**원인**

- `tickRideCameraFollow` 로직은 damping 있었으나 **입력이 200ms props**
- 사용자 확인: **free = 부드러움, 추적 = 끊김** → 카메라가 원인 확정

**After (`917e335`)**

- `tickRideCameraFollow()`를 **동행·본인과 같은 rAF tick**에서 호출
- 입력 = `sampleLiveLngLat()` 매 프레임
- React `useEffect` 카메라 추적 **제거**
- 기존 `CAMERA_*_TAU` damping 유지

## 3. 수정 후 데이터·렌더 경로 (요약)

```
[본인]
useVirtualRideSession rAF
  ├─ virtualDistanceRef (매 프레임)
  ├─ sampleLiveLngLat() ──┬─► MapView rAF: liveMarker.setLngLat
  │                       ├─► MapView rAF: syncLiveSelfRiderVisual
  │                       └─► MapView rAF: tickRideCameraFollow → jumpTo
  └─ setState (200ms) ──► HUD 거리·시간·liveForMap props (부수)

liveCourseRides onSnapshot (progressRatio)
  → CourseSharedPresence peerMarkers
  → MapView rAF: mergePeerTargets + stepPeerDrive (extrapolation)
  → peer DOM / GLB setLngLat
```

## 6. 설계 교훈 · 재발 방지

1. **맵상 연속 이동 ≠ React state**  
   HUD·Firestore publish는 throttle OK. **마커·카메라·GLB는 rAF + ref 단일 시계**.

2. **동행 위치는 progress 우선**  
   같은 코스면 `livePresence` lat/lng 대신 **`liveCourseRides.progressRatio` + geometry**.

3. **팔로우 vs free로 원인 분리**  
   free 부드럽고 follow 끊기면 → **카메라 입력 주기** 의심.

4. **프로토타입 아트와 분리**  
   iso2d / GLB / legacy 전환은 **표현** 문제; 끊김은 **갱신 파이프라인** 문제.

5. **코드 리뷰 가드**  
   MapView에서 `liveLngLat` props로 `setLngLat` / `jumpTo` 하는 경로 추가 시, rAF 샘플과 **동일 좌표 소스**인지 확인.

## 7. 남은 한계 (선택 개선)

| 항목 | 설명 |
|------|------|
| HUD vs 맵 | 거리 숫자는 여전히 200ms — 의도적 |
| 동행 extrapolation | Firestore 간격(5~12s)보다 짧은 미세 오차 가능; hard snap 없이 유지 중 |
| DOM Marker vs GLB | 고줌 pitch 3D에서 GLB가 구조적으로 유리 (별도 [Rider 프로토타입](260616-Rider-Prototype-비교-가이드.md)) |
| `map.stop()` + `jumpTo` 매 프레임 | Mapbox 부하 — 문제 시 `easeTo` duration 0 또는 FreeCamera API 검토 |
