## §2. 노드 계약 — 제품 GLB 에서 직접 읽은 실측값

추정이 아니다. `rider-lowpoly.glb` 를 파싱해 얻은 값이다. **새 후보는 이 형태를 그대로 따라야 한다.**

```

├ crank        matrix  T=(0, 0.2705, 0)          회전 NON-IDENTITY (크랭크 위상 baked)
│ ├ pedal_l    matrix  T=(0, +0.1725, +0.074)    회전 identity
│ └ pedal_r    matrix  T=(0, -0.1725, -0.074)    회전 identity   ← 좌우 180° 대칭
├ torso        TRS     T=(-0.14355, 0.80985, 0)  rotation 없음
├ leg_l        TRS     T=(-0.14966, 0.84452, +0.0814)   rotation 없음
│ └ leg_l_shin TRS     T=(0, -0.37840, 0)
│   └ ankle_l  TRS     T=(0, -0.35200, 0)
├ leg_r        TRS     T=(-0.14966, 0.84452, -0.0814)
│ └ leg_r_shin TRS     T=(0, -0.37840, 0)

```

여기서 **반드시 지켜야 할 세 가지**가 나온다.

### 2-1. `_l` = **+Z**, `_r` = **−Z** — 확정

`leg_l.z = +0.0814`, `leg_r.z = −0.0814`, `arm_l.z = +0.1804`, `arm_r.z = −0.1804`.
`riderRig.geometry.mjs` 의 `HIP_L = +PELVIS_HALF_Z` 와 `kneePole` 의 `zSign = side==='l' ? +1 : -1` 도 같다. **코드 전체가 일관되게 `_l` = +Z 다.**

신규 모델은 `hip.R.z = +0.1013` 으로 **자기 라벨상 R 이 +Z** 다. 따라서

> **신규 모델의 +Z 쪽 부위 → `*_l` 노드, −Z 쪽 → `*_r` 노드로 귀속한다.**
> 미러링하지 않는다(와인딩·노멀이 뒤집힌다). 소스 모델의 R/L 라벨을 따라가지 않는다.

### 2-2. rest 자세 = 사지가 로컬 **−Y**(수직 아래) — 이번 작업 최대의 함정

자식 노드 오프셋이 전부 `(0, −길이, 0)` 이다. `generate-rider-prototype-glb.mjs` 도 명시한다 — *"허벅지·정강이 — rest pose = 두 뼈 모두 **-Y(수직 아래)**"*, *"팔 — rest = 두 뼈 모두 **-Y(수직 아래)**"*. 그리고 제품 GLB 의 14노드는 **crank 를 제외하면 회전이 전부 identity** 다.

**신규 모델은 페달링 자세로 조각돼 있다**(좌우 다리가 서로 다른 크랭크 위상, 팔꿈치 35° 굴곡). 그대로 노드에 넣으면 앱이 rest 를 기준으로 회전을 **누적**하므로 자세가 이중으로 들어간다.

> **절단한 각 세그먼트를 rest(−Y) 방향으로 되돌린 뒤(un-pose) 노드에 넣는다. 노드 회전은 identity 로 굽는다.**
> un-pose 는 세그먼트별 강체 변환이므로 형상 손실이 없다.

#### ⚠ rev.2 정정 — `strip-node-rest.mjs` 는 un-pose 도구가 **아니다**

rev.2 는 이 도구를 지목했으나 **틀렸다.** 소스가 정반대를 명시한다:

```
apps/web/scripts/rider-cycle-fit/strip-node-rest.mjs:3   "rest rotation·scale **키만 삭제**한다"
                                                  :23-24 "⚠ 정점을 굽지 마라"
                                                  :126-135 delete node.rotation; delete node.scale;
```

이 도구는 **노드 메타데이터만 지우고 정점은 그대로 둔다.** 조각된 페달링 자세 메시에 쓰면 정점은 페달링 자세인 채 노드만 identity 가 되어, **이 문서가 막으려던 이중 자세가 정확히 그대로 발생한다.** 게다가 `crank`·`pedal_*` 처럼 `matrix` 형식 노드를 만나면 즉시 FAIL 한다. 이 도구의 자리는 단계 B 가 아니라 **제품 이식 직전 마지막 안전 패스**다.

`rotate-rider-nodes.mjs` 도 아니다 — 루트 노드의 translation 만 옮긴다(헤더 22행 "정점을 굽지 않는다").

## §4. Draco — 쓸 수 있다 (rev.2 에서 소스로 확인)

`node_modules/mapbox-gl` **3.23.1** `dist/mapbox-gl-dev.js` 를 직접 grep 한 결과:

- `KHR_draco_mesh_compression` 를 `decodeGLTF` → `loadDracoMesh` 에서 파싱한다. `model` 레이어의 `ModelManager.loadModel` → `loadGLTF` → `decodeGLTF` 경로와 동일하다. **지원한다.**
- `EXT_meshopt_compression` 도 지원한다.
- **`KHR_mesh_quantization` 은 소스 어디에도 없다 — 미지원.** gltf-transform 의 `draco` 는 종종 `quantize` 와 함께 쓰이는데, **quantize 를 켜면 로드에 실패한다.**
- 로더는 `extensionsUsed` 만 검사하고 `extensionsRequired` 는 보지 않는다. 익스포터가 `extensionsUsed` 에 넣는지 확인할 것.
- Draco WASM 디코더를 Mapbox CDN 에서 지연 로딩한다(`config.DRACO_URL`). **첫 모델 로드에 외부 요청이 하나 추가된다** — 오프라인/차단 환경 영향 확인 필요.

결론: 최종 후보를 Draco 로 낼 수 있다(비압축 약 2.0 MB → Draco 약 0.23 MB). 단 **quantize 없이**, 그리고 단계 D 에서 실제 로드 성공을 확인한 뒤 확정한다.

## §5. 증거 계약 — Claude Code 는 "했다"가 아니라 "파일"을 남긴다

감사 세션은 사용자 PC 에서 명령을 실행할 수 없다. 대신 **파일을 읽어 수치를 독립적으로 재계산**한다. 그래서 각 단계는 **정해진 경로에 기계가 읽을 수 있는 산출물**을 남겨야 한다. 로그 문장이나 "통과했습니다"는 증거가 아니다.

모든 산출물 루트:
```
apps/web/scripts/rider-cycle-fit/.out/candidates/<candidateId>/
```

| 단계 | 필수 산출물 | 감사가 재계산하는 것 |
|---|---|---|
| 0 | `manifest.json`, `inventory.json`, 기준선 PNG | 입력 SHA-256 재계산, manifest 값과 대조 |

## §8. 감사 프로토콜 — 이 세션이 무엇을 어떻게 검증하는가

### 할 수 있는 것
- 저장소·산출물 **모든 파일을 읽어** 계획서·보고 내용과 대조
- **SHA-256 독립 재계산** (제품 GLB 해시가 문서 260910 과 일치함을 이미 확인)
- **GLB 독립 파싱** — 노드·계층·변환·AABB·삼각형·정점·재질·확장을 직접 계산
- 보고된 수치를 **산출물에서 재유도**. 명령 재실행보다 강한 검증이다
- `node-mapping.json` 의 중복·누락, 캡 폐합, 상수 3중 동기화를 기계적으로 검사

### 할 수 없는 것
- 렌더 PNG 의 **미적 판정** — 그건 사용자 승인 영역
- 제품 확정·커밋 승인 — 사용자 게이트

> **rev.3 정정 — 감사 세션이 바뀌었다.** rev.2 의 감사자(Cowork 세션)는 쉘 접근이 없어 "명령을 실행할 수 없다"를 전제로 감사 프로토콜을 짰다. **rev.3 의 감사자는 Claude Code 수퍼바이저 세션이며 쉘·Blender·node 를 직접 실행할 수 있다.**
> 따라서 감사는 산출물 대조에 그치지 않는다 — **같은 계측을 독립적으로 재실행해 대조한다.** 실제로 P·P2·P3 에서 GLB 파싱·SHA-256·`verify-rider-glb.mjs` 실행·`decompose-v2-rider.py` 소스 판정을 감사 측이 직접 수행해 보고서의 주장 5건을 재현했고, 그중 1건(B4)을 뒤집었다.
> **집행 측은 "감사가 실행할 수 없으니 넘어가겠지" 를 전제하지 마라.**

### 감사가 FAIL 을 내는 조건
1. 산출물이 §5 의 경로·스키마대로 없음
2. 보고된 수치가 산출물에서 재계산한 값과 불일치
3. `unassigned`/`duplicates` 가 비어 있지 않음
4. rest 자세가 −Y 가 아님 / 노드 회전이 identity 가 아님(crank 제외)
5. 노드 오프셋과 rig 상수가 불일치
6. 제품 GLB 의 SHA-256 이 `a9d0d67...` 에서 바뀜 (단계 E 전)
7. 검증 기준을 실측 근거 없이 완화

## §9. 착수 전 결정

1. ~~**BLEND 불일치**~~ — **해결(P·P2).** manifest 필드 없음이 확인됐고, BLEND 는 "원본 소스"가 아니라 **분해 3메시의 입력**으로 승격됐다(§0). 별도 파일 `blend-glb-divergence.md` 로 기록한다.
2. **model-scale** — 화면 크기 유지(1.027) vs 실제 비율대로 조금 크게 ← **미결. 단계 C 에서 결정**
3. **Draco 채택** — 단계 D 에서 로드 성공을 확인한 뒤 결정. 확인 전 비압축 유지 ← **미결**
4. **un-pose 스크립트 신설** — §2-2 의 6개 변경 항목대로 새로 짠다. **단계 A 산출물(귀속·앵커)이 선행 입력**이므로 단계 A 완료 후 별도 지시로 착수 ← **rev.3 신규**
