## 2) 파일 단위 쪼개기(목표 구조)

**우선:** `npm create vite@latest` 등으로 **Vite + React + TypeScript** 앱을 두고, 레거시 로직을 컴포넌트·모듈로 이식한다. (동일 저장소 내 `apps/web` 등 서브폴더 여부는 팀 관례에 따름.) 구형 방식으로 **`js/` 폴더만 나눈 정적 HTML** 은 더 이상 권장하지 않는다.

### A. 프론트(브라우저 전용)

| 파일(제안) | 옮길 대상(현재 `app.js` 기준) |
|-------------|-------------------------------|
| `js/config.js` | `MAPBOX_ACCESS_TOKEN`, `INITIAL_CENTER`, `DEFAULT_ZOOM`, storage key 상수(임시로 로컬 어댑터가 쓸 수 있음) |
| `js/dom.js` | `document.getElementById(...)` 묶음, null-safe export |
| `js/geo.js` | `parseLngLat`, `formatLngLat`, `getDistanceMeters`, `interpolatePoint`, `getPointOnRouteByDistance`, `getBearingFromPoints`, `getRouteHeadingByDistance`, `getAverageHeadingAhead` |

| `js/map-boot.js` | `mapboxgl.Map` 생성, `ScaleControl`, `map.on("load")` 초기 1회 호출만(진입점에서 조립) |
| `js/map-style-3d-roads.js` | `BUILDING_LAYER_ID`, `TERRAIN_SOURCE_ID`, `ROUTABLE_ROAD_LAYER_ID`, `ensureTerrainSource`, `add3DBuildingsLayer`, `remove3DBuildingsLayer`, `apply3DState`, `applyRoadOverlayState`, `restoreRouteAfterStyleChange` |

| `js/elevation-ui.js` | `elevationProfileState`, `setElevationStatus`, `setElevationEmptyState`, `sampleRouteCoordinates`, `buildElevationSvg`, `calculateElevationGain`, `renderElevationProfile`, `updateElevationProgressMarker` — **fetch는 `js/services/elevation.js`로** |

| `js/main.js` | import 조합 + 최소 glue |

### B. 서비스 레이어(프론트 모듈, 구현만 백엔드로 바꿀 준비)

| 파일(제안) | 역할 | 현재 코드 |
|-------------|------|-----------|
| `js/services/geocoding.js` | `searchPlaces(query, proximity)` | `fetchPlaceSuggestions` → URL의 `access_token` 제거, `/api/geocoding?q=` 호출로 교체 예정 |
| `js/services/routing.js` | `getRoute(start, end, profile)` | `fetchRouteByProfile` |
| `js/services/elevation.js` | `fetchElevations(sampledCoords)` | Open-Meteo 직접 호출 → 필요 시 `/api/elevation` 프록시 |
| `js/services/storage-sessions.js` | `listSessions`, `appendSession` | `loadSessions` / `saveSessions` → 나중에 `GET/POST /api/rides` |
| `js/services/storage-routes.js` | `listMyRoutes`, `saveMyRoutes`, … | `loadMyRoutes` / `saveMyRoutes` / `applyMyRoute`의 저장 데이터 |

### C. 백엔드·데이터(현재 단계: Firebase 우선)

| 구성요소(제안) | 이유 |
|----------------|------|
| **Firebase Auth** (1차: Google) | PM 합의: Gmail 하나로 빠른 멀티 유저 검증 |
| **Firestore**(또는 Realtime DB, 제품 선택) | 세션 메타·방/코스 참여·프레즌스 최소 필드 |
| **Cloud Functions**(HTTPS) | Mapbox Directions/Geocoding **프록시**, 서버에서만 토큰 보유 |
| 규칙·원장성 민감 로직 | 클라이언트만 믿지 않음 — [Firestore→Postgres 체크리스트](260509-Firestore-Postgres-이전-체크리스트.md) 준수 |

분리 이후 **전용 Node/Nest API** 로 옮길 때 위 함수·컬렉션 모델을 **동일 도메인 이름**으로 대응시키면 이전 비용이 줄어든다.

### D. 순수 로직(웹·향후 클라이언트 공유)

| 후보 | 비고 |
|------|------|
| 거리·보간·경로상 위치 | TS 모듈로 추출; 안드로이드는 **웹 래핑 우선**이므로 당장 Kotlin 포팅 필수 아님 |
| 세션 요약(평균 속도, 칼로리 추정 등) | 순수 함수로 추출해 React와 Functions 입력 검증에 재사용 가능 |

맵·DOM·Mapbox GL은 **웹 클라이언트**에 둔다. 안드로이드 1차는 **동일 웹 자산 래핑**으로 정렬한다.

## 3) “어디부터” 분리해야 하는지 (우선순위)

1. **Mapbox Directions + Geocoding**  
   - 이유: 토큰 노출, 과금 단위, 요청 정책, Android와 동일 결과 필요.
2. **`localStorage` 세션 / 마이루트**  
   - 이유: 로그인·동기화·Starter 강제·코인 원장과 충돌하는 현재 모델의 한계.
3. **이벤트 리스너 덩어리(L1093~)**  
   - 이유: 테스트·유지보수; 기능 추가 시 회귀 방지.
4. **카메라/3D/티커**  
   - 이유: 제품 차별화 코드이므로 **맨 나중에** 건드려도 됨(이미 응집도 높음).

## 4) 실행 체크리스트 (갱신)

### Phase 0: Vite + React + TypeScript 골격 + Firebase 연결

- [x] Vite(React+TS) 프로젝트 생성 — 저장소 내 **`apps/web`** (패키지명 `boxcycle-web`).
- [x] Firebase 프로젝트·웹 앱 연동 — 팀에서 프로젝트 및 웹 앱 구성 완료. 로컬 값은 **`apps/web/.env`**(커밋 제외), **`apps/web/.env.example`** 과 필드명 일치. CLI 기본 프로젝트는 저장소 루트 **`.firebaserc`**.
- [x] Google 로그인 최소 플로우(UI): 로그인·로그아웃·`uid` 표시 — Firebase 콘솔 설정 후 동작 확인.
- [x] 멀티 유저 검증에 필요한 화면 일부 포팅: 실시간 로비(`rooms/.../members`), 입문 허브 동행(`coursePresence`), 주행 기록(`rides`), 코스 시드(`courses`) 등 — 레거시 단일 HTML 전체 동등 포팅은 계속.

**완료 기준:** 로컬에서 Vite 앱 실행 + Firebase Auth로 로그인 + Firestore 동기 경로 동작(현재 코드 기준 충족).

### Phase 1-A: 레거시 로직 모듈화(포팅 단위)

- [x] 핵심 런타임 이식: 지도 부트·경로 레이어·카메라·라이브 마커·고도 프로필·가상 주행 훅 등이 `apps/web/src` 컴포넌트·모듈로 동작 중 — §2 의 세부 파일 단위 1:1 분할은 진행 중·지속.
- [x] Mapbox 인스턴스 생명주기는 `MapView` 등에서 관리(추후 hook/스토어 더 분리 가능).
- [x] 레거시 루트 `index.html` / `app.js` 등은 포팅 완료 후 **저장소에서 제거**함(README·현재 단계 문서 갱신).

**완료 기준:** Vite 앱에서 경로 생성·주행·Firestore 연동까지 동등 이상 동작; 남은 차이는 이슈로 분할 추적.

### Phase 1-B: 서비스 인터페이스 고정 (URL은 아직 Mapbox 직행 가능)

- [x] 라우팅: `apps/web/src/services/mapboxDirections.ts` (`fetchRouteByProfile` 등) — UI에서는 서비스만 호출.
- [ ] Geocoding: 웹 앱에 장소 검색 UI·모듈 미포팅 시 해당 서비스 파일 신설 예정.
- [ ] 고도: Open-Meteo 호출이 `MapView.tsx` 내부에 있음 → `services/elevation.ts` 등으로 추출 예정.
- [ ] `localStorage` 세션/마이루트 캡슐화(레거시 저장 모델) — 웹은 Firestore `rides` 중심으로 이미 분기된 부분 있음.

**완료 기준:** UI에 Mapbox Directions URL 문자열 없음(현재 충족). Geocoding·고도·스토리지 분리까지 하면 Phase 1-B 전체 완료.

### Phase 1-C: Mapbox 프록시 + 멀티 유저 데이터

- [x] Cloud Functions **Callable `getMapboxDirections`** — Mapbox Directions REST 는 서버 시크릿(`MAPBOX_ACCESS_TOKEN`)만 사용. (`functions/` · 리전 `asia-northeast3`)
- [x] 웹은 Directions 에 대해 **브라우저에서 Mapbox REST URL·`access_token` 미사용**(Callable만). **예외:** Mapbox **GL JS** 타일용 **`VITE_MAPBOX_ACCESS_TOKEN`(pk.)**.
- [ ] Geocoding 프록시(REST 또는 Callable) — 웹에 장소 검색 도입 시 추가.
- [x] 주행·로비·코스 동행 최소 모델 Firestore 저장(`rides`, `rooms/.../members`, `coursePresence`, `courses` 등) — **2계정 동시 접속** 데모·Rules 전 코스 커버리지는 [현재 단계 §4](260509-BOXCYCLE-현재단계-범위-스택-및-1차마일스톤.md)·[Rules 일반화](260511-Firestore-Rules-일반화-방안.md) 후속.
- [x] Open-Meteo 고도: 브라우저 직행 중; 필요 시 Functions 프록시.

**완료 기준:** [현재 단계 문서](260509-BOXCYCLE-현재단계-범위-스택-및-1차마일스톤.md) §2 인수 조건 충족 + **Mapbox Directions(및 도입 시 Geocoding) REST** 에 한해 서버 프록시·클라이언트 비노출.

### Phase 1-D: 도메인 모델 이름 맞추기 (다음 단계 대비)

- [ ] `localStorage` 세션 항목 필드를 API 스키마에 맞게 rename 설계만: `endedAt` → `endedAt`, `distanceMeters` 유지 등, 문서 `260509-아키텍쳐-DB설계.md`의 `rides`와 필드 매핑 표 1행 추가.
- [ ] “My routes”를 `CourseDraft` 같은 개념으로 주석/타입만 정리(코인·검증은 아직 미구현).

### Phase 1-E: `sessions` 모델 도입 시 `roomId` ↔ `sessionId` 매핑 가이드 (1차 마일스톤 직후)

- [ ] **로비**(`rooms/{roomId}/members`)와 **세션**(`sessions/{sessionId}` + `presence/{sessionId}/members`)의 책임 분리: 로비는 "어디서 만나서 같이 탈지 약속하는 곳", 세션은 "실제로 같이 타고 있는 그룹". 한 로비에서 여러 세션 파생 가능.
- [ ] 입문 허브 진입은 **임시 매핑** `sessionId = courseId` 로 시작(Phase 1-C). 이후 자동 분류(스피드 그룹 등)로 다중 세션 가능.
- [ ] 본 항목은 [Phase별 실행 체크리스트 Phase 1-B·1-C](260511-Phase별-실행-체크리스트-Course-Session-Presence.md)가 단일 진실. 본 문서는 코드 위치만 가리킨다.

## 5) 리스크 & 주의

- **모듈 분리 후 전역 순서:** `map` 인스턴스가 생기기 전에 핸들러가 붙으면 안 됨 → `main.js`에서 `map.on("load", () => wireHandlers(...))` 패턴 권장.
- **토큰:** Directions REST 는 서버 시크릿만 사용. Mapbox GL 타일용 pk. 토큰은 클라이언트에 남음(URL 제한 권장).
- **분량:** 카메라/3D는 한 번에 나누지 말고, 1-A에서 물리적 파일만 분리하고 동작 검증 후 다음 커밋에서 이어가기.

## 6) 요약

- **가장 먼저:** Vite+React+TS 골격, **Firebase Auth(Google)**, 멀티 유저 최소 데이터 경로.
- **토큰·과금:** Mapbox Directions/Geocoding은 **Cloud Functions 등 프록시**로 이전.
- **프론트에 남길 것:** Mapbox GL, 레이어, 카메라, 티커, 마커, 대부분 UI.
- **안드로이드:** 웹 래핑 우선; Kotlin/RN은 필요 시만.
