## 0. 왜 이 문서가 있나

> 「우리는 절약할 것이 토큰과 시간뿐만 아니라 **좁디좁은 스마트폰의 화면**도 있다. …
>  쓸데없이 크게 만들어서 낭비되는 공간이 생기지 않도록 하는 것도 주의해야 한다.
>  이 척도는 **모든 앱에 공통으로 적용해야 할 요소**다.
>  매번 나는 이런 식의 짜증나는 작업 지시를 해 오고 있다.」(Chief, 2026-09-24)

**이 앱은 폰 가로 전용이고 CSS 높이가 약 275px 뿐이다.** 세로 공간은 거의 없다.
버튼 하나를 필요 이상으로 키우면 지도가 그만큼 사라진다. 지도가 이 제품의 본체다.

---

## 1. 규칙 (측정 가능한 것만)

| # | 규칙 | 근거 |
|---|---|---|
| **D1** | **단위는 그룹당 한 번, 제목에 올린다.** `2 km · 3 km · 5 km · 10 km` ❌ → 제목 `… (km)` + 칩 `2 3 5 10` ✅ | 같은 글자 네 번은 정보가 아니라 잡음이다. **단위를 아예 지우라는 뜻이 아니다** — 제목의 `(km)` 하나가 「이 숫자는 거리」를 알려 준다(Chief) |
| **D2** | 칩·버튼 폭은 **내용 + 최소 패딩**. 터치 44px 은 **높이와 패딩**으로 확보하지, 폭을 늘려 만들지 않는다 | 폭은 가로로 낭비되고, 세로는 어차피 44px 이 필요하다 |
| **D3** | **풀 폭 버튼은 「주 행동」 하나만.** 보조 행동을 풀 폭으로 두지 않는다 | 풀 폭은 강조 수단이다. 둘이면 강조가 아니다 |
| **D4** | 보조 행동은 **칩 행에 흡수**하거나 아이콘으로. 새 줄을 만들지 않는다 | 한 줄 = 세로 275px 중 약 6% |
| **D5** | 카드·패널 폭은 **내용에 맞춘다.** 고정 폭·임의 `min-width` 금지. ⚠ **폭을 줄였으면 텍스트가 넘치지 않는지 확인한다** — 넘친 글자가 지도를 덮으면 아낀 것이 아니라 더 나빠진 것이다(2026-09-24 지시10 에서 실제 발생) | 빈 여백은 지도를 가린 대가다 |
| **D6** | 라벨은 **2~4자**를 먼저 시도한다. 문장형 버튼 금지 | 「또는 입문 경로로 시작」 같은 줄은 링크로 충분하다 |
| **D7** | 같은 화면에 **이미 있는 좋은 예**를 따른다 — RouteDock 거리 칩(`1 3 5 10 20`) | 한 앱 안에서 두 가지 밀도를 쓰지 않는다 |
| **D8** | **임시·개발용 표면은 기존 UI 를 가리지 않는 자리에 둔다.** 겹치면 기존 것을 옮기지 말고 **임시 쪽이 비켜라** | 도구가 제품을 가리면 도구를 쓰는 동안 제품을 시험할 수 없다(2026-09-24 조명 조절판이 Quick Camera 4·5·6 을 덮었다) |

### D1 예시

```
단구동 · 여기서 첫 Ready Ride (km)
[ 2 ] [ 3 ] [ 5 ] [ 10 ]
```

단위가 **한 번은 반드시 보여야** 한다. 없애면 숫자의 의미를 잃는다.

### D8 적용 대상

`?lightlab=1` 같은 **URL 게이트 패널**, 계측 오버레이, 디버그 배지 — **붙이기 전에 그 자리에
무엇이 있는지 먼저 본다.** 폰 가로는 모서리 네 곳이 이미 다 쓰이고 있다
(좌상단 HUD·우상단 Quick Camera/계정·좌하단 카드/센서·우하단 주행 제어).

비킬 자리가 없으면 **접힌 상태를 기본**으로 하고 손잡이만 남긴다.

## 2. 하지 말 것

- 터치 타깃을 44px 미만으로 줄여 공간을 버는 것 — **이건 규칙 위반이다**.
  D2 는 「작게 만들라」가 아니라 「**넓게** 만들지 말라」다
- 글자 크기를 줄여 우겨넣는 것 — 폰 가로에서 루트 글꼴이 이미 13.5px 이다
- 여백을 0 으로 만들어 서로 붙이는 것 — 읽히지 않으면 절약이 아니다
- **단위를 통째로 지우는 것** — D1 은 「반복하지 마라」이지 「없애라」가 아니다

## 3. 검증 (UI 라운드는 이 숫자를 보고한다)

**폰 가로 근사 `740×300`** 기준으로:

| 항목 | 보고 |
|---|---|
| 카드·패널 rect (w × h) | 변경 전 / 후 |
| 카드 면적 / 뷰포트 면적 (%) | 전 / 후 |
| 가장 큰 버튼의 **내용 폭 대비 실제 폭 비율** | 1.5배를 넘으면 근거를 적어라 |
| 모든 터치 타깃 최소 44px | 충족 여부 |

**화면이 좁아진 만큼 지도가 넓어진 것**이 이 규칙의 성과다. 캡처는 전/후를 나란히 낸다.

## 4. 적용 범위

**신규·수정되는 모든 UI.** 지시서가 따로 말하지 않아도 이 문서가 적용된다.
기존 화면의 일괄 정비는 별도 라운드로 하되, **건드리는 김에 같은 화면 안의 위반은 함께 고친다.**
