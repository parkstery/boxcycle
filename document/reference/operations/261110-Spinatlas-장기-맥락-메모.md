# Spinatlas 장기 맥락 메모

> 용도: 새 AI 대화가 Spinatlas를 매번 처음부터 묻지 않도록 돕는 프로젝트 기억. 제품·기술의 정본이나 최신 진행 상태를 대체하지 않는다. 최신 작업은 항상 저장소의 HANDOFF·PROGRESS·해당 ops 문서와 Chief 결정을 다시 확인한다.

## 프로젝트 정체성

- 제품 표시는 **Spinatlas(스핀아틀라스)**. 과거 브랜드 RTW / Ride the World. 코드·리포·Firebase projectId는 `boxcycle`로 유지한다.
- 목적: 실내 자전거로 실제 지구의 도로를 달리고, 달린 길을 **내 도로망**으로 영구 축적해 운동을 재미와 성취감으로 이어 간다.
- 핵심 판타지 **Ride = Claim**. 운동·주행이 본체이고 정복은 보상이다. 게임 월드 그래픽이나 속도 경쟁보다 현실 지구 전체와 탐험의 축적을 차별점으로 삼는다.
- 코어 사용자 가설은 케이던스 이상 센서를 가진 캐주얼 실내 라이더. 센서 없는 체험도 진입을 돕지만, 정식 인정·순위 규칙은 테스트 완화 상태와 구분해야 한다.
- 핵심 흐름: 지역/첫 경로 발견 → Ready Ride 또는 경로 선택 → 센서 준비 → 주행 → 결과·새 도로 → 이어 달리기. 함께 달리기(Trail), 인터벌, 지역 통계·순위는 이 루프를 돕는다.

## 제품·협업 원칙

- 최종 사용 기기는 스마트폰 가로 화면. 지도와 달린 흔적이 주인공이고 HUD·입력창은 공간을 아낀다. Chief가 지정해 고정한 화면은 명시 지시 없이 바꾸지 않는다.
- Ontology 용어를 따른다: Route, Trail/Trailhead, Guest, 내 도로망/Conquest. 레거시 식별자와 Firestore 경로는 승인된 별도 계획 없이 일괄 rename하지 않는다.
- Chief(사용자)가 제품 방향과 중요한 데이터·아키텍처·비용·기능 의미를 결정한다. 일상 구현·검증은 자율 진행하되 계약 변경·배포는 별도 승인과 증거를 따른다.
- 사용자는 바이브코딩으로 Spinatlas를 개발 중이며 상용 서비스·소프트웨어 개발 실전 경험이 없다고 밝힘. 반복해서 고치고 지우는 과정 속에서 “방향이 맞는지, 중요한 축을 놓쳤는지”를 확인하고 싶어 한다. 답변은 도구 사용법이나 코드 정리만으로 좁히지 말고 제품·사용자·개발·운영 전체 맥락을 설명한다.
- 판단은 근거와 확신 수준을 밝혀 말한다. 문서상 계획, 로컬/합성 시험, 배포 증거, 실폰·실센서·실사용 검증을 서로 구분하고, 모르는 점은 모른다고 한다. 안심시키려고 미확인 사항을 완료로 표현하지 않는다.
