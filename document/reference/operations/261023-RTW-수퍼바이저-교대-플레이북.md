## 0. 원칙 — 기억은 대화가 아니라 리포에 둔다

- 수퍼바이저는 **교대된다**. 대화 맥락·agent 전용 메모리·agent 전용 도구에만 남은 정보는 다음 수퍼바이저에게 **없는 정보**다.
- 그래서 판단에 필요한 것은 모두 리포 파일에 둔다: 지금 상태는 [HANDOFF.md](../../ops/HANDOFF.md), 작업 단위는 ops 묶음, 규칙은 이 문서와 [협업 계약](261009-RTW-개발에이전트-협업-감리.md).
- agent 전용 기능(Claude 의 claude.ai 아티팩트·`~/.claude` 메모리·서브에이전트, Codex 의 `~/.codex` 설정 등)은 **써도 되지만**, 그 결과는 반드시 리포에 사본을 둔다. 예: 디자인 캔버스 → `ops/<묶음>/mockups/*.html` + `*.png`.
- **한 번에 수퍼바이저는 하나.** HANDOFF.md 맨 위 「담당」 줄이 지금 담당이다.

## 1. 시작할 때 (인수)

1. [HANDOFF.md](../../ops/HANDOFF.md)를 읽는다. 「담당」 줄을 자기 이름(예: `Codex`, `Claude Code`)과 시각으로 바꾼다.
2. `git status --short` · `git log --oneline -10` · `git diff --stat`으로 HANDOFF 의 「작업 트리」 기록과 실제를 대조한다.
   - **기록에 없는 변경**은 앞 수퍼바이저가 끊기기 직전의 작업이거나 실행자(Cursor 등)의 미완 작업이다. 해당 묶음의 최신 지시서·결과 파일과 맞춰 본 뒤 이어서 쓰거나, 범위 밖이면 손대지 않고 HANDOFF 에 적는다.
   - 절대 `git restore`·`git checkout -- .`·`git clean`으로 날리지 않는다.
3. HANDOFF 의 「다음 한 걸음」과 링크된 묶음 README·최신 지시서를 읽는다.
4. 「chief 결정 대기」에 답이 왔는지 대화를 확인한다. 답이 없으면 그 항목은 기다리고, 그것과 무관한 다음 일을 한다.
5. chief 에게 한 줄로 알린다: 「[감리] Codex 가 이어받았습니다 — 다음: ○○」.

## 2. 끝낼 때·끊기기 전 (인계)

토큰이 바닥나기 전, 그리고 **작업 단위(지시→감리→커밋)가 하나 끝날 때마다** 한다. 끊기면 마지막 HANDOFF 갱신 이후가 사라진다고 가정한다.

1. HANDOFF.md 갱신: 다음 한 걸음(구체적으로 — 파일·명령까지), 결정 대기, 진행 중 하위 작업, 작업 트리 상태, 최근 커밋·배포.
2. 해당 묶음에 결과/감리 파일을 남긴다(번호 규칙은 [ops README](../../ops/README.md)).
3. [PROGRESS.md](../../ops/PROGRESS.md) 맨 위에 한 줄, [ops README](../../ops/README.md) 맨 위에 한 줄(묶음 상태가 바뀐 경우).
4. 커밋할 수 있는 것은 커밋한다(문서는 수퍼바이저가 직접 커밋해도 된다). 다른 작업의 변경을 섞지 않는다.

## 4. 감리 (실행자 결과를 받았을 때)

실행자의 「통과」는 증거가 아니다. 수퍼바이저가 직접 다시 돌린다.

```
cd C:\20.HDev\boxcycle\apps\web
npx tsc -b --noEmit                       # -p . 는 빈 검사다. 반드시 -b
npx eslint <바뀐 파일>                     # 경고는 기존 기준선, error 0 이어야
npm run test:quick                        # 단위 전체(현재 1353)
cd C:\20.HDev\boxcycle
node scripts/check-code-tidy.mjs          # 안 쓰는 export·반복·큰 파일 래칫 — 수치가 늘면 안 됨
node scripts/check-dep-direction.mjs --check   # lib 도메인 의존 방향
cd C:\20.HDev\boxcycle\apps\web
$env:RTW_DEV_PORT=5016; npx playwright test ui-800x360 --workers=1 --retries=0   # 기존 실패 :84 1건만 허용
$env:RTW_DEV_PORT=5017; npm run test:e2e:ride                                    # 실제 앱·에뮬레이터 7/7
cd C:\20.HDev\boxcycle\functions; npm test                                        # 서버(현재 169)
```

- Git Bash 에서는 `export PATH="/c/Program Files/nodejs:$PATH"`를 먼저 한다. `~/bin/npm` 래퍼가 깨져 있어 pre-push 게이트가 전멸한다.
- 확인할 것: 실제 `git diff`(범위 밖 수정·검사 완화가 없는지), 캡처를 시안과 나란히, 경계 위반(의존 방향·export 증가), 주석·문구 규칙.
- **게이트를 통과시키려고 규칙(기준선·허용 엣지·검사식)을 넓히는 수정은 반려한다.** 코드를 고친다.
- 감리 결과는 묶음의 결과 파일 끝에 「감리」 절로 덧붙인다(판정·감리 수정·재검 숫자).

## 5. 커밋·푸시·배포

- 개발 base 는 `main2`. 커밋 메시지는 영어 제목 + 왜(본문), 끝에 그 agent 의 서명 줄(Claude: `Co-Authored-By: …`, Codex: 자체 규칙).
- pre-commit(eslint)·pre-push(10개 게이트)를 우회하지 않는다. `--no-verify`는 chief 승인 없이는 금지.
- **배포는 chief 승인 후 수퍼바이저가 직접.** 승인은 「커밋·푸시·배포」를 한 번에 묻는다(단계별로 다시 묻지 않는다). 명령은 그대로:
  - 함수: (루트) `firebase deploy --only functions`
  - 화면: (루트) `npm run deploy:hosting`
- 배포 뒤 확인: 함수는 토큰 없이 불러 401, 화면은 `https://boxcycle-dc2df.web.app` 번들에 새 문구가 들었는지(`curl` 로 assets js 를 받아 grep). 확인 결과를 보고에 적는다.
- 운영 데이터 삭제·이동은 chief 승인 + 사전 스냅샷. **Firestore 백업이 꺼져 있다**(2026-10-08 기준).

## 6. chief 와 말하기

- 한국어 존댓말, 호칭 「chief」. 결론부터, 쉬운 말로(chief 가 설명을 다시 AI 에게 해석시키는 일이 없게). 표·짧은 문단.
- 이미지·캡처는 `file:///C:/20.HDev/boxcycle/...` 절대 경로 링크로.
- 직접 확인을 부탁할 때는 **실행 폴더 절대 경로·복사 가능한 명령·주소·새로고침 여부**를 함께.
- 질문은 되돌리기 어렵거나, 요구가 충돌하거나, 권한·정보가 없을 때만. 그 밖에는 진행하고 보고한다.
- 각 단계는 **그림 먼저**: 화면 작업은 캡처를 보여 주고 승인받은 뒤 다음 단계.

## 7. 환경 사실 (틀리기 쉬운 것)

| 사실 | 내용 |
|---|---|
| localhost:3000 | chief 의 다른 프로젝트(imgman). **끄지 않는다.** 그 밖의 boxcycle 개발 서버는 꺼도 된다 |
| localhost:5000 (`npm run dev`) | **운영 Firebase 에 쓴다.** 데이터 시험은 에뮬레이터(5002, `test:e2e:ride`) |
| e2e 포트 | 여러 실행이 겹치면 `RTW_DEV_PORT=50xx`로 나눈다. webServer 타임아웃은 대개 포트 충돌 |
| 에뮬레이터 | `test:e2e:ride`가 `emulators:exec`로 자동 기동. 동시에 두 개 돌리면 포트가 막힌다 |
| 기존 실패 시험 | `apps/web/e2e/ui-800x360.spec.ts:84` (시작·센서·접기…) — 이번 작업과 무관하게 실패 |
| 「Trail 메뉴」 버튼 | 지도 아래 숨은 접근성 버튼. Playwright 는 `.focus()` 후 `Enter` |
| 메모리 | PC 메모리가 부족하면 백그라운드 실행(Cursor 등)이 강제 종료된다. 무거운 e2e 를 동시에 돌리지 않는다 |
| RTDB | 리전 URL(asia-southeast1)이 `.env`에 있어야 한다. 없으면 동행 동기화가 깨진다 |
| Cursor worktree | Cursor 가 worktree 를 만들면 junction 을 따라 비추적 파일(`.env.local`, node_modules)이 지워진 사고가 있다 → 지시서에 금지 |

## 8. 증상별 먼저 볼 곳 (회귀로 오해하기 쉬운 것)

- 지도 위 빨간 점이 안 보임 → 24시간 윈도·주행 폐기 정책부터. 회귀 아님인 경우가 많다.
- 표고 그래프가 없음 → Open-Meteo 일일 한도(429)부터.
- MENU 에 주행자 없는 Trail → `openTrailListings` 가 낡았는지부터.
- 동행 점이 튐 → 지도 표시는 15초, 멤버 목록은 240초 기준. 수신 시각 차부터.
- 하네스는 통과하는데 실제 앱이 실패 → 하네스가 App 과 다른 props·베낀 CSS 를 쓰는지부터.
- mapbox `isStyleLoaded()`를 적용 조건으로 쓰면 라이브 소스 때문에 영영 적용 안 될 수 있다 → 레이어 확인 + idle 재시도.
- 「없다」고 판단하기 전에 어디를 찾았는지 적는다(리포 루트 `blender/` 를 자주 빠뜨린다).
- 같은 수정 3번·주행 시험 5분 진전 없음 → 접근을 바꾼다.
