## 역할과 인계

- Chief: 제품 방향·중요 결정·최종 완료 승인. AI 사이의 반복 전달을 맡지 않는다.
- Codex Supervisor: 요구 해석, 작업 분할, 지시, 실제 diff·시험·화면 검수, 재작업 판정과 상태 보고.
- Developer: 기본 Cursor AI/CLI. Chief가 OpenCode 사용을 명시적으로 요청할 때만 GLM-5.3을 사용하고, 사용 불가 시 Cursor로 돌아온다. 같은 지시·보고·검수 기준을 따른다. 안내·질의·권한 요청은 한국어로 작성한다.

1. 작업 묶음 README와 최신 지시를 읽는다. 채팅 기억보다 파일·현재 소스를 우선한다.
2. 지시는 담당·허용 파일·금지 범위·완료 조건·검증 명령·결과 경로·승인 조건을 포함한다. 첫 투입은 작은 조사로 인계를 검증한다.
3. 시작 때 branch/HEAD/dirty와 실제 모델·세션을 기록한다. 같은 작업의 쓰기 담당은 한 명이다. 다른 변경을 되돌리거나 섞어 커밋하지 않는다.
4. 교대 때 기존 실행을 중지하고 별도 결과 파일에 완료·미완·변경 파일·마지막 시험·다음 행동을 남긴다. 후임은 기록과 현재 diff를 대조한다.
5. Developer는 명령·종료 코드·PASS/FAIL/미실행·증거 경로·한계를 기록한다. 계획이나 모델의 자기평가는 실행 증거가 아니다.
6. Supervisor는 실제 diff·범위·증거를 확인하고 필요한 검증을 독립 재실행한다. 검수는 별도 파일, 재작업은 새 번호로 남긴다. APPROVED와 Chief의 최종 CLOSED는 구분한다.
7. 작업 완료 보고에는 Chief의 직접 테스트를 위한 실행 폴더 전체 절대 경로와 이동 명령, 복사 가능한 실행 명령, 접속 주소·확인 순서를 함께 적는다(2026-10-17 Chief 지시). 상대 경로만 제시하거나 이미 배포된 것으로 오해하게 안내하지 않는다.

## 모바일 UI 감리

- 최종 타겟 스마트폰, PC는 개발·반복 검증 환경. PC 캡처만으로 모바일 합격 처리 금지.
- 현행 폰 가로 방향·회전 안내 유지. 세로 지원은 별도 제품 결정.
- 검증 후보 CSS viewport: 740×300(기존 기준), 667×300(좁은 가로), 844×390(여유 있는 가로), PC 1366×768.
- 준비·탐색·주행·결과와 긴 주소·센서 미연결·로딩·오류를 검토한다.
- 터치 타깃 44px 이상, 안전 영역·브라우저 높이 변화·스크롤·패널 충돌 확인. 지도 확보를 위해 글자·터치 영역을 축소하지 않는다.
- 전후 캡처와 패널 rect·점유율·잘림·겹침·터치 영역을 보고한다.
- PC 모바일 에뮬레이션과 실기기 검증을 구분한다. Bluetooth·터치 체감·브라우저 UI·성능을 에뮬레이션만으로 통과 처리하지 않는다. 실기기 미검증은 명시한다.

## 단계·권한

조사 → 모바일 대표 화면·공통 규칙 초안 → Supervisor 검수 → Chief 디자인 방향 승인 → 작은 구현 단위 → 기능·시각 검수 → 최종 완료 승인.

현재 디자인 작업은 코드 작성 금지 상태다. 조사 제안을 구현 승인으로 해석하지 않는다. 운영 데이터·배포·아키텍처·공용 인터페이스 변경은 별도 범위·결정 조건을 확인한다. 승인된 일상 작업의 중간 전달·재작업은 Supervisor가 맡는다.
