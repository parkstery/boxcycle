## 0) 실행 단계와 본 문서의 역할

### 0.1 현재 채택 (본 개발 초기 ~ 1차 마일스톤)

PM·시니어 합의 기준(2026-05-09, 2026-05-11 보강):

- **서비스 비전·도메인 분류·UGC 정책의 단일 진실**은 [260511-RTW-마스터-비전-및-종합계획.md](260511-RTW-마스터-비전-및-종합계획.md). 본 문서는 그 결정을 **장기 Postgres 관점**에서 보강한다.
- **클라이언트:** Vite + TypeScript + React. 안드로이드는 **웹 래핑(WebView / Capacitor 등)** 을 우선하고, **Kotlin·React Native** 는 필요 시에만 검토한다.
- **데이터·백엔드(초기):** **Firebase 단일**로 서비스 동작·멀티 유저를 검증한다. 스키마는 이후 Postgres 분리를 고려해 [Firestore→Postgres 체크리스트](260509-Firestore-Postgres-이전-체크리스트.md)를 준수한다.
- **인증(1차):** **Google(Gmail)** 로 빠른 검증.

### 0.2 본 문서 §1 이하의 위치

- §1 **MVP 기능·플랜**, §2 **PostgreSQL 스키마**, §3 **REST API 초안**, §4 **Nest·Redis·PostGIS 등** 은 **장기 제품·인프라 목표** 및 분리 이후 설계의 참고안이다. 코드에 즉시 반영해야 하는 계약으로 읽지 않는다.
- 8주 로드맵(§5)은 **방향성 예시**이며, 달력 주차는 **현재 단계 문서·실행 체크리스트**와 재정렬할 수 있다.

## 1) MVP 기능 명세 (무료/유료)

### A. 공통 핵심 기능
- 회원/인증: 이메일/소셜 로그인(구글 우선), 기기 식별, 기본 프로필
- 코스 타입
  - `starter`: 신규 유저 온보딩 강제 코스
  - `curated`: 운영자 선별 코스
  - `ugc_private/public`: 사용자 생성 코스
- 주행 세션: 시작/일시정지/종료, 거리/시간/평균속도/칼로리 추정 기록
- Presence: 현재 코스 실시간 탑승자 수, Ghost rider, 최근 24시간 흔적(replay-lite)
- 코인 시스템: 완주/거리/미션으로 획득, 코스 생성/검증에 사용, 원장 기반 감사
- 코스 공유/평점: 공개 코스 북마크, 별점/신고, 월간 인기 코스 선정

### B. 무료 플랜
- Starter + Curated 코스 이용
- 개인 코스 생성 월 2회 (초기 예시)
- 1회 생성 가능 거리 최대 50km
- 기본 기록(최근 30일)
- 기본 뱃지/주간 미션

### C. 유료(Pro) 플랜
- 개인 코스 생성 월 30회(또는 무제한)
- 50km 제한 해제
- 프리미엄 scenic 코스 이용
- 고급 분석(FTP 추정, 존별 시간, 주간 리포트)
- 커스터마이징(트레일, 닉네임 스타일, 저지 스킨)
- 시즌 챌린지 보상 강화
- 기록 보관 무제한

## 2) DB 스키마 초안 (PostgreSQL + PostGIS)

### 핵심 테이블
- `users`
  - `id`, `email`, `provider`, `nickname`, `country_code`, `created_at`
- `user_profiles`
  - `user_id`, `weight_kg`, `height_cm`, `privacy_level`, `avatar_style`
- `plans`
  - `id`, `code(free/pro)`, `monthly_price`, `features_json`
- `subscriptions`
  - `id`, `user_id`, `plan_id`, `status`, `start_at`, `end_at`
- `courses`
  - `id`, `creator_user_id(nullable)`, `type(starter/curated/ugc)`
  - `title`, `description`, `is_public`, `status(draft/verified/published/archived)`
  - `distance_m`, `elevation_gain_m`
  - `route_geom(LineString, 4326)` (PostGIS) — 입문 허브 소형만; 사용자 코스는 `geometry_url` 사용 권장 ([저장 계층화](260511-경로저장-계층화-Frozen-Route-Segment.md))
  - `style_mode(2d/3d/mixed)`, `created_at`
  - **(2026-05-11 추가)** `lifecycle_stage(temporary/active/public_candidate/public_approved/inactive/archived/deleted)` — [코스 수명 정책 §3](260511-코스-수명-UGC-품질-정책.md)
  - **(2026-05-11 추가)** `last_activity_at(timestamptz)`, `score(numeric)`, `owner_kind(personal/public)`
  - **(2026-05-11 추가)** `visibility(public/unlisted/private)`, `presence_enabled(boolean)`, `is_in_conquest_collection(boolean)`, `is_pinned_by_owner(boolean)`
  - **(2026-05-11 추가)** `geometry_url(text, nullable)` — Object Storage 포인터, encoded polyline. 본 컬럼이 있으면 `route_geom`은 NULL 가능
- `course_points` (선택)
  - `id`, `course_id`, `seq`, `lat`, `lng`, `elevation_m`
- `rides`
  - `id`, `user_id`, `course_id`, `started_at`, `ended_at`
  - `duration_sec`, `distance_m`, `avg_speed_kmh`, `calories_est`
  - `source(android/web)`, `is_completed`
- `ride_samples` (초기 생략 가능)
  - `id`, `ride_id`, `ts`, `distance_m`, `speed`, `cadence`, `power`
- `presence_sessions` *(레거시 명; 아래 (2026-05-11 추가) 두 테이블로 분해 권장)*
  - `id`, `user_id`, `course_id`, `joined_at`, `last_seen_at`, `state`
- **(2026-05-11 추가)** `sessions` — 같은 코스에서 여러 세션이 동시 존재 가능 ([RTW 마스터 §2.1](260511-RTW-마스터-비전-및-종합계획.md))
  - `id`, `course_id(FK courses)`, `mode(public/private/event)`, `visibility(public/unlisted/private)`
  - `max_players`, `created_by(FK users)`, `created_at`, `closed_at(nullable)`
- **(2026-05-11 추가)** `presence` — 세션 내부 실시간 상태(고빈도 쓰기, Redis 캐시 권장)
  - `session_id(FK sessions)`, `user_id(FK users)`, `lat`, `lng`, `speed`, `heading`, `last_seen_at`
  - PRIMARY KEY (`session_id`, `user_id`)
- `coins_ledger`
  - `id`, `user_id`, `delta`, `reason`, `ref_type`, `ref_id`, `created_at`
- `coin_balances` (캐시성)
  - `user_id`, `balance`, `updated_at`
- `course_ratings`
  - `id`, `course_id`, `user_id`, `stars`, `comment`, `created_at`
- `course_bookmarks`
  - `user_id`, `course_id`, `created_at`
- `missions`, `mission_progress`, `mission_rewards`
- `reports`
  - `id`, `reporter_user_id`, `target_type`, `target_id`, `reason`, `status`
- `audit_logs`

### 인덱스/제약 포인트
- `courses(route_geom)` GiST 인덱스
- `coins_ledger(user_id, created_at)` 복합 인덱스
- `rides(user_id, started_at desc)` 인덱스
- `course_ratings(course_id, user_id)` 유니크 제약
- 코인 정합성 기준은 `coins_ledger`, `coin_balances`는 조회 캐시

## 4) 권장 아키텍처

### 4.1 단기(현재 단계와 정렬)

- **Client:** React + TypeScript(Vite 빌드), 웹 우선 → 안드로이드는 래핑 우선.
- **BaaS:** Firebase(Auth, Firestore 등)로 멀티 유저·영속화 검증.
- **Mapbox 등 외부 API:** 가능한 한 **토큰은 서버 측**(예: Cloud Functions 또는 추후 전용 API)으로 옮긴다.

### 4.2 장기(분리·성장 이후 참고안)

- Client: React(Web) 유지; 네이티브 앱이 필요하면 그때 Kotlin 또는 React Native 검토.
- API: NestJS 등 Node 계층(또는 이와 동등한 구조화된 API 서버).
- DB: PostgreSQL + PostGIS
- Realtime: Redis + WebSocket Gateway 등
- Queue: BullMQ (경로 검증/썸네일/리포트 생성)
- Storage: S3 호환
- Observability: Sentry + Grafana

핵심 원칙: 지도 렌더링보다 **코스·프레즌스·(향후) 경제** 도메인을 서버 기준으로 설계한다. 초기에는 Firebase 규칙·함수로 이 원칙을 최대한 지키고, 이후 동일 도메인을 Postgres로 옮긴다.
